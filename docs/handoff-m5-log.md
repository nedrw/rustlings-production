## 段 1：第一性原理评审，与它落成的三件事（2026-10-27）

1. **补丁链是全仓最脆的产物类**（本 session 三起手改损坏）。处置：`kiln prepare` 子命令

   `tools/rebuild-patches.py`（铺链 → 可选 fixes → rustfmt → 按已提交补丁的段标签/段序重生成 →

2. **i18n 机制从未装过真翻译**——回退链、结构检查、漂移检测全是未负载检验的机制。处置：
   zh-Hans 首批三步（mailer 1.1–1.3），`kiln i18n status` 结构 0 error、`--lang zh-Hans` 时正文
   解析到 `course/docs/steps/zh-Hans/…`。机制给翻译定了两条硬规则，实测才显形：**标题行必须逐字

3. **门的作用域曾是隐式的**（`unsafe-budget` 收尾时的按步化是第一次显式化）。处置：规则写进

## 段 3：第三个 flake——`4.1` 的跨连接竞态

CI 的 lakelet selftest 在 4.1 挂了一次（12 个测试并行时 3/4 复现）：`a_frame_that_is_not_one…` 等
的是**垃圾连接**的拒绝日志，而它断言的记录在**另一个连接**的落盘里——两个事实互相独立，守护进程
晚一点读第二个 socket，规格就在落盘前打开了 spool。修法是等自己那个事实：第二个连接自己的
`accepted=1 rejected=0` 收线日志。规格改动重钉 manifest（24 份），修后五次并行全绿。三个 flake
（1.21 容器、这个、以及 review 轮的容器门）的共同教训已经一致：**测试要等它断言的那个事实的发生
信号，而不是另一个并发方的信号。**

## 段 4：子 agent 评审，以及它抓到的八条

按用户的请求拉了一个子 agent 评审段 1–3 的全部产物。它自己铺链、比对旧树与新树、逐条试错，
抓到的不是风格问题而是**真缺陷**（`git diff 6cc157b..86a548b` 是它的证据）：

1. **`--check` 对"补丁少了一个文件段"失明**（最重）。工具只重生成补丁自己列出的段，所以一份漏掉
   某文件改动的补丁会通过检查——正是工具要抓的那一类。**但根因比这更深**：树是补丁铺出来的，
   一份当初就写错的补丁，它的树也是错的。工具真正能抓的是"补丁与它定义的树脱节"（手改过的补丁、
   没格式化的交付物、链的不一致）；漏写只在**下一步**的脚手架里露出，因此一条 track 的**最后一步**
   没有这样的证人。工具的文档改为说清这件事（而不是声称"逐字节一致"——那句本来就不成立：比较是
   语义的，hunk 头与上下文宽度是差异器的自由度）。
2. **写模式会静默丢段**：两棵树都没有的文件（`Cargo.lock` 由构建生成、树里没有）的段会消失而无
   提示。现在保留原段。
3. **`--steps` 是不可能工作的**：过滤掉链的前面几步之后，第一步的脚手架没有可比较的前一棵树。
   现在 `--steps` 选的是**写哪些**，链照铺。
4. **工具的自我描述不实**（"逐字节一致"）、**plan 章节指针错**（§6 → §10）、**审计数字错**
   （8/10/3 → 4/10/3 = 17，另 3 份是工具自己的假漂移）、**xtask 的失败消息不指名真正的原因**。
5. **已跟踪的 `.pyc`**（`tools/__pycache__/…`）——删掉并加 gitignore。
6. 风险两条已修：用户的 git 配置（颜色/外部 diff/前缀）不再影响输出；rustfmt 现在格式化树里
   **所有** `.rs`（`xtask/src/main.rs` 也在内，而 `fmt` 门判的是整个项目）。

**工具因此有了自己的自测**（`--self-test`，CI 也跑）：四条保证各配一个合成用例——"补丁漏掉一个
被改动的文件会被发现"、"两棵树都没有的文件的段被保留"、"上下文宽度与 hunk 边界不是内容"、
"增删行变了就是内容变了"。第四条的样本一开始写错了（把改动写成了上下文，等于一个空补丁），
是自测自己抓到的。

**没有采纳的一条**：README 里易腐的散文计数仍然不做文档断言检查（理由同段 1）。

## 段 5：共享构建目录让 CI 说了一句关于课程的谎（第三个 flake 的根）

CI 的第二轮在 `mailer/1.6` 与 `1.7` 报 "BROKEN STEP: the spec passes on the scaffold"——而这两步
在别的每一轮里都是绿的。查下去是**机制**而不是内容：

* 规格用 `env!("CARGO_BIN_EXE_mailer")` 启动服务进程。cargo 把编译出的二进制**上提到**
  `<target>/debug/<name>`——每个包名一个路径——而 `CARGO_BIN_EXE_<name>` 指的就是它。
* `kiln selftest` 用的是**全机共享**的 target 目录。于是任何一次"另一个树里的同名包"的构建
  （另一次 selftest、或一次被杀掉的运行留下的 cargo）都会把那个文件换掉。
* 被换掉的那次构建带的是**参考解的**二进制（被杀掉的运行已经走过 1.6 的解），于是新沙箱的
  **脚手架**跑出了解的行为——判决说"这一步分不开两个状态"，而真相是"这次跑的二进制不是这棵树的"。

**修法**：`kiln selftest` 的构建目录改为**本次运行自己的**（沙箱目录下的 `target/`），而不是全机共享的。
代价是每条 track 每次运行要重编依赖（实测 mailer 冷目录约 +1 分钟），换来的是"另一次构建换不掉这次
要启动的二进制"这条性质——按目录而不是按包名隔离。

**运行器的判决也改了**：脚手架通过时，它现在把两种可能都说出来（这一步真的分不开两个状态 / 这次跑的
二进制不是这棵树的），并指出"单独跑这一步能分辨"。一个只说第一种可能的判决，会让下一次调查从错误的
方向开始。

**顺带的一条**：CI 那一轮还撞上一次 crates.io 索引停顿（"failed to transfer more than 10 bytes in
30s"），一步因此被判红。cargo 的默认是"三十秒内不到十字节就放弃、重试三次"——那是为笔记本上的咖啡馆
wifi 调的，不是为一台同时被一百个构建索取的机器。运行器现在给 cargo 三个更耐心的默认值
（`CARGO_NET_RETRY=10`、`CARGO_HTTP_TIMEOUT=120`、`CARGO_HTTP_LOW_SPEED_LIMIT=1`），而且**调用方自己
写的值优先**（学员想用 cargo 自己的行为、或 `CARGO_NET_OFFLINE=true`，都还是他的）。一个单测把这三个
默认值钉住。

## 段 7：术语表——一条规则指向了一个从未存在的文件

`authoring.md` §8 一直写着"术语查 `glossary.toml`；新术语先加进词表再翻译"，而**这个文件不存在**。
这是"规则写了、机制没装"的又一例（和 i18n 回退链、门作用域同族）。这一段把它装上，并且**让它被检查**——
一张没人读的词表和没人查的 lint 表是同一种装饰。

**词表**（`course/glossary.toml`，69 条）：一个英文词 + 每种语言约定的说法，可选 `note`（给译者）与
`except`（这个词在某个说法里是另一个意思，表不管——`probe` 既是本课程的探题，也是 Kubernetes 的探针）。

**检查**（`kiln i18n status`，以及 `kiln check` 的 `i18n` 门）：英文正文用了表里的词、而译文没用约定的
说法，就报一条漂移告警。它**只读散文**——代码片段、行内代码、链接文字都不算词汇：实测第一版把
`mailer/1.1-workspace`、`Argon2::default()` 当成了词，一轮就报了八条假阳性。中文词被换行拆开时
（「默」/「认」）也算说到了。

**裁决过程本身就是检查的价值**：它先报了 14 条，逐条看下来——
- `step` 的约定说法是「步」而不是「步骤」（中文说「第 N 步」「这一步」）；
- `default` 是「默认」而不是「默认值」（形容词的位置）；
- `workspace` 保持拉丁（Cargo 自己的词，`[workspace.lints]` 更是逐字节不动）；
- `app factory` 是「app 工厂」，与课程自己的 [t1-mailer.md](t1-mailer.md) §4 一致；
- 1.1–1.3 的「must 门」改成「must 闸门」，与词表和后来的译文一致。

**译文的覆盖面**：zh-Hans 从 3 步到 **10 步**（mailer 1.1–1.8 + 之前的三步复核），结构 0 error、漂移 0 warning。
两个翻译 agent 各自独立指出词表缺词与冲突（`probe` 与存活探针、`app factory`、缺 catch-all/fallback/extractor），
这些都补进了表里。

## 段 8：一个死了的 owner 能把 CI 搁置半小时

CI 这次挂在 `kiln` 自己的一个集成测试上（`coverage_measures_the_step_module_or_names_the_component_to_install`），
原因不是课程而是**锁**：`coverage` 门在共享缓存里建一个有锁的构建目录，锁文件记下 owner 的 pid 与时刻，
但**没人检查那个 pid 还活着没有**。我为了并行工作杀掉的 CI 留下的锁，让下一个运行等满 `CLAIM_STALE`
（三十分钟）——而那个 pid 早就死了。

修法：`claim_within` 在拿不到锁时读 pid，用 `ps -p <pid>` 问一句；问不到就立刻接管（与"文件比 `stale`
更老"的旧规则并存，那条仍是兜底）。`ps` 是这个仓库已经在用的 POSIX 工具（进程夹具的 `SIGTERM` 就是
它），`std` 里没有等价的问法。pid 会被复用，所以这个答案只是"大概不在了"——代价有界（锁被接管、两个
运行写同一个构建目录），所以只在紧接着又一次 `take` 时才动手，旧的时间规则照旧兜底。两个单测钉住
两侧：owner 死了要接管，owner 活着要等。

**同一段里的一句自省**：这次的失败是**我自己并行跑工作**撞出来的（CI 在跑 `cargo test` 时我在同一个
`XDG_CACHE_HOME` 下跑别的 kiln 命令）。这条也记在 [m4-t5-progress] 的记忆里：门之间共享的目录与锁，
是为了让并发的运行互相绊住——所以**验证 CI 时不要在同一份缓存上并行做别的 kiln 工作**。

## 段 9：耐心必须有界，判决必须点名网络

上一段给 cargo 加的"耐心"旋钮设错了量级：10 次重试 × 120 秒，而一步的死线是 300 秒。网络真的断掉时
（这台机器当时连不上 `index.crates.io`，curl 也超时），一个步骤把整条死线烧完，然后报告"timed out"——
一句把读者引向课程的错误的话。改成 3 × 30 秒：慢传输仍然不判红，而"没有路由"在死线之内失败。

并且让判决**说出真相**：`kiln selftest` 在两种情况下都改口——脚手架的规格"失败"、以及参考解的规格
"仍然失败"——只要 cargo 的输出里有注册表不可达的痕迹（`spurious network error`、`failed to get`、
`Couldn't connect to server` 等），判决就说"这次跑不成：crate registry 不可达——这是网络，不是这一步，
它对脚手架什么也没证明"。一个"规格在脚手架上失败"的判决如果是网络造成的，那是另一种假证据：规格根本
没跑过，什么都没证明。单测把这两条钉住。

**当时的 CI 状态**：`relay/2.1` 因为断网超时，这一轮没有绿——记在这里，等网络恢复后重跑。

## 段 10：翻译的边界被写下来，并被检查

用户指出了一条本来就该有、但仓库只在 plan.md 里写反了的原则：**只有课程内容需要翻译；运行器的报错、
提示、闸门名、规格失败文本都不翻。** plan.md §3 D5 原来写的是"`kiln` 自己的提示语也在 `ui.toml`，
所以切换接口同时覆盖课程正文与 CLI"——那句话把一个按政策不做的事说成了承诺，而 `i18n status` 每次还会
打印一行 `cli catalogue: none (built-in English is used)`，读起来像一个待填的缺口。

改了三处：
1. **plan.md §3 D5** 改成真正的边界：译文覆盖步骤正文（外加课程自己的两句招呼语），运行器其余输出保持英文，
   并写明理由——它们引用代码、路径、标识符与编译器输出（`error[E0308]`、`assertion left == right failed`），
   翻译后既不能复制粘贴，也会给每次消息改动多添一份译文；
2. **`i18n status`** 只在真的有目录时才打印那一行；
3. **检查（`glossary::translated_output`）**：译文把运行器的输出写成自己的散文时，报一条漂移告警。标记是
   `error[E`、`panicked at`、`test result:`、`must gate`、`spec tests pass` 等；代码片段里的引用不算
   （那是引文，允许的）。单测钉住两侧。

**顺带把上一段的"两档 CI"问题记在这里**：内容改动（译文）跑全量 CI 是三十分钟换十秒该做的事；仓库目前
没有"这次改了什么"的概念。可行的形状是内容档（links / i18n / lint-caps / 文档计数）与全量档（只有改动落在
`kiln/`、`xtask/`、`course/tracks/`、`course/probes/` 时才跑）。没有做，因为这一轮先把边界本身立住。
