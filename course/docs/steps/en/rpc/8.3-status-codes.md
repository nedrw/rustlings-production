# A status code is part of the API

## WHY

A gRPC status is a small closed set, and clients branch on it: a backoff retries `UNAVAILABLE`, a
form shows the message for `INVALID_ARGUMENT`, and nobody retries `INTERNAL` because it will not
become true. Mapping an internal failure onto the wrong code is not cosmetic — a validation error
reported as `UNAVAILABLE` is a retry storm of something that can never succeed, and a database
outage reported as `INVALID_ARGUMENT` is a client that stops retrying exactly when retrying is the
only cure.

The set is small on purpose. Six failures cover the way services fail, and each has one canonical
code; the retry decision follows from the code, not from a per-call-site judgement.

## TASK

The scaffold added `src/status.rs` and its `pub mod status;` line; both functions are stubs.

- **[`code_for`]** — the canonical code for an internal failure: a bad request is
  `INVALID_ARGUMENT`, a missing row `NOT_FOUND`, a duplicate `ALREADY_EXISTS`, an overloaded server
  `RESOURCE_EXHAUSTED`, a bug `INTERNAL`, a failing dependency `UNAVAILABLE`.
- **[`retryable`]** — `true` for `UNAVAILABLE`, `RESOURCE_EXHAUSTED` and `DEADLINE_EXCEEDED`; never
  for `OK`, `INVALID_ARGUMENT`, `NOT_FOUND`, `ALREADY_EXISTS` or `INTERNAL`.

## DONE WHEN

- `kiln run rpc/8.3-status-codes` — the spec passes
- `kiln check rpc/8.3-status-codes` — every must gate is green
- an overloaded server and a dead dependency are retryable; a bug and a bad request are not

## TRAP

1. **`INTERNAL` for everything.** The catch-all code turns every validation error into a page and
   every retryable outage into a "server bug"; the spec's mapping tests are the six that catch it.
2. **Retrying a caller's mistake.** `INVALID_ARGUMENT` will fail identically on every attempt; a
   retry loop around it is a load test with a fixed result.
3. **Not retrying `RESOURCE_EXHAUSTED`.** Overload is the one failure that retrying *after a pause*
   fixes; mapping it to `INTERNAL` loses that.
4. **A code from the HTTP vocabulary.** `404` and `NotFound` are the same idea and not the same
   protocol: a gRPC client branches on the gRPC code, and a status body that says "404" is a string
   the client parses as `UNKNOWN`.
