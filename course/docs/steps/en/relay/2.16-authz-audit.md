# The authorization matrix, and the audit trail behind it

## RECALL

`sec/authz-tenant-isolation@apply` — `mailer/1.18-authz-boundary`: a subscriber asks for its own
deliveries, the query carries `subscriber_id = $1`, and a row that belongs to somebody else answers
`404` — the same answer a row that does not exist gets. One route, one check, written inside the
handler that could answer it.

## DELTA

That was resource-level ownership: *this* row, *this* caller, one route. What changes here is that
the question is no longer asked per route, and the answer is no longer the whole story:

- **the permission model is data, and the routes are data too.** A table of (role, action, scope)
  holds every grant, a table of routes says which action each route is, and one layer asks the
  second about the first. Adding a route without adding a permission is now a visible omission
  rather than a handler somebody forgot to guard — and the *absence* of a cell is a decision a
  reviewer can read: there is no cell anywhere that grants one tenant another tenant's rows;
- **a refusal has three reasons, not one.** "I do not know you" is `401`, "I know you and you may
  not" is `403`, and "that is not yours" is `404` — and the third one is the same `404` a missing
  row gets. `mailer/1.18` had the last one. It did not have the other two, and it did not have the
  rule that decides between them: **`403` is about an action, never about a row.** A `403` for
  somebody else's row is a service confirming that the row is there, which is the information the
  guesser was fishing for;
- **a privileged decision is written down before it is acted on, and the trail is readable.** A
  log line is written for whoever is watching the process; the trail is a table in the database the
  service already owns, filtered by the same tenant rule as everything else, and it answers "who
  moved this, and what did we decide" months later. That means a decision is written *before* the
  handler runs: a process that dies halfway through a privileged action has to have left a row
  saying it was about to do it. It also means a refusal is a row — and that a trail which cannot be
  written refuses the action.

Where the layers sit is `relay/2.1-project-skeleton`'s lesson and it does not move: correlation id,
log, quota, then **identity**, and now one layer after identity whose only job is to ask the matrix.
The split between the last two is the new thing, and it is deliberate: identity resolves *who*
(a request with no key and a request with a key nobody issued are both anonymous, and telling them
apart is a way to sort guesses), and nothing about *what may be done* is written anywhere but the
matrix.

## TASK

### `migrations/0008_audit.sql`

`ls migrations` first: the next free number is the one you use, and two migrations with the same
number make `sqlx` refuse all of them. Two things go in:

- **the role lives on the tenant.** `tenants.role` (`text not null default 'tenant-admin'`, with a
  `check` that names the roles this service has) is this service's simplification and worth saying
  out loud: a tenant here has exactly one API key, so "a role per credential" and "a role per
  tenant" are the same thing. One key per person, per laptop, per CI runner is the general answer,
  and it is a table keyed by the credential instead of a column;
- **the trail.** One row per privileged decision: the tenant, the role it acted with, the action,
  what the action was aimed at, the decision, the correlation id of the request, and when. The
  credential is not a column and never will be: this table outlives the key it is about, and a trail
  that quoted the key is a second copy of it with a longer retention. Add the index the one query
  this table has needs — one tenant's rows, newest first.

### `src/authz.rs`

The scaffold ships the types and an empty matrix. Fill in, as data:

| role | may do | on |
| --- | --- | --- |
| anonymous | read health, readiness, the contract | the process itself |
| tenant-reader | the three above, plus read endpoints, events, dead letters | its own tenant |
| tenant-admin | everything a reader may do, plus register endpoints, accept events, replay dead letters, read the trail, read metrics | its own tenant |

- `GRANTS` — every cell, each one `Scope::Own`. The scaffold's shape makes a grant for another
  tenant's rows impossible to write, which is the point;
- `granted(role, action)` — the widest scope a role has for an action;
- `decide(role, action, scope)` — a *total* function. A grant covers its own scope and everything
  narrower; a grant that does not reach the asked scope is `Deny(NotVisible)`; no grant at all is
  `Deny(Unauthenticated)` for an anonymous caller and `Deny(NotPermitted)` for a known one;
- `ROUTES` — the routing table as data: method, the path **as axum matches it** (`/dlq/{id}/replay`,
  placeholders and all), and the action. Every route this service serves is in it, `/audit`
  included, or the layer below never asks the matrix about it;
- `Action::is_privileged` — the actions that change something, and therefore leave a row;
- `Action::is_metered` — the actions that spend a *tenant's* quota. The three process routes are not
  metered: an orchestrator told `429` by the readiness probe of a busy service restarts it.

### `src/audit.rs`

- `record(pool, entry)` — one insert, before the action. `decision` is the token `Decision::as_str`
  produces: `allow`, or the reason.
- `list(pool, tenant, limit)` — the caller's rows, newest first, with the tenant in the `where`
  clause. Filtering *after* the limit is a list that hands out somebody else's rows on the first
  page.

### `src/http.rs`

- `identify` replaces the layer that used to refuse: it looks a key up and inserts the `Principal`
  when there is one. A request with no key, and a key that belongs to nobody, both continue
  *anonymous*;
- `authorize` runs after it. It reads the matched route (axum puts the *matched* path in the request
  as `MatchedPath`), asks `authz::decide(role, action, Scope::Own)`, and either runs the handler or
  answers with the refusal's status. A request that no route matched, or one whose method the route
  does not have, is left to the router: axum's own `404` and `405` are the honest answers there, not
  a `403`;
- a privileged action writes its row **before** `next.run(request)`, and a trail that cannot be
  written ends the request. The target recorded is the *route* (`POST /events`), never the path the
  caller typed: an audit column that quotes caller input is a column full of whatever the caller
  felt like sending;
- `/audit` is a read like any other, so reading it does not add to it;
- the limiter asks `Action::is_metered` about the matched route before spending a bucket, rather
  than a second list of "the routes that are limited";
- the router is **one** router now. There is no "public" sub-router: `/healthz` is reachable without
  a key because that is what the matrix says, not because of how the routes are assembled.

### `src/config.rs`, `src/db.rs`, `src/auth.rs`

A tenant entry is `name=key` or `name:role=key` — the role goes on the *name*, because a key is an
opaque secret that may contain any character while a tenant name's alphabet is closed. An entry
that names no role is an administrator, so configuration written before this step keeps working.
`seed_tenants` writes the role, and the lookup in `auth.rs` reads it in the same query as the name:
the role is a property of the row the key was found in, and after that lookup nothing a *request*
says can change it.

### `src/error.rs`

One new variant: `Forbidden(String)`, `403`, the stable token `forbidden`. Its message names the
action that was refused and nothing else.

### `src/openapi.rs`

`GET /audit` and its schemas, with every status it can answer. `relay/2.3-contract-first` is a
standing rule, not a one-off: a route that is not in the document is a route whose answers nobody
agreed to, and the document is checked against the running service.

## TRAP

1. **A matrix in the handlers.** Every route calls `decide` at the top of its body and it works,
   until somebody adds a route. Then that route answers to anybody with a key, and nothing in the
   file it was added to looks wrong. The spec's route table is written from outside for exactly
   this: a route that never asked is a route that answers `200` to a caller the matrix refuses.
2. **`403` for a row that belongs to somebody else.** `GET /dlq/{id}` with another tenant's id that
   says "forbidden" has answered a question the caller had no right to ask — the row exists. The
   only safe answer for that row is the one a row that does not exist gets, byte for byte, which
   means the check that produces it is the *query's*, not the matrix's.
3. **Believing a header.** `X-Role: tenant-admin`, `X-Tenant-Id`, `X-Forwarded-Tenant`, a `role`
   key in the body: each one is text somebody typed, and a service that reads one has an
   authorization model that anybody on the network can edit. The spec sends all of them, as a
   reader, and expects the same `403` each time.
4. **A trail written after the action.** The interesting rows are the ones where the process died
   in the middle. Write the row, then act: an action this service cannot account for is an action
   it does not take, and the failure path is therefore a refusal rather than a log line nobody
   reads.
5. **A trail of every read.** One row per request sounds thorough and is a table that grows faster
   than the traffic it describes, in the database the service is trying to serve from. Privileged
   means "changed what we owe or who may reach it".
6. **The credential in the trail.** Not in the columns, not in the target, not in a `request_id` an
   attacker chose: a request id is caller input until this service decides it is plausible, and the
   trail is read by people who may not be allowed to see the key. Assert it: the spec greps the
   whole table for the key and for the signing secret.
7. **A role validated at boot and not by the database.** Configuration refuses a role the service
   does not have, and then somebody runs `update tenants set role = 'owner'` at three in the
   morning: the check constraint is the answer for the rows that were not written by this code, and
   the lookup has to fail loudly on a role it does not know rather than default to something.
8. **`401` where `403` belongs.** They are not interchangeable: an operator reads `401` as "the
   caller's key is the problem" and `403` as "the caller's key works and the request is what is
   wrong". Answering `401` to a reader who may not write sends someone to rotate a key that is
   fine — and a client that retries on `401` (a token refresh) will do it for ever.
9. **A route missing from the document.** `/audit` is a new route with a new status (`403`), and the
   document is checked against the running service: it has to declare the path, and it has to
   describe the status the service actually answers.
10. **Metering the process routes.** The quota is keyed by the caller, and a readiness probe has no
    key: put the limiter in front of `/readyz` and a busy service is told `429` by the very probe an
    orchestrator uses to decide whether it is healthy. A tenant's quota belongs on the routes that
    work for a tenant.
11. **Recording a decision that no tenant made.** An anonymous request has no tenant, so a
    *privileged* request from one answers `401` and leaves no row — there is nothing to attach it
    to. That is a boundary worth knowing rather than a gap to paper over: the log line is where an
    unauthenticated attempt is visible.
