# Only deliver where we are allowed to: target validation

## WHY

A subscriber is a URL, and a *tenant* chooses it. That is the whole service: somebody signs up,
registers `https://their-app.example/hooks`, and this process makes HTTP requests to whatever they
typed. Which means the interesting question is not "can we reach it" but **"who else can we reach
with the same request"**.

The answer, in every real incident of this kind, is the deployment's own network:

- **the metadata endpoint.** Every cloud provider answers instance credentials on a fixed address —
  `169.254.169.254`, and `fd00:ec2::254` on the IPv6 side. It is inside the link-local block, it
  needs no authentication, and anybody who can make one HTTP request from inside the instance can
  read the role's credentials out of it. A webhook service that will dial any URL a tenant types is
  that request;
- **the process's own neighbours.** `127.0.0.1` is where the admin port, the health endpoint and the
  metrics exporter live; `10.0.0.0/8`, `172.16/12` and `192.168/16` are where the database and the
  internal services are. They are reachable *precisely because* they assumed nobody outside the
  network could ask;
- **and the failure is silent.** A delivery to an internal address that answers `200` is recorded as
  delivered. Nothing in the logs looks wrong: one tenant is calling the metadata service and the
  service is proud of it.

The client this step builds on — `outbound/http-client@apply`, step `relay/2.7-outbound-client` — is
about *time*: three deadlines, connection reuse, and a redirect policy that counts hops and refuses
a loop. None of that is repeated here, and none of it is the question. `relay/2.7` decides how long
an attempt may take and how far it follows; this step decides **whether it may be made at all**.

And the decision has a shape that catches almost every first attempt at it:

> a URL is not an address.

`http://evil.example/hook` says nothing about where the bytes go. The address is decided by whoever
answers for that name, at the moment a connection is made — and that is a party the attacker
chooses. The classic bug is a check that resolves the name, is satisfied, and then hands the *name*
to the HTTP client, which resolves it **again**. The attacker answers the first question with a
public address and the second with `169.254.169.254`. The window between the two answers is the
whole attack, and it has a name: DNS rebinding.

## TASK

The scaffold added `src/target.rs`: the types, the port, and the signatures with `todo!()` bodies.
Everything in it is `target::Rules`' — what a deployment is willing to talk to — and two checks that
answer different questions.

### `src/lib.rs` and `src/target.rs`

Declare the module, then implement:

- `Class::of(address)` — the class of an address: `Public`, `Loopback`, `Private`, `LinkLocal`, or
  `Metadata`. IPv4, IPv6, and **the IPv4 address inside an IPv6 one** (`::ffff:127.0.0.1` is
  `127.0.0.1` wearing a hat, and a check that reads only the text sees neither); the link-local
  block with the metadata endpoint inside it (that one address is checked first: an allowlist that
  permits a whole `/16` of neighbours still refuses the one that answers with credentials);
  `100.64.0.0/10`, multicast, and the blocks reserved for documentation and benchmarking as
  not-public. `Class::as_str` is the word that ends up in an operator's `last_error`.
- `host_of(url)` — the host and the port of a target, or why the authority is not one. The two
  shapes are a bracketed IPv6 literal (`[::1]:8443`) and everything else; **brackets exist because a
  colon inside an address is not a port separator**, and an authority that carries credentials
  (`http://user@host/`) is refused rather than parsed. The name is normalised once — lower case, no
  trailing dot — and the normalised form is what is resolved and judged.
- `check_name(name)` — the names that can only mean "here": `localhost`, `*.localhost`, `*.local`,
  `*.internal`.
- `Rules` — four flags (loopback, private, link-local, metadata), `permissive()` (nothing refused),
  `public_only()` (only the public internet), `allows()`, `allows_local_names()`, and `check()`.
  `Rules::of(&Config)` is the deployment's: **`delivery.allow_private_targets` is off unless a
  deployment turns it on**.
- `check(url, rules)` — everything registration can decide *without* resolving anything: the shape
  of the authority, a literal address, and a name that means "here".
- `Resolver` — the port: the host becomes addresses here, and it is a port because a test cannot ask
  a real name service to answer one thing for the check and another for the connection.
  `System` is the deployment's, over `tokio::net::lookup_host`.
- `pin(host, rules, resolver)` — **resolve once**, check *every* address the name answered with, and
  answer the `SocketAddr` the client will connect to. `Unreachable::Refused` is a decision, `Unreachable::Unresolved` is a failure; the caller acts differently on the two.
- `Unreachable` and `Refusal` — why a target is not one this service will reach, in words that name
  the address and the rule (`"10.0.0.5 is a private address…"`, `"…is a metadata address…"`,
  `"`localhost` is a name that means this machine…"`). `Refusal::kind()` is the stable token.

### `src/config.rs`

Add a `delivery` section with `allow_private_targets: bool`, from `delivery.allow_private_targets`
(file) or `RELAY__DELIVERY__ALLOW_PRIVATE_TARGETS` (environment), **defaulting to `false`**, read
through the same layering as every other setting and refused when it is not a boolean. Report it in
`--check-config` (`delivery.allow_private_targets = false`).

### `src/outbound.rs`

- `Policy` gains `targets: Rules`. `Policy::default()` must stay *permissive*: it is the value a
  library caller and a test build, and this track's own specs (and `relay/2.7`'s) dial a scripted
  server on `127.0.0.1`. The service's rules come from `Policy::of(&Config)`.
- `Client::resolving(policy, resolver)` — a client that resolves names through an injected
  `Arc<dyn Resolver>`; `Client::new` keeps using `System`.
- The connection path: split the authority with `target::host_of`, get the address from
  `target::pin`, and connect **to the address**. Nothing between the check and the socket asks a
  name service anything.
- Classify the two kinds of failure apart: a refusal is `Outcome::Permanent` (another attempt
  resolves the same name and consults the same rule — it is a decision, and the delivery is buried
  with a readable reason in `dead_letters`), while a name service that did not answer stays
  `Outcome::Retryable`, like any other failure that says nothing about the subscriber.

### `src/http.rs` and `src/openapi.rs`

`POST /endpoints` runs `target::check(&url, &Rules::of(state.config()))` and answers **`422`** with
`error = "target_rejected"` when it refuses — a policy decision about a URL that was understood, not
a `400` about a body that was not. Add that status to the document: `relay/2.3-contract-first`'s
rule is that every status a route can answer with has a schema.

## TRAP

1. **Checking the name and then connecting to the name.** The check resolves, is happy, and then
   `TcpStream::connect(("evil.example", 80))` resolves *again* — the second answer is the attacker's.
   Nothing about the code looks wrong, and the test that would catch it has to drive the resolver
   twice. The spec does: a name that answers a public address first and `10.0.0.5` second must be
   asked exactly once.
2. **Reading the host out of the authority with a `split(':')`.** `http://[::1]:9/hook` then reads as
   the host `[`, the check passes, and the connection goes to the loopback interface — the brackets
   exist precisely so that the colons inside an address are not read as a port. Same class of bug:
   `http://public.example@127.0.0.1/hook`, where the part before the `@` is a user name the attacker
   chose.
3. **Only refusing IPv4.** `http://[::1]/`, `http://[fd00::1]/` and the `::ffff:` spelling of every
   IPv4 address are the same addresses one protocol later, and `::ffff:169.254.169.254` is the
   metadata endpoint in a hat. A classifier with an `Ipv4Addr` arm and a `todo!()` in the other is a
   classifier with a way around it.
4. **Turning the delivery-time check into the only check, or the registration-time check into the
   only one.** Only-at-delivery means a tenant registers a target that can never work and finds out
   from `dead_letters`; only-at-registration means a name that changes its answer walks in. Two
   checks, two questions, and the file says which is which.
5. **Making `Policy::default()` strict.** It is the value every test that dials a scripted target on
   `127.0.0.1` builds, so a strict default turns `relay/2.7`'s ten cases red on the final tree — the
   failure looks like a broken client, not a security decision. The strictness belongs to the
   deployment, in `Policy::of`, which is also the only version that can be configured.
6. **A refusal classified as retryable.** Then `127.0.0.1` is retried until the budget runs out, the
   subscriber is hammered with requests that can never be delivered, and the dead letter says "gave
   up after N attempts" instead of naming the address.
7. **Refusing if *any* resolved address is internal — or connecting to the one that is not.** A name
   that answers with a public address *and* an internal one is a name this service does not dial at
   all: picking the address you like is picking the address the attacker wants, and mixing "one
   address failed" with "one address passed" is how a check becomes a coin flip.
8. **Forgetting that a redirect is a second question.** `Location` is a stranger's instruction. The
   hop is cheap to check and it is the one an attacker will not send the first time; every hop of
   the chain goes through the same rules, which is why nothing here has a "first hop" exception.
9. **The setting that is silently false.** `RELAY__DELIVERY__ALLOW_PRIVATE_TARGETS=1n` read as
   "did not match `true`, so false" turns a deployment's deliberate decision into the opposite of
   what it wrote. Values are parsed where they are read, and text that is not a boolean is a
   configuration error.
10. **Reading `delivery.allow_private_targets` as "the SSRF check".** It is not a switch for the
    check — the check runs either way, with different rules. What the setting changes is who the
    deployment considers a subscriber, and it exists because a test (and a deployment behind a
    network boundary) legitimately has subscribers on `127.0.0.1`.
