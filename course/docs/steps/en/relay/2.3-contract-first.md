# The API as a contract: generated document, snapshot, compatibility

## WHY

A second client is being written against this service — a partner's integration, an internal
dashboard, a customer's script — and every one of them is written against a guess. The guess is
made of whatever they could find: a README from two releases ago, a `curl` they ran once, a field
that appeared in an answer and was never promised. The first time a field is renamed, the guess
costs a support thread, and the answer is always "that was never part of the API" — which is true,
and useless, because nothing said so.

So the API is written down, in a format a client can *read*, and the service publishes it. That is
`GET /openapi.json`. But a document that only exists is worse than none: it is a promise nobody
checks, and it drifts one field at a time. What makes it a contract is that the test suite compares
it with the service — the routes it declares to the router that serves them, the fields it calls
required to the bodies the handlers demand, its schemas to the JSON that actually comes back. The
snapshot is what a reviewer reads in a pull request: a diff of the document is a diff of the API,
and a diff of the API is a conversation about whether it should happen.

## TASK

The scaffold added `src/openapi.rs` with one function, `document()`. The document itself, the route
that publishes it, and the wiring are yours.

### `src/lib.rs`

Declare the module: `pub mod openapi;`.

### `src/openapi.rs`

Return the OpenAPI document as a `serde_json::Value`. It has to be the shape a client expects:

- a top-level `openapi` version (a `3.x` string) and `info` with a non-empty `title`;
- `paths`: one entry per route, each keyed by the lower-case method. Every route this service
  serves has to be in there — `/healthz`, `/readyz`, `/endpoints` (both methods), `/events` — and
  the document describes `idempotency-key` as a **required header parameter** of `POST /events`,
  because a body is not the whole request;
- `requestBody` schemas for the routes that take one, `responses` for the statuses a route can
  answer with — including the `400` and `401` a caller will meet, and the `200` **and** `201` that
  `POST /events` answers with;
- `components.schemas`: every schema declares its `type`; a record declares `required` and closes
  itself with `additionalProperties: false`; a free-form `payload` is `{"type": "object"}` with
  no fields, which is how a document says "whatever the caller sent";
- every `$ref` points at a schema the document declares. Build the document from data — a helper per
  repeated shape — rather than spelling the same field list twice: the TRAP is what happens to the
  second copy.

The document has to be **reproducible**: same bytes, call after call. No clock, no `HashMap`
iteration order, no version that moves on its own.

### `src/http.rs`

- Serve it: `GET /openapi.json`, **public** — a client reads what this service promises before it
  has a key, and a contract that needs a key is a contract nobody fetches.
- The handler returns the document as JSON. It is a thin adapter on purpose: the document is built
  in `src/openapi.rs`, where a test can call it.
- The bodies have to agree with the document, and the part that does *not* follow automatically is
  `additionalProperties: false`: `serde` ignores unknown fields unless you say otherwise, so the
  request structs get `#[serde(deny_unknown_fields)]`. The document promises a caller that a
  misspelled field is a `400` rather than a silent no-op, and the promise is either true of the
  code or a lie.

## DONE WHEN

- `kiln run relay/2.3-contract-first` — the spec passes
- `kiln check relay/2.3-contract-first` — every must gate is green
- `curl -sS localhost:8080/openapi.json | jq '.paths | keys'` lists the routes the service serves,
  and two runs of it produce byte-identical output
- renaming a field in `document()` (or in a response struct) turns the spec red: that is the check a
  snapshot in a pull request relies on

## TRAP

1. **A document nobody compares.** Writing the document and stopping there is the default outcome:
   the routes are right on the day it is written and wrong two steps later. The spec's first question
   is whether every path and method in the document answers something other than a `404`/`405`, so
   a route that is added to `router()` and forgotten here fails the step.
2. **`required` that the code does not enforce.** A field listed as required that the handler treats
   as optional is documentation of an intent, not of a behaviour: a client omits it, everything
   works, and the day the handler *starts* caring every such client breaks at once. The spec builds
   a body out of the document's own `required` list and drops the fields one by one.
3. **A closed object that the code leaves open.** `additionalProperties: false` and
   `#[serde(deny_unknown_fields)]` are the same claim in two places; with only the first, a caller
   who misspells `payload` gets a `201` and an event with no payload in it.
4. **The same field list spelled three times.** One schema for the request, one for the answer and
   one for the row is three places to rename `.kind` and two places to forget. Build the shapes
   once (`answer`, `event_schema`) and let the paths name them.
5. **A document with a clock in it.** A `version` read from the environment, an `info.generated_at`,
   or a map iterated in hash order makes every run of the generator produce a different document:
   the snapshot diff becomes noise, and a reviewer stops reading it — which is the one thing the
   snapshot is for.
6. **A `$ref` into nowhere.** `{"$ref": "#/components/schemas/Event"}` with no `Event` below is a
   document that a generator crashes on and a human reads as if it were fine. The spec walks every
   reference in the document.
7. **Serving the document behind authentication.** It looks tidier — the document is about the API,
   and the API needs a key — and it means every client has to be configured before it can find out
   how to be configured. `GET /openapi.json` is public.
8. **Answering `404` for a route the document sells.** A path in the document and not in the router
   is worse than a missing entry: a client's code is written against it, and the first thing it
   does is fail. The document and the router are two views of one table.

## FURTHER

- [OpenAPI Specification 3.1](https://spec.openapis.org/oas/v3.1.0.html) — the `paths`,
  `components.schemas`, `required` and `additionalProperties` this document is built from
- [`additionalProperties`](https://json-schema.org/understanding-json-schema/reference/object.html#additional-properties)
  — why closing an object is a compatibility promise, not pedantry
- [serde: `deny_unknown_fields`](https://serde.rs/container-attrs.html#deny_unknown_fields) — the
  attribute that makes the promise true of the handler
- [Stripe: versioning](https://docs.stripe.com/api/versioning) and
  [Zalando's API guidelines](https://opensource.zalando.com/restful-api-guidelines/#api-versioning)
  — two well-argued answers to "what is a breaking change?", which is the question the snapshot
  forces you to answer
- [json-schema: the `$ref` keyword](https://json-schema.org/understanding-json-schema/structuring#dollarref)
  — how a document shares one shape between paths without copying it
- [utoipa](https://docs.rs/utoipa/latest/utoipa/) — the crate that generates this document *from* the
  handlers; read it after this step, when you can see what it would generate for you
