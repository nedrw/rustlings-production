# A segment is columns: encode, compress, and prove the round trip

## WHY

A sample is `(series, ts_millis, value)`, and a store that keeps one row per sample pays
**twenty-four bytes** for it: eight for the clock, eight for the value, and eight for a short series
name and its length. At a thousand samples a second that is 2.1 GB a day, 760 GB a year, per metric —
and almost none of those bytes are information. The same series is repeated in every row, the clock
advances by a step you could count on, and a temperature holds still for a while. Rows spend eight
bytes to say "same series as the last one" and eight to say "one second later, again".

Columnar storage is the observation that those three redundancies become *encodable* the moment the
records are laid out by column instead of by row: a series written once and counted, a clock written
as its steps, values written as runs — and then one block compressor over the three streams, because
the bytes that are left are still full of repetition. On this project's own workload (1 024 samples
over 8 series, a clock that steps by a second, values that hold for sixteen samples) the same records
cost **170 bytes as a segment against 29 700 bytes as rows** — twenty-nine bytes a row, because these
names are eleven bytes long and carry a two-byte length — and the size budget in this step is where
that claim is a number somebody can check instead of a paragraph somebody can believe.

The encoding is not free, and the price is what this step is really about. It is **a format**:
bytes laid out by hand, documented in `docs/format.md`, with a version in front and a seal over the
block, because a segment format nobody else can read is a bug with a deadline. It is **a decode
path**: an encoder-only store cannot be recovered, cannot be compacted and cannot be handed to a
repair tool, and a reader that guesses at damaged bytes answers a shorter store instead of refusing.
And it is **the temptation of `unsafe`**: bit packing, `transmute`, reading an `f64` through a
pointer — the first genuinely unsafe-shaped code in this track. That is why
`unsafe-budget@0` arrives with this step and why the project's manifest now *denies* `unsafe_code`:
at zero, the compiler is the one holding the line, not a reviewer reading a diff.

## TASK

Five properties make up this step. Everything else is packaging.

- **The round trip is exact and ordered.** Every value in, the same value out, in the same order —
  for an empty segment, one record, thousands over thousands of series, a flat line, and the values
  that break encoders written in a hurry: `i64::MIN` next to `i64::MAX` (their difference is not an
  `i64`), `-0.0` next to `0.0`, `±inf` and `NaN`. Exact means *bits*: `-0.0` has a sign that no later
  step can restore, and a `NaN` payload has to come back as the `NaN` it was. `to_bits`/`from_bits`,
  never a comparison, never a decimal.
- **The layout is bytes, not behaviour.** The column block — the count, the three framed columns, the
  four encodings — is pinned by a **golden vector** in the step's spec: four known records, byte by
  byte, exactly as `docs/format.md` states them. This is `store/wal-recovery@apply —
  lakelet/4.4-wal-recovery`'s discipline applied to a closed artefact, and the reason this track
  needs no `semver@baseline`: the contract is the bytes. The **compressed** bytes are deliberately
  *not* pinned — a `zstd` release may answer different bytes for the same input, and failing a learner
  for a dependency's choice would test nothing.
- **Size is the reason the encoding exists.** Every column is written with the shorter of the two
  encodings it speaks (`DIC` against `PLAIN` for the series, `DELTA` against `PLAIN` for the clock,
  `RLE` against `PLAIN` for the values), a tie going to the lower tag so that the choice is a rule
  rather than a branch order, and the whole block goes through one `zstd` frame. The budget lane
  measures it: `bytes_per_sample_max` and the counts around it, compared with
  `course/tracks/lakelet/budget/4.7-columnar-segments.toml`.
- **A segment is a file, and a stranger's bytes are a typed error.** Write one into a directory, read
  it back, and hand `decode` a foreign file, a truncated one and one with a flipped bit: every one is
  an `Error::Protocol` naming what disagreed. Never a panic, never the records that happened to decode
  before the bytes ran out — a log is replayed to a prefix, a segment is either whole or refused.
- **Write the format down and the budget with it.** `docs/format.md` is a page other people read: the
  header byte by byte, the column order, the four tags and their payloads, the choice rule, the values
  that break a careless encoder, the refusals, and the metric names the budget is written in. The
  step's spec reads the page back, so a page that drifted from the code fails the build.

**Where this sits beside the steps around it.** `io/batching@design — lakelet/4.5-batch-writes`
changed how *many calls* the write path makes, and not one byte of what it wrote; this step changes
what the bytes *are*, and the batch a flush writes is now the record set a segment holds. The record
format itself is untouched: `lakelet/4.4-wal-recovery`'s `[length][payload][seal]` records behind the
`LKLT` header are still the log, and a segment is a second, closed artefact written *from* a batch —
not a change to the log, and not a second write path. What comes after is
`lakelet/4.8-compaction`, which merges segments while readers keep reading.

**What the course gives you, and what is yours.** The scaffold declares the shape, because a format
is a contract other steps read:

- `src/engine/segment/encode.rs`, `decode.rs`, `compress.rs` and `mod.rs` — the layout constants
  (`LKLS`, the version, the column order, the four tags, every width), the signatures, and the doc
  comments that state what each promise is. The bodies are yours, and so are the private helpers;
- `docs/format.md` — the page, as a template: the layout, the encodings, the values that break a
  careless encoder, the refusals and the budget table are yours to state;
- `tests/budget_segments.rs` — the course's harness, which is what `slow:bench-budget@10` runs. It is
  not yours to edit, and it measures both a telemetry block and a flat line;
- `Cargo.toml` gains `zstd = "0.13"` and, in `[lints.rust]`, `unsafe_code = "deny"`.

## TRAP

1. **A delta written as `b - a`.** An `i64` of milliseconds reaches 292 million years either side of
   the epoch, so two timestamps at opposite ends have a difference that is not an `i64` at all: the
   subtraction panics in a debug build and wraps in a release one, and the same records then produce
   two different files depending on how the compiler was invoked. `wrapping_sub` on the way
   out and `wrapping_add` on the way back is the identity for every pair, and
   `the_values_that_break_a_careless_encoder_round_trip` is the case that says so.
2. **A run-length that groups with `==`.** `-0.0 == 0.0` is true, so those two records merge into one
   run and the sign of the zero is gone for good; `NaN != NaN`, so a flat line of `NaN` gets one run
   per sample and the encoding silently stops helping. Compare `to_bits()`.
3. **A value that goes through anything decimal.** `serde_json`-shaped output, a `format!`, a parse:
   `±inf`, `NaN` and `-0.0` do not survive the round trip, and the failure looks like an arithmetic
   bug three steps later. The column is eight bytes of `to_bits`.
4. **The compressed bytes pinned in a case.** Asserting a `zstd` frame's bytes makes the course fail
   on the next `zstd` release, for a reason that is not the learner's. Size and the round trip are
   the claims; the golden vector is the *column block*, before compression.
5. **A reader that answers with a prefix.** Returning the records that decoded before the bytes ran
   out turns a cut segment into a shorter store — and it passes every case that only writes and reads
   whole files. `every_truncation_of_a_segment_is_refused` walks every cut of a real segment.
6. **Trusting a length before comparing it with the bytes.** `Vec::with_capacity(stated)`, a slice
   `[start..end]` on a field a stranger wrote, a run of four billion records: a corrupt file gets to
   choose your allocation or panic your process. Every length is checked against the bytes actually
   there before it is used as an end, an offset or a capacity.
7. **No header check.** A reader that starts at the first byte of *any* file reads somebody else's
   text as a segment with no records in it. `LKLS`, the version and the column count are what make
   "not this store's file" a decision; a foreign file is an `Error::Protocol` naming the header it
   found and the one it expected.
8. **A seal over the payload only.** If the length fields are outside what the checksum covers, a
   flipped bit in a length can still "verify" and hand back bytes from the wrong offset. The block is
   sealed in the shape `lakelet/4.4-wal-recovery` already defined: the length *and* the bytes.
9. **Choosing an encoding by what compresses best.** Compressing every candidate and keeping the
   smallest makes the bytes depend on the `zstd` release, and the golden vector stops being a
   contract. The choice is the encoded payload's length, the tie goes to the lower tag — and a
   chooser that turns `<` into `<=` moves every tie, which the vector catches as a *series column*
   that moved.
10. **Reaching for `unsafe` to make the bit packing fast.** `unsafe_code = "deny"` is in the
    manifest, so the compiler refuses the block before the gate is asked — which is the point of
    `unsafe-budget@0`: at zero occurrences there is nothing to review, because nothing can be written.
    The one move the lint cannot see is an `#[allow(unsafe_code)]`, and that is exactly what the gate
    is for.
11. **A `Vec` sized by what the block claims rather than by what it holds**, in the encoder's
    dictionary or in the decoder's runs: a legitimate segment and a hostile one then cost the same
    process two very different amounts of memory.
12. **The page left as it came.** The spec's last case reads `docs/format.md`, fails on a `TODO` and
    on a metric it does not name: the page, the harness and the baseline have to be one vocabulary,
    or the gate is guarding a number nobody explained.
13. **A `todo!()` left in any of the four files.** `no-todo` runs over every target, including the
    `decode` paths the spec reaches only through one case.

## FURTHER

- **Parquet** is this page at production scale: the
  [encodings](https://parquet.apache.org/docs/file-format/data-pages/encodings/) include a
  dictionary, a run-length/bit-packing hybrid, and `DELTA_BINARY_PACKED` for exactly the near-constant
  clocks this step delta-encodes. Read its encoding list against the four tags here: the two formats
  differ in the number of choices, not in the reason for them.
- **Facebook's Gorilla** ([VLDB 2015](http://www.vldb.org/pvldb/vol8/p1816-teller.pdf)) is the paper
  behind delta-of-delta timestamps and XOR-compressed values, with the compression numbers of a real
  monitoring system attached. The gap between this step's `DELTA` and its delta-of-delta is the
  cheapest next improvement in the format, and the paper prices it.
- **`zstd`'s levels** are a trade between bytes and milliseconds, and
  [RFC 8878](https://www.rfc-editor.org/rfc/rfc8878) is the frame format. This project fixes level 3
  in one constant on purpose: a level tuned until a budget passed would be a decision nobody made, and
  `lakelet/4.16-profiling` is where a decision like that gets measured instead of guessed.
- `lakelet/4.8-compaction` is the step this format hands over to: how many records one segment holds,
  and what happens to a reader when two segments holding the same series become one.
- `lakelet/4.11-query-engine` leans on this layout for the number it prints with `EXPLAIN` — which
  columns a query actually read — and `lakelet/4.15-budget-regression` is where the cost of a segment
  is attributed to the stage that spent it.
