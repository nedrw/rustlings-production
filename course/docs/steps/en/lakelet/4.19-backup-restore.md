# Backups are only real once you have restored one

## WHY

Every step before this one treats the store as somewhere a *process* writes: a log is replayed at
open, a flush closes a segment, a merge swaps the manifest. The day the disk dies, none of that
matters — what matters is whether somebody can move the directory somewhere else and get the same
store back. That is a different kind of work, and it fails in ways no earlier test would catch. A
copy taken while the store was being written is two stores at once, and nobody finds out until the
restore. A copy whose segment lost a byte in transit is a directory that looks exactly like a good
one. A half-restored directory is a *trap*: it is not a store, so nothing answers out of it, and an
operator who opens it to look will watch the store's own recovery delete what is in it. And a copy
nobody has ever restored is not a backup at all — it is a hope with a timestamp.

So this step is about the two numbers an operator decides with: **RPO**, what the crash had already
lost before the copy began — which is the write path's policy and not the backup tool's business —
and **RTO**, how long putting the store back takes. Neither is a count this project's gates can
judge, so both are *measured*, written down on a page, and made checkable by a drill that a reader
can re-run.

## TASK

The scaffold created four contract files, a complete harness, and the page's skeleton:
`src/engine/backup/mod.rs` (the copy), `src/engine/backup/manifest.rs` (the copy's own manifest),
`src/engine/backup/restore.rs` (the restore), `src/cli/backup.rs` (three commands), the stub
`docs/dr-drill.md`, and `tests/sim_backup.rs` — the drill the `sim` gate runs, which is **complete**
and is what your work is judged by. It also inserted `pub mod backup;` into the marked block of
`src/engine/mod.rs` and of `src/cli/mod.rs`, and — inside the marked block of
`src/engine/compaction/mod.rs` — it gave you the two doors a tool that only *reads* a store comes in
by: **`Manifest::read`**, the store's manifest without opening the store, and **`Manifest::load`**,
which is that manifest and every segment it names checked against its file. `copy` is the first
caller of the second, and the reason they exist is the first thing `copy` has to get right: a copy
reads its source and never writes it, and opening a store *is* a write.

**`copy(source, destination, interruption)`** takes the store at `source` into `destination`, in the
order the module docs argue: the store's own manifest first (it is the file list — the manifest *is*
the store, and a file in `segments/` it does not name is an orphan a crash left behind, so it is not
part of what a store is), then every segment it names in its order, then the prefix of the log a
replay proves and not one byte past it. Write each file, wait for the device, and only *then* append
the entry that names it: that ordering is what makes "the copy's manifest says what is complete" a
property of the code rather than a claim about a filesystem. Never take the sidecar indexes (derived
state, `lakelet/4.14-index-pruning`) and never `*.pending`. `Interruption::AfterBytes(n)` stops the
copy once `n` bytes of file contents have been written: a file the budget cuts through is left
**partial and unnamed**, and the copy is over. The `Report` is the counts an operator reads, and the
refusals are typed: a source that holds no store, a destination that is already a store, and whatever
the store's own reader refuses with.

**`backup.manifest` is a log, not a format of your own.** The copy's own manifest is
`lakelet/4.4-wal-recovery`'s format byte for byte — `wal::segment::introduce` for its first entry and
`encode` for every later one — so a copy interrupted mid-entry recovers exactly like a store's log:
the proven prefix, the bytes nobody can read, and the `Stop` that says why. The entry's codec is
explicit bytes: the name relative to the store's root, a kind, the byte count, the record count where
the file states one, the first and last millisecond where it states one, and the **crc32 over the
whole file** (`crc32fast`, the checksum family the log already uses). `Manifest::load` answers the
entries, the discarded bytes and the `Stop` — and a copy whose manifest is not there at all is a
typed refusal, never an empty list.

**`restore(source, destination)`** is one order, and it is the whole of the safety argument: load the
copy's manifest, refuse a destination that already holds a store, **verify every entry before
writing anything** (present, the length the manifest states, the crc32 it states), and only then
write — with the store's own `segments.manifest` **last**, because that file is the commit point
(`lakelet/4.8-compaction`: a directory is a store because of that file). A refused restore therefore
leaves the destination exactly as it found it, and a restore interrupted before the last file leaves
a directory that is not a store — which is why the page has to say that one must not open a
half-restore to look at it. Damage is a typed vocabulary with a `Display` that names the file and,
where there are two numbers, both of them: missing, short, another checksum, unreadable.

**Then the operator's side.** `src/cli/backup.rs` is three commands, additive to
`lakelet/4.10-downsampling`'s grammar and keeping `jobq/3.15-cli-contract`'s promises: `backup
--store <DIR> --to <DIR>`, `restore --from <DIR> --to <DIR>`, and `drill [--store <DIR>]` — the
rehearsal, which builds a store with the real write path, models a machine death, copies,
restores, and does the same again for a copy interrupted inside a segment. Their answers are the
tool's two shapes (one `name=value` per line, or one object under `--json`), and the failure
classes are `4.10`'s unchanged: `3` the thing asked about is not there, `4` the store refused, `2`
a wrong call, `1` a deployment that cannot work. `drill`'s output format is written out in
`DRILL_LINES` at the top of the file: it is an interface a page and a script both read, so it is
stated where it cannot drift. The dispatch arm, the `USAGE` lines and the class each command
leaves are edits in `src/cli/mod.rs`.

**`docs/dr-drill.md` is the deliverable.** Write it from a run, never from an intention: what a copy
of this store is and what it deliberately does not do (it is not a live copy — say what a live copy
would need instead), the operator's five steps as commands, what "verified" means one class of damage
at a time, **RPO measured** with the sentence that explains it, and **RTO as a wall clock with the
machine and the store size named**. Its pinned block is the whole output of `lakeletq drill`, line for
line, and the spec re-runs that command and compares — so the block carries no clock, and the timing
line (`LAKELET_DRILL_TIMED=1`) stays in the prose.

Do not touch `src/engine/compaction/**`, `src/engine/wal/**` or `src/engine/spool/**`: the file list,
the log's prefix rule and the write path's durable boundary are earlier steps' contracts, and
`lakelet/4.4-wal-recovery`'s spec asserts them.

## TRAP

1. **Taking the whole log.** `cp -r` copies the tail a crash left behind, and that tail is the middle
   of a record: the copy then holds bytes no replay can prove, and every store restored from it starts
   recovery at the same byte. Take `Recovered::bytes()` and stop.
2. **Naming a file before its bytes are on the device.** Appending the entry first, or in the same
   breath as the write, makes "the manifest says what is complete" a claim about a page cache. A copy
   that stops anywhere after that has a manifest naming a file that is not there, and a restore of it
   refuses — or worse, on a device that lies, succeeds.
3. **Writing the store's manifest first.** A restore that writes `segments.manifest` first has a commit
   point that means nothing: the next thing that fails leaves a directory that *is* a store by the
   only definition this project has, with segments missing behind it. Write it last.
4. **Verifying while writing.** Checking each file just before writing it looks like the same thing and
   is not: the first failure lands halfway through the restore, and the destination is now a directory
   an operator will open to look at. Verify the whole copy, then write.
5. **Opening a half-restore to see what is in it.** A directory with segments and no manifest is a
   store whose segments are all orphans, and opening a store deletes what its manifest does not name.
   The same trap in the other direction: a restore into a destination that already holds a store would
   merge two stores, which is why `Occupied` is a refusal and not a warning.
6. **Leaving the sidecar indexes out of the copy and calling the restored store equal.** It is equal —
   that is `4.14`'s rule — but a *ledger* rebuilt from a store with no indexes keeps series a store
   that lost segments can no longer prove it holds. Compare the series and their counts, and read the
   windows as the difference they are.
7. **Putting the RTO number in the block the spec compares.** A wall clock makes two runs of the same
   command print different bytes, and the `sim` gate fails a step whose seeds decide nothing. The
   block is the run with no clock in it; the timing line lives behind `LAKELET_DRILL_TIMED`.
8. **Printing a refusal on standard output.** A script that pipes this tool into a parser must never be
   handed half an answer beside a complaint: stdout is the answer, stderr is one sentence, and the
   exit code is the class. `4.10`'s cases and this step's both assert it.
