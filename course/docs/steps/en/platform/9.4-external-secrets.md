# A secret is a reference, never an artifact

## WHY

A secret baked into an image is a secret in every registry copy, every layer cache, and every laptop
that ever pulled it. The platform-native answer is a **reference**: the manifest names a path and a
key in a secret manager, the workload resolves it at start-up, and the image contains the reference
and nothing else. Rotation then becomes a restart (or a reload), not a rebuild.

Two judgements carry the design, and the second is the one reviews miss:

- **resolution is strict.** A missing path or key is an error naming it — never an empty string that
  starts the service with a blank password, which fails later, somewhere else, as an authentication
  bug;
- **the artifact is clean.** A secret value anywhere in the manifest is a leak, including in a
  comment: the manifest is committed, reviewed and shipped, and a comment is a line of the file.

## TASK

The scaffold added `src/secrets.rs` and its `pub mod secrets;` line. `resolve` and `leaks` are the two
stubs; the types are given.

- **[`resolve`]** — every reference to its value, or [`SecretError::Missing`] naming the first path
  and key that is not there. A failed resolution returns no partial map.
- **[`leaks`]** — the non-empty manifest lines that contain any of the secret values.

## DONE WHEN

- `kiln run platform/9.4-external-secrets` — the spec passes
- `kiln check platform/9.4-external-secrets` — every must gate is green
- a reference to an existing path and key resolves; a missing key names the path; a value in a
  comment is found

## TRAP

1. **`unwrap_or_default()` on the lookup.** A missing key becomes an empty password, and the failure
   surfaces as a login bug in a different service. The spec's *"an error, not an empty value"* is
   this defect.
2. **Returning the references, not the values.** A "resolver" that returns `env → path` leaves the
   caller to fetch the secret, which puts the manager's API in every workload.
3. **Auditing only `value:` lines.** A secret in a comment, a label or an annotation is still in the
   file that ships; the spec's comment case is the cheap version of that.
4. **An empty secret matching everything.** The `leaks` scan must skip empty values — an empty
   string is contained in every line.
