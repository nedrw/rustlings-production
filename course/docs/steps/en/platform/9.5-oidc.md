# A token is somebody else's claim, checked here

## WHY

An OIDC token is a bearer credential minted by an identity provider: whoever holds it is whoever it
names. Validating it is not "parse the claims" — it is comparing them against what *this* service
accepts, and the checks have an order because some are cheap and one is the difference between a
service and a confused deputy:

- **issuer** — another provider's token is another provider's user;
- **audience** — the check everybody forgets. A token minted for any client of the same provider is
  valid *somewhere*, and a service that does not compare the audience accepts its neighbours' tokens.
  One shared provider is all it takes;
- **not-before** — a token that is not valid yet is not valid;
- **expiry** — exclusive, like every deadline in this course: at the second it names, it is over.

The order is part of the contract: a token that is both expired and for another audience is the wrong
audience, because the audience is the check that decides whether this service should look at it at
all.

## TASK

The scaffold added `src/oidc.rs` and its `pub mod oidc;` line.

- **[`validate`]** — the subject when every check passes, else the first failure in the order
  issuer, audience, not-before, expiry.

## DONE WHEN

- `kiln run platform/9.5-oidc` — the spec passes
- `kiln check platform/9.5-oidc` — every must gate is green
- a token for `relay` presented to `mailer` is refused even when it has also expired

## TRAP

1. **No audience check.** It passes every test that only uses valid tokens and accepts every token
   its provider ever minted for anyone. The spec's *"a token for another audience"* is the assertion.
2. **`decoded.exp > now` with a unit mismatch.** Seconds versus milliseconds makes every token valid
   for a thousand months, or expired the moment it is issued; the type here is `u64` seconds on
   purpose.
3. **The expiry boundary.** `now == expires_at` is expired; `>=` versus `>` is the same off-by-one
   the TTL steps have.
4. **Trusting the token's own algorithm field.** Not modelled here (there is no signature to check),
   and it is the classic JWT hole: `alg: none` accepted by a verifier that reads the header. The
   lesson to carry: **verify with the key you chose, never the one the token names.**
