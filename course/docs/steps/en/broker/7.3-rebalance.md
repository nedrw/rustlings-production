# Every partition has exactly one owner

## WHY

A consumer group is several processes pretending to be one reader. The pretence only works if, at
every moment, **each partition is assigned to exactly one member**: two owners double-process, no
owner stalls, and a partition changing hands mid-stream is the rebalance that everyone complains
about.

The assignment rule in this step is the range assignor — the simple one, and the one that makes the
properties visible:

- **contiguous ranges.** Member `a` gets `0..k`, `b` gets `k..m`: a member's partitions are a range,
  not a scatter, so its reads are sequential;
- **every partition exactly once.** The union of the assignment is the partition list, with no
  duplicates;
- **the remainder goes to the earliest members.** An uneven split has to put the extra somewhere;
  "sorted members, extra first" is the rule that makes the assignment deterministic;
- **more members than partitions leaves some empty.** That is an honest answer, not an error: the
  group is over-provisioned, and the extra members will pick up partitions when one leaves.

## TASK

The scaffold added `src/assignment.rs` and its `pub mod assignment;` line.

- **[`assign`]** — the partitions each member owns, as a map from member name to a contiguous list:
  sorted members, `partitions / members` each, the remainder to the first ones, and an empty list
  for a member with no partition.
- **No members** is an empty map; **no partitions** gives every member an empty list.

## TRAP

1. **Round-robin assignment.** `partition % members` spreads evenly and scatters: member `a` gets
   `0,2,4` and its reads jump around the log. The spec's contiguous assertions are the witness.
2. **Overlapping ranges.** An off-by-one in the split (`next..=next + count`) gives partition `k` to
   two members; the "every partition exactly once" test catches it.
3. **The remainder to the last member.** It is still a valid partition set and it disagrees with the
   range assignor every other consumer expects; the uneven-split test pins the rule.
4. **Unsorted members.** The assignment then depends on the order the caller passed, and two members
   computing it from the same set can disagree — which is a split brain with extra steps.
