# Alert on the run that says behind

## WHY

A liveness check answers "is the process running". A lag alert answers "is it keeping up" — and
those are different questions on the day a consumer is alive and ten minutes behind. The second one
is the alert that matters, and it needs two parameters that a single sample cannot provide:

- **a threshold** — how much lag is "behind" for this queue;
- **a run length** — how many consecutive samples above the threshold before somebody is paged.

Both boundaries are the ones every alert gets wrong once. The threshold is *strictly* above: a lag
exactly at the number somebody chose is at it, not past it, and an alert that fires there fires on
every well-behaved window. The run length is a run: one noisy sample is not an incident, and one
quiet sample does not mean recovery — the run resets, and the *trailing* run is what gets reported.

## TASK

The scaffold added `src/alert.rs` and its `pub mod alert;` line.

- **[`evaluate`]** — for the end of a lag history: `Lagging { samples, lag }` when the trailing run
  of samples strictly above `threshold` is at least `consecutive` long; `samples` is the length of
  that trailing run and `lag` is the most recent sample; `None` otherwise (including a history
  shorter than the run, and `consecutive == 0`).

## DONE WHEN

- `kiln run broker/7.9-lag-alert` — the spec passes
- `kiln check broker/7.9-lag-alert` — every must gate is green
- `[3, 6, 7]` against a threshold of 5 and a run of 2 alerts with two samples; `[9, 9, 1, 9]` does
  not

## TRAP

1. **Alerting on one sample.** The first sample above the threshold pages somebody, and a queue that
   spikes once a minute pages every minute: the run length exists for this.
2. **`>=` for the threshold.** A lag exactly at the number chosen is the number chosen; the boundary
   test fails, and every steady window alerts.
3. **Reporting the first run, not the trailing one.** A dip in the middle ends a run; reporting the
   older, longer one describes a recovery that already happened.
4. **`consecutive == 0` alerting everything.** An empty run length is a configuration mistake; the
   spec asks for `None` rather than "every sample alerts".
