# The final drill: multi-node failures, then an audit that proves what survived

## WHY

Every step of this track has argued that a decision survives something: a vote survives a lost node, a
commit survives a partition (`5.14`), a snapshot survives a restart (`5.4`), a membership change
survives its window (`5.5`), an upgrade survives two builds (`5.21`). This step is the check that the
argument held — from the outside, after the fact, without trusting any single node's story.

That last clause is what makes it an audit rather than a test. A node's own counters (`5.18`) say what
it believes; an audit asks every node the same two questions and compares the answers:

- **how far have you applied?**
- **what is your state at that position?** (a digest, and `5.10` made it a function of the entries and
  nothing else)

## TASK

- `src/audit.rs` — the module this step adds:
  - `State { node, applied, digest }`: one node's answer;
  - `audit(&[State]) -> Report`: the common prefix (the smallest applied index), who diverged (nodes
    *at* the prefix whose digest is not the majority's), and how many answered;
  - `Report::is_healthy` and `Report::summary`: the sentence a runbook prints, naming the node and the
    index — which is what an operator acts on.
- `docs/audit.md` — the page this step ships (`links` judges it): what a node is asked, what the audit
  derives, and the three drills it closes.

## DONE WHEN

```sh
cargo test -p meshkv --test spec_consistency_audit
```

is green, and the seven cases say: a cluster that agrees is healthy, a node ahead is not a finding, a
node that diverged is named, the majority digest is the one that counts, an audit of nobody is
refused, a node answering twice is refused, and a cluster where nobody agrees still produces an
actionable sentence.

## TRAP

- **The comparison happens at the common prefix only.** A node ahead of it cannot be compared yet;
  comparing it with nodes that have not applied those entries is how an audit of a busy cluster fails
  for no reason.
- **Being ahead is not a finding.** The leader is ahead by definition; the audit's job is agreement at
  a shared position, not sameness of progress.
- **Divergence is the failure the track exists to prevent**, and the report has to name the node and
  the index. "Audit failed" is a sentence nobody can act on.
- **A collector that answers the same node twice is a bug in the collector.** The audit refuses it
  rather than double-counting one node.
- **An audit of nobody is not a healthy audit.** It is refused: a check that passes when it heard from
  no one is the class of check this course keeps removing.

## FURTHER

- The shape is what a distributed store's `verify` command is: ask every node, compare at a common
  position, and name what disagrees. `lakelet/4.22`'s reproducible-build check compares two builds of
  one tree; this compares several states of one log, and the digest is the same idea in both.
- The track ends here: twenty-two steps, one cluster, and a sentence that says whether it is one
  cluster or not — which is the only question a distributed system ultimately has to answer.
