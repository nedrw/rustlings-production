# The SDK is the product: one client, typed errors, and a contract of its own

## WHY

Every rule this track has established — the leader (`5.7`), the idempotency key (`5.8`), the read
index (`5.6`), the state machine's determinism (`5.10`) — is a rule a *client* has to obey. If the
client is an example in a README, every caller writes their own version of those rules, and one of
them forgets the key. The SDK is where the rules become a product: an API that is correct by
construction, because the rules are inside it.

Three decisions make it an SDK rather than a thin wrapper:

- **the error type is the contract.** `NotLeader` (retry there), `Unavailable` (retry later),
  `Refused` (do not retry), `RetriesExhausted` (give up) have different remedies, and a caller that
  cannot tell them apart cannot behave correctly. `is_retryable()` is the two-line version of the
  table.
- **the retries are the SDK's.** Following a redirect, retrying a timeout with the *same* key, and
  stopping after a bound are one policy — and a policy in the SDK is a policy every caller gets.
- **a write that was applied is a success, however many times it was asked.** The caller asked for a
  write; the write exists; whether it took one attempt or three is the SDK's business.

## TASK

- `src/sdk.rs` — the module this step adds:
  - `SdkError::{NotLeader, Unavailable, Refused, RetriesExhausted}` with `is_retryable`, so a caller
    can decide what to do without matching on strings;
  - `Reply::{Applied, Redirect, NoLeader, Refused}`: what one call to a backend answers;
  - `Backend`: the port — one `write` and one `read`. The trait is the seam `conformance@2` uses;
  - `Sdk<B>`: the retry policy. A write computes its key **once** (a key per attempt would turn a
    retry into a second write), follows redirects, and stops at `MAX_ATTEMPTS` (or immediately on a
    refusal).
- `conformance.toml` and `tests/support/mod.rs` are course content: the project declares two
  implementations of the port — a **scripted** table and the **in-process** cluster — and the gate
  runs the same suite against both with `KILN_BACKEND`.
- `docs/sdk.md` — the page this step ships.

## DONE WHEN

```sh
KILN_BACKEND=scripted   cargo test -p meshkv --test spec_client_sdk
KILN_BACKEND=in-process cargo test -p meshkv --test spec_client_sdk
```

Both green, and the eight cases say the same thing on each: the leader serves, a follower redirects,
a refusal is not retried, the same write twice is one write, and the SDK never asks the caller for a
key.

## TRAP

- **A key per attempt is a second write.** The idempotency key is computed once per *call*, not per
  try; the retry is the same write, and that is what makes it safe.
- **A refusal is not retryable.** Retrying a `Refused` spends the caller's patience on an answer
  that will not change.
- **A node that is down and a node that is not the leader are different failures.** The first is
  `Unavailable` (retry later), the second is `NotLeader { leader }` (retry there); collapsing them
  gives a client that either spins on a dead node or gives up on a live one.
- **The bound is a number.** A cluster that never names a leader must produce `RetriesExhausted`,
  not a client that spins; `MAX_ATTEMPTS` is the number the suite checks.
- **A compare-and-set the leader can see will not match is refused before it costs a log entry.**
  Otherwise the state machine answers `Mismatch` for ever and the caller cannot tell a refusal from
  a slow write.
- **Two implementations, one suite.** A policy that passes on the scripted backend and fails on the
  in-process one depends on an accident of the implementation — which is exactly what
  `conformance@2` exists to find.

## FURTHER

- The shape is the one every client SDK has: a typed error, a retry policy with a bound, and a
  transport port. `openraft`'s `Client` is the same three pieces.
- `5.12` gives the SDK a consistency dial: the same `read` with a level, and the level decides
  whether it goes to the leader (linearizable), to any node with a bound (bounded-stale), or from
  the local state (local).
