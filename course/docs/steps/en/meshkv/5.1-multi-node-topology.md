# A cluster is a list of names: node identity, the topology, and the line two nodes greet with

## RECALL

- `repo/workspace-layout@apply` — `mailer/1.1`: one project, one `[workspace]`, a library and a thin
  binary, `fmt` and `clippy` wired before anything else.
- `err/typed-errors@design` — `jobq/3.3`: an error enum whose variants say *where* the refusal came
  from, and calls that document what they refuse.
- `domain/parse-dont-validate@apply` — `jobq/3.14`: a value that can only exist if it was checked —
  a name becomes a type, and the rest of the system never re-validates it.
- `async/graceful-shutdown@operate` — `jobq/3.7`: a daemon installs its signal handlers before it
  accepts anything, and stopping is a path with a last line rather than a kill.
- `cli/contract@apply` — `jobq/3.15`: a binary refuses `--kiln-exit-code-probe`-shaped nonsense *by
  name*, with a non-zero exit and no panic.

## DELTA

Four projects have given you one process that talks to clients. This one is the first that has to
talk to *itself*: a cluster is several processes that must agree about who is in it before they can
agree about anything else, and every later step in this track — votes, replication, commits,
partitions — is written against identities this step hands out.

Two things are new, and both are about the difference between a **name** and an **address**:

- A node's name is what the system commits, votes and replicates about. Its address is where it
  happens to be reachable today. A deployment that moves a node to another port has changed an
  address; it has not changed who that node is. Keep those apart in the type system now, because
  every step after this one writes code that would quietly conflate them: a membership change
  (`5.5`) rewrites addresses, a certificate (`5.9`) authenticates a name, and a redirected client
  (`5.7`) is told a name it should retry.
- A cluster is **data before it is a network**. The whole of what a node knows about its peers is
  one string, and parsing it is a pure function with refusals — duplicates, nameless entries,
  addresses that are not `host:port`. The steps from `5.13` on will swap the network underneath a
  cluster for a simulated one, and they can only do that because the topology never was a socket.

The gates are the other difference. This track starts at the ladder T4 ended at: `clippy@4` carries
its full rung (the pedantic whitelist included), `unsafe_code = "deny"` is in the manifest from this
step rather than from the one that first needs `unsafe`, and the page you are reading is the only
hint you get.

## TASK

- `src/cluster.rs` — `NodeId::parse` with the accepted alphabet spelled out in the refusal;
  `Topology::parse` over `id=addr,id=addr` with a refusal that names the entry it refused; `len`,
  `is_empty`, `lookup` (a name nobody has is a refusal that quotes it), `render` (the canonical
  specification, so two nodes can compare what they were handed).
- `src/node.rs` — `hello_line` and `parse_hello` for the one-line handshake
  `MESHKV/1 hello <id>`; `Node::bind`, which refuses a name the topology does not have before it
  opens a socket; `Node::accept`, which reads a handshake, checks the name against the topology,
  answers with its own, and returns a `Session` — or refuses, naming what was wrong, without taking
  the listener down; `greet`, which connects, shakes hands as itself, and checks that the node at
  the address it reached is the node it *meant* to reach.
- `src/cli/mod.rs` — `Flags::from_args`: `--cluster`, `--node`, `--listen`, `--help`, `--version`,
  and everything else refused by name.
- `src/bin/meshkvd.rs` and `src/bin/meshkvc.rs` — the daemon prints `listening on <addr>` and stops
  on `SIGTERM` with `draining`; `meshkvc topology --cluster <spec>` prints `id addr` per line, so an
  operator and the library can be shown to read one specification the same way.

## DONE WHEN

`cargo test -p meshkv --test spec_multi_node_topology` is green, and this prints two identical lines:

```sh
cargo run -q -p meshkv --bin meshkvd -- --cluster n1=127.0.0.1:7101,n2=127.0.0.1:7102,n3=127.0.0.1:7103 --node n2
cargo run -q -p meshkv --bin meshkvc -- topology --cluster n1=127.0.0.1:7101,n2=127.0.0.1:7102,n3=127.0.0.1:7103
```

## TRAP

- **Names are not addresses, and the type is the only place that stays true.** The first version of
  this step in most projects keys everything by address because it is convenient *today* — and then
  `5.5` moves a node and every map in the system is stale.
- **A duplicate name is worse than a missing one.** Two nodes answering to `n1` is a cluster that
  can commit the same index twice under one identity. That is why the parser refuses it, not the
  operator at 3am.
- **The handshake is a line, and a line has to be bounded.** Reading a line with no limit is a peer
  choosing how much memory this process holds. The limit is checked as the bytes arrive, before the
  peer's identity is believed.
- **Believing an identity before checking it is the same bug as no authentication at all.** A
  handshake states a name; the topology is what decides whether that name is a member. `5.9` will
  add the certificate that makes the statement unforgeable — this step already refuses names it does
  not know, so the step that adds cryptography has something to attach it to.
- **`--listen 127.0.0.1:0` is normal, not a mistake.** The kernel picks the port and
  `Node::local_addr` tells you what it picked; a test that assumes 7000 is racing the machine.
- **A peer that fails the handshake must not take the node down.** Accepting is a loop, and the
  refusal belongs to the connection, not to the process.

## FURTHER

- The Raft paper's §1 and §2 (*In Search of an Understandable Consensus Algorithm*, Ongaro &
  Ousterhout) describe membership and identity exactly in these terms — a configuration is a set of
  servers, and everything else is a message between them.
- `openraft` (plan §7 D-1's rejected option) has the same two types under the names `NodeId` and
  `Membership`; reading its `Node` type now is a way to see how far the design you are writing
  generalises.
- `meshkvc topology` is the first operator command. `5.15` and `5.22` turn this idea into a drill
  harness and an audit — both of them start by asking a node what it believes.
