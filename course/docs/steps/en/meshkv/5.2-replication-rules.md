# A write is a log entry, and a log entry is committed by a majority

## WHY

Every replicated system is a story about one list. The list is append-only, every node holds a
prefix of it, and saying "this write happened" means the same thing as "this entry is on the list
for good". Everything a database calls durability, ordering and consistency is a property of how
that list is copied and when a position on it may be believed.

This step is the *rules* of that list, before there is a network to move it. That order is
deliberate: the rules are four sentences, and every one of them is easier to get wrong in code than
to say out loud. Writing them as values — a term, an entry, a quorum, a log with refusals — is what
makes the next step (a Raft with elections, heartbeats and a wire) a matter of wiring rather than
of re-deciding what a decision is.

The page the step asks you to write is not documentation for its own sake. It is the same four
rules in English, and the spec compares it against the code: drift between the two is exactly how a
distributed system ends up with a comment that lies about its own protocol.

## TASK

- `src/raft/mod.rs`, `Term`: a number that only moves up (`next`), with an ordering you can compare.
- `Entry`: the term that proposed a write and its one-based position.
- `Quorum`: how many nodes a majority is (`size / 2 + 1`), and whether a count of acknowledgements
  meets it. A cluster of zero nodes has a majority of one — nothing ever commits, which is the
  honest answer rather than a panic.
- `Log`: append-only, with two refusals that matter. An entry must go at `len() + 1` (a gap is an
  entry this node never received), and its term may not be older than the last entry's (the log is
  the memory of what this node has seen). `truncate_from(index)` drops a conflicting suffix — the
  operation a follower performs when a leader's log disagrees with its own.
- `committable`: **an entry of the leader's current term that a majority holds.** Both clauses, in
  that order of importance.
- `docs/consensus.md`: the four rules (`raft::RULES`, verbatim, in order) and the failure catalogue
  (`raft::FAILURES`, one table row per entry, same words in both cells).

## DONE WHEN

`cargo test -p meshkv --test spec_replication_rules` is green, and this prints four rules and five
rows:

```sh
sed -n '1,80p' docs/consensus.md
```

## TRAP

- **The term clause of the commit rule is not a technicality.** A leader that counts an *inherited*
  entry as committed can announce a decision the next election undoes — the one outcome a log must
  never produce. The spec has a case where every node acknowledges an entry from a previous term
  and it still must not commit.
- **A majority is a property of the cluster, not of the acknowledgements.** `Quorum::of` takes the
  cluster's size; `is_met` takes what arrived. A quorum derived from the acknowledgements would
  always be met.
- **A gap is not a short log.** An entry at index 7 arriving at a log of 3 is not "the rest will
  follow"; it is a node that cannot answer what it does not have. Refuse it, and let the leader
  resend from where the follower actually is.
- **`truncate_from` drops a suffix; it does not merge two logs.** The first mismatch is the last
  position the two nodes agree on; everything after it is the leader's to replace.
- **Four rules, five rows, on one page and in one constant each.** The spec compares them row by
  row: a page with a fifth rule and a catalogue without it is a page that will be trusted about
  something the code never does.

## FURTHER

- Raft's paper, §5.3: "Log Matching Property" and "Figure 8" are the two paragraphs this step turns
  into `Log::append` and `committable`. Figure 8 is the reason for the current-term clause; read it
  once and the trap above stops being surprising.
- `openraft` calls the same values `Term`, `LogId` and `Quorum`; its `LogId` pairs a term with an
  index exactly as `Entry` does here, which is not a coincidence — every Raft implementation needs
  this type.
- `5.3` will add the message types that carry these values, and the first thing it will do with
  `committable` is call it on the leader's own term only.
