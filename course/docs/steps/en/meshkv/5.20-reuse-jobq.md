# The graduation of the engine: jobq's crate, zero lines changed

## WHY

This is the step the whole course's `path`-dependency rule exists for (plan §3 D6). Every other track
was forbidden to depend on another track's crate, for a good reason — so that skipping a track is
safe — and T5 is the one exception, because the question it answers cannot be answered any other way:

> if the engine `jobq` built is really a library, then a *different* project can depend on it without
> touching it.

That sentence is the deliverable. The dependency is `jobq = { path = "../jobq" }` — the learner's own
T3 project, which the course lays as a prerequisite — and the acceptance is not "it compiles". It is
**`jobq` needed no change**: no `pub` widened, no `derive` added, no `cfg` flipped. A library that
needed any of those was not one, and this step would have found out.

What meshkv does with it is deliberately small. The engine's `JobId` — the identity `jobq/3.1` made a
type so a queue can talk about a job without a string — becomes a key in this store. The job's state
can then be replicated by the consensus log the previous nineteen steps built: that is the distributed
scheduler the track promised, with the engine that owns the job's behaviour untouched.

## TASK

- `Cargo.toml` — the `path` dependency, inside the marked block (this step's scaffold adds it).
- `src/reuse.rs` — the whole adapter:
  - `pub use jobq::engine::JobId;` — the engine's identity type, reachable through this project;
  - `job_key(id)`: the key a job's state lives under (`job:<id>`), namespaced here rather than in
    `jobq`;
  - `record_job(id, state)`: the command that records the state, produced by this project's own
    command encoding (`5.10`).
- `docs/reuse.md` — the page this step ships (`links` judges it): the dependency, the empty diff, and
  what meshkv does with the engine.

## DONE WHEN

```sh
cargo test -p meshkv --test spec_reuse_jobq
```

is green, and the page's acceptance line holds:

```sh
git -C app/jobq diff --stat      # empty
```

## TRAP

- **The dependency is on the learner's project, not a copy.** A vendored copy would make "zero
  changes to `jobq`" true by construction — and the graduation claim an empty sentence.
- **A `pub` added to `jobq` to make this compile is the step failing.** The boundary `jobq/3.1`
  drew is what is being tested; if it needs widening, it was not a boundary.
- **The namespacing belongs to the adapter.** `job:` prefixes live in `meshkv`, not in `jobq`; a
  library that had to know how another project keys its store would have taken on a job it does not
  have.
- **The prerequisite is real.** `kiln` refuses to judge a meshkv step while `app/jobq` is missing:
  the steps build on the learner's own T3 work, and a sandbox lays the reference tree so the course's
  own checks can judge this step the same way.

## FURTHER

- `jobq/3.1-engine-boundary` is the step this one collects on: the library/service split, the public
  surface, and the rule that the engine depends on nothing that runs it.
- `5.22`'s audit runs over a cluster whose state includes replicated job records — the last
  demonstration that the engine's identity survives a network.
