# A partition is an input: the minority stops committing and says why

## WHY

`5.13` made a partition an input — a playbook a seed replays. This step makes it an **assertion**:
what must be true when the cluster is split, written as sentences a test checks.

That is a different kind of work. A playbook says what happens; a drill says what *must* happen, and
the sentences are the ones an operator's runbook is written in:

- **an isolated node does not commit** — the minority must not decide anything, or the two sides of a
  split become two clusters;
- **the majority keeps working** — a partition that stops everything is an outage with a nicer name;
- **the scenario is the scenario** — a drill over two writes is not a drill over three.

And there is one distinction that the first draft of every partition test gets wrong, which is the
reason this step exists: **a single cut link is not an isolation**. In a three-node cluster, a node
cut from one peer still reaches a majority through the other, so a write sent to it commits —
correctly. Only a node cut from *every* peer (or crashed) is a minority. A drill that called the
first case a split brain would be a drill that fails on a healthy cluster.

## TASK

- `src/drill.rs` — the module this step adds:
  - `Check::{Attempted, RefusedWhileIsolated, CommittedWhileConnected}`, the three sentences;
  - `Drill::judge(transcript)`: walks the transcript once, carrying the cut graph and the crashed
    set, and judges each write against the state **at that moment** — a transcript's final state
    says nothing about whether a write happened while the cluster was split;
  - `built_in()`: the checks the course's scenario has to satisfy.
- `docs/partitions.md` — the page this step ships (`links` judges it): the distinction, the three
  sentences, and the scenario.
- `tests/sim_partition.rs` is course content: the drill across schedules.

## DONE WHEN

```sh
cargo test -p meshkv --test spec_partition_drills      # the six cases
KILN_SIM_SEED=1 cargo test -p meshkv --test sim_partition -- --nocapture
```

The second prints the verdicts the drill draws and the digest; every seed has to show exactly one
refusal (the write sent to the isolated node) and commits after the heals.

## TRAP

- **A single cut link is not an isolation.** A node cut from one peer still reaches a majority; a
  drill that asserts otherwise fails on a healthy cluster. The spec has a case that pins this
  distinction from both sides.
- **Judge each write against the state at that moment.** Reading the transcript's end and inferring
  backwards is how a drill passes a scenario it should fail.
- **A crashed node is isolated too.** The same sentence, a different fault; the drill treats a node
  that is down as one that cannot reach a majority.
- **The count is part of the drill.** A scenario with one write cannot satisfy a drill that requires
  two, and a run that attempted fewer says less than the drill claims.
- **The heals have to be symmetric with the cuts.** Two cuts need two heals; a scenario that leaves
  a link cut and then expects commits is a scenario that is wrong, not a cluster that is broken.

## FURTHER

- The distinction "cut from one peer" vs "cut from all peers" is the arithmetic of quorums, and
  `5.5`'s joint consensus is the same arithmetic applied to membership: any majority of the old and
  any majority of the new must intersect.
- `5.15` rolls the same drill out over restarts, `5.16` turns the faults into a matrix with an
  expected behaviour per cell, and `5.22` audits that what the majority committed is what every node
  ended up holding.
