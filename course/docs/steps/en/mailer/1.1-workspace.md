# Split the crate into a library and a thin binary

## WHY

Most Rust services start as one `main.rs`, and that is where they stay: every decision lives in the
function that also prints to a terminal. The cost only shows up later. You cannot test the parsing
without starting a process and reading its stdout. You cannot reuse it from the worker you will
write in step 14. When the router arrives in step 7, it lands in the same file, and the file becomes
the place where every change conflicts with every other change.

Splitting the crate is a five-minute decision that buys all of that back. The library owns what the
service *does*; the binary owns how it *looks* to whoever started it. Every later step of this track
adds to the library, and the binary stays a shell.

## TASK

- Create `src/lib.rs`. Everything that decides something goes there — today that is argument
  parsing, and by step 7 it will be the router, the store and the worker.
- Keep `main.rs` a shell: it asks the library what to do, prints the answer, and exits with the code
  the library decided. The spec allows **20 lines of code** there (blank lines and comments are not
  counted).
- Keep all three behaviours the skeleton already has: `--help` prints the usage and exits 0,
  `--version` prints the version and exits 0, and an unknown flag prints a message that names it and
  exits non-zero.
- Do not move the printing into the library. `clippy::print_stdout` is a library lint at rung 1 of
  the ladder (step 2), because a library that writes to a terminal cannot be used from anything that
  is not a terminal.

`kiln run` copies this step's spec into `app/mailer/tests/spec_layout.rs` and runs it. It checks
three things: `cargo check --lib` accepts the package as a library, the binary still answers all
three ways, and `main.rs` is a shell. The third one is a *measurement* rather than a behaviour, and
the reason is worth knowing: a test of a crate that may not have a library target yet cannot call
into that library, so "the binary is thin" is checked as a budget instead of invoked. The other two
are behavioural, and they are what breaks if you get the split wrong.

## DONE WHEN

- `kiln run mailer/1.1-workspace` — the spec passes
- `kiln check mailer/1.1-workspace` — every must gate is green
- `cargo run -- --help` prints the usage, and `cargo run -- --version` prints `mailer 0.1.0`

## TRAP

1. **Keeping a second copy of the logic in `main.rs`.** The usual shape is: move everything into
   `src/lib.rs`, then write the `match` again in `main.rs` "because it is only four lines". The
   budget assertion fails with `main.rs has 26 lines of code (budget: 20)`, and the two copies drift
   the moment one of them changes.
2. **Delegating by `pub fn main()`.** A library function called `main` is legal Rust and reads
   nicely from `main.rs`, but it makes the entry point a library API: the next step needs a shape it
   can call from a test as well as from a binary. Give the entry point a name about what it does
   (`parse`, `launch`, `run`).
3. **Deleting the usage text while moving it.** Moving `USAGE` into the library and forgetting that
   `--help` printed it leaves a binary that exits 0 and says nothing; the spec's help assertion
   reports exactly that.
