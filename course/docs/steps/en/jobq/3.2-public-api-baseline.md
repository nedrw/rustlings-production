# Write the public surface down, so a break is a compile error

## RECALL

- `api/library-design@aware` — `jobq/3.1-engine-boundary`: the arrow only points one way, the engine
  runs a queue with no server in the process, and the port's methods return `BoxFuture` because an
  `async fn` in a trait is not dyn-compatible. That step drew the boundary; it did not say which
  names a caller may depend on. Today everything under `jobq::engine` is public — the layout
  included, so `jobq::engine::store::memory::MemoryStore` is as much of a promise as `Engine` is.
- `err/typed-errors@apply` — `mailer/1.5-errors`: the failure type is part of the API, the variants
  are what a caller matches on, the causes are reachable through `source()`, and the shell gets an
  exit code. One service's callers were its own tests and its own binary. Here the callers are other
  programs, and this step is where that difference starts to cost something.

## DELTA

What is new is not a shape but a **promise with a version behind it**. `jobq/3.1` made the engine
compile without the daemon; this step makes the engine's surface something you can break *visibly*.
Those are different jobs, and the four moves below are the whole of it:

- **paths stop being API.** A module's layout is an implementation detail: `jobq::engine::domain::…`
  exists because the engine's own code is tidier that way, not because a caller should be able to
  name it. Split `scheduler` in two and every caller of `jobq::engine::scheduler::Engine` has to be
  rebuilt for a refactor. What a caller may name is what `jobq::engine` re-exports, and after this
  step that list is the whole surface — moving a type is then the crate's business, not the
  caller's.
- **growth is declared.** `JobState`, `Error`, `Job` and `SubmitRequest` are all going to grow:
  `jobq/3.14` adds states, `jobq/3.3` gives the error enum a source chain, `jobq/3.7` gives a job a
  lease. `#[non_exhaustive]` is how a crate says "this will grow" in the one place a caller's
  compiler reads it: outside the crate a `match` over the type needs a wildcard arm, so the release
  that adds a variant is not the release that breaks every consumer.
- **the port closes.** The store port's documentation promises that every implementation behaves the
  way the conformance suite of `jobq/3.5-store-port-conformance` asserts. That promise can only be
  kept by the crate that runs the suite — so the trait gets a supertrait from a private module, and
  `impl Store for MyStore` stops compiling in anyone else's program. This is the one change here that
  is *narrowing* the API on purpose, and it is narrowing it to keep a promise the wider version
  could not.
- **the evidence is not yours.** A test you write about your own surface is a test you can weaken.
  The course ships a witness of the surface (`course/tracks/jobq/api/3.2-public-api-baseline.rs`,
  compiled as `tests/semver_baseline.rs`): a function pointer per public function, a `match` arm per
  public variant, `..` per struct pattern. It compiles against your crate or the step is not done —
  and because it is course content, "the surface still holds" is a statement about the crate rather
  than about the test.

The habit this step is really teaching is the one the release step `jobq/3.25-release-artifacts`
spends: a breaking change is allowed, but it has to be *paid for* — a version bump and a changelog
line, not a surprise for whoever upgraded.

## TASK

- Make the engine's modules internal: `pub(crate) mod domain;`, `error`, `scheduler`, `store`, and
  `pub(crate) mod memory` inside `store`. Nothing under `src/engine` is a `pub mod` any more.
- Re-export at `jobq::engine` every name that was public before, so that a path moves and no name
  disappears: `Job`, `JobId`, `JobState`, `Queue`, `SubmitRequest`, `WorkerId`, `QUEUE_NAME_MAX`,
  `DEFAULT_MAX_ATTEMPTS`, `Error`, `Engine`, `MemoryStore`, `Store` and `BoxFuture` (the port's
  methods return it, so a caller who reads the port's signature has to be able to name it).
- Seal the port. A private module (`mod sealed;` under `src/engine`) holds `pub trait Sealed {}`;
  `Store` takes `Sealed` as a supertrait, and every backend the crate certifies implements it
  (`impl Sealed for MemoryStore {}` — the compiler will insist, which is the point).
- Mark `JobState`, `Error`, `Job` and `SubmitRequest` `#[non_exhaustive]`. Mark the **type**, not a
  variant and not a field: the daemon builds `Error::Config { detail }` itself, and a
  `#[non_exhaustive]` on the variant would stop it.
- Speak the surface in the crate's own code: `src/service/**` and `src/bin/jobqd.rs` name
  `crate::engine::{Error, MemoryStore, Queue}` rather than the private module paths, and no public
  doc comment links to a module that just became `pub(crate)` — `cargo doc --no-deps` warns
  `public documentation for … links to private item …`, and the documentation of a library is part
  of what it promises.
- Make the course's witness compile: `cargo test -p jobq --test semver_baseline` (the file arrives
  as `tests/semver_baseline.rs` when the step is prepared; the `semver@baseline` gate is exactly
  this command).

## DONE WHEN

- `kiln run jobq/3.2-public-api-baseline` — the spec's four claims pass: the surface runs a job,
  the engine's modules are not public paths, the port cannot be implemented from outside, and the
  four types that will grow say so.
- `kiln check jobq/3.2-public-api-baseline` — every must gate is green, `semver@baseline` included.
- `cargo test -p jobq` in `app/jobq` — every suite passes, `jobq/3.1`'s spec included: a step that
  moves the surface must not break what was already promised about it.

## TRAP

1. **Re-exporting most of the names.** Making `domain` `pub(crate)` and forgetting `BoxFuture`,
   `QUEUE_NAME_MAX` or `DEFAULT_MAX_ATTEMPTS` in the `pub use` list compiles fine inside the crate
   and fails in the witness with `error[E0432]: unresolved imports …`, naming the items that
   vanished. The rule the step is about: a path may move, a name may not disappear.
2. **Marking one enum and not the other.** The witness's wildcard arms are compiled under
   `#![deny(unreachable_patterns)]`: leave `#[non_exhaustive]` off `Error` (or off `JobState`) and
   `cargo test --test semver_baseline` fails with `error: unreachable pattern` pointing at the arm
   that is supposed to be the caller's protection.
3. **Writing `pub mod sealed;`.** The seal is the *unreachability* of `Sealed`: a module anybody can
   name is a module anybody can implement `Sealed` in, and `impl Store for TheirStore` compiles
   again. The spec reports it by file and line — "declares the sealed module as a public path".
   Sealing the trait and forgetting `impl Sealed for MemoryStore {}` fails earlier, with
   `error[E0277]` — the trait bound `MemoryStore: Sealed` is not satisfied — at the `impl Store for
   MemoryStore` line the compiler points at.
4. **Putting `#[non_exhaustive]` on `Error::Config` instead of on `Error`.** The daemon constructs
   that variant, so `src/bin/jobqd.rs` stops compiling with `error[E0639]: cannot create
   non-exhaustive variant using struct expression`. The attribute belongs on the type: what a caller
   must plan for is the enum growing, not the variant's fields.
5. **Leaving the module doc links behind.** `src/engine/mod.rs` names `domain`, `store` and
   `scheduler` in `[...]` links, and those resolve only while the modules are public. `cargo doc
   --no-deps` then answers "public documentation for `engine` links to private item `domain`" — once
   for each link — and a caller reading the crate's documentation follows links that go nowhere. No
   gate on this step builds documentation, so this is the one item on this list you catch by looking.

## FURTHER

- [`#[non_exhaustive]`](https://doc.rust-lang.org/reference/attributes/type_system.html#the-non_exhaustive-attribute)
  — what the attribute does at each position (enum, variant, struct, field) and what it deliberately
  does not do.
- [The Cargo book: SemVer compatibility](https://doc.rust-lang.org/cargo/reference/semver.html) —
  the list this step is a smaller copy of: which changes are breaking, and which only look like it.
- [`rustc --explain E0603`](https://doc.rust-lang.org/error_codes/E0603.html) — the error a caller
  gets when a path they used stops being public, which is the thing to avoid and the thing a
  deliberate break accepts.
- [`rustdoc` lints](https://doc.rust-lang.org/rustdoc/lints.html) — `private_intra_doc_links` among
  them, the trap above.
- [`cargo-semver-checks`](https://github.com/obi1kenobi/cargo-semver-checks) — what the production
  version of this check looks like; this course's `semver@baseline` gate compiles a witness with
  `rustc` instead, so a step never depends on a tool you might not have installed.
