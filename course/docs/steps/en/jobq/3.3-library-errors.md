# An error type is part of the API: variants, sources, and wording you can promise

## RECALL

- `err/typed-errors@apply` — `mailer/1.5-errors`: one variant per way the service can fail, the
  cause of a failure exposed through `source()` instead of flattened into a sentence, an `exit_code`
  for the shell, and `# Errors` sections on every public fallible function from that step on.
- `api/library-design@apply` — `jobq/3.2-public-api-baseline`: the surface is what `jobq::engine`
  re-exports, the types that will grow are `#[non_exhaustive]`, and the course's witness
  (`tests/semver_baseline.rs`) is what says the surface still holds. `Error` is one of the four
  types that step marked as growing — this step is where one of those growths actually happens.

## DELTA

In `mailer` the caller of this type was the same program: the service's own tests, its own binary,
its own HTTP layer. Here the caller is *somebody else's program*, and that changes what an error type
can afford to be:

- **the caller does not share your dependencies.** A variant whose cause is `sqlx::Error` makes every
  caller depend on `sqlx` — and `jobq/3.4` has to build this crate without the durable backend at
  all. So the store's cause is boxed: the engine hands over the backend's own error, a caller that
  knows the concrete type gets it back with `downcast_ref`, and a caller that does not gets its
  `Display`. The driver stays on the backend's side of the port, which is what the port is for.
- **the engine classifies; the caller decides.** `is_retryable()` is a question the *caller* asks,
  because the caller owns the policy — how many attempts, with what backoff, against what deadline.
  A service that owns its retry loop does not need the distinction; a library that is called by a
  worker it has never seen does.
- **the wording is published.** `Display` text ends up in runbooks, dashboards and tickets, so it is
  pinned by a test the *course* owns. A message you rewrite without meaning to is a change to the
  interface, and this step is where that becomes visible in review.
- **growth is additive.** The enum is `#[non_exhaustive]` and every caller writes `_ =>`, so the
  compatible way to add a failure is to add a variant — reshaping one that exists is the breaking
  change, and it breaks the witness of `jobq/3.2` as well as every caller.

The line this step draws for its own tree: **the failures a caller may have to walk carry a
`#[source]`** — the store's, and the operating system's behind `Io`. `Invalid`, `NotFound` and
`Config` keep a sentence, because what they describe is this crate's own judgement about a value
("`worker.batch` must be at least 1") rather than somebody else's failure being passed through.

## TASK

- Give the store's variant the backend's failure as its cause: `Store { #[source] source: Box<dyn
  std::error::Error + Send + Sync + 'static> }`. Not a `detail: String` — the spec proves the chain
  carries the backend's own error by downcasting to a type it defined itself.
- Keep `Io`'s `#[from] source: std::io::Error` whole, kind included: `?` on an `io::Result` stays
  the shortest path to the variant, and a caller that branches on `ErrorKind` still can.
- Leave `Invalid`, `NotFound` and `Config` as they are: a sentence each, no `#[source]` on a field
  that is not a cause.
- Add `is_retryable()`: `true` for the store's failure, `false` for everything else, and `false` for
  any variant a later step adds until somebody argues otherwise — the safe half of the decision, and
  the reason the body of the method names the one retryable variant instead of listing the others.
- Keep `exit_code()` exactly as it is. `jobqd` and `jobqc` already exit with 2 for a bad call, 3 for
  a missing thing, 4 for a refused store and 1 for a broken environment; a tidy-up of that table is
  a change to two binaries' contract, not a refactor.
- Keep every public item documented, `# Errors` sections included: `docs:public` has been a must
  gate since `mailer/1.5-errors`, and `clippy@3` — the rung this step moves the track to — denies
  `missing_errors_doc` and a small pedantic whitelist on top of `clippy@2`.

## DONE WHEN

- `kiln run jobq/3.3-library-errors` — the spec's four claims pass: the text of every variant is
  pinned, the chain walks to the real cause, retryability is per class, and the exit codes stand.
- `kiln check jobq/3.3-library-errors` — every must gate is green, `clippy@3` and
  `semver@baseline` included: `jobq/3.2`'s witness still compiles, so the shape you kept is the one
  that was promised.
- `cargo test -p jobq` in `app/jobq` — every suite passes, including the earlier steps' specs.

## TRAP

1. **Flattening the cause into a `detail`.** Keeping the old field and writing
   `Store { detail: format!("{error}") }` compiles, prints *exactly* the same line — and
   `source()` returns `None`, so the spec fails with "the chain must carry the backend's own error":
   a caller that wants to tell a connection reset from a constraint violation has nothing to walk.
2. **Naming the driver's type.** `Store { #[source] source: sqlx::Error }` is the tempting way to
   "not box it". `tests/spec_library_errors.rs` is compiled without `sqlx`, so it stops compiling
   with `error[E0308]: mismatched types` — and the crate stops being *assemblable*: gated behind a
   feature the `--no-default-features` build of `jobq/3.4` fails to compile, ungated it pulls a
   database driver into the binary of every caller who wanted only the queue.
3. **Being generous with `is_retryable`.** Returning `true` for `Io` ("a read can be interrupted")
   or for `Invalid` ("the caller might fix it") reads reasonable and fails the spec on the class
   it names: `Error::Io` is retryable = false — *a full disk does not become empty by asking again*.
4. **Reshaping a variant instead of adding one.** Renaming `Config`, or folding `Io` into it,
   changes the shape `jobq/3.2`'s witness matches on: `cargo test --test semver_baseline` fails with
   `error[E0599]: no variant or associated item named …`, which is the baseline doing its job — the
   change is allowed, but it has to be paid for.
5. **Rewording a message while you are in the file.** `store: {source}` → `store failure: {source}`
   looks like a readability fix; it is a change to a published string, and the spec's pinned text
   fails on it. Operators grep for these lines at three in the morning.
