# 用"落后"的连续段告警

## 为什么

存活检查回答"进程在不在跑"。lag 告警回答"它跟不跟得上"——在消费者活着、落后十分钟的那天，这是
两个不同的问题。要紧的是第二个，而它需要单个样本给不了的两个参数：

- **一个阈值**——对这个队列来说，多少 lag 算"落后"；
- **一个连续段长度**——连续多少个超阈值样本才叫人。

两个边界都是每个告警都写错过一次的地方。阈值是**严格**高于：恰好落在选定数字上的 lag 在它上面、
没有越过它，在那里响的告警会在每个正常窗口都响。连续段是一段：一次噪声样本不是事故，一次安静样本
也不代表恢复——段会被重置，而要报的是**末尾**那一段。

## 任务

脚手架加上了 `src/alert.rs` 和它的 `pub mod alert;` 那一行。

- **[`evaluate`]**——对一段 lag 历史的末尾：当末尾连续严格高于 `threshold` 的样本数达到
  `consecutive` 时给出 `Lagging { samples, lag }`；`samples` 是那一段的长度，`lag` 是最近的样本；
  其余情况（包括历史比段短、`consecutive == 0`）是 `None`。

## 完成标准

- `kiln run broker/7.9-lag-alert` —— 规格通过
- `kiln check broker/7.9-lag-alert` —— 每个 must 闸门都是绿的
- 阈值 5、段长 2 时，`[3, 6, 7]` 告警并报两个样本；`[9, 9, 1, 9]` 不告警

## 陷阱

1. **一个样本就告警。** 第一个超阈值样本就把人叫起来，而一分钟尖峰一次的队列每分钟叫一次：段长正是
   为这个存在的。
2. **阈值用 `>=`。** 恰好等于所选数字的 lag 就是所选数字；边界测试失败，每个平稳窗口都在告警。
3. **报第一段而不是末尾那段。** 中间的一次低谷结束了一段；报那一段更早、更长的，描述的是已经过去的
   一次恢复。
4. **`consecutive == 0` 时什么都告警。** 空的段长是配置错误；规格要的是 `None`，而不是"每个样本都
   告警"。
