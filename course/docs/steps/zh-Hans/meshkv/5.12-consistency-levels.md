# 一致性是一个旋钮：每个级别承诺什么，代价是什么

## 为什么

`5.6` 给读只给了一个答案：leader，带租约，而且是线性一致。那是最强的承诺，也是最贵的——每次读都要
leader，而 leader 是三个节点里的一个。

大多数读不需要它。每十秒刷一次的仪表盘，不在乎一毫秒前落下的那次写入；一个预热缓存的程序，能忍一秒
的陈旧；运维问“*这个*节点上有什么”，要的是完全另一个问题的答案。旋钮就是调用方说明自己问的是哪一
种的方式，而这里的三个级别，是每个复制存储都提供的那三个：

| 级别 | 承诺 | 谁能作答 |
| --- | --- | --- |
| `linearizable` | 读开始后的某一刻为止是正确的 | leader，租约已确认 |
| `bounded-stale:<n>` | 最多落后集群的提交 `n` 个条目 | 任何能*证明*自己落后不超过 `n` 的节点 |
| `local` | 这个节点应用了什么就是什么 | 任何节点 |

有意思的不是那个枚举。是**每一个级别在兑现不了的时候，都必须拒绝**。一个 follower 被要求做线性一致的
读，必须照实说，而不是拿自己的状态作答；一个节点被要求 bounded-stale，必须能*证明*自己的滞后，而不
是假定。被悄悄降级的级别比被拒绝的级别更糟，因为调用方永远不知道它拿到的是哪个承诺——而分不清的调用
方，就是一个对自己的读没法推理的调用方。

## 任务

- `src/consistency.rs`——这一步新增的模块：
  - `Level::{Linearizable, BoundedStale { max_lag }, Local}`，带 `parse`/`render`
    （`linearizable`、`bounded-stale:<n>`、`local`）和 `is_linearizable`；
  - `Answer::{Served { index }, Refused { reason }}`；
  - `answer(level, is_leader, lease_index, applied, commit, leader)`：整个策略就是一个纯函数。它需
    要的每一个事实——包括滞后——都是参数，所以一个级别的边界可以离开集群来测。
- 滞后不在这里测量：节点知道自己的应用下标，而 leader 的提交下标是它从 leader 的消息里学来的
  （`5.3`）。调用方把两者都传进来；这个模块不碰时间，也不碰网络。
- `tests/sim_consistency.rs` 是课程内容：三个滞后不同的节点，每个节点每个级别一次读，种子决定顺序和
  滞后。

## 完成标准

```sh
cargo test -p meshkv --test spec_consistency_levels      # the eight cases
KILN_SIM_SEED=1 cargo test -p meshkv --test sim_consistency -- --nocapture
```

第二条打印落后最多的那个节点的滞后，以及每个级别对它的判定；另一个种子是另一组滞后，规则相同。

## 陷阱

- **follower 不得回答线性一致的读。** 它不知道自己落后多远；老实的回答点名 leader，调用方去那里重
  试。
- **没有租约的 leader 也答不了。** 它*多半*还是 leader，而“多半”正是这门课一直在删掉的那类答案
  （`5.6`）。
- **没有 leader 可以丈量，界就无从证明。** 一个没听说过任何 leader 的节点，证明不了自己的滞后，
  所以它拒绝而不是猜——拒绝就是老实的答案。
- **回答会点名它对哪个下标成立。** 对 bounded-stale 和 local 的读，那是节点的应用下标；对线性一致的
  读，那是租约的下标，不是更新的提交——被告知更新那个下标的调用方，会相信一个在这一轮之后才提交的
  值。
- **领先于自己所知道的提交的节点，不是“负落后”。** 滞后是零，而一个为零的界会服务它。
- **被悄悄降级的级别就是那个 bug。** 这个旋钮的价值在于调用方可以相信自己要的那个承诺；一个会悄悄降
  级的级别，一点价值都没有。

## 延伸阅读

- 这正是业界争来争去的那个取舍，“linearizable 对 bounded-stale 的读”；要紧的是算术，而这一步让算术
  变得可测。
- `5.18` 把这些级别放上仪表盘：集群的 SLO 按级别分别声明，因为一次 bounded-stale 的读和一次线性一致
  的读，预算不一样。
