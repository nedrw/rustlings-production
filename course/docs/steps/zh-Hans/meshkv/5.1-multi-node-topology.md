# 集群是一张名单：节点身份、拓扑，以及两个节点彼此问候的那一行

## 回顾

- `repo/workspace-layout@apply`——`mailer/1.1`：一个项目、一个 `[workspace]`，一个库加一个薄薄的
  二进制，`fmt` 和 `clippy` 在别的一切之前先接好。
- `err/typed-errors@design`——`jobq/3.3`：一个错误枚举，变体说得出这次拒绝*从哪儿*来；每个调用的
  文档写明它拒绝什么。
- `domain/parse-dont-validate@apply`——`jobq/3.14`：一个只有被检查过才可能存在的值——名字变成一个
  类型，系统其余部分再也不重新校验它一遍。
- `async/graceful-shutdown@operate`——`jobq/3.7`：守护进程在接任何东西之前先装好信号处理；停止不是
  被杀掉，而是一条有最后一行的路径。
- `cli/contract@apply`——`jobq/3.15`：一个二进制拒绝 `--kiln-exit-code-probe` 那样的胡话时会*点名*，
  以非零退出码结束，且不 panic。

## 变化

前四个项目给你的，都是一个跟客户端说话的进程。这一个头一回要跟*自己*说话：集群是几个进程，它们得
先对「谁在里面」达成一致，才谈得上对别的事达成一致；而这条 track 之后的每一步——投票、复制、提交、
分区——都是对着这一步发出去的那些身份写的。

新东西有两样，都关乎**名字**与**地址**的区别：

- 节点的名字，是系统提交、投票、复制时谈论的东西；它的地址，只是它今天恰好能从哪儿被连上。一次
  部署把节点挪到另一个端口，改变的是一个地址，没有改变这个节点是谁。现在就在类型系统里把两者分开，
  因为这一步之后的每一步都要写那种会把两者悄悄混起来的代码：成员变更（`5.5`）重写的是地址，证书
  （`5.9`）认证的是名字，而一个被重定向的客户端（`5.7`）被告知的，是它该去哪个名字上重试。
- 集群**先是数据，然后才是网络**。一个节点对同伴的全部所知，就是一个字符串；解析它是带拒绝的纯
  函数——重名、没有名字的条目、不是 `host:port` 的地址。从 `5.13` 起的那些步骤，会把集群底下的
  网络换成一套模拟网络；它们能做到这件事，只因为这套拓扑从来就不是一个套接字。

还有一处不同在闸门。这条 track 从 T4 结束的那根横档起步：`clippy@4` 把这一级的全部要求都带上了
（包括那份 pedantic 白名单），`unsafe_code = "deny"` 从这一步就进了 manifest，而不是等到第一个
需要 `unsafe` 的步骤；而你能拿到的提示，只有你正在读的这一页。

## 任务

- `src/cluster.rs`——`NodeId::parse`，拒绝里写明接受的字母表；`Topology::parse` 解析
  `id=addr,id=addr`，拒绝时点名它拒绝的那个条目；`len`、`is_empty`、`lookup`（一个谁都没有的
  名字，是一个会把它引用出来的拒绝）、`render`（规范写法，好让两个节点比对各自拿到的东西）。
- `src/node.rs`——`hello_line` 和 `parse_hello`，管那句一行的握手 `MESHKV/1 hello <id>`；`Node::bind`，
  开套接字之前先拒绝一个拓扑里没有的名字；`Node::accept`，读一句握手，拿名字去对拓扑，用它自己的
  名字作答，返回一个 `Session`——或者拒绝，点名哪里不对，而不把监听器一起带倒；`greet`，连上去，
  以自己的身份握手，然后确认它在这个地址上连到的，正是它*想要*连到的那个节点。
- `src/cli/mod.rs`——`Flags::from_args`：`--cluster`、`--node`、`--listen`、`--help`、`--version`，
  其余一切按名字拒绝。
- `src/bin/meshkvd.rs` 和 `src/bin/meshkvc.rs`——守护进程打印 `listening on <addr>`，收到 `SIGTERM`
  时带着 `draining` 停下；`meshkvc topology --cluster <spec>` 每行打印 `id addr`，于是可以证明
  运维和库把同一份规格读成了同一个样子。

## 完成标准

`cargo test -p meshkv --test spec_multi_node_topology` 通过，而下面这段打印出两行一模一样的话：

```sh
cargo run -q -p meshkv --bin meshkvd -- --cluster n1=127.0.0.1:7101,n2=127.0.0.1:7102,n3=127.0.0.1:7103 --node n2
cargo run -q -p meshkv --bin meshkvc -- topology --cluster n1=127.0.0.1:7101,n2=127.0.0.1:7102,n3=127.0.0.1:7103
```

## 陷阱

- **名字不是地址，而类型是唯一守得住这一点的地方。** 大多数项目里这一步的第一版，用地址给一切做键，
  因为*今天*这样方便——然后 `5.5` 挪了一个节点，系统里每张 map 都过期了。
- **重名比缺名更糟。** 两个节点都应着 `n1`，就是一个能在同一个身份下把同一个 index 提交两次的
  集群。所以拒绝它的是解析器，不是凌晨三点的运维。
- **握手是一行字，而一行字必须有上界。** 不限长地读一行，等于让对端决定这个进程占多少内存。上限
  要在字节到达时就检查，在相信对端身份之前。
- **先信身份再去核对，和不做认证是同一个 bug。** 握手说出了一个名字；决定这个名字是不是成员的，
  是拓扑。`5.9` 会加上证书，让这句声明没法伪造——而这一步已经在拒绝它不认识的名字，所以后面加
  密码学的那一步，有东西可挂上去。
- **`--listen 127.0.0.1:0` 是正常写法，不是错误。** 端口由内核挑，`Node::local_addr` 告诉你它挑了
  哪个；一个假定 7000 的测试，是在跟机器赛跑。
- **握手失败的对端，不能把节点一起带倒。** accept 是一个循环，拒绝属于这条连接，不属于这个进程。

## 延伸阅读

- Raft 论文的 §1 和 §2（*In Search of an Understandable Consensus Algorithm*，Ongaro & Ousterhout）
  正是用这套话讲成员与身份的——一份配置就是一组服务器，其余一切都是它们之间的消息。
- `openraft`（plan §7 里 D-1 否掉的那个选项）也有同样的两个类型，名字叫 `NodeId` 和 `Membership`；
  现在读一读它的 `Node` 类型，就能看出你正在写的这套设计能推广到多远。
- `meshkvc topology` 是第一条运维命令。`5.15` 和 `5.22` 把这个想法做成一个演练装置和一次审计——
  两者都从问一个节点它相信什么开始。
