# 一次写入就是一条日志条目，而日志条目由多数派提交

## 为什么

每个复制系统讲的，都是同一张清单的故事。这张清单只追加，每个节点持有它的一个前缀；说「这次写入
发生了」，就等于说「这条条目永远留在清单上了」。数据库所说的持久性、顺序和一致性，全是这张清单
怎么被复制、以及清单上的某个位置何时可以相信的性质。

这一步讲的是那张清单的*规则*，而且是在有网络来搬动它之前。这个次序是故意的：规则只有四句话，而
每一句写进代码，都比说出口容易错。把它们写成值——一个任期、一条条目、一个多数派、一份带拒绝的
日志——下一步（一个有选举、心跳和线缆的 Raft）才只是接线的问题，而不是重新决定什么叫一个决定。

这一步要你写的那一页，不是为文档而文档。它就是同样四条规则的英文写法，而规格拿它跟代码比：两者之间
的漂移，正是一个分布式系统最后带着一条对自己协议撒谎的注释的原因。

## 任务

- `src/raft/mod.rs`，`Term`：一个只往上走的数（`next`），带一个能拿来比较的顺序。
- `Entry`：提出一次写入的那个任期，以及它从 1 起算的位置。
- `Quorum`：多数派是多少个节点（`size / 2 + 1`），以及一组确认的数目够不够它。零个节点的集群，
  多数派是一——什么都永远不会提交，这是诚实的答案，而不是 panic。
- `Log`：只追加，带着两处要紧的拒绝。一条条目必须落在 `len() + 1`（中间有空缺，就是一条这个节点
  从没收到过的条目），而它的任期不能比上一条的旧（日志是这个节点见过什么记下来的记忆）。
  `truncate_from(index)` 丢掉一段冲突的后缀——这是 leader 的日志跟自己的日志对不上时，follower 要
  做的那件事。它还要回答日志到哪儿为止：`last_index()`（最后一条条目的位置，空日志是 0）和
  `last_term()`（空日志是任期 0）——每一条复制消息都会问对端的两个问题。
- `committable`：**一条属于 leader 当前任期、且有多数派持有的条目。** 两个子句都在，重要性按这个
  顺序。
- `docs/consensus.md`：那四条规则（`raft::RULES`，逐字，按顺序），以及失败目录（`raft::FAILURES`，
  每条条目一行表格，两个格子里是同样的字）。

## 完成标准

`cargo test -p meshkv --test spec_replication_rules` 通过，而下面这段打印出四条规则和五行：

```sh
sed -n '1,80p' docs/consensus.md
```

## 陷阱

- **提交规则里关于任期的那一句，不是技术细节。** 一个把*继承来的*条目算作已提交的 leader，可能宣布
  一个下次选举就会撤销的决定——而这是日志绝不能产出的唯一一种结果。规格里有一个用例：每个节点都
  确认了一条来自上一个任期的条目，它仍然不能提交。
- **多数派是集群的性质，不是确认的性质。** `Quorum::of` 拿的是集群的大小；`is_met` 拿的是实际到了
  多少。从确认里推出来的多数派，永远都够。
- **空缺不是短日志。** 一条落在 index 7 的条目，到了一份长度为 3 的日志上，不是「剩下的随后就到」；
  那是一个节点在回答它没有的东西。拒绝它，让 leader 从 follower 真正所在的地方重发。
- **`truncate_from` 丢一段后缀，不合并两个日志。** 第一处对不上，就是两个节点意见相同的最后一个
  位置；它之后的全部，都归 leader 去替换。
- **`last_index()` 是位置，不是数目。** 今天这两个数相等，因为日志持有它拿到过的一切。`5.4` 开始做
  合并，从那时起 `len()` 就比最后的位置小——所以这个 crate 算出的每一个位置都来自 `last_index()`，
  从来不来自 `len()`。
- **四条规则、五行，写在一页上，也各写进一个常量。** 规格逐行比较它们：一页写着第五条规则、目录里
  却没有它的文档，是一份会被信任去讲一件代码从不做的事的文档。

## 延伸阅读

- Raft 论文 §5.3：「Log Matching Property」和「Figure 8」就是这一步变成 `Log::append` 和
  `committable` 的那两段。Figure 8 是当前任期子句的理由；读一遍，上面的陷阱就不再意外。
- `openraft` 把同样的几个值叫 `Term`、`LogId` 和 `Quorum`；它的 `LogId` 把一个任期和一个 index 配在
  一起，和这里的 `Entry` 一模一样，这不是巧合——每个 Raft 实现都需要这个类型。
- `5.3` 会加上承载这些值的消息类型，而它第一次用 `committable`，就是只拿 leader 自己的任期去调它。
