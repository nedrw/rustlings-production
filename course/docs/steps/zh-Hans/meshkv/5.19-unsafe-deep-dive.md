# unsafe 何处值回成本：miri 与 loom 之下的手写结构

## 为什么

这一步之前的每一步都禁掉了 `unsafe`。从 `5.1` 起，manifest 里就一直立着 `unsafe_code = "deny"`，而它
们谁都没需要它——这是正确的默认，也正是由这一步来改动它的理由：一个有界的单生产者单消费者**环形队列**，
全部职责就是让两个线程之间的那条路径上没有锁。安全版本每条消息要么加锁、要么分配；环形队列两样都不做。

这一步的要点不是「把 unsafe 写出来」。而是一个需要它的结构能为它**拿出论证**，而这份论证恰好有三项
义务：

1. **初始化**——一个槽在被一次 push 写入之前是未初始化的，而队列的不变量（`head <= tail`、`tail` 处
   只有一个写者、`head` 处只有一个读者），让每一次读都站得住；
2. **独占访问**——两个线程靠索引算术碰到不同的槽，而索引是原子量，两者之间隔着一对
   `Release`/`Acquire`；这一对就是全部的同步；
3. **恰好 drop 一次**——`Drop` 实现 drop 掉 `head` 与 `tail` 之间的槽，别的一概不碰。

每个 `unsafe` 块都带着一条 `// SAFETY:` 注释，点名它所依据的那项义务，而闸门（`unsafe-budget@5`）数块
的个数、并要求这些注释——所以这个 track 的元数据里的数字，就是这一个文件里块的个数。

## 任务

- `src/ring.rs`——这一步新增的模块：`Ring<T>` 建在 `Box<[UnsafeCell<MaybeUninit<T>>]>` 上，带一个
  `head` 原子量、一个 `tail` 原子量、`push`（环形队列满时拒绝，并把值交还）、`pop`、`len`、`is_empty`，
  以及一个恰好 drop 掉环形队列里那些值的 `Drop`。
- `Cargo.toml`——crate 级的 `unsafe_code = "deny"` 拿掉，在它原来的位置留一条注释，说明是哪一步为这次
  改动说了理由、替代它的是什么。
- `tests/loom_ring.rs`——课程内容：`loom` 检查的两个模型（一个用 `Release` 发布的值，恰好被一次
  `Acquire` 读到；一个槽在 `head` 越过它之前不被复用）。
- `docs/unsafe.md`——这一步交付的页面（`links` 判它）。

## 完成标准

```sh
cargo test -p meshkv --test spec_unsafe_deep_dive     # the six cases, including two threads
cargo test -p meshkv --test loom_ring                 # the two models, exhaustively
```

两条都绿，而且在预算就位的情况下 `cargo clippy` 干净。

## 陷阱

- **这个工具链上没有 `Miri`**（`1.98.1-aarch64` 不带 `miri` 组件——handoff M4 §1）。这一步把它明说：
  证据是 loom 加上写下来的论证，而页面点名缺了什么，而不是暗示一道跑不起来的检查。
- **内存序就是论证，不是装饰。** 在发布值的那个索引上用 `Relaxed`，消费者就可能读到一个还没写的槽——
  `loom_ring.rs` 里的模型，正是能找出它的那种交错。
- **满的环形队列拒绝；它不阻塞，也不丢弃。** 拒绝会把值交还，因为一个悄悄丢东西的队列，替调用者做了一
  个对方没做的决定。
- **`Drop` 是泄漏藏身之处。** 一个忘了 drop 自己内容的队列，会一直悄悄泄漏，直到忙起来；规格用例里的那
  个计数器，是唯一看得见它的办法。
- **预算数的是块的个数，而注释是闸门的一部分。** 新增一个 `unsafe` 块，就要提高 `track.toml` 里的数字；
  一个没有 `// SAFETY:` 注释的块，不管数字对不对，都过不了闸门。
