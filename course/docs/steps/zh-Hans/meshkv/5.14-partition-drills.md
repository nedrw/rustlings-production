# 分区是一种输入：少数派停止提交，并说出原因

## 为什么

`5.13` 把分区变成了一种输入——一份由种子重放的剧本。这一步把它变成**断言**：集群被切开时什么必须
为真，写成测试会检查的句子。

这是另一种活。剧本说会发生什么；演练说*必须*发生什么，而这些句子，正是一位运维的 runbook 用的那种
句子：

- **被隔离的节点不提交**——少数派不能决定任何事，否则一次切分的两侧就成了两个集群；
- **多数派照常工作**——一次让一切都停下来的分区，只是一次换了个好听名字的停机；
- **情景就是情景**——两笔写入的演练，不是三笔写入的演练。

还有一个区分，每一个分区测试的初稿都会弄错，而这一步存在的理由就是它：**切断一条链路不算隔离。**
在三节点集群里，一个与某个邻居断开的节点，仍然能通过另一个邻居够到多数派，所以发给它的写入会
提交——而且提交得对。只有与*每一个*邻居都断开的节点（或者崩掉的节点），才是少数派。一场把前一种
情况叫作脑裂的演练，会在一个健康的集群上失败。

## 任务

- `src/drill.rs`——这一步新增的模块：
  - `Check::{Attempted, RefusedWhileIsolated, CommittedWhileConnected}`，那三句话；
  - `Drill::judge(transcript)`：把运行记录走一遍，一路带着切断关系图和崩掉的节点集合，拿**那一刻**的
    状态去判每一笔写入——运行记录的最终状态，说不出集群被切开期间有没有发生过一次写入；
  - `built_in()`：课程的情景必须满足的那几条检查。
- `docs/partitions.md`——这一步交付的页面（`links` 判它）：那个区分、那三句话，以及情景。
- `tests/sim_partition.rs` 是课程内容：跨调度的演练。

## 完成标准

```sh
cargo test -p meshkv --test spec_partition_drills      # the six cases
KILN_SIM_SEED=1 cargo test -p meshkv --test sim_partition -- --nocapture
```

第二条打印演练给出的裁决和摘要；每个种子都必须恰好显示一次拒绝（发给被隔离节点的那笔写入），以及
各次愈合之后的提交。

## 陷阱

- **切断一条链路不算隔离。** 与某个邻居断开的节点仍然够得到多数派；断言相反情形的演练，会在一个健康
  的集群上失败。规格里有一个用例，从两头把这条区分钉住。
- **拿那一刻的状态去判每一笔写入。** 读运行记录的结尾再往回倒推，一场本该失败的演练就是这么通过一个
  情景的。
- **崩掉的节点也算被隔离。** 同一句话，另一种故障；演练把下线的节点当作够不到多数派的节点。
- **数量是演练的一部分。** 只有一笔写入的情景，满足不了要求两笔的演练；而一次尝试得更少的运行，能
  说明的东西比演练声称的少。
- **愈合必须与切断对称。** 两次切断就要两次愈合；一个留着链路断开却还指望提交的情景，错的是情景，不是
  集群。

## 延伸阅读

- "与一个邻居断开"和"与所有邻居断开"的区分，就是多数派的算术；而 `5.5` 的联合共识，是同一套算术用在
  成员上：旧的任意一个多数派，与新的任意一个多数派，必须相交。
- `5.15` 把同一场演练铺到重启上，`5.16` 把故障变成一张每个格子一个预期行为的矩阵，`5.22` 则审计
  多数派提交的东西，是不是每个节点最后持有的东西。
