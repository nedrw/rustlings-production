# 最后一场演练：多节点故障，然后用一次审计证明什么活了下来

## 为什么

这个 track 的每一步都在论证：一个决定扛得住点什么——投票扛得住一个失去的节点，提交扛得住一次分区
（`5.14`），快照扛得住一次重启（`5.4`），成员变更捱得过自己的窗口（`5.5`），升级扛得住两个构建
（`5.21`）。这一步检查的是这些论证是否立住了——从外面、事后，并且不信任任何一个节点单方面的说法。

最后这一句，是它成为审计而不是测试的原因。一个节点自己的计数器（`5.18`）说的是它相信什么；审计则问每
个节点同样两个问题，再比对答案：

- **你已经应用到哪个位置了？**
- **在那个位置上，你的状态是什么？**（一个摘要，而 `5.10` 让它只由条目决定，别的不算）

## 任务

- `src/audit.rs`——这一步新增的模块：
  - `State { node, applied, digest }`：一个节点的回答；
  - `audit(&[State]) -> Report`：公共前缀（最小的已应用索引）、谁分了叉（*在该前缀上*、摘要与多数派不
    同的节点），以及有多少节点作了答；
  - `Report::is_healthy` 和 `Report::summary`：runbook 打印的那句话，点出节点和索引——运维者据以行动的
    正是它。
- `docs/audit.md`——这一步交付的页面（`links` 判它）：问节点什么、审计推出什么，以及它收尾的三场演练。

## 完成标准

```sh
cargo test -p meshkv --test spec_consistency_audit
```

通过，七个用例说的是：意见一致的集群是健康的，跑在前面的节点不算发现，分叉的节点被点名，作数的是多数派
的摘要，没有一个人答话的审计被拒绝，同一个节点答两次被拒绝，而一个谁都不一致的集群，仍然产出能据以行动
的一句话。

## 陷阱

- **比对只在公共前缀上进行。** 跑在它前面的节点暂时没法比；拿它去和还没应用那些条目的节点比，就是一个繁
  忙集群的审计无缘无故失败的方式。
- **跑在前面不是发现。** leader 按定义就在前面；审计的职责是在共享位置上意见一致，而不是进度相同。
- **分叉是这个 track 存在就是为了防住的那种失败**，而报告必须点出节点和索引。「Audit failed」是一句谁也
  没法据以行动的话。
- **把同一个节点答两遍的采集器，是采集器自己的 bug。** 审计拒绝它，而不是把一个节点数两遍。
- **没有一个人答话的审计，不是健康的审计。** 它被拒绝：一道在谁都没答话时也能通过的检查，正是这门课一
  直在删的那类检查。

## 延伸阅读

- 这个形状，就是分布式存储的 `verify` 命令：问每个节点，在公共位置上比对，点出不一致的东西。
  `lakelet/4.22` 的可复现构建检查，比的是同一棵树的两个构建；这里比的是同一份日志的几个状态，而摘要
  在这两处是同一个想法。
- 这个 track 到这里结束：二十二步、一个集群，以及一句话，说它到底算不算一个集群——这是一套分布式系统最
  终必须回答的唯一问题。
