# SDK 就是产品：一个客户端、类型化的错误，以及一份自己的契约

## 为什么

这条 track 立下的每一条规则——leader（`5.7`）、幂等键（`5.8`）、读索引（`5.6`）、状态机的确定性
（`5.10`）——都是*客户端*必须遵守的规则。如果客户端只是 README 里的一个示例，每个调用方都会写出自己
版本的那套规则，而其中总有一个忘了带键。SDK 就是规则变成产品的地方：一个构造出来就正确的 API，因为
规则就在它里面。

三个决定让它成为 SDK，而不是一层薄包装：

- **错误类型就是契约。** `NotLeader`（去那里重试）、`Unavailable`（稍后重试）、`Refused`（不要重
  试）、`RetriesExhausted`（放弃）各有各的补救办法，而分不清它们的调用方没法做对。`is_retryable()`
  是那张表的两行版本。
- **重试归 SDK 管。** 跟着重定向走、用*同一个*键重试一次超时、到界就停，是同一项策略——而 SDK 里的
  策略，是每个调用方都拿得到的策略。
- **一次已被应用的写入就是成功，不管问了多少次。** 调用方要的是一次写入；写入存在了；它用了一次还是
  三次尝试，那是 SDK 的事。

## 任务

- `src/sdk.rs`——这一步新增的模块：
  - `SdkError::{NotLeader, Unavailable, Refused, RetriesExhausted}`，带 `is_retryable`，好让调用方
    不必对着字符串 match 就能决定做什么；
  - `Reply::{Applied, Redirect, NoLeader, Refused}`：对后端的一次调用会回答什么；
  - `Backend`：那个端口——一个 `write`，一个 `read`。这个 trait 就是 `conformance@2` 用的那条缝；
  - `Sdk<B>`：重试策略。一次写入**只算一次**键（每次尝试一个键，会把重试变成第二次写入），跟着重定
    向走，到 `MAX_ATTEMPTS` 就停（或者在拒绝时立刻停）。
- `conformance.toml` 和 `tests/support/mod.rs` 是课程内容：项目为这个端口声明了两个实现——一个
  **脚本化**的表和一个**进程内**集群——而闸门用 `KILN_BACKEND` 对两者跑同一套用例。
- `docs/sdk.md`——这一步交付的页面。

## 完成标准

```sh
KILN_BACKEND=scripted   cargo test -p meshkv --test spec_client_sdk
KILN_BACKEND=in-process cargo test -p meshkv --test spec_client_sdk
```

两边都通过，八个用例在每一边说的是同一件事：leader 直接服务，follower 重定向，拒绝不被重试，同一次
写入做两遍是一次写入，而 SDK 从不向调用方要键。

## 陷阱

- **每次尝试一个键，就是第二次写入。** 幂等键按*调用*算一次，不是按尝试；重试是同一次写入，这才让
  它安全。
- **拒绝不能重试。** 重试一个 `Refused`，是把调用方的耐心花在一个不会变的答案上。
- **宕掉的节点和不是 leader 的节点，是两种失败。** 前者是 `Unavailable`（稍后重试），后者是
  `NotLeader { leader }`（去那里重试）；把两者压成一个，得到的客户端要么在一个死节点上空转，要么对
  一个活节点放弃。
- **界是一个数。** 一个从不点名 leader 的集群必须产出 `RetriesExhausted`，而不是一个空转的客户端；
  `MAX_ATTEMPTS` 就是用例检查的那个数。
- **leader 看得出不会对上的比较并交换，在花掉一个日志条目之前就被拒绝。** 否则状态机会永远回答
  `Mismatch`，而调用方分不清一次拒绝和一次慢写入。
- **两个实现，一套用例。** 一项在脚本化后端上通过、在进程内后端上失败的策略，依赖实现里的某个偶
  然——那正是 `conformance@2` 存在要抓的东西。

## 延伸阅读

- 每个客户端 SDK 都长这个样子：一个类型化错误、一项有界重试策略、一个传输端口。`openraft` 的
  `Client` 是同样的三块。
- `5.12` 给 SDK 一个一致性旋钮：同一个 `read` 加一个级别，由级别决定它是去 leader（linearizable）、
  去任何能守住界限的节点（bounded-stale），还是从本地状态读（local）。
