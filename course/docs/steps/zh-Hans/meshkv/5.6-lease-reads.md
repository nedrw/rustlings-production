# 读问的是此刻：线性一致的读，以及让它们变便宜的租约

## 为什么

复制日志回答「发生了什么」。读回答「现在*是什么*」，而这是两个不同的问题：一个 follower 可以落后
一百条条目，却仍然拿一个集群两秒前就替换掉的状态自信作答。这就是陈旧读，而它不是小问题——一次读
之后拿陈旧答案做一次写，就是一次丢失的更新，而共识日志的全部意义，正是拦住这个。

每个复制的存储都用同样的办法解决它，而这一步把解法的两半都实现了：

- **读 index。** 想作答的 leader 不信任自己的记忆。它发一次心跳，等集群的多数派*在 leader 自己的
  任期里*确认它，然后才用它在这一轮之前看到的提交 index 作答。多数派就是证据：这个任期里别的节点
  不可能当选，除非这些确认里至少有一份在它那里。
- **租约。** 这份证据不必为每一次读重来一遍。如果多数派在 `t` 时刻确认了 leader，而选举超时是 `T`，
  那么在 `t + T` 之前，别的节点赢不了选举——所以 leader 在此期间可以在本地作答。这个窗口就是租约，
  而它之所以安全，只因为它**严格短于**选举超时：一个活得比超时还长的租约，就是一次多绕了几步的
  陈旧读。

这一步是 `design` 深度，只为一个理由：有意思的部分不是代码，而是关于*时间*的论证。读路径的正确性
取决于两个时长之间的关系，而评审要能核对的就是这个关系。所以规格来核对它：那句话就是
`is_safe_lease(lease, timeout)`，课程自己的常量必须满足它。

有一条设计规则塑造了这里每一个函数：**时间是参数，不是调用。** 一个自己去读 `SystemTime::now()` 的
租约，测不了（测试会跟窗口赛跑），也模拟不了（`5.13` 用虚拟时钟驱动这段代码）。每个需要知道此刻
的函数，都收一个以毫秒计的 `now`，而「现在」是什么意思，由调用方——守护进程、装置、模拟器——
决定。

## 任务

- `src/raft/read.rs`——`Lease`（一个到期时刻，和它覆盖的位置）、`ReadAnswer`（`Served`、`NotLeader`、
  `NeedsQuorum`）、`LEASE_MILLIS`、`ELECTION_TIMEOUT_MILLIS`，以及 `is_safe_lease`。
- `src/raft/state.rs`：
  - `confirm_read(now)`：只限 leader；把提交 index 记成读 index，并返回那些能证明领导权的心跳；
  - `complete_read(acknowledged, now)`：这个任期里的多数派就在读 index 上授予租约，回答 `Served`；
    少一点就回答 `NeedsQuorum`，什么都不授予；
  - `serve_read(now)`：follower 回答 `NotLeader`（知道 leader 就带上它）；leader 只在租约之内回答
    `Served`，租约之外回答 `NeedsQuorum`；
  - `read_index()` 和 `lease()`：节点当前持有的东西；
  - 而节点一旦不再当 leader，租约就被丢掉——一个关于「我是 leader」的承诺，活不过领导权本身。

## 完成标准

```sh
cargo test -p meshkv --test spec_lease_reads
```

## 陷阱

- **follower 答不了，也不许假装答得了。** 它根本不知道自己落后多少；诚实的答案是 leader 的名字，
  客户端去那里重试。
- **没做过一轮确认的 leader，不是一个可以作答的 leader。** 它*多半*还是 leader——而「多半」正是
  这门课一路在清掉的那类答案。那一轮确认，就是把它变成知识的东西。
- **租约回答的是那一轮证明过的位置，不是最新的提交。** 一轮之后才提交的值，可能还没落到多数派上。
  拿更新的位置作答，等于声称一个那一轮并没证明过的决定。
- **租约随领导权一起死。** 一个下台的节点（更新的任期、另一个竞争的 leader），必须在丢掉角色的
  同一口气里忘掉自己的租约和读 index；否则它就在为一个已经结束的任期继续作答。
- **和选举超时一样长的租约，已经太长了。** 选举可以在租约该结束的那一瞬间开始，所以这个比较必须
  是严格的。`is_safe_lease` 就是那句话。
- **时间靠注入，绝不靠读取。** 一个去调时钟的函数，是确定性模拟器驱动不了的函数——而读路径恰恰是
  模拟器必须驱动的那段代码，因为租约是一句关于时间的话。

## 延伸阅读

- Raft 论文 §8（「Client interaction」）就是用这套话讲读 index 和租约的：leader 用一轮心跳确认，
  然后在确认过的 index 上服务这次读，或者等它需要的那条条目。
- `openraft` 把同一个想法暴露成 `ReadPolicy::LinearizableRead`；它的 `Leader` 句柄要等一个等价的
  确认之后，才会回答读。
- `5.12` 把这一步给出的单一答案变成一个*旋钮*：有界陈旧的读、从已知延迟的 follower 读，以及每
  一种的代价。
