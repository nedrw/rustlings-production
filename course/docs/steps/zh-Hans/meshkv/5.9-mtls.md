# 线那头的 peer，就是它自称的那个节点：mTLS 与轮换窗口

## 为什么

`5.1` 给了节点一个名字和一句话的握手。那够用来路由消息，除此之外什么也不够：任何一个能打开套接字的
进程都能说 `MESHKV/1 hello n1`，而一个相信它的集群，会把自己的日志复制给任何开口要的人。在集群里，
这不是路由的 bug——这是一个网络上随便什么东西都能加进来的集群。

修法不是“加上 TLS”打个勾。有三条规则必须成立，而每一条都是一条集群被攻破的路子：

- **签发者必须被信任。** 证书是某个人作出的声明；信任库是这个节点信得过的那些人的名单。陌生人给的
  证书就是陌生人，不管它写得多规整。
- **窗口必须包含此刻。** 证书会过期，而一个被攻破的密钥正是靠这个机制才失去用处。不做窗口检查的节
  点，信任库只会越变越大。
- **证书里的名字必须是声称的那个名字。** 一张给 `n2` 的有效证书证明对端是 `n2`；对一个声称自己是
  `n3` 的对端，它什么也证明不了。

还有第四件事，它不是规则，而是一次操作：**轮换**。这是集群同时握着两个真相的唯一时刻——旧证书和新
证书——而做错这件事的集群，每次换证书都要宕一次，也就是说，经常如此。

校验的结果是一个 [`Identity`]，而这个类型就是这一步的关键：它没法手工造出来，所以任何接收它的代码，
手里拿到的是证据，而不是某个人敲进去的字符串。这是把 `domain/parse-dont-validate@apply` 用在一个安
全决定上——检查与保证的区别，在于没被检查的值还能不能到达在乎它的代码。

## 任务

- `src/security.rs`——这一步新增的模块：
  - `Certificate`：一个主体、一个签发者，以及一个半开的有效期窗口（`not_before` 含端点，
    `not_after` 不含）。空窗口或倒着的窗口，在构造证书时就被拒绝。
  - `TrustStore`：一个节点信得过的签发者，用 `trusts` 查。
  - `verify(certificate, store, now)`：那三条规则，每个拒绝都点名失败的是哪一条。
  - `authenticate(claimed, certificate, store, now)`：校验，**并且**检查证书的主体就是声称的那个名
    字。
  - `Identity`：校验过的名字，没有公开的构造函数——`verify` 和 `authenticate` 是仅有的两扇门。
  - `Rotation`：一个节点当前和下一张证书。`presented(now)` 回答这个节点拿给对端看的是哪一张（从新
    证书有效的那个瞬间起，就是新的那张），`accepts(peer, store, now)` 回答对端的证书收不收（两张都
    有效期间，哪张都收），而 `earliest_safe_retirement(overlap)` 是让一次轮换不至于变成宕机的算
    术。
- `docs/mtls.md`——这一步交付的页面（`links` 判它）。
- `tests/sim_mtls.rs`——课程内容：`slow:sim@3` 闸门跑的那个情景，种子决定握手发生的顺序。

## 完成标准

```sh
cargo test -p meshkv --test spec_mtls        # the ten cases
KILN_SIM_SEED=1 cargo test -p meshkv --test sim_mtls -- --nocapture
```

第二条打印一份像这样的记录

```text
meshkv-sim rotation overlap_start=200 overlap_end=500
meshkv-sim handshake peer=n2 phase=overlap verdict=accepted
meshkv-sim overlap_accepted=3
meshkv-sim handshake peer=n2 phase=retired old=refused new=accepted
meshkv-sim after_retirement_accepted=3
meshkv-sim safe_retirement=300
```

而另一个种子用另一种顺序握手，得出同样的判定。

## 陷阱

- **证书在对着对端的主张核验过之前，还不是身份。** 验了证书链却忽略名字的握手，认证的是“某个人”，
  不是这个对端——而在集群里，“某个人”正是攻击者想要的那个身份。
- **窗口半开。** 证书在过期的那一刻就无效，而不是一毫秒之后；比较时安全的那一侧，是拒绝的那一
  侧。
- **证书过期和签发者不受信，修法不一样。** 两种拒绝会说清是哪一种，因为“握手失败”会把运维送到错的
  地方。
- **新证书只在有效时才拿出去。** 提前拿出去，会在每一个还没更新的对端那里失败——一次以全集群拒绝开
  场的轮换。
- **两张都有效时，两张都收。** 重叠不是松懈；它是轮换没有缝的唯一办法。让它安全的是它会结束。
- **按算术退役，不凭胆量。** `earliest_safe_retirement` 是新证书的起点加上分发时间；在它之前退役，
  是一场排好日程的宕机。
- **时间靠注入，从不读取。** 有效期窗口正是测试必须能站到两侧去的那类东西（handoff M3，`5.6`）。

## 延伸阅读

- Rustls 的书里讲客户端与服务端认证的那一章，就是这一步的规则所站在前面的那个线路格式。这一步故意不
  实现握手；它实现的是握手必须做的那些决定。
- `sec/token-lifetime@apply — relay/2.21` 是同一套三条规则，用在 bearer token 上；这里的差别是证书按
  连接出示，而不是按请求，这正是轮换重叠成为*集群*问题、而不是客户端问题的原因。
- `5.21` 同时跑两个版本的集群；版本偏斜和证书轮换是同一种形状的问题——一个两种真相并存的窗口，而它
  何时结束有一个算术上的答案。
