# 任期、投票和心跳：一个三个节点能达成一致的小 Raft

## 为什么

`5.2` 把四条规则写了下来。这一步让它们*动起来*：三个进程、一份日志，再加一条关于谁可以决定什么的
规则。一个复制的键值存储后来做的一切——不许读到陈旧值的那些读、成员变更、分区演练——都建立在一个
问题的答案上：**三个互相看不见的进程，怎么才能一致认为某次写入发生了？**

这一步实现的答案是 Raft 的，而它值得自己写，而不是直接引进（`openraft` 在延伸阅读里点了名）：一个
你没写过的协议，就是一个你测不了的协议。下面的规格说出「一个节点只把票投给日志至少和自己一样长的
候选人」这句话时，能对*你的*代码言之有物，因为代码是你的。

有两个形状让这件事成立，而两个都是这一步的要点：

- **状态机是一个值。** `src/raft/state.rs` 里没有套接字、没有时钟、没有随机性：节点的状态之所以变，
  是因为来了一条消息，或者因为有人提出了一次写入。搬字节、等超时的那套管道，住在这步附带的*装置*
  里（`tests/sim_raft.rs`），两者从不见面。这不是洁癖——这是让一个协议有可能被测的东西。
- **调度是一个种子。** 装置在 `turmoil` 里跑这个集群——那是一个带虚拟时钟和虚拟网络的模拟器。种子
  决定消息到达的顺序，于是「再跑一次，还是一样」是机器能保证的事，而「换一种交错」是闸门能要求的
  事。

## 任务

- `src/raft/message.rs`——那四种消息（`RequestVote`、`Vote`、`Append`、`AppendAck`）和它们的文本
  编码。解析是严格的：不是这四种之一的一行，是一个把这一行引用出来的拒绝；而条目的载荷以十六进制
  随行，好让一次含换行的写入破坏不了它所在的那一行。
- `src/raft/state.rs`——状态机：
  - `campaign()`：在下一个任期里变成 candidate，投自己一票，然后问所有人；
  - 只有在候选人的日志至少和你的一样长、**并且**这个任期里还没有别人拿到你的票时，才给出一票；
  - 拿到多数派的票，你就成为 leader；
  - leader 把自己的写入追加进日志并发出去；接受它们的 follower 会回答自己的日志现在到哪儿；
  - leader 提交一个**多数派**持有的最大位置——而且只提交条目属于 leader **自己任期**的位置；
  - 来自更新任期的消息，会让你重新做一个 follower；来自更旧任期的消息，会被用你自己的任期拒绝。
- `src/raft/state.rs`，`become_leader`：新 leader 在复制任何东西之前，先写**一条自己任期的空条目**。
  规格会检查它在，理由在陷阱里。

装置是课程内容，已经在你的代码树里：读 `tests/sim_raft.rs`，看你那个状态机被要求做什么，以及选举
超时和心跳住在哪儿。

## 完成标准

```sh
cargo test -p meshkv --test spec_teaching_raft          # the rules, one case at a time
KILN_SIM_SEED=1 cargo test -p meshkv --test sim_raft -- --nocapture
```

第二条打印出这样一份记录：

```text
meshkv-sim leader=n3
meshkv-sim committed=1
meshkv-sim entries=2
```

而同一个种子打印同样的三行，换一个种子则会选出另一个节点。

## 陷阱

- **候选人自己那一票也算。** 三节点集群里的 candidate 只需要再多一票，不是两票。（规格的写法，会
  让一个把自己数了两遍的 leader 在不足多数派的情况下提交——这个 bug 是这一步自己的仪器在写它的
  过程中抓到的。）
- **只有 leader 自己任期的条目会提交。** 从更旧任期继承来条目的 leader，没法靠自己把它们提交掉；
  所以它赢下选举时，会写一条自己任期的空条目：空条目一提交，继承来的那些就跟着提交了。跳过这一步
  的 leader，可以一直握着一条旧条目的多数派，却永远提交不了它。
- **「我的日志至少和你的一样长」，先比的是任期。** 一个条目更多、来自旧任期的日志，*落后于*一个
  条目更少、来自新任期的日志。比长度而不比位置，会选出一个日志终将被覆盖的 leader。
- **拒绝也是一个回答。** 谁都不给票的节点会说出来，而不是保持沉默。沉默是 candidate 永远等下去的
  方式。
- **follower 的日志是被纠正的，从来不是被合并的。** leader 和 follower 第一处不一致的条目，决定了
  它之后的一切：follower 的后缀被丢掉，leader 的写进来。已提交的条目从不会不一致——这就是全部的
  安全性论证，而规格检查纠正的方向。
- **载荷对共识层是不透明的。** 一次复制的写入，是日志搬的一些字节，仅此而已；这些字节*意味着*
  什么，是 `5.10` 的主题；一个开始读它们的协议，就接下了一份卸不掉的任务。

## 延伸阅读

- 上面每一条规则都出自 Raft 论文（§5.1–§5.4）；当前任期那句话和那条空条目背后，是 §5.4.2
  （「Leader completeness」）和 Figure 8 这两段。
- `openraft` 是你刚写的东西的生产形态：同样的四个想法、同样的类型（`Term`、`LogId`、`Quorum`），
  多得多的机械。这一步之后去读它的 `RaftLog`，是看清 Raft 里哪些部分是协议、哪些部分是工程的好
  办法。
- `5.13` 把装置的虚拟网络换成一个更丰富的（`madsim`），而 `5.14` 用它把集群切成两半——一个确定性
  模拟器的意义，就在于分区变成一份*输入*，而不是一件你去等的事。
