# 引擎的毕业：jobq 的 crate，零行改动

## 为什么

这一步就是整门课的 `path` 依赖规则存在的理由（plan §3 D6）。其他每个 track 都被禁止依赖另一个 track
的 crate，理由很充分——好让跳过一个 track 是安全的——而 T5 是唯一的例外，因为它回答的那个问题，没有别
的答法：

> 如果 `jobq` 造出来的引擎真是一份库，那么一个*别的*项目就能依赖它，而不必动它。

那句话就是交付物。依赖是 `jobq = { path = "../jobq" }`——学习者自己的 T3 项目，课程把它作为前置条件铺
好——而验收标准不是「它编得过」。而是**`jobq` 一行都不用改**：没有放宽的 `pub`，没有新增的 `derive`，
没有翻转的 `cfg`。一份需要其中任何一项的库，本来就不是库，而这一步会把它查出来。

meshkv 拿它做的事，故意做得很少。引擎的 `JobId`——`jobq/3.1` 把身份做成一个类型，好让队列不用字符串也
能谈论一个作业——成了这个存储里的一个键。作业的状态于是能由前面十九步造出的共识日志来复制：那就是这个
track 承诺过的分布式调度器，而拥有作业行为的引擎纹丝未动。

## 任务

- `Cargo.toml`——`path` 依赖，放在标记出来的块里（这一步的脚手架会加上它）。
- `src/reuse.rs`——整个适配器：
  - `pub use jobq::engine::JobId;`——引擎的身份类型，经由这个项目可达；
  - `job_key(id)`：作业状态所住的键（`job:<id>`），命名空间放在这里，而不是放在 `jobq`；
  - `record_job(id, state)`：记录状态的命令，由这个项目自己的命令编码生成（`5.10`）。
- `docs/reuse.md`——这一步交付的页面（`links` 判它）：依赖、空的 diff，以及 meshkv 拿引擎做了什么。

## 完成标准

```sh
cargo test -p meshkv --test spec_reuse_jobq
```

通过，并且页面上的验收那一行成立：

```sh
git -C app/jobq diff --stat      # empty
```

## 陷阱

- **依赖的是学习者的项目，不是一份拷贝。** 一份内嵌的拷贝，会让「对 `jobq` 零改动」在构造上就为真——也会
  让毕业这个主张变成一句空话。
- **为了让这里编得过，往 `jobq` 里加一个 `pub`，就是这一步失败。** 受测的正是 `jobq/3.1` 划出的那条边
  界；如果它需要放宽，那它本来就不是边界。
- **命名空间归适配器。** `job:` 前缀住在 `meshkv`，不在 `jobq`；一份得知道别的项目怎么给它的存储起键的
  库，就揽下了一份它本来没有的活儿。
- **前置条件是真的。** `app/jobq` 不在时，`kiln` 拒绝判任何一步 meshkv：这些步建在学习者自己的 T3 工作
  上，而沙箱会铺下参考树，好让课程自己的检查用同样的方式判这一步。
