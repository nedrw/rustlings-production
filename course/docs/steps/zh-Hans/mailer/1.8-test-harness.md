# 端到端测试装置：一个跑在随机端口上的 app 工厂

## 为什么

这是第一个必须让服务真跑起来的测试，也是第一个会时好时坏的测试。端口写死，两个测试就没法同时跑
——而 `cargo test` 恰恰是并发跑的，于是失败总落在"碰巧第二个起"的那个上。用 `static` 只起一个应用，
一个测试的残留状态就成了下一个测试的初始条件。靠手工拼路由的装置，验的是一个二进制根本不会提供的东西。

这一步把这些账一次付清。此后每个测试——数量不少，注册、订阅、关停都在内——都起自己的服务：端口由操作
系统挑，零件和 `main.rs` 用的是同一批，结束时再停掉。装置的价值全在这里：测试能写得短，是因为枯燥的
部分搬到了别处；测试能保持诚实，是因为那枯燥的部分就是真东西。

## 任务

脚手架放好了 `tests/support/mod.rs`：`TestApp` 的壳子，没有行为。它是普通的项目代码——cargo 不把
`tests/support/` 下的东西当测试目标，所以规格用 `mod support;` 把它引进来：规格和你自己写的测试走向
同一个 app 工厂。把它填上：

- **`TestApp::start(config)`** 绑定 `127.0.0.1:0`，向 socket 问它实际拿到哪个端口，再用这个监听器把
  应用跑起来。`config` 里的端口被忽略：让测试自己挑端口，挑到的很可能正是另一个测试在用的那个。
- **提供二进制提供的那同一个应用。** 这要在库里动一处：把 `http::serve` 拆成"先绑定，再在监听器上
  服务"，装置才能接过后半截（`serve_on`）——端口之所以能在第一个请求之前就知道，也正因如此。
- **让服务跑在自己的线程里**，配一个自己的 Tokio 运行时。于是测试就是一个普通的阻塞式 `#[test]`，
  而装置拥有那个运行时，永远不会把它嵌进另一个运行时的里面。
- **一个极小的 HTTP 客户端**（`get`、`post`、`request`），通过 `std::net` 说 HTTP/1.1，于是每个
  测试只要三行：启动、请求、断言。`Connection: close` 让每个回答都有尽头。
- **`stop` 和 `Drop`** 把应用关掉并回收它的线程——停下来的应用必须停止*接受*连接，而一个忘了调
  `stop` 的测试也不能漏掉一个线程。
- **与其他测试零协调**：不写死端口，不共享文件，不用 `static`。规格会同时起三个应用、中途停掉其中一个，
  只为确认这一点。

## 完成标准

- `kiln run mailer/1.8-test-harness` — 规格通过
- `kiln check mailer/1.8-test-harness` — 每个 must 闸门都是绿的
- 加一个一次性的 `#[test]`，启动一个 `TestApp` 并断言 `GET /healthz` 是 `200`，然后连着跑两次
  `cargo test`，两次都通过
- `cargo test -p mailer -- --test-threads=1` 和 `--test-threads=8` 给出同样的结果

## 陷阱

1. **固定端口。** 单独跑能过，和别人一起跑就坏：第二个测试会从装置那边收到
   *"Address already in use"* 的 panic，或者——更糟——两个测试轮流回答对方的请求。规格那条
   *"three apps share one port"* 的失败，就是同一个缺陷从内部看到的样子。
2. **整个二进制共用一个应用。** `static`/`OnceLock` 存的应用，或者放在全局变量里的端口，会让每个测试
   都变成上一个的续集。规格以*"stopping one app stopped another"*失败：一个测试一个应用这个承诺，只有
   装置自己能守。
3. **在装置里自己拼路由。** 只拼测试用得着的那几条，是写出"一片绿、却对服务什么也没说"的测试的最短
   路径：规格会在 404/405 那两条断言上失败，报的是*"the factory has to serve the same fallbacks as
   the binary, not a router of its own"*。
4. **运行时套运行时。** 在测试自己的异步运行时里再建一个 Tokio 运行时，或者在其中调 `block_on`，都会
   panic：*"Cannot start a runtime from within a runtime"*。运行时要归装置，跑在自己的线程里；测试只管
   发请求。

## 延伸阅读

- [`tokio::runtime::Builder`](https://docs.rs/tokio/latest/tokio/runtime/struct.Builder.html) —
  显式地搭一个运行时，以及为什么一个测试夹具想要自己的一份
- [`axum::serve`](https://docs.rs/axum/latest/axum/fn.serve.html) — 提供一个由别人绑好的监听器，
  这正是端口号能被提前知道的原因
- [Cargo: test targets](https://doc.rust-lang.org/cargo/reference/cargo-targets.html#tests) — 为什么
  `tests/support/mod.rs` 不是测试目标，以及什么才是
- [`std::net::TcpStream`](https://doc.rust-lang.org/std/net/struct.TcpStream.html) — 一个零依赖
  客户端所需要的 socket，仅此而已
