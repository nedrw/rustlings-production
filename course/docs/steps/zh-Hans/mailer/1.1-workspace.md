# 把 crate 拆成一个库和一个薄二进制

## 为什么

大多数 Rust 服务都从一个 `main.rs` 起步，然后就再没挪过窝：所有决定都挤在那个既做判断、又往终端
打印的函数里。代价要到很久以后才显现——不启进程、不读它的 stdout，你就没法测参数解析；第 14 步要
写的 worker 也用不上它。等第 7 步加路由时，路由还是落进这个文件，于是每改一处都要和别处的改动打架。

拆分只花五分钟，却能把这些统统赚回来。库负责这个服务**做什么**，二进制负责它在启动它的人眼里
**长什么样**。此后本 track 的每一步都在往库里添东西，二进制始终只是一层壳。

## 任务

- 创建 `src/lib.rs`。一切"做决定"的东西都放在那里——今天是参数解析，到第 7 步会是路由、存储
  和 worker。
- 让 `main.rs` 保持是一个壳：它问库该做什么，打印答案，以库决定的退出码退出。规格允许那里有
  **100 行代码**（空行和注释不计）——够放一个服务会逐渐长出的接线，放不下服务本身。
- 保留骨架已有的三种行为：`--help` 打印用法并以 0 退出，`--version` 打印版本并以 0 退出，未
  知旗标打印一条点名它的消息并以非零退出。
- 不要把打印搬进库。`clippy::print_stdout` 在阶梯的第 1 级（第 2 步）是一个库 lint，因为一个
  会往终端写东西的库没法被任何非终端的东西使用。

`kiln run` 把本步的规格拷进 `app/mailer/tests/spec_layout.rs` 并运行。它检查三件事：
`cargo check --lib` 把这个包当作库接受、二进制仍然以三种方式应答、以及 `main.rs` 是一个壳。
第三条是*测量*而不是行为，原因值得知道：一个测可能还没有库目标的 crate 的测试，没法调用那个
库，所以"二进制是薄的"以预算的形式被检查而不是被调用。另外两条是行为的，它们正是你拆错时
会坏掉的东西。

## 完成标准

- `kiln run mailer/1.1-workspace` — 规格通过
- `kiln check mailer/1.1-workspace` — 每个 must 闸门都是绿的
- `cargo run -- --help` 打印用法，`cargo run -- --version` 打印 `mailer 0.1.0`

## 陷阱

1. **在 `main.rs` 里留一份逻辑副本。** 常见的形状是：把所有东西搬进 `src/lib.rs`，然后"因为
   只有四行"在 `main.rs` 里把 `match` 再写一遍。预算断言以 `main.rs has 143 lines of code
   (budget: 100)` 失败，而且两份副本从任何一方改动的那一刻起开始漂移。
2. **用 `pub fn main()` 委托。** 一个叫 `main` 的库函数是合法的 Rust，从 `main.rs` 里读起来也
   顺眼，但它把入口点变成了库 API：下一步需要一个既能从测试调用、又能从二进制调用的形状。给
   入口点起一个关于它做什么的名字（`parse`、`launch`、`run`）。
3. **搬用法文本的时候把它删了。** 把 `USAGE` 搬进库却忘了 `--help` 要打印它，留下一个退出 0 且
   一言不发的二进制；规格的 help 断言报告的正是这件事。

## 延伸阅读

- [Cargo targets: the lib target and target auto-discovery](https://doc.rust-lang.org/cargo/reference/cargo-targets.html#target-auto-discovery)
  — 是什么让 `src/lib.rs` 不需要任何配置就成为库目标

  库可以把"如何收场"作为一个值返回

  — 同样的 `lib.rs` + 薄 `main.rs` 形状，出于同样的理由
