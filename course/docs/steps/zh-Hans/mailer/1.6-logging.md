# 每次运行一个关联 id 的结构化日志

## 为什么

一行写着「starting mailer on 127.0.0.1:8080」的日志没问题，直到有人得再把它找出来。到那时它就
只是一句话：主机是一个子串，端口是一个子串，而一个想按端口分组的看板不得不去解析自己没写过的散
文。一行带*字段*的结构化日志才是数据——采集器给它建索引，查询筛它，而你改掉一个字段的名字就会
弄坏那条查询，这正是你想要的反馈。

后半截是关联 id。一个进程服务着许多请求，而一个请求会牵动许多行；每一行里没有 id 的话，「这 40
行里哪些是一起的？」就只能靠猜时间戳来回答。机制是一个 span：一个带字段的工作单元，它的事件继
承这些字段。今天这个单元就是这次运行本身——步骤 1.7 会把每个 HTTP 请求包进同一种 span，而这套装
置什么都不用改。

## 任务

脚手架加上了依赖，并把入口点放进 `src/logging.rs`：一个能用的 `RunId`，和两个还什么都没做的函数
`init` 与 `announce`。把这两个填上，再接进二进制：

- **`init` 装上订阅器**，用两个从配置（步骤 1.4）里读出来的设置项：日志级别来自 `log.level`
  （`error`、`warn`、`info`、`debug`、`trace`），格式来自 `log.format`——终端用 `pretty`，采集器
  用 `json`。
- **字段是 `&str`，不是句子。** 这条公告是一个 `info` 事件，字段有 `host`、`port`、`log_format`
  和 `database`，消息是 `mailer is starting`。`database` 说明是 `set` 还是 `unset`——密钥有没有被
  配置是值得知道的；密钥本身不是（步骤 1.4 的规则在这里照样成立）。
- **再来一个 `debug` 级别的事件**，好让级别这个设置项有东西可以解锁：`info` 是健康服务运行的级别，
  而一个把自己的内部细节也记在那儿的构建，是没人会读的构建。
- **这次运行的 span**：`announce` 跑在一个叫 `run` 的 span 里，字段 `run.id` 设成这次运行的 id
  （`RunId::of_this_process()`——脚手架给的那个类型；正是这个 span 让 id 出现在这次运行的每一行
  上，而不必重复它）。
- **`pretty` 不许给管道上妆。** 终端可以有颜色；`stdout` 是文件、管道或者采集器时就给朴素的一行，
  因为 `host=127.0.0.1` 必须能在捕获到的东西里被找到。
- **日志在服务做的其他任何事之前就开始**，而且*只*在服务这条路径上开始：`--help`、`--version` 和
  `--check-config` 在没有订阅器的情况下作答，配置报告于是仍然是脚本能读的东西。
- 把它接上：库里的 `pub mod logging;`，以及二进制初始化日志并公告这次运行。装不上订阅器也是一种
  配置形状的失败，和别的没什么两样：给它错误枚举里的一个变体，配上它自己的 `# Errors` 一节和
  退出码。

## 完成标准

- `kiln run mailer/1.6-logging` — 规格通过
- `kiln check mailer/1.6-logging` — 每个 must 闸门都是绿的
- `MAILER__LOG__FORMAT=json cargo run` 每行打印一个 JSON 对象，里面有 `fields.host`、
  `fields.port`、`fields.log_format`、`fields.database`，每个对象里还有一个 `run` span
- `MAILER__LOG__FORMAT=pretty cargo run` 把同样的事实打印给人看，stdout 不是终端时没有转义序列
- `MAILER__LOG__LEVEL=debug cargo run` 多出那行 debug；`MAILER__LOG__LEVEL=error cargo run` 什么
  都不打印
- `MAILER__DATABASE__URL=postgres://user:pw@localhost/db cargo run` 说 `database=set`，而那个 URL
  在输出里哪儿都不出现

## 陷阱

1. **颜色还留着。** `fmt()` 默认上色，于是捕获到的那一行里含着
   `\x1b[2mhost\x1b[0m\x1b[2m=\x1b[0m127.0.0.1`：规格以
   *"`host=127.0.0.1` is missing from: …"* 失败，而终端看起来完美得很。给输出上妆之前，先问一句
   这是不是终端。
2. **把配置本身记进日志，而不是关于它的字段。** `info!(?config, "…")`，或者没带 `skip_all` 的
   `#[instrument]`，会把每一个设置项——包括数据库 URL——记进那一行或者那个 span。规格会因为那个
   URL 出现在输出里而失败，而这个 URL 必须轮换。
3. **用一句格式化的话代替字段。** `info!("starting on {}:{}", host, port)` 产出的是一行人喜欢、
   采集器却没法建索引的东西：规格以 *"this event has no field `host`"* 失败。
4. **用不上的那个级别。** 配置写着 `debug`，订阅器却留在它自己的默认值（`INFO`）上，于是那行
   debug 永远不出现：规格以
   *"`MAILER__LOG__LEVEL=debug` has to unlock the debug lines this build has"* 失败。
