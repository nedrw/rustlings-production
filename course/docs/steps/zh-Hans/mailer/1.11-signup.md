# 注册：密码哈希，以及把唯一约束当作并发原语

## 为什么

注册端点看起来是这个服务里最好写的处理函数：校验、哈希密码、插入一行。可这句话的前后两半各藏着一个
决定，而它们决定了这个服务是**一直能用**，还是只用得了一次。

**谁来判断某个地址已经注册过？** 最直觉的答案是应用自己：先把那行读出来，有就回 `409`。这个答案是错的，
而且不是风格问题——它错得跟算错数一样：

```text
A: SELECT ... WHERE email = 'ada@example.com'   -> no row
B: SELECT ... WHERE email = 'ada@example.com'   -> no row        <- both callers are inside the
A: INSERT ...                                   -> commits          window at the same time
B: INSERT ...                                   -> ERROR: duplicate key value violates unique
                                                   constraint "subscribers_email_key"
```

应用层没有哪一种修法值得要。`Mutex` 只能串行化一个进程，跨副本什么都不是——而恰恰因为有多个副本，这个
地址才需要唯一。`SELECT ... FOR UPDATE` 要在一行*还不存在*的行上加锁，而行锁做不到这件事。能裁决两个
进程之间竞态的，只有它们共同对话的那一方；而它已经有答案了：`subscribers.email` 是 `UNIQUE`
（`mailer/1.9-postgres` 步）。于是这一步把决定权交给约束：

```sql
INSERT INTO subscribers (email, name, password_hash) VALUES ($1, $2, $3) ON CONFLICT (email) DO NOTHING RETURNING id
```

`ON CONFLICT (email) DO NOTHING` 把"已经有人占了这个地址"从一个错误变成*没有插入行*，而 `RETURNING id`
让它可见：赢家拿回它的行，输家什么也拿不到，而两者都不必先去读任何东西。

**`password_hash` 里装什么？** 不是密码。一张密码表，备份要出事、迁移导出要出事、支持工程师看一眼也要
出事。真正存进去的是一个 PHC 字符串（`$argon2id$…`）：算法、参数、*为这一个订阅者*生成的盐，以及摘要。
盐让被偷走的表没法一次查遍所有订阅者，参数让每一次猜测都变贵。校验——调用它的是登录，见
`mailer/1.16-sessions` 步——先把候选值哈希再比对，所以这个函数返回之后，原文在哪儿都不需要了。

另外还有两个小一点的决定，它们关乎边界而不是密码学：拒绝时要说清是*哪个*字段错了，且**绝不**把那个值
重复一遍（`mailer/1.10-domain-types` 步——值可能是密码，而消息最终会进日志）；调用方能补救的失败回 4xx，
只有部署方能补救的回 5xx，且不带任何解释。

## 任务

脚手架加了 `src/signup.rs`：请求的形状，外加一个故意写错的函数。路由归你写，它要用的两个错误变体也归你。

### `src/lib.rs`

声明模块：`pub mod signup;`。（在你这么做之前，脚手架的文件不参与编译——在那之前规格看到一个没有
`/signup` 路由的服务。）

### `src/error.rs`

两个变体，两个都进退出码表：

| variant | message | exit code | HTTP |
| --- | --- | --- | --- |
| `AlreadySubscribed { email: String }` | `` `ada@example.com` is already subscribed `` | `2` | 409 |
| `PasswordHash { source: argon2::password_hash::Error }` | `the password could not be hashed` | `1` | 500 |

地址**确实**是 `AlreadySubscribed` 的一部分（与 `InvalidInput` 不同）：必须告诉调用方哪个地址被占了，
而那是他们已经送来的一个值。哈希失败的 source 被保留下来，好让 `source()` 的链条保持完整（第
`mailer/1.5-errors` 步），而哈希失败是部署方的问题——它不是调用方换一个值就能修的。

### `src/signup.rs`

`hash` 就是脚手架里那个，它把密码原样返回。把它换成真的哈希：

- `argon2` 已经是依赖（脚手架把它放进了 `Cargo.toml`）。`Argon2::default()` 是 Argon2id，用这个 crate
  推荐的参数；
- 盐每次调用现生成，跟着返回的字符串一起走——0.6 的 API 里哈希器替你做了这件事，代码就两行，想不小心传
  个固定盐都难；
- 回来的是 PHC 字符串（`hash.to_string()`），那正是这一列要存的东西。

然后写这一步真正的那个流水线。它的形状，也就是路由要调用的东西：

```rust
pub async fn subscribe(pool: &PgPool, request: SignupRequest) -> Result<Email, Error>
```

1. **先解析**：`Email::parse`、`SubscriberName::parse`、`Password::parse`（`mailer/1.10-domain-types`
   步）。必须在哈希之前：解析器的长度上限，是陌生人和"哈希一个 GB 数据"之间唯一的拦截；被拒的值要停在
   400、**一行都不写**，而不是留下一行没人能用的数据；
2. 哈希密码；
3. 插入，用这条语句、**这段文本**：

   ```sql
   INSERT INTO subscribers (email, name, password_hash) VALUES ($1, $2, $3) ON CONFLICT (email) DO NOTHING RETURNING id
   ```

   按这个顺序绑三个值，用"可能没有"的方式取行（`fetch_optional`），而不是"必须有一行"（`fetch_one`）——
   "没有行"在这里是正常答案，不是失败。Rust 字面量可以折行；要紧的是这个字符串的*值*，因为 `sqlx` 哈希
   的是它（见陷阱 4）；
4. 取回一行，说明是这次调用插进去的——回解析过的 `Email`。没取回，说明别人先到了，那就是
   `Error::AlreadySubscribed`，地址按存储形态给出（已规范化，答案与表里存的是同一个东西）。

### `src/http.rs`

一个路由，`POST /signup`，和一张把失败映射成答案的表。规格判的契约：

| request | answer |
| --- | --- |
| 三个可用值的注册 | `201` 与 `{"status":"pending","email":"<as it was stored>"}`——没有密码，没有哈希 |
| 同一个地址再来一次 | `409`，一句话点名那个地址 |
| 一个领域拒绝的值 | `400`，一句话点名那个字段而不点名那个值 |
| 一个不是注册的 body（缺字段、不是 JSON、不是对象） | `400`，一句话说的是 body 本身——并且不从里面引回任何东西 |
| 一次合法注册，但没有配置数据库 | `503`——进程活着，这个路由没就绪（第 `mailer/1.9-postgres` 步） |

三个细节决定了它：

- **提取器得允许失败**：body 取成 `Result<Json<SignupRequest>, JsonRejection>`，别用朴素的
  `Json<SignupRequest>`。朴素提取器会用它自己那套拒绝话术回答，那不是这个服务的句子；而这一步的拒绝，
  不许把 body 里的东西引出来；
- **一张表，一条规则**：在处理函数旁边写 `fn status_of(&Error) -> StatusCode`，与 `Error::exit_code`
  一一对应——调用方能补救的给 4xx，只有部署方能补救的给 5xx。4xx 原样重复失败那句话；5xx 不重复（原因
  进日志，调用方只拿到一句对服务内部只字不提的话）；
- **`Body` 要长大**：它是每个非成功答案的 JSON body，而从这一步起它带的是一句由失败拼出来的话，所以
  `status` 字段得是 `String`，不再是 `&'static str`。

状态码在这里不是装饰：规格的竞态测试要求一个 `201`、其余全 `409`，所以一个已被占用的地址，不能带着
数据库的抱怨以 500 回来。

## 完成标准

- `kiln run mailer/1.11-signup` — 规格通过（它会起一个 Postgres 容器，所以这个文件的第一次运行比之前几个
  多花几秒）
- `kiln check mailer/1.11-signup` — 每个 must 闸门都是绿的
- 为 ` Ada@Example.COM ` 注册回 `201` 且 `"email":"ada@example.com"`，而行里存着规范化后的名字与
  `status = 'pending'`
- 同一个地址再来一次回 `409`，而表里仍然只有一行
- `SELECT password_hash FROM subscribers` 里是一个以 `$argon2id$` 开头的值，它不是密码；两个选了同一个
  密码的订阅者有两个不同的值
- 路由用不了的 body 回 `400`，且不把它引回来
- 没有 `DATABASE_URL`、也没有数据库在跑时 `cargo build` 成功：让这件事成立的是 `.sqlx/` 里的离线元数据，
  而这也是查询被写成宏的原因

## 陷阱

1. **先 `SELECT` 再 `INSERT`。** 脚手架的 `hash` 是那个响亮的陷阱；这一个是安静的那个，而它正是这一步存在
   的理由。它通过每一个顺序测试——手工测试里的两个调用方从不重叠——并在第一次有两个人在同一毫秒注册时
   恰好丢掉一个请求：规格的 *"concurrent signups for one address have to be decided by the unique
   constraint"* 把它显示成 `[201, 500, 500, 500]`。没有任何应用层锁能修它；约束就是那个决定，
   `fetch_optional` 是你读它的方式。
2. **把密码存进去。** 脚手架的 `hash` 原样返回它拿到的东西，所以一个只写了路由的步骤有一个能跑的注册
   端点，和一张满是密码的表。规格的 *"the password was stored as it was typed"* 就是那个失败从外面看到
   的样子。
3. **所有东西共用一个盐。** 一个硬编码的、从配置来的、或者从地址推出来的盐看起来像盐，其实不是：相同的
   密码产生相同的摘要，而那正是盐要防止的事。每次调用都生成它——规格会检查两个用同一密码的订阅者是两个
   不同的值。
4. **改写语句。** `.sqlx/query-<hash>.json` 以宏拿到的查询文本的 SHA-256 为键，而脚手架只为上面那条语句
   准备了条目，别的什么都没有。一条改写过措辞的语句——列清单少了一个、`ON CONFLICT ON CONSTRAINT
   subscribers_email_key`、给 `"email"` 加了引号——是一个不同的键，构建会以 *set `DATABASE_URL` to use
   query macros online, or run `cargo sqlx prepare`* 停下。要么照给定的写，要么对一个迁移过的数据库
   跑 `cargo sqlx prepare`（第 `mailer/1.9-postgres` 步的容器加 `sqlx migrate run` 就够），并提交它重写
   的东西。
5. **在一个可能冲突的插入上用 `fetch_one`。** `ON CONFLICT DO NOTHING` 不返回行在这里是一个正常的答案，
   而 `fetch_one` 把它变成一个 `RowNotFound` 错误——对"调用方是第二个注册的"这个普通情况回一个 500。
6. **该回 409 的地方回 500。** 让唯一约束的违反作为数据库错误到达边界，会通过手工测试（日志说
   *duplicate key*）而在规格里失败：两次并发注册必须以一个 `201` 和一个 `409` 收场，而一个被告知"服务无法
   回答这个请求"的调用方没有任何可做的事。
7. **错误路径里的密码。** `Error::InvalidInput { value, … }`（或者一个带着数据库抱怨的 500 body，对一行
   坏数据来说它可能点名一个列和一个值）把密钥放进日志行。规格检查一次拒绝不重复它拒绝的值，而第
   `mailer/1.10-domain-types` 步的 TRAP 4 是解析器一侧的同一条规则。
8. **先哈希再解析。** `Password::parse` 才是把输入截在 128 字符的东西；先哈希，这个上限就只保护一个已经
   做完昂贵事情的请求的响应时间。先解析，再哈希，再插入。

  — 这条约束保证什么，以及为什么两次并发插入不可能都成功

  `READ COMMITTED` 下两条语句之间的那个窗口，也就是第 1.11 步关上的窗口
- [OWASP: password storage cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
  — 为什么是 Argon2id、参数买到了什么，以及该做什么而不是自己生成盐
- [the PHC string format](https://github.com/P-H-C/phc-string-format/blob/master/phc-sf-spec.md) —
  `$argon2id$v=19$m=…,t=…,p=…$<salt>$<hash>` 是怎么拼起来的，以及一个校验器需要从它那里拿到什么
- [`argon2` crate](https://docs.rs/argon2/latest/argon2/) — `Argon2::default()`、`PasswordHasher`，以及
  默认值正是这一步所存的那组参数的 `Params`
- [sqlx: offline mode and `cargo sqlx prepare`](https://docs.rs/sqlx/latest/sqlx/#offline-mode) —
  `.sqlx/` 是什么、以什么为键，以及为什么 CI 能在没有数据库的情况下构建一个满是 `query!` 宏的 crate
- [`Result::map_err`](https://doc.rust-lang.org/std/result/enum.Result.html#method.map_err) — 这一步
  整个错误路径所写成的那种形状：驱动的错误变成这个服务的变体，一次，在调用的边缘
