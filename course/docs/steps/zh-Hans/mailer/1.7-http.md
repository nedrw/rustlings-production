# HTTP 骨架：路由、提取器，以及诚实的 404 和 405

## 为什么

这一步，服务变成了网络上能对话的东西，而它第一层对外接口就是日后衡量一切的那个基准。这一步
里的两个决定，事后都很难改。

第一个决定是：*无人应答*的请求长什么样。一个对任何未知路径都回 200 加一个 HTML 页面、或者回一个
空正文的服务，会逼得每个客户端都去解析散文，才知道究竟发生了什么。一个说得出有哪些路由存在的
404，和一个点名了本来能用的方法的 405，能把一个集成 bug 变成五秒就能读完的东西。

第二个决定是 `/healthz` 意味着什么。它回答的是*进程*的账，不是它的依赖的账：一个因为数据库不在
就变红的存活探针，会把一个正做着分内事的服务重启掉——而第 1.9 步会为那些可能不在线的部分补上
一个就绪应答。

## 任务

脚手架加上了 `axum` 和 `tokio`，并把 `src/http.rs` 放到位，里面有两个桩：`router()` 和 `serve()`。
把它们填上，再接进二进制：

- **`router()` 把整个对外接口作为一个值返回。** 没有 socket，没有运行时：测试构造它，再通过它
  发出一个请求（第 1.8 步的 app 工厂正是建立在这之上）。
- **`GET /healthz`** 回 `200`，正文是 `{"status":"ok"}`，除了进程本身不碰任何东西。
- **未知路径是 `404`**，正文是一份说明这一点的 JSON——不是空正文，也不是一个假装自己是 404
  处理函数的兜底路由。
- **已知路径配错方法是 `405`**，正文是同一种 JSON 形状，*并且*带上 `Allow` 头。路由知道一条路径
  有哪些方法；兜底路由不知道，所以这个回退是给路由自己的答案加装点东西，而不是替换掉它。
- **`HEAD /healthz`** 回 `200` 且没有正文——这就是框架里 `GET` 的含义，它应该保持这样。
- **`serve(config, id)` 绑定配置好的地址**，把**它真正绑上的那个地址**作为结构化事件（`address`）
  记进日志，然后一直服务到进程停止。端口 `0` 的意思是"随便哪个空闲的"，所以日志里那个地址是
  调用方得知端口的唯一途径——一个把配置里的 `:0` 记进日志的服务是够不着的。
- **绑定失败是一种有类型的失败**，不是 panic：消息里带上那个地址，`Error` 里有它自己的变体，
  退出码表里有它自己的一行，`serve` 上有一节 `# Errors`。
- **二进制跑在运行时上**（`#[tokio::main]`），它原来的 `Idle` 路径现在改为服务，而不是说没事可做。

## 完成标准

- `kiln run mailer/1.7-http` — 规格通过
- `kiln check mailer/1.7-http` — 每个 must 闸门都是绿的
- `MAILER__LOG__FORMAT=json cargo run -- --listen-port 0` 打印一个带绑定地址的 `listening` 事件，
  而 `curl -i <that address>/healthz` 回 `200`
- `curl -i <address>/nope` 回 `404`，正文是 JSON；`curl -i -X POST <address>/healthz` 回 `405`，
  并带上 `allow: GET,HEAD`
- `cargo run -- --listen-port 1; echo $?` 以非零退出码退出，并说出它没能绑上的那个地址

## 陷阱

1. **用兜底路由代替回退处理。** `Router::fallback` 才是诚实的做法；一个返回 404 的
   `.route("/{*rest}", ...)` 连方法也一起吞掉，于是 `POST /healthz` 得到一句*"没有这样的路由"*
   ——规格在 405 那条断言上失败，因为路由根本没机会说出这条路径有哪些方法。
2. **把配置的地址记进日志。** 用了 `--listen-port 0`，日志里写的是 `127.0.0.1:0`，每个读到它的
   调用方都连不上任何东西。规格以*"服务必须记下它绑定的地址 … 而它从来没有记过"*失败。
3. **在 `async` 里用阻塞式 socket 绑定。** 在 Tokio 任务里调 `std::net::TcpListener::accept` 会
   阻塞工作线程，于是第一个请求被回答了，第二个永远不会被回答：规格一直挂到截止时间，报的是
   *"服务没有接受连接"*。
4. **404 的正文是空的。** 状态码是对的，人却什么也看不到：规格以*"正文为空的 404 什么都没告诉
   调用方"*失败。
