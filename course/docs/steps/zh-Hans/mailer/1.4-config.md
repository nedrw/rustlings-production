# 带成文覆盖顺序的类型化配置

## 为什么

一个服务同时从四个地方取设置：代码里写死的默认值、二进制旁边的文件、启动它的那个进程的环境，以及
人手动敲的旗标。凡是"在我机器上是好的"开头的故障，追下去几乎都是在争这四者谁说了算。所以覆盖顺序
不是留到以后再摸的细节，它就是契约——说不清自己被配置成什么样的服务，没人运维得动。

第二个理由是：一个任何来源都没提到的设置项，只有在你**已经知道**答案时，它的答案才显而易见。于是
`MAILER__LISTEN__PROT` 这种笔误必须被明确拒绝，而不是悄悄退回 8080。同样，仓库里带着默认值的密钥
不叫密钥，那是一个比泄漏它的那次部署活得更久的密码。

## 任务

脚手架已经放好 `src/config.rs`：设置项与默认值写成类型，错误类型带消息，外加两个空桩
（`Config::load`、`Config::report`）和这个文件需要的两个依赖。剩下都归你：

- **覆盖顺序就是契约**：默认值 < 文件 < 环境 < 旗标。每一层只改它点名提到的设置项，没提到的继续用
  上一层给的值。
- **文件**读工作目录下的 `mailer.toml`，或者 `--config <path>` 指的那个路径——一旦指了路径，默认文件
  就*不*读。所有设置项都可选；服务不认识的设置项算错误，不算默认值。默认文件不存在是正常的，命令行
  上点名的文件必须存在。
- **环境变量**：`MAILER__LISTEN__HOST`、`MAILER__LISTEN__PORT`、`MAILER__LOG__LEVEL`、
  `MAILER__LOG__FORMAT`、`MAILER__DATABASE__URL`。前缀是 `MAILER__`，设置项名字的各段之间用 `__`
  隔开。带了这个前缀却对不上任何设置项的变量，按名字拒绝。
- **旗标**：`--listen-port <port>`，加上给文件层用的 `--config <path>`，再加上 `--check-config`。
  数据库 URL 故意没有旗标——敲在命令行上的密钥会留在进程列表里，也会留在每一条 shell 历史里。
- **用不了的值**要连同设置项、值和来源一起拒绝：`log.format = "xml"` 要报出 `log.format`、`xml`，以及
  它来自哪个文件或哪个变量。一律非零退出：被拒绝的配置不许悄悄降级成默认值。
- **`--check-config`** 打印生效的配置并成功退出：`database.url`、`listen.host`、`listen.port`、
  `log.format`、`log.level`，每项一行 `key = value`，按 key 排序。
- **密钥只标注、不打印**：`database.url` 没被任何来源设置过是 `<unset>`，设置过就是 `<redacted>`
  （已打码）——配置报告是会被贴进 issue 的东西。
- **配置先于一切加载**，所以一份坏配置能拦下服务，哪怕启动时没带 `--check-config`。`--help` 与
  `--version` 例外：问二进制的问题不该依赖服务的状态。
- **要提交的是** `mailer.toml.example`，里面放占位值；装着真值的那个文件进 `.gitignore`。

## 完成标准

- `kiln run mailer/1.4-config` — 规格通过
- `kiln check mailer/1.4-config` — 每个 must 闸门都是绿的
- `cargo run -- --check-config` 打印这五个设置项并以 0 退出
- `MAILER__LISTEN__PORT=9111 cargo run -- --check-config` 显示端口 9111
- `MAILER__LISTEN__PROT=9111 cargo run -- --check-config` 点名那个环境变量并以非零退出
- `MAILER__DATABASE__URL=postgres://user:pw@localhost/db cargo run -- --check-config` 打印
  `<redacted>`，密码在输出里任何地方都不出现

## 陷阱

1. **把读文件失败吞掉。** `read_to_string(path).ok()` 会把"你给的路径不对"变成"我用了默认值"，服务
   于是带着另一台主机的设置启动。规格报的是
   *"the report must mention \"absent.toml\""*——你点名的那个文件，恰恰是报告必须说出来的东西。
2. **按读取顺序叠层，而不是按生效顺序。** 环境如果排在旗标之后生效，`--listen-port 9222` 就输给了这
   次部署恰好设了的 `MAILER__LISTEN__PORT`，`--check-config` 显示的不是他要的端口。
3. **把密钥打印出来。** `--check-config` 里带上 `database.url` 看着挺方便，直到它被贴进 issue。规格
   会因输出里出现原始 URL 而失败，而那个 URL 从此必须轮换。
4. **放过不认识的环境变量。** `match` 带一个兜底分支，把 `MAILER__LISTEN__PROT` 吞了，服务照样按默认
   端口起来——部署看着一切正常，然后什么都不工作。
