# 令牌是别人的声明，在这里核对

## 为什么

OIDC 令牌是身份提供方签发的持有者凭证：谁拿着它，谁就是它点名的那个主体。验证它不是"把声明解析
出来"——而是把它们和*这个*服务接受的东西做比较，而检查是有顺序的，因为其中一项在读到任何声明之前：

- **算法**——它不是声明，而是第一道检查：这个服务只用一个它自己选定的算法验证，点了别的
  （包括 `none`，那意味着"没有签名"）的令牌在看签发方之前就被拒。一个读 `alg` 来决定*怎么*
  验证的实现，等于让令牌自己定规则——让"相信头部"出了名的那个 JWT 漏洞；
- **签发方**——另一个提供方的令牌，就是另一个提供方的用户；
- **受众**——所有人都忘记的那一项。同一个提供方为任何客户端签发的令牌，在*某处*是有效的；
  不比对受众的服务会接受它隔壁邻居的令牌。共用一个提供方就足够出事；
- **未生效**——还没生效的令牌不生效；
- **过期**——和这门课里每个截止时间（deadline）一样是开区间：在它点名的那一秒，就结束了。

顺序是契约的一部分：一个既过期、受众又不对的令牌，答案是不对的受众，因为受众才是决定"这个服务该
不该看它"的那一项。

## 任务

脚手架加上了 `src/oidc.rs` 和它的 `pub mod oidc;` 那一行。

- **[`validate`]**——所有检查都通过时给出主体，否则按 算法、签发方、受众、未生效、过期 的顺序给出
  第一处失败。

## 完成标准

- `kiln run platform/9.5-oidc` —— 规格通过
- `kiln check platform/9.5-oidc` —— 每个 must 闸门都是绿的
- 签给 `relay` 的令牌拿到 `mailer` 上会被拒，即使它同时已经过期
- `algorithm` 是 `none` 的令牌，在检查签发方之前就被拒

## 陷阱

1. **不查受众。** 它能过掉所有只用合法令牌的测试，并接受提供方为任何人签发过的每一个令牌。规格里
   *"另一个受众的令牌"*就是这条断言。
2. **`decoded.exp > now` 的单位对不上。** 秒与毫秒之差，会让每个令牌有效一千个月，或者签发即过期；
   这里故意用 `u64` 秒。
3. **过期边界。** `now == expires_at` 已经过期；`>=` 与 `>` 之争和 TTL 那几步是同一个差一。
4. **相信令牌自己写的算法字段。** 读 `alg` 来决定怎么验证，就是让令牌自己定规则：`alg: none`
   要求根本不签名，而一个照办的验证器会接受它。这道检查在最前面，且对着这个服务自己选定的列表。
   要带走的教训是：**用你选的算法验证，永远不要用令牌点名的那一个。**
