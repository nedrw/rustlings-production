# 持久性是一个决定：fsync 的代价，以及你接受哪几种崩溃

## 为什么

`lakelet/4.1-ingest-protocol` 给了这个存储一个只追加的文件，和一条听起来像承诺的规则：记录能被读回来，
`Spool::append` 才作答。由*谁*读回来，就是这一步的全部。一次写入落进操作系统的页缓存，`write` 就返回
了——字节在这台机器的内存里，不在它的设备上——而 `append` 照样回答了它的客户端。如果进程死了，没关系：
内核还拿着那些字节，文件是完好的。如果*主机*死了，页缓存没了，而一个被告知“已存下”的客户端，欠它一个
解释。

把这个窗口变小要花一个系统调用，而那个调用不是免费的：

- **等设备是以毫秒计的。** 在写下这一步的那台机器上，一次持久写入要花 **4.1 ms**（`File::sync_all`，
  在 macOS 上就是 `F_FULLFSYNC`，真正等闪存单元的那个调用）。每条记录 4.1 ms，这个存储的天花板就是
  **大约 240 条记录/秒**，不管接了多少客户端，也不管这块盘其余时候有多闲。一个总共只收 240 个样本/秒
  的遥测存储，算不上一个存储；
- **便宜的那个调用是陷阱。** 同一台机器上，光秃秃的 `fsync(2)` 只要 **52 µs**——便宜八十倍——而在
  macOS 上，它被允许在驱动器拿到字节之前就返回。一个测了 `fsync` 就把结果叫作“一次设备刷盘”的存储，
  测错了系统调用，而且会挑出一个往丢数据的方向错的数字；
- **这个窗口的代价，取决于你说的是哪种崩溃。** 被杀的进程不丢任何已经写下的东西；断电的机器丢掉内核
  还没刷下去的一切；在写入*进行中*死掉的机器，会留下一条尾部是垃圾的记录；一个*名字*从没同步过的
  文件，可能跟着它的目录项一起消失；而一个自己的刷盘都失败的设备，把“已确认”变成一个问题。这五种
  不是同一种失败，没有一个数字能盖住全部。

所以，对遥测摄取来说，“每条记录都 fsync”和“永不 fsync”都是错的，而且错在同一个理由上：没人写下它
花多少、又让出什么。答案是**一个间隔**——一个占空比，从一个测量里选出来，并且明确规定一次机器死亡最多
能吃掉写入窗口的多少。选出这个数字，就是这一步。让它保持诚实，是剩下的部分：这个决定是**代码里的一个
值**（`Policy`、`Policy::DEFAULT`），也是**文档里的一句话**（`docs/adr/0001-write-path.md`），而两
者要互相对得上，因为一个活在某人记忆里的持久性保证，会在那个人离开时变样。

这份记录值得写，还有第二个理由。`lakelet/4.4-wal-recovery` 是这个问题的一半：它重放日志的一个前缀，
拒绝撕裂的尾部——而它只有在知道写入路径承诺了什么之后才能这么做。你在这里写的崩溃点清单就是那张地图：
它逐点说明一次 append 作答之后设备上有什么，而后面每一步都得保住这些。

## 任务

- 实现 `src/engine/wal/policy.rs`。决定就是数据：
  - `Policy` 带三个答案——`PerRecord`、`Interval { millis }`、`Never`——每一个都写明**它花什么**
    （这个存储多久等一次设备）和**它丢什么**（一次机器死亡会带走哪些已确认的记录）；
  - `Policy::ALL`（这个构建能被要求的每一个策略）、`Policy::DEFAULT`（这个构建实际做的）、
    `Policy::name()`（种类：一个稳定的字符串，因为文档要点它的名）、`Policy::describe()`（整个策略，
    包括数字）、`Policy::parse()`（把 `describe()` 的写法读回来，别的一律拒绝，并用一句话点名哪些
    写法可用，作为 `Error::Invalid`，好让一个笔误是配置错误而不是存储故障）、`Policy::losses()` 和
    `Policy::syncs_per_record()`；
  - `Losses`——`Nothing`、`BoundedBy { millis }`、`EverythingSinceTheLastFlush`：崩溃点表里机器
    可读的那一半，好让表和旗标能被机器互相比较。
- **在你自己的机器上测一次持久写入**，再去选数字。在 `/private/tmp` 下写一个用完就扔的程序，带它自己
  的 `CARGO_TARGET_DIR`，照 `Spool::append` 的写法往一个文件里追加一条记录，给真正的调用
  （`File::sync_all`）计时，而不是 `fsync(2)`。也不带它地给 append 计时，还有单跑 `fsync(2)`。把
  命令、机器和这些数字都记进 ADR——数字就是决定之所以是这个决定的理由，而一份没有数字的决策记录，
  只是一种偏好。
- 从这次测量推出 `DEFAULT`。一条经得起评审的规则：**设备最多占用挂钟时间的十分之一**，所以间隔至少是
  一次刷盘代价的十倍，再取整到一个人类会念出声的数字。`Policy::DEFAULT` 必须是一个 `Interval`；每条
  记录都等的存储跟不上，而从不等一次的存储没法辩护。
- 用这门课的文体写 `docs/adr/0001-write-path.md`（例子是 `relay/2.6-at-least-once`）：一个
  `# 0001 — <title>` 标题、一个 Status/Context 块、`## Decision`（哪个策略、测到的数字、推导过程）、
  `## Alternatives`（每个被否掉的答案以及它输在哪——per-record、never，还有你考虑过的任何机制）、
  `## Consequences`，以及什么情况下会重提这件事。它必须点名 `Policy::DEFAULT.describe()`——点名
  那个写法，而不是转述。
- 写 `docs/crash-points.md`：至少五个点，每个点一个 `###` 标题，并且**每一个**点都要说明设备上有
  什么、恢复会看到什么、哪些策略丢什么、运维会观察到什么。它必须点名这个构建里的每一个
  `Policy::name()`，还要链接到 ADR 和它讲的代码（`links` 闸门会解析每一个目标）。
- 教 `Spool` 什么叫持久，同时不动 `4.1` 承诺过的东西。签名已经在那儿了：脚手架在
  `src/engine/spool/durable.rs`——写入路径旁边那个模块——声明了 `Spool::with_policy`、
  `Spool::policy`、`Spool::len`、`Spool::is_empty`、`Spool::durable_offset` 和 `Spool::sync`，
  每个都带着一个 `todo!()` 的函数体——所以规格第一次运行就会调用它们，而**你写的是语义，不是形状**。
  `with_policy` 用交给它的策略打开存储，`durable_offset` 是这个 spool 写下的内容里有多少字节确定在
  *设备*上，`len` 是它写下了多少，`is_empty` 是它是否写过任何东西，`sync` 让剩下的都变持久，而
  `append` 会问策略——`PerRecord` 在调用里等，`Interval` 和 `Never` 不等。间隔策略可以在它的间隔
  过去时刷盘（它为此读时钟，而时钟在这里就只干这一件事）。`Spool::open` 还是原来那个调用，含义是
  `Spool::with_policy(directory, Policy::DEFAULT)`，因为守护进程走的是那条路。
- 让 `durable_offset` 保持**真实**：它在一次刷盘成功之后才前进，之前绝不。它是 `4.4` 重放到的边界，
  而一个只有希望、并不真实的数字，比没有数字更糟。

## 陷阱

- **一个就是 `len` 的 `durable_offset`。** 它是最短的路，但它输在那个要紧的用例上：在 `never` 下，
  一次 append 之后两个数字必须不同（`0 of 41 byte(s)`），所以一个回答“全部”的值，让整个策略成了
  装饰。镜像的那一个——一次不刷盘就把边界前移的 `sync`，或者在刷盘失败之后前移的——能过顺利路径的
  用例，然后对 `4.4` 撒谎。
- **`Spool::open` 写死一个策略。** 在那里放 `PerRecord` 是诱人的“安全”选择，而它会输在打开一个不带
  策略的 spool 的那个用例上：`open` 挑的就是一个部署拿到的，而 ADR 里那句话讲的是那个值。
- **测 `fsync(2)` 还把它叫作持久性的代价。** 在 `fsync` 不等设备的地方（macOS/APFS：**52 µs**，
  而 `sync_all` 是 **4.1 ms**），占空比规则会递给你一个一毫秒左右的间隔——一个套着间隔名字的逐记录
  策略，两边的坏处都占：没有吞吐量，还有一个你以为被自己编的数字约束住的丢失窗口。
- **一个比 `describe` 更宽容的 `parse`。** `interval`、`interval(50)`、`interval(-1ms)`、
  `per_record` 和空串都必须被拒绝，`kind()` 是 `invalid`；在笔误上回答 `Policy::DEFAULT`，就是让
  一个存储跑起一个没人选过的持久性策略的方式，而一次不点名哪些写法可用的拒绝，会输在那个从消息里读
  这些名字的用例上。
- **一份只是关于崩溃的散文的崩溃点清单。** 五段从不写 `per-record`、`interval` 或 `never` 的话，过
  不了逐点的用例；而正确字眼只出现在部分点里的清单，同样过不了。不点名任何策略的那个点，正是运维
  在事故里读到的那个点。
- **代码里有一个没有文档点名的策略，或者文档点名了一个代码已经丢掉的策略。** 往 `ALL` 里加一个间隔
  策略却忘了 `docs/crash-points.md`，过不了点名用例；在表仍然列着某个策略时把它移出 `ALL`，同样
  过不了，而那个方向更糟，因为表是有人照着做规划的东西。
- **一份只说“一个间隔”却不说数字的 ADR。** 记录里必须写下 `describe()` 的原样写法（`interval(50ms)`），
  而三个小节（`## Decision`、`## Alternatives`、`## Consequences`）是形状的一部分：一个不带被否掉
  选项的决定只是一种偏好，下一个人会从头再吵一遍。
- **在任何地方留下 `todo!()`。** 脚手架的桩是 `no-todo` 的事，每个 target 都算，包括规格永远不调用
  的那些。
- **有 `len` 没有 `is_empty`。** `clippy@4` 把警告当错误，而 `Spool::len` 一旦没有配对的那个方法，
  `clippy::len_without_is_empty` 就会开火：
  `struct Spool has a public len method, but no is_empty
  method`。脚手架声明了这一对，所以撞上
  这一条的唯一方式，是把一半弄丢——而无论哪种方式答案都一样：写入路径也要回答 `is_empty`，对一个
  spool 来说，那意味着存储里还没有任何字节。
- **把一份红的规格读成坏掉的课程。** 规格第一次运行，十四个用例里有十三个失败，每一个都停在脚手架里的
  一个 `todo!("step lakelet/4.3-write-path-adr")`（`src/engine/wal/policy.rs`、
  `src/engine/spool/durable.rs`），因为决定的*形状*随脚手架来了，语义没来。那里的
  `test result: FAILED` 是这一步的起跑线，而每一个桩都消失之后仍然红的那个用例，才是有话要说的那个。

## 延伸阅读

- `lakelet/4.4-wal-recovery` 是下一半：日志被重放成一个前缀，而那个前缀就是这一步的
  `durable_offset` 画出的边界。你崩溃点清单里的撕裂写入是 4.4 的主题——一条记录得先有校验和，读者
  才能分清一次短写和一次完整的写。
- `lakelet/4.5-batch-writes` 讲的正是逐记录策略负担不起、而间隔策略使之可能的事：一次刷盘许多条记录，
  以及一个数，说明这样省下了多少。
- 同样的三选一，在四个系统里的生产参考：SQLite 的 `PRAGMA
  synchronous`（`FULL` 是逐记录，`NORMAL`
  是间隔，`OFF` 是从不）、MySQL 的 `innodb_flush_log_at_trx_commit`（`1`、`2`、`0`——同一根轴上的
  同一个枚举）、PostgreSQL 的 `synchronous_commit` 配 `wal_writer_delay`（默认 200 ms：同一个间隔，
  不同的数字，不同的论证），以及任何一个用组提交让一次刷盘服务许多事务的 WAL。挑一个读，然后问他们的
  数字量的是什么。
- 这些调用本身，在你机器自带的手册页里：`fsync(2)`、`fdatasync(2)`（它跳过对读回数据无所谓的元数据，
  并不等于等待）和 macOS 的 `F_FULLFSYNC`（那个会等的）。Rust 的 `File::sync_all` 是把你想要的
  意思说出来的可移植写法，而它的代价是你面前那台设备的属性，所以去测，而不是相信一个 2015 年的数字。
- 读一个你依赖的项目里的 `docs/adr/` 目录。好的记录很短、点出输掉的那些选项、并且有日期。这一份是
  `0001`；这个决定被重提时，新记录是 `0002`，它链接回这里，而不是来改这一页。
