# 基数就是账单：给序列设上限，并给你留下的那些定价

## 为什么

这个 track 到目前为止量过的每一个数字都是一个*体积*：每载荷字节写出多少字节、一个计划没读多少块、每个查询
阶段多少工作。体积是操作者看得见的轴。基数是他看不见的那一个：一个值由*应用*选择的标签——`host=<pod name>`、
`user=<id>`、`request_id=<uuid>`——把一个指标变成一百万条序列，而流过的字节没有任何一部分告诉你这件事发
生了。每条记录仍然很小，每个帧仍然有效，每次写仍然成功。改变的是写路径下游一切东西的形状：段格式里一百万
条字典条目、sidecar 索引词表里一百万个词项、每个答案的标识里一百万个名字，以及一个现在有一百万样东西可
分组的查询计划器。存储死于基数，是被*要求*持有它，而不是持有得太慢。

所以防御是一份在事故之前就定下的策略：这个存储跟踪多少条序列的上限、一个在它拒绝时开口说话的计数器，以及
一页为它保留下来的那些序列定价。让这一步不只是一个数字的，是*上限必须住在哪里*。一个由每个进程根据**自己**
准入了什么来执行的上限，是一个每次重启都归零的上限——一个被进程管理器每小时重启一次的部署，每小时就长出
一个限额，而任何地方都没有计数器说出来。这一步落到的规则是 `lakelet/4.14-index-pruning` 的那一条，用
在基数上：序列的台账是**派生状态**，从存储自己持有的东西重建，所以上限所作用的那个数，是关于存储的事实，
不是关于发问的进程的。

## 回顾

`store/columnar@apply` — `lakelet/4.7`：一个段把记录按列摆开，其中一列是序列名，而这个名字对每个不同的序列
写一次，不是每条记录写一次。正因如此，账单跟着基数走，而不是跟着体积走；也正因如此，一个新名字的第一笔开
销，落在格式的字典里。

`obs/metrics-slo@design` — `jobq/3.17`：一个指标的身份，是有人选择用来给它分组的标签，而看板上每一个看起来
免费的选项，在这里都是一次乘法。同一个决定，在早一个 track 里表现为 SLO 的分组，在这里表现为存储的序列
数。

## 变化

上限是一份关于**状态**的策略，不是关于流量的。发送一条序列一百万个样本的客户端，是这个存储乐于服务的客户
端；一条百万条序列、每条约一个样本的客户端，才是花钱的那一个，而对请求设的上限，会拒绝错那一个。台账数
*名字*，全部理由就在这里。

两个后果让这一步的代码不同于前三步加的计数器。第一，台账不能是这个模块自己写的一个文件：一个因为 sidecar
过期而在自己的基数上搞错的存储，正是 4.14 反对过的那个失败，而答案也一样——从存储重建它（日志里的记录，
用各段的 sidecar 索引裁剪一遍），并让缺失的索引损失精度，而不是损失答案。第二，拒绝不是能告诉客户端的东西：
摄入协议是单向的，`lakelet/4.1-ingest-protocol` 决定了客户端从它的*连接*留下的计数器、以及从之后能对存储
问的东西里，得知它的帧发生了什么。`lakeletq inspect series` 就是那后一半。

## 任务

脚手架造了两个模块，并声明在引擎模块图保存它们的地方：

- `src/engine/cardinality/cap.rs`——策略作为一个值：`Cap`（上限、`Cap::DEFAULT`、`Cap::new`、`limit`）和
  `Admission`（`Admitted` / `Rejected { tracked, limit }`），带一个日志行或客户端能读的 `Display`；
- `src/engine/cardinality/mod.rs`——台账：`Cost`（记录数、字节数、第一个和最后一个毫秒），以及
  `Registry`，带着 `admit`、`charge`、`cost_of`、`tracked`、`rebuild`、三个计数器
  （`series_admitted`、`series_rejected`、`tracked_count`），和它们服从的等式
  （`offered == admitted + rejected`）。

它还留下了作为骨架的 `docs/cardinality.md`。函数体、接线和这一页都归你。

**上限的规则，两句话。** 存储已经在跟踪的序列永远被准入——上限不能弄断一条正在被上报的序列，否则一个到
了限额的部署会丢掉它已经持有的数据。存储从未见过的序列，在台账还有地方时被准入，没地方时就拒绝。拒绝不记
账、不移动任何东西，并且会被计数；而一个**帧**是作为它所在的那一批来判的，因为写路径要么整份载荷都存下、
要么一点都不存（`lakelet/4.5-batch-writes`）——一个被上限拒绝的帧，是每一条序列都被拒绝的帧，包括存储已
经有的那些。

**台账是重建的，不是保存的。** `Registry::of_store` 就是那条规则：存储的日志携带的记录（写路径从不截断
它，`docs/soak.md`）记到它们所点名的序列上，然后用存储仍然持有的那些段的 sidecar 索引裁剪一遍。某个活着
的索引可能持有的序列，就是存储仍然有的；没有任何索引可能持有的序列，就是它已经忘掉的——保留让携带它的段
过期了——而这正是让上限不会变成一个窗口故意遗忘的存储上的终身配额的东西。一个**缺失或损坏**的索引是
`SegmentIndex::unstated`，它可能持有一切：它证明不了什么，也丢不掉什么，代价是跟踪的精度，永远不是答案。
打开一个存储会跑这件事，这就是为什么重启后的守护进程不会从零开始数。

**守护进程的那一半，也是拒绝变得可见的地方。** 上限是部署的数字，`series.limit`，经由
`lakelet/4.6-ingest-backpressure` 立下的四层读取（file < environment < flag），而 `lakeletd` 带着它打开
存储。摄入路径在队列*之前*问上限——队列的答案是"这些字节已经在文件上了"这个承诺，所以一个存储不会收的帧，
绝不能到达写者——并在连接自己的 `rejected` 里数这个帧（连接关闭时那一行报告的就是它），再记一行日志，点
名那条序列和做出决定所依据的两个数字。停止路径把这次运行的台账打印在队列的数字旁边。

**工具的那一半。** `lakeletq inspect series --store <DIR>` 打印存储重建出的台账：每条被跟踪的序列一行——
名字、它的记录数、它的字节数，以及它窗口的两端——按名字排序，加上 `--json` 时把同样的对象打印成一个 JSON
数组。它是一次读：它不创建存储，而没有序列的存储是 `[]`，不是一个错误。

**然后是这一页。** `docs/cardinality.md` 是数字住的地方：这个构建出厂的上限以及为什么、三个计数器和那条
等式、一个被拒绝的客户端能观察到什么、那笔算术——一条序列一天花多少，*在你测量的工作负载上*，不是在你断
言的一个上——以及一段讲上限的代价，因为你拒绝的那些序列，是之后没人查得到的。

## 完成标准

- `cargo test -p lakelet --test spec_cardinality`——这一步的用例通过。
- `kiln run lakelet/4.18-cardinality-cost`，然后 `kiln check lakelet/4.18-cardinality-cost`——项目构建通
  过，规格在你的树上通过，每个 must 闸门都是绿的。慢闸门是 `lakelet/4.17-soak` 的装置加上上限，它在这里
  是故意的：一个会泄漏的上限，是长时间运行才能发现的东西。
- `lakeletq inspect series --store <a store you wrote>` 打印存储持有的一切，而 `docs/cardinality.md` 引
  用一次你自己的运行。

## 陷阱

1. **用这个进程准入过的东西搭出来的台账。** 它在单个进程里通过每一个用例，却在重启时归零——正是这一步存
   在要防止的泄漏，也是 `Registry::of_store` 在打开时被调用、而不是计数器从零开始的原因。
2. **拒绝一条存储已经在跟踪的序列。** 一个到了限额的部署，就此一次一个样本地丢掉了它已经持有的序列，而任
   何地方都没有错误。检查只针对*新的*名字。
3. **准入半个帧。** 队列的承诺是被接受的字节已经写下（`lakelet/4.5-batch-writes`），所以一个已跟踪的序列
   进去了、新序列没进去的帧，是一次协议里没有任何东西能表达的半写。
4. **在引擎里读时钟。** 台账里的 `Instant::now()` 会让同一个工作负载的两次运行报告两个不同的窗口，而一份
   预算或一次浸泡就此自相矛盾。`now` 是一个参数，而把它写下来的那个用例会扫源码找它。
5. **数记录，或者把一个被拒绝帧的序列数成已准入。** 上限讲的是名字；`offered == admitted + rejected` 是
   泄漏越界的那条线，而它按被提供的每条序列成立。
6. **把台账写进它自己的文件。** 那就是 4.14 拒绝过的第二个真相来源：一个因为 sidecar 过期而在自己的基数
   上搞错的存储，回答的是关于一个并不存在的存储的问题。
7. **把布隆过滤器的 `yes` 读成证明。** 一个答 `true` 的 `may_hold`，代价是一次读；把它当成"存储持有这
   个"，会把裁剪变成错误答案的来源，而一个 `unstated` 的索引——一个谁都没能读出词表的段——可能持有一切。
