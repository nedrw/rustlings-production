# 剖析就是证据：采样进程，读它，并说清它意味着什么

## 为什么

计数器报告的是它被造出来数的东西，而那个从没被数过的数，才是决定事故走向的数。一个查询剖析是绿的、吞吐却
只有应有十分之一的存储，并不矛盾：那是一个计数器只看进程的一半，而另一半在等设备。要发现这件事，唯一的办
法是*看进程本身*——采样器就是去看的那件量具，因为它打断正在跑的东西，而不是报告某人记得去埋点的那部分。

这一步的交付物之所以是一**页**，也是这个道理。没人写下来的剖析只是一则轶事：数字在一台机器上、一个终端
里、来自一个构建，下一个人读到它，只能当作道听途说。一页若带上调用方式、采样器自己的输出，以及一句话说该
改什么，它就是别人能复现、能反驳、能据以行动的证据。

## 任务

脚手架加了这个模式、通向它的两行代码，以及这一页的骨架：`src/bin/lakelet-load/profile.rs` 就是 `--profile`
的全部，里面有两个 `todo!()` 的函数体；加载器在它标好的块里声明它，并在 ingest 语法读到那行命令的任何一个
词之前就分派给它；而 `docs/profile.md` 是一个满是 TODO 的桩子。

**`cycle`——循环的一轮，以及它由什么组成。** 给你的工作负载是 `simulate` 为一批记录生成的东西，在
`src/bin/lakelet-load.rs` 里；`from` 是这次运行可以写入的第一个时间戳（你外面的框架会把它算出来）。你的
cycle 有四步，按一次负载运行做它们的顺序：把工作负载挪到 `from` 上、此后每轮再往后挪一个窗口，让这些记录
走一遍协议路径（客户端会发的那种帧，从它们自己的字节里再读出来，好让存储持有线缆真正载过的东西），把它们
封印进存储，然后对存储**就你刚写的那段 span 问一个问题**，用 `lakelet/4.15-budget-regression` 立下的阶段
来计数。第一轮的 trace *就是*这次运行的报告，之后每一轮都合并进去。

规格检查的是这个形状的两个性质，而它们正是这个循环这样写的全部原因：

- **一轮摄入的记录，就是它查询读到并作答的记录。** `decode`、`filter` 和 `aggregate` 算出来等于
  `records`，`blocks` 和 `decompress` 等于 `cycles`，而 `headers` 是每轮每段一个清单条目。一个往更
  早处伸的问题会破坏第一条，而失败消息会说是哪个阶段碰到了一个它不该碰的段；
- **一次被计数的运行，没有任何部分取决于机器。** 没有时钟、没有线程数、没有墙上时间能碰到那些计数器，所以
  两次 `--cycles 8` 的运行打印同样的字节。`--seconds` 是人去采样的那种运行，允许它有变化；但绝不能有任何
  东西取决于它跑到了多少轮。

**`lines`——这个模式打印的形状。** 每个阶段一行，*按一次查询走过它们的顺序*，然后是 `cycles=`、
`records=` 和 `bytes=`，计时运行最后还有 `seconds=`。同一个文件里的 `USAGE` 把这个格式写了出来，带着一次
`--cycles 8` 运行打印的数字，而阶段的名字来自 `Phase::name`，不是字符串字面量：剖析是给脚本读的，所以它
是一个形状，不是一句话。

**一个程序只留下一个退出类别。** 这个模式的 `exit_code` 就是那条规则；也从加载器的 `main` 里问它，好让一个
*ingest* 模式读不了的旗标以 `2` 退出，和这个模式里的旗标一样。一个对自己的命令行答 `1` 的部署，是在谎报
出了什么事。

**`docs/profile.md` 是交付物。** 从一次运行写它，绝不要从意图写：

- **采样了什么**——`kiln doctor` 在你机器上报告的剖析器状况，以及确切的调用方式：一个 release 构建、
  `--seconds 30`、那个 pid，以及对它执行 `sample <pid> <seconds> -file out.txt`；
- **排在最前面的两个符号**，照报告打印的样子，以及它们在这次存储里各自干什么；那张表上方的调用图，才说明
  它们从哪来；
- **这些数字所支持的那项改动**——一句话，系在阶段计数器上，然后是为让那项改动可见、计数器里必须动的是什
  么。如果答案是"什么都不会动"，就照说，并说清为什么那本身就是一个发现：计数器和采样器不是同一个数的两种
  拼写；
- **那张机器可查的表**——一个围栏块，它的每一行正好是你在上一句里写明的 `--profile --cycles <n>` 的全部
  输出。规格会重跑那条命令、逐行比较，这一页就是这样做到不跟代码漂移的。

不要碰 `src/engine/trace/**`：阶段的名字和它们的含义是 `lakelet/4.15-budget-regression` 的契约，前面有
四个规格对它们做断言。

## 完成标准

- `cargo test -p lakelet --test spec_profiling`（在 `app/lakelet` 里）——十三个用例全过，每个一个主张：
  两次被计数的运行打印同样的字节（`the_same_cycles_print_the_same_bytes`）；每个阶段一行，按查询走过它们
  的顺序（`every_phase_is_one_line_in_the_order_a_query_walks_them`）；`lakelet/4.15-budget-regression` 定
  下的等式（`the_phases_add_up_the_way_4_15_says_they_do`）；循环自己的守恒
  （`the_records_a_cycle_ingests_are_the_records_a_query_answers`）；一次被时钟停下的计时运行，并说明是被
  哪一边界停下的（`a_seconds_run_is_stopped_by_the_clock_and_says_which_bound`）；调用方的类别，两遍
  （`a_line_this_mode_cannot_read_is_the_callers`）；一个不是目录的路径
  （`a_path_that_is_not_a_directory_is_a_deployment_that_cannot_work`）；一个打不开的存储
  （`a_store_that_cannot_be_opened_is_the_stores`）；一次往给它的存储里追加的运行
  （`a_run_appends_to_the_store_it_was_given`）；这一页的块对着它写明的命令
  （`the_page_carries_the_profile_the_command_prints`）；这一页关于采样器的事实
  （`the_page_states_the_sampler_and_what_it_sampled`）；ingest 模式的语法和类别，还是原来的
  （`the_loader_still_speaks_the_protocol_it_spoke`）；以及这个模式在本进程里驱动存储，而不是走 socket
  （`the_profile_mode_drives_the_store_in_this_process`）。
- `kiln run lakelet/4.16-profiling`——同一批用例，跑课程的副本。
- `kiln check lakelet/4.16-profiling`——九个 must 闸门全绿，`links` 也在内：项目的 markdown 是整篇判的，
  所以 `docs/profile.md` 上的每个链接都必须能解析。
- `kiln doctor`——采样任何东西之前，先读它的剖析器那一节。
- 在 `app/lakelet` 里 `cargo build --release -p lakelet --bin lakelet-load`，然后
  `./target/release/lakelet-load --profile --seconds 30`，再对它报告的 pid 执行
  `sample <pid> 5 -file out.txt`。读报告的最后一节，把它贴进这一页。
- `kiln run lakelet/4.15-budget-regression`——仍然绿：这一步打印那一步造出来的计数器，不改它们的意思。

## 陷阱

1. **采样 `cargo run`。** `cargo run` 会把加载器作为*子进程*启动：你采样的 pid 是 cargo 的，报告是一份关
   于 cargo 在编译和等待的报告。直接跑 `target/release/` 里的二进制，采样它的 pid。
2. **引用一个你没有打印的数。** 这一页上的块是拿一次实时运行来比的，所以一个手工改过的计数——哪怕看起来合
   理——会失败，两份清单并排摆着。从一次运行去编辑这一页，循环有任何改动之后都重跑一遍。
3. **从答案而不是从运行去记各阶段的账。** 一个事后拿 `records` 填满 trace 的循环，在这个工作负载上会打
   印同样的数字，却一文不值：每个阶段一个计数的要点，是它记在*工作发生的地方*。向执行器要它自己的 trace，
   把那些合并进来。
4. **问整个存储，而不是问这一轮写了什么。** 对一个不断长大的存储，自然而然的做法是查它的全部，而这就破
   坏了守恒：`decode` 变成到目前为止每一轮的总和，不再是 `records`。一轮只问它刚写的那段 span。
5. **把一次拒绝打印到标准输出上。** 一个用半份剖析再加一句抱怨来回答 `--profile --cycles` 的运行，是脚
   本没法用管道接走的运行：用例断言只要退出码不是 `0`，标准输出就是空的，而 `Lakeletq` 的规则是同一
   条（`lakelet/4.10-downsampling`）。
6. **剖析一个 debug 构建，然后相信它。** 一个 debug 构建的采样，大部分是未优化代码的采样，那是关于
   `cargo build` 的事实，不是关于这个存储的。说清楚这一页讲的是哪个构建。
7. **对一次 `--seconds` 运行写断言。** 一次计时运行跑到了多少轮，是机器的事，所以把它钉住的规格会在忙碌
   的下午变红——正是 `jobq/3.22-bench-budget` 写出来要避免的那个失败。一次计时运行唯一值得引用的，是它跑
   过。
8. **承诺一台机器没有的采样器。** `cargo-flamegraph` 装了，但没有 root 跑不起来，`samply` 则没装：一页
   把读者送去用其中任何一个，就是第一步就失败的那一页。`kiln doctor` 才是在量哪个采样器能用，而这一页说
   出它发现了什么。
