# 冷数据离开这台机器：端口背后的分层，以及会说 S3 的客户端

## 回顾

- `outbound/http-client@apply — relay/2.7`：一次你能推敲的 HTTP 请求——请求行、头部、一个 body，
  以及一个 body 在 `content-length` 说的位置结束、而不是在连接关闭处结束的回答。那一步的客户端是
  一个*投递*客户端：三个截止时间、keep-alive、一个重定向策略，以及一个由上层据以行动的类别
  （`success`、`retryable`、`permanent`）。这一步留下的是那只鞋：跑在 `TcpStream` 上的 HTTP/1.1，
  自己写而不是委托出去，因为一个不是你写的依赖，是在 `403` 到来时你读不懂的依赖。它加上的是 2.7
  不需要的一切——2.7 向一个陌生人的 webhook 发不带签名的 POST，而这一步的客户端，对话的是一个会
  检查**谁**在问的服务。
- `store/retention@apply — lakelet/4.9`：那个删掉整个 segment 的 pass，以及这一步的策略与之同属
  一套、而非另起一个想法的那套词汇。策略是一个值，截止点是 `now - window`，比较是半开的
  （`last < cutoff`，所以正好*在*边界上的记录会留下），一个没人写下年龄的 segment 永远不会被动，
  而一次 pass 是在调用者递进来的某个 `now` 上施加的。那些句子每一句也是这一步的，只换了一个词：
  保留是删掉，分层是*搬走*。
- `sec/hmac-signing@apply — relay/2.11`：对离开套接字的确切字节算一个带密钥的 MAC，算在一个包含
  请求*为了什么*的元组上，结果写进一个头部。它反对的失败正是这一步的失败：签的是载荷的重新序列化，
  而不是载荷本身，就是你造出一个没人能验证的签名的方式。
- `store/compaction@design — lakelet/4.8` 和 `ops/backup-restore@apply — lakelet/4.19`：这一步所
  立足的两种顺序。4.8 在它点名的字节之后写 manifest；4.19 先写一个文件的字节，*然后*才写说它们
  完整的那条 manifest 条目，正是这一点让一份被打断的副本能说出自己的实情。这一步的顺序是这个家族
  里的第三个，也是由一个用例、而不是一段话判的那个。

## 变化

这个阶段的每一步都在量这台机器：写路径数自己的调用，一个 segment 的字节被钉住，一次运行被归给买单
的阶段，一次浸泡看着五个实时计数器，而 `lakelet/4.20-capacity-model` 给这一切标了价。这一步是第一
个对着账单做点什么的，而它做的事是存储里最老的把戏：**遥测存储持有的东西，大部分再也不会被读到，
而它们不必待在贵的那台机器上**。冷掉的 segment 进到一个分层里——一个 bucket，或者一个目录——在
有东西要它们的时候再回来。

三个决定让它安全，而没有一个显而易见：

- **端口说的是 blob，不是 segment。** `Objects` 是 `put`、`get`、`delete` 和一个会分页的列表；里面没有
  任何东西知道 segment 是什么。正是这一点让规则和两个 pass 只写一次、却能对两个实现运行——一个
  目录，以及一个架在这一步也要写的客户端之上的 S3 形状端点——也正是项目根目录的
  `conformance.toml` 的用途：这一步自己的套件每个后端各跑一次，`KILN_BACKEND` 设成那个名字，而
  一个分层只能对着目录工作的步，是一个没被测过的步；
- **对象先落地，本地文件后走。** 窗口里发生崩溃，segment 会*两个地方都有*，而两处是同样的字节，
  因为是 `put` 把它们放过去的——所以这个存储带着分层、不带分层都读得出来。反过来那个顺序有一个
  窗口，manifest 点名的 segment 两个地方都没有，那不是冷存储，是丢了的存储。那就是 4.19 为副本、
  4.8 为合并论证过的顺序，用在那唯一一个把东西搬离这台机器的操作上；
- **分层不保留自己的 manifest。** 分层里有什么，是问它问出来的——`list`，分页——而不持久写任何
  东西。一张从序号到 key 的映射，会是第二个可能和分层闹矛盾的文件，而一个信了它的存储，会因为
  一个谁也看不见的原因拒绝打开。代价是说出来而不是藏起来的：一个丢了列表的分层就是什么都不持有的
  分层，这是一个调用者能据以行动的真相。

这一步的另一半，是把 `outbound/http-client` 做到**设计**深度，而 apply 与 design 的差别，在于
客户端要为哪些东西负责。2.7 的客户端发字节、给回答分类。这一个被要求发出*带签名*的请求，而签名
正是 HTTP 客户端不再是管道的地方：

- **规范请求是用那个被发送的请求搭出来的。** `http::Request` 保存方法、路径、成对的 query、头部
  和 body，由它们渲染出上线字节，又从同一批字段算出规范请求。同一个请求不会在任何地方被第二次
  拼装，而只有这样才能让「被签的字符串不可能和发出去的字节闹矛盾」成为一个性质而不是一个希望——
  而一旦矛盾，就是一个 `403`，它的消息只说签名不匹配，绝口不提十五行里哪一行不同；
- **时刻是一个值。** `x-amz-date`、凭据范围里的日期戳和签名，全都来自调用者构造的配置。分层里
  没有任何东西读时钟，正是这一点让一条钉住的签名向量成为测试而不是一条 flake；
- **key 同时就是幂等键。** 一个 segment 的对象名是它身份的函数，所以发了两次的 `put` 只写了一个
  对象——这就是让重试安全的论证，和 `relay/2.8-retry-budget` 的论证完全不同，那里重试需要预算，
  因为一次投递出去的 webhook 就是投递出去了；
- **状态类别是一个值，而重试是一个计数。** `2xx` 是答了，`404` 是不在（不在是一个值：`get` 答
  `None`），其他每个 `4xx` 都拒绝、不做第二次尝试，`5xx` 和传输失败可以重试 `ATTEMPTS` 次。
  没有截止时间、没有退避、没有抖动：一个读时钟的重试策略，是两台机器会给出不同答案的策略，而
  这一步的整个主题，就是两边都一样的字节。

有三样东西故意**不**在这里，而每一样都是决定，不是缺口：

- **存储的 manifest 不变。** `lakelet/4.9-retention` 钉住了它的布局和它的版本字节，而一个为了
  说清某个 segment 的字节在哪就把它升版的步，会弄坏早先一步的规格和一个学习者的存储。所以分层把
  segment 放在点名它们的 manifest *旁边*，而回填把一个 segment 的字节写回 manifest 已经点名的那个
  文件；
- **日志和 sidecar 索引都不分层。** 日志是定义崩溃后能不能读的那个文件（4.4），而 sidecar 是可以
  重建的派生状态（4.14）。分层持有的，是存储唯一重建不了的东西：segment；
- **没有任何东西决定一次 pass *什么时候*跑。** `sweep` 和 `hydrate` 各自只是一次 pass，留给一个
  掌管调度的任务——和 `Segments::compact`、`Segments::expire` 一样的形状。

留下的是一个值得大声说出来的陈述，因为操作者就是在这页上找到它的——而它是这一步唯一一个属于*后果*
而不是特性的部分：

- **`sweep` 需要存储跑着；`hydrate` 不需要。** `sweep` 拿一个活的 `&Segments`，因为删掉一个
  manifest 点名的文件，是拥有这个存储的进程必须做的改动。`hydrate` 拿存储的**目录**，通过
  `lakelet/4.19-backup-restore` 的只读门读 manifest（`compaction::Manifest::read`——不创建、
  不 flush、不删任何东西），这正是它能在一个没有进程拿着存储的情况下把存储拼回去的原因：一个
  运行中的存储回填它马上要读的 segment，然后接着答；而进程已经停下的存储，在打开*之前*回填；
- **一个冷 segment 已经出了这台机器的存储，在回填之前打不开。** `Segments::open` 会拒绝一个
  manifest 点名、目录里却没有的 segment，而这个拒绝是诚实的答案——一个照着点名了谁都没有的文件的
  manifest 作答的存储，答的是一个洞——但它现在是一个命令能撤销的状态，而不是故事的结局。先回填
  目录，再打开它：open 仍然会把找到的每个文件对着 manifest 说的长度检查，所以一个不是那个 segment
  的文件仍然被拒绝，而不是被读。它的代价是操作者必须带来的一样东西：分层的列表，因为分层是它持有
  什么的权威（`list` 是一次逐页的遍历，而一个它没有的 key 是一个点名那个 key 的拒绝）；
- **这个构建仍然不做的是按需拉取。** 一个在读到一个冷 segment 时就把它拉进来的读者——在存储自己
  的 open 里，或者在读路径里——才是部署真正想要的，而 `lakelet/4.8-compaction` 的读路径里没有
  任何东西知道这个模块存在。所以调用者先回填、后读，而回填是调用者关于*什么时候*的决定，也就是
  4.9 的保留 pass 已经有的形状。它故意不放在这一步：它会改动 `lakelet/4.8-compaction` 的 open，
  而 `lakelet/4.19-backup-restore` 的规格正是钉在它上面的。这一步说出的是：进来的门是开着的——
  `Manifest::read` 存在——所以想要一个冷 segment 的调用者，在读之前用对目录的一次 `hydrate` 把
  它拉进来。

## 任务

脚手架造了四个引擎文件、两个课程自己的测试文件，和一条声明：

- `src/engine/tier/mod.rs`——端口、规则和两个 pass，函数体是 `todo!()`，整个表面都有文档；
- `src/engine/tier/filesystem.rs`——一个目录作为分层；
- `src/engine/tier/http.rs`——客户端；
- `src/engine/tier/s3.rs`——S3 的形状（SigV4 架在 `http` 上）；
- `tests/s3_stub.rs`——**完整的**：一个进程内的 S3 形状端点，规格把它声明成一个模块；
- `tests/support/tier.rs`——**完整的**：两个后端都要经过的那个工厂；
- `conformance.toml`——闸门读的那条声明，里面只有**一个**后端；
- 以及标记块里的四处插入：`src/engine/mod.rs` 里的 `pub mod tier;`、`tests/support/mod.rs` 里的
  `pub mod tier;`、`Cargo.toml` 里的 `sha2 = "0.10"` 和 `hmac = "0.12"`。

**`src/engine/tier/mod.rs` 是契约。** `Objects` 是端口，它说清一个分层能被问的四件事：`put`
（幂等——同一个 key 和同样的字节留下同一个对象）、`get`（不在是 `None`，不是错误）、`delete`
（幂等，因为一次删掉早已不存在之物的 pass，已经到达它要的状态），以及 `list(prefix, cursor)`，
答的是**一页**。`Cursor` 是一个*key*，不是偏移量：偏移量数的是遍历开始时前缀持有什么，所以遍历
中间来了一个 key，它之后的每一页都会错位。`listing` 是走一个端口各页的那个循环，它住在这里而不是
调用者那里，有两个原因：「端点说还有」是一个只有循环能据以行动的事实；而一个两次答同一个游标的
端点没有在前进——一个信了它的话的循环会永远问下去，所以那是一次传输层拒绝。

`Policy` 就是 `cold_after_millis`，[`Policy::DEFAULT`] 是一周，而规则是 4.9 的，只换了一个词：
**一个 segment 冷，恰好当 manifest 为它写下的最后一个时间戳低于 `now - cold_after_millis`**。
决定它的是*segment 自己的*范围，而不是存储的地板，原因在于 segment 是什么——一个文件，作为一个
对象搬走，而它里面最新的记录决定还有没有人会再读这个文件。一个没人写下范围的 segment 永远不冷：
一次 pass 不会依据一个没人写下的数字搬字节。

`sweep(store, objects, policy, now)` 把这个顺序执行出来：对 manifest 点名、策略判为冷的每个
segment，读文件、`put` 对象，只有之后才删本地文件。`hydrate(directory, objects)` 是另一半：读
manifest——通过存储的只读门，`lakelet/4.19-backup-restore` 的 `Manifest::read`，所以进程已经停下
的存储也能拼回去——然后，对本地文件缺失**或者不是 manifest 所说的长度**的每个 segment，取回对象，
在写任何东西*之前*把它的长度对着 manifest 的数字检查，再写回去。一个完整的存储一个东西都不问
分层——不列表、不发请求——正是这一点让回填便宜到可以在每次读之前都跑一遍。两者都答一个 `Report`，
而里面每个计数器说的都是*manifest* 说的，而不是一个目录碰巧持有的。

**`src/engine/tier/filesystem.rs` 是那个无聊的实现，而它存在是故意的。** 一个目录当对象存储不是
部署——它和存储在同一个机器上、同一个故障域里——而这恰恰让它成为那个说明端口不是围着 S3 设计的
实现。里面有三件事是决定：key 不是一个在根下面的路径就被拒绝（一个 key 能走出根之外的端口，就能
被要求往任何地方写）；`put` 等设备落盘*也*等点名那个对象的目录条目，因为 sweep 正是由于这个对象
才删掉本地文件；而列表是一个前缀、按 key 顺序，也就是 S3 形状端点作答的顺序——正是这一点让同一套
测试判两边。

**`src/engine/tier/http.rs` 是客户端达到设计深度的地方。** 请求和回答都是值，`Class` 是调用者
必须有所行动的四种情况，`ATTEMPTS` 是一个计数，而 `Request::canonical_request` 是由请求自己的
字段搭出来的——包括 `Request::payload_hash`：`x-amz-content-sha256` 头部由它而来，签名*也*
在它上面计算，所以两者不可能漂移。`Client` 拥有它阻塞其上的 tokio 运行时（端口是同步的，而一个
必须是 `async` 的端口，会是一个没法在测试里跑的引擎），每次尝试开一个连接，并读一个 body 到它
承诺的长度。它**不**做 `https`、分块回答或连接复用，而且它把这一点说出来了。

**`src/engine/tier/s3.rs` 是 S3 的形状：SigV4。** 规范请求、被签头部列表（从请求自己的头部推导
出来——一份由调用者手工维护的列表，会在有人加一个头部的那天不再匹配请求）、凭据范围、待签字符串、
四步 MAC 的签名密钥，以及 `authorization` 头部。`PutObject`、`GetObject`、`DeleteObject` 和
`ListObjectsV2`；`get` 上的 `404` 是 `None`；`403` 被拒绝、不做第二次尝试，它的消息说签名被
拒绝、并引用那个范围，因为那才是操作者能据以行动的东西。

**`conformance.toml` 是这一步自己的交付物，而脚手架给了你一个后端。** 把第二个加上：
`backends = ["local", "s3"]`，旁边用一句话说清第二个条目是什么意思。`conformance@2` 闸门对每个
条目跑一次 `cargo test -p lakelet --test spec_tiering`，`KILN_BACKEND` 设成那个名字，并要求每次
运行都通过——一个只列一个后端的步没有做这份活，而 `["local", "local"]` 是同一个实现写了两遍。

不要碰 `tests/s3_stub.rs` 或 `tests/support/tier.rs`：它们是课程的文件，是完整的，而夹具是唯一读
`KILN_BACKEND` 的地方。这套测试就是同一套跑两遍——不要写一个后端专属的测试文件，也不要让 `local`
的用例跳过 `s3` 的用例所做的工作。闸门照样会通过；但这套测试就不再是一套一致性测试了，而那就是
它本身。夹具有一个细节，在你读结果之前值得知道，因为它说清了什么在哪儿受判：`KILN_BACKEND` 决定
*端口用例*是**通过**哪个实现跑的——一个目录，还是端点——而关于客户端的用例（一个签名、一个载荷
哈希、一次重试、一个请求的形状、一个页令牌）在**每一次**运行里都搭一个 S3 形状的端口，因为它们
讲的是两边同一个问题。端点是进程内的，不花什么成本，而在一次运行里把那一半省掉，就会把它从变异
遍历里省掉，而变异遍历只跑这套测试一次。

## 完成标准

- `cargo test -p lakelet --test spec_tiering`（在 `app/lakelet` 里）——二十七个用例通过，每个一条
  主张：`put` 然后 `get`，而一个没写过的 key 是不在，而不是拒绝
  （`put_then_get_answers_the_same_bytes_and_an_unwritten_key_is_absent`）；`delete` 删掉，删两次
  不是失败（`delete_removes_and_deleting_twice_is_not_a_failure`）；一次列表按顺序答一个前缀，而
  一页接在前一页后面（`a_listing_answers_one_prefix_in_order_and_a_page_continues_the_one_before_it`）；
  比分层小的一页仍然答出全部，而遍历数它的页
  （`a_small_page_still_answers_everything_and_the_walk_counts_its_pages`）；key 是 segment 身份
  的函数，两个存储不会撞（`keys_are_the_segments_identity_and_two_stores_do_not_collide`）；一次
  sweep 恰好搬走冷的 segment，它的计数是 manifest 的
  （`sweep_moves_the_cold_segments_and_leaves_the_warm_ones_alone`）；来回一趟逐条记录对得上，之后
  从目录打开的存储也一致（`the_round_trip_answers_record_for_record`）；对象和删除之间的那个窗口，
  从两边都读得出来（`the_window_between_the_object_and_the_delete_is_readable_from_both_sides`）；
  一次回填把存储带回来，而在什么都不缺时什么都不问
  （`hydrate_brings_back_a_store_whose_files_are_gone_and_asks_nothing_when_they_are_not`）；取回的
  对象不是 manifest 的长度时被拒绝，且不留下任何文件
  （`hydrate_refuses_an_object_that_is_not_the_length_the_manifest_states`）；一个 segment 已经冷掉
  的停下的存储，被一个点名文件的 open 拒绝，然后**按目录**回填、再打开、逐条记录答得出来
  （`a_stopped_store_whose_segments_are_cold_is_hydrated_by_path_and_then_opens`）；回来的路是
  manifest 点名的每个 segment 一个对象，因为 key 就是存储自己的路径
  （`the_way_back_for_a_stopped_store_is_one_object_per_segment_it_names`）；策略边界有一毫秒宽
  （`the_policy_boundary_is_one_millisecond_wide`）；key 不是一个在根下面的路径就被拒绝
  （`a_key_that_is_not_a_path_below_the_root_is_refused`），而一个还不存在的根什么都不持有，而不是
  拒绝（`a_tier_root_that_is_not_there_yet_holds_nothing_rather_than_refusing`）；客户端拒绝一个它
  没法对话的端点（`a_client_refuses_an_endpoint_it_cannot_speak_to`）；被签的请求就是厂商自己的
  向量（`the_signed_request_is_the_vendors_own_vector`）；没有 `content-length` 的 body 在关闭处
  结束（`a_body_with_no_content_length_ends_at_the_close`）；载荷哈希点名被发出去的那个 body
  （`the_payload_hash_names_the_body_that_was_sent`）；`500` 会重试，而对象恰好在那里一次
  （`a_500_is_retried_and_the_object_is_there_exactly_once`）；`403` 不重试，它的拒绝点出签名
  （`a_403_is_not_retried_and_its_refusal_names_the_signature`）；那些操作就是 S3 端点所指的请求
  （`the_operations_are_the_requests_an_s3_endpoint_means`）；第二页用了第一页返回的令牌
  （`the_second_page_used_the_token_the_first_page_returned`）；一个永不前进的列表被拒绝，而不是被
  永远跟下去（`a_listing_that_never_advances_is_refused_rather_than_followed_for_ever`）；分层留在
  引擎里面，而边界在有一个端口的情况下仍然成立
  （`the_tier_stays_inside_the_engine_and_the_boundary_holds_with_a_port_in_it`）；引擎在分层的
  文件里不读时钟（`the_engine_reads_no_clock_in_the_tiers_files`）；报告数一次 pass 看了什么，而
  分层不持有自己的映射
  （`a_report_counts_what_a_pass_looked_at_and_the_tier_holds_no_map_of_its_own`）。
- `KILN_BACKEND=s3 cargo test -p lakelet --test spec_tiering`——同样的二十七个用例，对着进程内端点
  而不是目录。这就是 `conformance.toml` 第二个条目买来的那一次运行，而手动跑一遍，是看出一处悄悄
  依赖本地实现的用例的最快办法。
- `kiln run lakelet/4.21-cold-tiering` 和 `kiln check lakelet/4.21-cold-tiering --slow`——每个
  must 闸门都绿，包括两个慢的：`slow:conformance@2` 打印 `local ✓ s3 ✓`（这套测试每个后端各跑一
  次），`slow:mutants@80` 走这个解写下的十二行。
- **然后把这个顺序弄错，这正是那个用例的意义。** 把 `sweep` 里的 `std::fs::remove_file` 挪到
  `objects.put` 上面（或者去掉 `put`）：第一个冷 segment 在对象存在之前就离开这台机器，存储既没有
  本地文件也没有对象，而
  `the_window_between_the_object_and_the_delete_is_readable_from_both_sides` 变红——sweep 仍然
  拒绝，用例则失败在不在分层里的那个对象上。改回去，测试又绿了。

## 陷阱

1. **在对象进到分层之前删掉本地文件。** 这是这一步围绕着的那个错误，而它一直到一台机器死在错误的
   指令上才现形：两次写之间的窗口，要么是「两个地方都有」，要么是「两个地方都没有」，而只有其中
   一个是你能读的存储。测试没法在选定的指令上杀死一台机器，所以那个用例用一个 `put` *落地了却不
   作答*的分层——同一个状态的现实版本。
2. **相信一页的长度。** 端点可以答出比它被要求的 `max-keys` 更少的 key，而课程的桩是故意这么做
   的：客户端要一千，端点答两个，而 `IsTruncated` 是唯一说还有更多的字段。一个在第一页末尾就停下
   的客户端，会把分层的三分之一报成全部——而每个关于 sweep 的用例都会通过，因为 sweep 只写不读。
3. **把游标当成偏移量。** 偏移量数的是遍历开始时前缀持有什么，所以遍历中间来了一个 key，下一页就
   会跳过一个；走掉一个 key，下一页就会重复一个。游标是一个 key：一个不管期间发生了什么、意思都
   相同的位置——而分层恰恰就是有人遍历时会变的东西。
4. **在检查长度之前回填。** 分层里一个 segment 的副本，复制的是一个有既定长度的东西；副本不是那个
   长度，就不是那个 segment。先写后查，留下的文件会被存储自己的 open 随后拒绝——原因谁也
   trace 不到分层，这是最难查的那类拒绝。检查在写之前，而一个本来就错了的文件被删掉，而不是留下。
5. **用错的数字判断冷。** 存储的地板是它*已经忘掉*的东西，而一个 segment 的第一条记录，说明不了
   这个文件还会不会被读到：一个 segment 冷，是因为它的**最后**一条记录旧了。用地板会把还在被查询
   的 segment 分层，用第一条记录则会把最新记录才五分钟的 segment 分层。
6. **签一个你没发出去的请求。** 这个失败在每一份 SigV4 实现的每一次评审里都有名字：规范请求用一组
   值拼出来，然后请求又用同一组值、以稍微不同的顺序写出来，两者一直一致，直到有人加了一个头部，
   或者忘了编码一个 `/`。唯一结构性的答案就是这个模块采用的那个：一个值，两种渲染，签名从这个值
   算出来。
7. **签名里有一个时钟。** 从 `SystemTime::now()` 取 `x-amz-date`，会让每个签名都不一样，钉住的
   向量也就无从谈起；更糟的是，它让一个 `403` 取决于一个请求等了多久，那是一个只在负载下出现、
   从不在开发者的机器上出现的 bug。时刻是配置里的一个值，这一步如此，理由和 4.3 当初把 fsync
   策略做成一个值一样。
8. **重试一个 `4xx`。** `403` 就是一个回答：第二次尝试得到同一个，而花在它上面的每次尝试，都是
   下一个请求要用的尝试。「端点答不了」（`5xx`、死掉的套接字、超时）和「端点答了，答的是不行」
   之间的那条线，就是 `Class` 的全部，也是分层宕掉和分层配错之间的差别。
9. **一个作为截止时间的重试上界，或者一个根本不存在的上界。** 这一步的客户端把一个请求重试
   `ATTEMPTS` 次，期间不读时钟：没有退避、没有抖动、没有截止时间。截止时间是一个关于*时间*的
   策略，想要它的部署会把调用点包起来；而一个根本没有上界的重试循环，是一次永不结束的 pass，而
   一次永不结束的 pass 占着存储的调度。`relay/2.8-retry-budget` 才是带时钟的预算该待的地方，那是
   一个每分钟和别人的服务器说很多次话的服务。
10. **指望一个被 sweep 过的存储能打开，而且用存储、而不是它的目录去回填。** `Segments::open` 会
    拒绝一个 manifest 点名、目录里却没有的 segment，它也应该如此：替代方案是照着一份点名了谁都
    没有的文件的 manifest 作答。一个 segment 冷掉时进程就停下的存储，因此*不是一个你能打开的
    存储*——而把它放回去的那次 pass 拿的是**目录**，不是进程已经没有了的那个活存储。一个先 sweep、
    再停掉写入器、然后起一个这个存储的构建的操作者，得到的是一句点名某个文件的拒绝：一句关于这个
    存储的真话，也是先回填它目录的提示。回填造不出来的是分层：key 是存储自己的路径，所以一个没了
    的 bucket，真的只能靠每个 segment 手工复制一份，而 open 会检查复制过来的东西。
11. **写一点持久的东西来记住什么是冷的。** 存储旁边一张从序号到 key 的映射，是第二个可能和分层
    闹矛盾的文件，而在它闹矛盾的那天，存储要么因为一个谁也看不见的原因拒绝打开，要么打开并答出
    一个洞。这里没有任何东西被持久写下；`list` 是权威，而弄丢它，是一个调用者能据以行动的真相。
12. **用只有一个后端、或者同一个后端两份的 `conformance.toml` 交差。** 当声明太小时，
    `conformance@2` 是失败而不是阻塞，而 `["local", "local"]` 是同一个实现写了两遍。第二个条目
    才是活。
