# 一个受限的查询引擎：解析、规划，拒绝回答不了的问题

## 为什么

有一个查询接口，还有一种*语言*。`lakeletq query --store … --from … --to … --window … --agg …`
是五个旗标加一个形状：它恰好回答它能拼出来的那个问题，而其他每一个问题——"这两段时间之间 `h0`
上 `cpu` 的均值，按序列分组，取最吵的三个"——得让人写个 shell 循环去问。存储会被看板、告警
规则和其它程序查询，而他们是不会写循环的客户：他们写一个字符串，读一个退出码。于是这个问题得到
了一套**语法**，而语法正是一个存储决定它不做什么的地方。

最后那句才是这一步。一门什么都回答的查询语言，是一门回答它付不起的问题的语言：跨一年的 `mean`、
一个任何段都剪不掉的 `OR`、一个保留清理已经删掉的范围、一个没人摄入过的指标名。每一个都*接受*
起来便宜，回答起来昂贵甚至不可能，而每一个都是一个等着看起来正确的错答案。
`lakelet/4.11-query-engine` 是它们每一个都变成一个带退出码的**类型化拒绝**的地方，而且是在
**打开存储之前**就决定——也是 `EXPLAIN` 把将要做这些读取的计划打印出来的地方，让人看得见这次
查询即将花掉什么。`lakelet/4.12`–`4.18` 之后才让那些读变便宜；这一步是让它们*说得出来*。

## 任务

语法是固定的，`docs/query.md` 这一页把它印出来；关于它有六件事，是要你保持自洽的决定，而不是要你
照抄的语法：

- **时间范围是强制的，而且半开。** `ts BETWEEN a AND b` 是 `[a, b)`：落在 `a` 的记录在答案里，
  落在 `b` 的记录属于下一个问题。这个存储里的每个范围本来都是半开的（`Range`、`Partition`、段
  声明的 span），而*强制*的那一半是会自己回本的：一次读遍所有时间的遥测查询，是一场
  背后有一整个机群的事故，它会被一句话拒绝，而不是被一次扫描回答。
- **`FROM` 点名指标，`WHERE` 点名标签对，都是精确的。** 一条记录的序列是 `metric,tag=value,…`；
  摄入侧接受任意字节，所以查询侧不许假设格式良好，也不许折叠大小写。`Series::of` 是*全函数*——
  指标是第一个逗号之前的一切，一个键在 `=` 前面的对是标签，别的什么都不是标签、也永远匹配不上——
  而 `Query::selects` 是 `FROM` 和 `WHERE` 唯一有意义的地方。
- **只有 `AND`。** 每个谓词都必须成立；`OR` 是拒绝而不是实现，因为它是唯一一个出现就会改变计划能
  剪掉什么的子句（`lakelet/4.14-index-pruning` 有完整的论证）。
- **`GROUP BY time(<window>)` 是强制的，窗口在绝对网格上。** 一次不说桶有多宽的查询，就没说出
  它要什么；每个桶都是 `[n * width, (n + 1) * width)`，从 Unix 纪元数起——是
  `lakelet/4.10-downsampling` 的对齐，不是第二套，所以一个长度不是整数个窗口的范围，会比你数到
  的多碰到一个窗口。
- **`GROUP BY …, series` 才让答案按序列分开。** 没有它，一个答案混着谓词选中的每个序列——对整个
  机群是对的，对一台主机是错的；有了它，答案就是每个序列一张桶列表，按名字排序，每行带着它讲的
  那个序列。
- **`LIMIT` 限制的是序列，而且需要 `GROUP BY …, series`。** 对一个混合答案设的上限，没有点名
  任何可限的东西；`LIMIT 0` 被拒绝，理由和空范围一样。

**这些拒绝是语法的另一半。** 每一个都是一个自带分类的变体，而分类就是 `jobq/3.15-cli-contract`
定下的退出码：调用错了是 `2`（文本错了、一个不存在的聚合、一个 `OR`、一个什么也不限的上限、
一个低于存储下界的范围），问的东西不在是 `3`（这个存储从未持有过的指标——一个错字不许看起来像
一个安静的机群），存储答不了是 `4`，这次部署坏了是 `1`。调用方弄错的一切，都在**打开存储之前**
决定。

**课程给你什么，什么归你。** 脚手架写下契约，规格对着它编译，语义才是这一步：

- `src/engine/query/series.rs`、`lex.rs`、`parse.rs`、`plan.rs`、`exec.rs`——完整的公开表面，
  带着陈述上面那些规则的文档注释和 `todo!()` 的函数体。每个函数体都归你，访问器也算：签名是
  接口，规则才是活。
- `src/engine/query/mod.rs`——模块树，五个声明已经加在它的标记块里。
- `src/cli/mod.rs`——**归你**，而这一步加上它的 `--sql` 那一半：旗标，拒绝时把所给的形式一并说出来（文本
  *就是*整个问题，所以一个意思相同的旗标不能同时给出），经 `parse`/`Plan::of`/`execute` 的分发，
  两种答案形状，以及点名这个形式的 `USAGE` 文本。`src/bin/lakeletq.rs` 不变。
- `src/engine/compaction/snapshot.rs`——**归你**，而且它需要一个方法：`Snapshot::records()` 读
  每一个段，而一个会剪枝的查询必须只读计划留下的那些段。在它旁边加 `records_of(&SegmentInfo)`，
  走同样的三步（读文件、把清单的计数和它实际持有的内容对一下、丢掉下界以下的）。加一个方法
  不是回归；
  改 `records()` 的承诺才是（`docs/handoff-m3.md` §1 规则 10）。
- `docs/query.md`——**归你**：拒绝表的读者会打开的那一页。它必须印出语法、带每个拒绝分类的拒绝
  表、`EXPLAIN` 打印的键，以及计划描述的那条流水线。在页面写完并且里面每个链接都能解析之前，
  `kiln check` 会让 `links` 闸门失败，所以脚手架留下的占位链接就是清单。
- `src/engine/query/**` 的其余部分是 `lakelet/4.10-downsampling` 的 `downsample`，原样不动，
  而你的执行器调用它，而不是重新实现它：每个序列一次 `downsample` 调用，或者对选中的记录一次。
  一个 `mean` 的第二份实现，是一年之后会算错的那个看板。

**命令行。** `lakeletq query` 有两种问法，而两者互斥；`--store` 在两种里都是旗标，因为查询文本
点名的是一个指标，不是一个目录：

| 调用 | stdout | 退出码 |
| --- | --- | --- |
| `query --store <dir> --from <ms> --to <ms> --window <d> --agg <name> [--series <s>]` | 4.10 的那些行 | 0 |
| `query --store <dir> --sql 'SELECT mean(value) FROM cpu WHERE host = '"'"'a'"'"' AND ts BETWEEN <a> AND <b> GROUP BY time(5m), series LIMIT 3'` | 每行 `<series> <start> <count> <value>` | 0 |
| `query --store <dir> --sql 'EXPLAIN SELECT …'` | `key = value` 行 | 0 |
| 调用方弄错的任何东西（包括 `--sql` 旁边还有旗标，或者一个要求超过 `MAX_WINDOWS` 个桶的范围） | *空* | 2 |
| 这个存储从未持有过的指标 | *空* | 3 |
| 一个拒绝了的存储（这个构建读不了的清单或段） | *空* | 4 |
| 一个坏掉的环境 | *空* | 1 |

没有 `GROUP BY …, series` 的时候，文本形状是 4.10 的三个字段和那个混合答案；有它的时候，序列名
是第一个字段。`--json` 在两种里都是一种格式：旗标形式打印它一直打印的那个数组，文本形式打印一个
对象——查询花掉的计数就在它的桶旁边。旗标形式的输出和以前逐字节一致，它的规格也是你验收的一部分：
这一步加的是问法，不是一个新答案。

**你最先看到的东西。** `cargo test -p lakelet --test spec_query_engine` 先构建，然后十八个
用例全失败，每个失败都是一个 `todo!()` 抛出的 `not yet implemented` panic——其中两个根本不是
panic：二进制被一个指望文本形式存在的调用方塞了 `--sql`，而 `docs/query.md` 还是一张清单。这是
正常的形状。

## 完成标准

- `cargo test -p lakelet --test spec_query_engine`（在 `app/lakelet` 里）——十八个规格用例
  通过，每条用例对应一条主张：序列语法（`a_series_name_is_a_metric_and_the_tags_it_carries`）；
  扫描器的四种 token 和它的两次拒绝（`the_scanner_reads_words_numbers_values_and_the_four_symbols`、
  `an_unterminated_value_is_refused_at_the_quote_that_opened_it`）；五个单位和两个被拒绝的
  窗口（`a_window_is_a_number_and_one_of_five_units`）；每个拒绝的变体和分类，通过二进制各跑
  两遍（`every_refusal_is_a_variant_and_the_class_is_what_the_binary_exits_with`）；强制、
  半开的范围（`the_time_predicate_is_mandatory_and_its_upper_end_is_not_in_the_answer`）；
  标签谓词（`a_tag_predicate_selects_exactly_the_records_whose_series_carries_that_pair`）；
  五种聚合和它们的大小写
  （`the_five_aggregates_are_the_window_passs_and_the_grammar_folds_their_names`）；计划、
  `EXPLAIN`，以及一个段读不了的存储（`the_plan_prunes_from_the_manifest_and_explain_opens_nothing`）；
  一个存储从未持有过的指标对上它一条也没有的范围
  （`a_metric_the_store_never_held_is_not_a_quiet_range`）；下界
  （`a_range_below_the_floor_is_refused_in_a_sentence_that_names_it`）；两种输入形式对同一个
  问题答得一样（`the_two_forms_answer_the_same_question_the_same_way`）；`LIMIT`
  （`a_limit_bounds_the_series_an_answer_covers_and_not_the_buckets_it_holds`）；执行后的计数
  和它们之间的恒等式（`the_outcome_states_what_it_read_and_what_it_answered`）；不属于调用方的
  三类失败，以及一个问题最多能要多少个桶
  （`a_store_that_is_not_there_a_store_that_refused_and_a_broken_deployment`）；两种形式一起
  给出（`a_call_that_gives_both_forms_is_the_callers_class`）；这一步不许打扰的旗标形式
  （`the_flag_form_the_earlier_step_shipped_still_answers`）；以及边界
  （`the_query_sources_do_not_reach_into_the_service_and_the_page_is_there`）。
- `kiln run lakelet/4.11-query-engine`——同样的用例，跑课程的副本。
- `kiln check lakelet/4.11-query-engine --slow`——每个 must 闸门都是绿的，包括
  `slow:mutants@80`，以及读 `docs/query.md` 的那个 `links` 闸门。
- `kiln run lakelet/4.10-downsampling`——仍然绿，没变：这一步在窗口遍历上加了语法，而脚本已经
  在用的那些旗标，答的还是以前答的东西。
- 在 `app/lakelet` 里跑 `cargo run -q --bin lakeletq -- query --store <dir> --sql "SELECT
  count(value) FROM cpu WHERE ts BETWEEN <a> AND <b> GROUP BY time(1m), series"`——再用前面
  加 `EXPLAIN` 的同一句查询，以及每一类各一次拒绝。

## 陷阱

1. **报告了剪枝，却没真的剪。** `Snapshot::records()` 读每一个段；一次查询说
   `segments_pruned = 6` 却照样读完全部八个，就有一个对着预算唯一在乎的那个数撒谎的计划。规格
   把一个*被剪掉*的段的文件覆盖成长度相同的字节：计划照样作答，答案不变，而一个真打开那个文件的
   查询会以 `4` 退出。
2. **`first_millis <= to` 而不是 `<`。** 最早记录正好在 `to` 的段，不装着这个问题问到的任何东西，
   打开它读的是随后被丢掉的记录——计数会抓住它，因为 `segments_opened` 是对着清单里的 span
   断言的。
3. **`last_millis > from` 而不是 `>=`。** 另一端，而且更糟：最后一条记录恰好是 `from` 的段被
   剪掉，而 `from` 上的那条记录——半开规则说它在答案*里*——消失了。一次悄悄丢掉调用方明明能在
   存储里看见的记录的查询，是一个计划不许有的失败。
4. **窗口遍历的第二份实现。** 一个自己累加窗口的执行器，一个发布之内就会和
   `lakelet/4.10-downsampling` 走散：两头的部分桶、网格，以及 `mean = sum / count`，是四个
   决定，两份拷贝就是两个答案。规格把答案和同一批记录上的 `downsample` 比。
5. **为了判断一个名字在不在而读整个存储。** 一个错字和一个安静的机群之间的差别，值得一句话，
   而它是从范围碰到的那些段判断的：一个存储没有任何段落在其中的范围，无论 `FROM` 点名什么，都
   答空，而页面写明这一点，而不是为了显得聪明去读整个存储。
6. **"暂时"接受 `OR`。** 它不是语法细节：一个计划没法用只有半个析取项匹配的谓词排除一个段，所以
   接受它的那天，剪枝的故事就变了。它现在就被拒绝，4.14 负责论证。
7. **把低于下界的范围用剩下的东西回答。** `lakelet/4.10-downsampling` 是那样答的（现在也还是，
   它的规格是你的验收）；而*语法*拒绝它，并点名下界，因为一个写了存储已经遗忘的范围的调用方，
   需要被告知。
8. **把未知指标答成一个空答案。** 那正是这一类存在的理由：一个什么都不显示的看板和一个什么都不
   上报的机群看起来一模一样，而只有存储知道是哪一个。
9. **限制桶的 `LIMIT`。** 它限制的是一个答案覆盖多少*序列*；对一个混合答案设的上限，要么什么都
   不做，要么撒谎。这个拒绝归语法，`LIMIT 0` 是其中之一。
10. **把 `--json` 当成第二条代码路径。** 那个"另作处理"失败的 JSON 分支，一个月内就会漂。规格
    把每一个失败调用跑两遍，带 `--json` 和不带，比较退出码和诊断两者。
11. **把那句用法文本落下。** `USAGE` 是脚本读的接口；一个回答 `--sql` 却不说明的工具，会把每个
    调用方都送回源码。规格断言文本点名了这个形式。
12. **任何文件里留下一个 `todo!()`。** `no-todo` 会扫每一个目标，而这一步加的五个文件，是闸门
    最先看的地方。

## 延伸阅读

- **一个受限方言要付什么、买到什么。** Prometheus 的
  [PromQL](https://prometheus.io/docs/prometheus/latest/querying/basics/) 和 InfluxDB 的
  [Flux](https://docs.influxdata.com/flux/v0/) 是这个交易在现实里的两端：一门小语言，组合范围
  向量；一门完整的数据流语言，带一个标准库。`lakelet` 的语法故意更靠近前者，理由正是这一步讲的
  那个——一个存储规划不了的查询，是一个存储承诺不了的查询。
- **计划和打印计划。** PostgreSQL 的
  [`EXPLAIN`](https://www.postgresql.org/docs/current/sql-explain.html) 把这一步涉及的两半
  都写明白了：`EXPLAIN`（它*会*做什么，也是计划唯一诚实的来源）和 `EXPLAIN ANALYZE`（它做了
  什么，以及得出来的那些计数）。这个分离，就是这里计划报告 `segments_pruned`、结果报告
  `rows_scanned` 的原因。
- **按元数据剪枝，这才是重点。** [Parquet](https://parquet.apache.org/docs/file-format/) 格式的
  逐行组统计，和 [Iceberg](https://iceberg.apache.org/spec/) 的分区摘要，是这一步的
  `SegmentInfo` span 在工业规模上的样子，而 `lakelet/4.14-index-pruning` 是一个存储开始保留
  第二种摘要的地方（`blocks_pruned`，以及一个罩住序列名的布隆过滤器）。
- **一门可以交给别人的语法。** [`sqlparser`](https://docs.rs/sqlparser) crate 是这个项目拒绝
  掉的另一条路（docs/m3-plan.md §3）：一个真正的 SQL 前端，不用你自己写。花五分钟读它的
  `Parser`，是看清"受限"替你省了什么、又花了什么的最便宜办法——没有子查询、没有连接、没有 `OR`，
  是一门比 SQL 自己选择的要小的语言。
- **为什么是类型化拒绝，而不是一个字符串。** `jobq/3.3-library-errors` 为一个库论证过同一条
  规则：一个按消息分支的调用方，是一个一改措辞就坏的调用方。这里，分类是脚本读的退出码，而那句话
  只是写给必须把它修好的人的。
