# 同一份源码，同样的字节：可复现构建与供应链

## 回顾

- `release/container-image@apply — mailer/1.21`：两个阶段，一个只携带二进制的运行时，以及一个
  25 MB 的上限，断言出厂的那个阶段是运行时而不是构建环境。那一步的主张是*镜像跑的就是你测过的那个
  二进制*，而它的闸门问镜像里的二进制的问题，和问宿主机上那个的问题一样。这一步保留的是那个形状和
  那道闸门；它加深的是*这个二进制是由什么做成的*——编译器、它被构建所在的目录、它由之构建的
  crate——因为一个从没人能重建的树上构建出来的镜像，复现的是一个瞬间，而不是一份源码。
- `repo/toolchain-pinning@apply — mailer/1.2`：把钉住写成一个文件，带一个具体的三段式 channel 和
  闸门要跑的那些组件，再加上一条教训：钉住只有通过 rustup 才咬得住。在那里，这个文件挡住了「在我
  的机器上能编译」。在这里，它是比对三个输入中的一个：一棵树的两次构建只在编译器也是它们一致的东西
  之一时才一致，而 `channel = "stable"` 让每一次构建都成为当天那个 Rust 的构建。
- `ci/pipeline@apply — mailer/1.3`：一份检查清单而不是两份，由 workflow 调用，外加那个让任务运行器
  可测的嵌套运行守卫。这个项目没有 `xtask`——它自己就是一个 workspace，而它的流水线就是那个
  workflow——所以这条教训以设计深度到来：命令住在一个文件里，*工具链*写在一个文件里，而两者中任何
  一份的第二份拷贝，都是那一步反对的漂移。
- `supply/deny-policy@apply — relay/2.21`：`deny.toml` 带四个小节和每个小节执行的那句话，由一个
  当时正在发布东西的项目写的。这里的策略是第四个项目的，而它的清单是**从这棵树自己的 lockfile 上
  读下来的**，不是挑出来的：依赖声明的许可证、出现两次的 crate、它们来自的 registry——所以一个和
  树漂开的策略是一个失败的用例，而不是一段过时的文字。
- `release/artifacts@apply — jobq/3.25`：一个产物是一个有名字、有版本、有校验和、有 changelog
  条目的东西——一个别人能指认的发布。这一步是它的另一半：让这样一个名字*背后*的字节可复现的东西是
  什么，以及当它们不可复现时，还剩下哪些差异。

## 变化

这个阶段的每一步都量了存储的某个东西，而最后三步量了它花多少钱
（`lakelet/4.18-cardinality-cost`、`lakelet/4.19-backup-restore`、
`lakelet/4.20-capacity-model`）。这一步量的是它们全都站在上面、却没有一个检查过的东西：**构建**。
那些页面上的每个数字——每个摘要、每个计数器、每个字节——都出自一个编译器、一组依赖、一组旗标和
一个目录，而如果这棵树的两次构建对不上，那么「页面量的那个东西」根本就不是一个东西，它是一个
星期二的下午。

这一步能诚实做出的主张是*逐字节相同，或者剩下的差异被点名并解释*，而它的形状，由一台机器实际上
能把什么按住不动来决定：

- **编译器是一个输入。** `rust-toolchain.toml` 钉住 channel 和组件，而回答的编译器不是文件点名
  的那个时，复现器拒绝构建。这就是 `mailer/1.2` 的文件，出现在一个比对依赖它的项目里；
- **依赖是输入。** `Cargo.lock` 被提交，每次构建都带 `--locked`，所以 cargo 要么构建这棵树测过的
  那些版本，要么拒绝。这就是 lockfile 之所以是一个文件、而不是构建产物的全部理由；
- **位置是一个输入，而且是最有意思的那个。** 编译器把它读过的文件的名字写进它的产物，而它读过、
  没人想得到的那个文件，是*它链接的那份库*——它住在 target 目录下面。于是两个目录里的两次构建，
  产出两个记录了两个地方的产物，而那些名字之后每一件对长度敏感的东西都跟着它们动（一个 rlib 自己
  的成员索引按字节计数）。机制是 `--remap-path-prefix`，传给**两次**构建，覆盖**整个构建位置**——
  那棵树的副本和它旁边的 target 目录，先把它们解析成同一种拼法，因为在 Darwin 上
  `/var/folders/…` 和 `/private/var/folders/…` 是两个名字下的同一个目录，而一个只点名其中一个的
  重映射，会留下一个差异；
- **时间戳是留下的那个差异，而它不在字节里。** 两份副本的修改时间不同，而且永远会不同，这就是
  为什么比对是比内容，为什么那一块说的是 `difference_timestamp=mtimes_differ`，而不是假装两份副本
  是同一个文件。这些产物里没有任何东西记录时间：一个 rlib 的归档成员携带零修改时间，因为 rustc
  就是这么写的，而 `SOURCE_DATE_EPOCH`——那些确实会把时间盖进输出的工具的标准杠杆——在这里什么都
  没改变。把它说出来，是「考虑过」和「从没听说过」之间的差别。

这一步的后半是供应链，而它是从另一头问的同一个问题：一次可复现的构建，是*从什么*可复现。
`deny.toml` 说明这棵树可以由什么构建出来——四个问题，每个带着它的一句话——而里面的清单不是编的，
因为它们是从这棵树自己的 `Cargo.lock` 上读下来的：它依赖声明的许可证族、出现两次的那四个 crate
以及每一份第二拷贝从哪来、每个 crate 都从它取的唯一一个 registry。那个会跑这条策略的工具
（`cargo-deny`）没装在这里，也不是钉住的工具链的组件，而这一步在三个地方把这一点说出来，而不是
交一道假装不是这样的闸门：那个文件、`docs/supply-chain.md`，以及流水线——它在一条注释里点名那条
命令，而不运行它。

而流水线是这一切变成一张清单的地方：`cargo fmt --all --check`，然后
`cargo clippy --workspace --all-targets --locked -- -D warnings`，然后
`cargo test --workspace --locked`，然后是复现器——同样的命令、同样的顺序，课程自己的 CI 就是这么
跑的，而工具链写在一个、且只有一个文件里。

## 任务

脚手架放了六个文件，又故意把第七个省掉。它们每一个按现状都过不了这一步的规格，而脚手架就是干这个
的。

- `Dockerfile`——**一个阶段，形状是 `mailer/1.21-container` 的第一版**：工具链和源码留在那个运行
  的镜像里。这一步声明了两个镜像（`rust:1.98-alpine` 和 `alpine:3.20`），而文件里到目前为止只有
  一个；
- `scripts/repro.sh`——一个说出计划、以非零退出的桩；
- `deny.toml`——四个小节，有名字，是空的；
- `.github/workflows/ci.yml`——一次 checkout 和注释里的四条命令；
- `docs/build.md`、`docs/supply-chain.md`——带这一步页面那些标题的 `[TODO](TODO)` 桩；
- 以及**没有 `rust-toolchain.toml`**，这是一个决定而不是疏忽：一个交出这台机器没有的 channel 的
  脚手架，会让 `rustup` 去找一个没装的工具链，而缺失的文件是一个失败的用例。钉住由你来写。

七个文件，各有各的任务。

**`scripts/repro.sh` 就是这一步。** 它把同一棵树构建两次，从两个故意不同深度的目录，用钉住的工具链
和锁住的依赖，把 release 构建产出的库和三个二进制逐字节比对。关于它，有三件事是这份活：

1. **两个位置不同，而且宽度也不同**，好让一个*只是*路径的差异必须表现为字节上的差异，而不是被
   两个同样长度的路径藏起来；
2. **在两个构建被比对之前，构建位置被重映射**——两边都做，覆盖每一个点名它的东西，解析成同一种
   拼法。`liblakelet.rlib` 是这要紧的那个产物：三个二进制在 release 构建里不带位置，而库的元数据
   带，一个只比二进制的项目会得到一块绿，以及编译它的依赖所依据的那个文件里一个解释不了的差异。
   脚本**检查**这一点，而不是断言它：在打印任何东西之前，只要有一个产物仍然包含它被构建所在的
   目录，它就失败；
3. **它的输出就是结论**，而它的输出可引用。每个事实在 **stdout** 上打一行 `name=value`，别的一概
   不打——进度，包括两次 `cargo build`，都走 stderr——里面不放摘要、不放路径、不放时间：摘要会让
   引用它的页面在下一个 crate 动一动时失效，而时间是每台机器都不一样的数字。那一块带着：哪些
   产物、比了几个、几个相同、几个不同、一棵树的两次构建可能有的那两个差异各自是什么结果，以及
   一个裁断。有某个差异是那一块没点名的，就以非零退出。

流水线和规格都用 `sh scripts/repro.sh` 跑它，而那不是细节：文件带着 `#!/bin/sh` 那一行，但这一步
的文件是以 patch 到来的，而课程的施加器写的是内容、不是权限位，所以可执行位从来不是 patch 能交付的
东西。把解释器写出来，有那个位没有那个位都做同一件事；在你自己的项目里 `chmod +x`，它就成了一条
你能直接跑的命令。

两个环境变量是接口的一部分，因为这一步的规格要用它们：`LAKELET_REPRO_ROOT=<dir>` 把两份副本构建
在 `<dir>` 下面，而 `LAKELET_REPRO_KEEP=1` 把它们留在那儿——规格就是这样进到两棵树里面，去看那一
块说它比过的产物。一个什么都没比就打印裁断的脚本，必然通不过这一关，它也确实通不过。

**`Dockerfile` 是两个阶段。** 构建阶段是 `${BUILDER}`，运行时阶段是 `${RUNTIME}`，两个都是 `ARG`，
默认值是这一步声明的两个镜像——这是 `mailer/1.21-container` 立下的约定，不是装饰：在一个 registry
镜像站后面，同一个镜像住在另一个名字下，而 `container-repro` 闸门把那些默认值对着本地镜像库解析，
并把这个引擎实际拥有的名字作为构建参数传回去。运行时阶段携带二进制、一个非特权用户和**一点配置都
没有**：连一个容器需要的监听地址都没有，因为闸门拿镜像答的配置报告和这台宿主机的二进制答的那份
比对，而它只把 `MAILER__` 名字的环境变量传进去——这是那道闸门当初为第一个项目写的遗留。一个烤进
镜像里的 `LAKELET_*` 变量，是闸门报成失败的一个差异，这是一个比品味更锋利的理由，说明环境应当
归部署所有。`ENTRYPOINT` 是 `lakeletd`，正是这一点让
`docker run <tag> --check-config` 答出闸门要比对的那份配置报告。

**`rust-toolchain.toml` 是那个钉住。** 一个具体的三段式 channel——课程钉的那个，好让这台机器构建
的二进制和镜像构建的二进制出自同一个编译器——以及闸门要跑的两个组件（`rustfmt`、`clippy`），再加
一条注释，说明一个浮动 channel 会让*这一步*的主张付出什么代价。规格把这个文件和实际跑它的编译器
比对，所以一个没人在跑的 `channel` 是一个失败的用例。

**`deny.toml` 是把策略写成工具能跑的文件**，它的四个小节就是四个问题：`[advisories]`（一条已知
的公告、一次被撤回的发布）、`[licenses]`（这个 lockfile 声明的那些族，以及任何需要例外的
东西连同它旁边的理由）、`[bans]`（一个 crate 的两个版本、一个通配要求）、`[sources]`（一个
registry，不要 git）。清单不是你编的：用 `cargo metadata` 从树上读下来，让规格去判它们，因为一个
许可证清单连自己的依赖都不放过的策略文件，是没人能跑的策略。

**`.github/workflows/ci.yml` 是流水线**，按失败代价最低的排在最前的顺序，而工具链不在里面点名——
checkout 里的 `rust-toolchain.toml` 是 channel 被写下来的唯一地方，第二个钉住就是第二个答案。规格
把**这个文件当文本**读：这个项目没有 YAML 解析器，而且不能长出一个来。

**`docs/build.md` 是那次运行**，照着一次运行写：脚本打印的那一块（规格会重跑脚本并逐行比对）、
然后点名并解释每一个剩下的差异、钉住、`--locked` 和 lockfile 买来了什么、镜像改变了什么、让镜像
闸门变红的那个演练，以及这个项目**没有**做到什么。**`docs/supply-chain.md` 是评审者读的那份策略**：
什么被钉住、钉在哪儿，四个小节和每个小节执行的那句话，流水线跑什么，会让这份策略变成谎话的五个
改动，以及一段讲 `cargo-deny` 如果装了会加上什么。规格拿两页对着 `deny.toml` 读：一页承诺了文件
没说出的策略，或者一个文件拒绝了页面从没提过的东西，就是那一对文件存在要抓的漂移。

## 完成标准

- `cargo test -p lakelet --test spec_reproducible`（在 `app/lakelet` 里）——十五个用例通过，每个
  一条主张：钉住是一个文件，它的 channel 就是正在作答的编译器，而且是一个具体版本，不是指针
  （`the_pin_is_a_file_and_the_compiler_answering_is_the_one_it_names`）；钉住是*课程的*钉住，而
  不是关于这个项目用哪个 Rust 的第二种意见
  （`the_pin_is_this_course_pin_and_not_a_second_opinion`）；复现器答得出一次运行——`sh
  scripts/repro.sh` 退出零，并打印一块每个事实一行 `name=value` 的输出
  （`the_reproducer_answers_a_run_as_the_pipeline_runs_it`）；页面上的块就是命令打印的块，逐行
  不差（`the_page_carries_the_block_the_reproducer_prints`）；这次运行真的比了文件——块点名的
  每个产物在**两棵**树里都存在、两份副本逐字节相同、它们住在不同的构建根下，而且哪一个都不点名
  它被构建所在的目录（`the_run_compared_files_that_exist_in_both_builds`）；镜像是两个阶段，
  `ARG` 的默认值是这一步声明的两个镜像，而运行时阶段携带的是二进制，不是构建阶段或源码
  （`the_dockerfile_is_two_stages_and_the_runtime_stage_is_not_the_builder`）；镜像的入口是守护
  进程，而守护进程对 `--check-config` 答出闸门要比对的四层报告
  （`the_image_answers_the_configuration_question_the_gate_asks`）；策略文件有四个非空小节，接纳
  这个 lockfile 声明的每个许可证，点名它装了两次的每个 crate
  （`the_policy_file_states_four_answers_that_fit_this_tree`）；策略文件和供应链那一页说的是同一
  件事，一个键一个键、一张清单一张清单地
  （`the_policy_and_the_page_state_the_same_thing`）；workflow 按课程的顺序跑课程的四条命令，
  `-D warnings` 和 `--locked` 都在它们该在的地方，而且不点名任何版本
  （`the_workflow_runs_the_course_commands_in_the_course_order`）；这一步的文件*运行*的东西里，
  没有任何一个是钉住的工具链不提供的命令
  （`no_file_of_this_step_names_a_command_this_project_does_not_have`）；lockfile 钉住 manifest
  声明的每个依赖（`the_lockfile_pins_every_dependency_the_manifest_declares`）；页面点名这次运行
  有的那些差异——而且没有第三个（`the_page_names_the_differences_the_run_had`）；供应链那一页
  点名四个小节和那个钉住（`the_supply_chain_page_names_the_four_sections_and_the_pin`）；这一步
  受判的一侧没有任何东西把墙钟读进一个数字，而页面做出的每条主张都有一个文件来实现
  （`nothing_on_this_steps_judged_side_reads_a_wall_clock_into_a_number`）。
- `kiln run lakelet/4.22-reproducible-build`——规格通过；
  `kiln check lakelet/4.22-reproducible-build --slow`——每个 must 闸门都绿。那些闸门里有两个是
  关于镜像的，而其中之一是这一步的全部要点：`images` 把声明的两个基础镜像对着本地库解析，而
  `container-repro` **从这棵树构建镜像**，把运行时阶段压在 25 MB 以内，并拿镜像答的配置报告和
  这台宿主机答的那份比对。
- **然后弄坏它，这就是给这一步打分的那个演练。** `container-repro` 是抓坏镜像的那道闸门，而最
  便宜的弄坏是一行：把运行时阶段指向构建阶段（`FROM ${BUILDER} AS runtime`）再重建。闸门用大小
  回答——一个携带 `cargo`、`rustc` 和源码的运行时阶段是几百兆，不是几十兆。把那行放回去，它又绿
  了。在写这一步所用的那台机器上，容器引擎根本起不了一个容器（一次 overlay 挂载以输入/输出错误
  失败），所以闸门报**阻塞**，用的是引擎自己的那句话，而不是裁断；比对中 `--check-config` 那一半
  也是同样情况，原因还值得知道：闸门通过 `cargo run --package lakelet` 问*宿主机*的二进制，而这
  个项目有三个二进制、没有 `default-run`，于是 cargo 拒绝猜该跑哪一个。两件都是关于机器和闸门、
  而不是关于那七个文件的事实，两件都在这里被点名，而不是抹平——一条没人能复现的绿线，比一条带
  理由的红线更不值钱。

## 陷阱

1. **只重映射源码根，不重映射 target 目录。** 活下来的差异在库的元数据里，它点名 `cargo` 链接的
   那些 rlib——而那些住在 target 目录下面。它在二进制里看不见，所以一个只比二进制的项目，会在
   一个没人能复现的库上交付一块绿。重映射整个构建位置，两次构建都做。
2. **一个能用两种拼法写出来的构建位置。** 在 Darwin 上 `/var/folders/…` 和
   `/private/var/folders/…` 是两个名字下的同一个目录，而 `$TMPDIR` 给出第一种拼法，构建记录的却
   是第二种：重映射盖住一个，产物就不同。这不是假设——这一步自己的复现器第一版就是这么干的，也是
   为什么脚本在使用工作根之前先把它解析掉。一个路径不会因为你敲过它就是规范的。
3. **比对元数据而不是内容，或者在页面上引用摘要。** 两份副本的修改时间不同，而且永远会不同；一次
   对元数据的比对，是一次在一个能工作的构建上失败的比对。而块里的一个摘要，会让页面在下一次有
   什么动一动时失效，而这是一页测量最不能成为的东西——规格会重跑命令并逐行比对块，所以一个带哈希
   的块，在别人的机器上就是一个失败的用例。
4. **把配置烤进镜像。** `ENV LAKELET_LISTEN_ADDR=0.0.0.0:7000` 是每本容器指南都会说的，而在这里
   它会让 `container-repro` 失败：闸门拿镜像的配置报告和宿主机的二进制那份比对，只把 `MAILER__`
   名字的环境变量传进去，所以镜像里的一个 `LAKELET_*` 变量，是两个本该是同一个二进制的二进制
   之间的差异。部署拥有自己的环境；镜像拥有二进制。
5. **一个其实就是构建阶段的运行时阶段。** 不复制二进制，而是 `COPY --from=builder /src /src`，或者
   在运行时阶段再来一次 `cargo build`，镜像就重达几百兆——那个上限就是「交付的阶段是运行时」这个
   断言。`COPY --from=builder` 是让它成真的那一行，而它*从*哪儿复制的那个路径必须在闸门挂载的构建
   缓存（`/opt/kiln/target`）之外，因为挂载不是一个层。
6. **一份清单没人查过的策略文件。** `allow = []` 拒绝这棵树有的每个依赖；一份从别的项目抄来的
   清单，会拒绝其中三个，还放过一个它不该放过的。从这棵树上读许可证（`cargo metadata`），把你做
   的例外连同理由写在它旁边，点名你容忍的重复——规格拿文件对着 lockfile 判，所以一份不合自己树的
   策略是一个红用例，而不是一段文字。
7. **一条 workflow 跑一个钉住不安装的工具。** `cargo deny check` 是放在策略文件旁边的那个显然要加
   的步骤，而它是一项在装了 `cargo-deny` 的机器上通过、在 runner 上失败的检查——钉住工具链的组件
   是 `rustfmt` 和 `clippy`。这条命令在页面上和一条注释里被点名，在哪儿都不运行。说清缺哪个工具，
   而不是交一个从没跑过的步。
8. **在一个没有 `.dockerignore` 的项目里 `COPY . .`。** 构建上下文是一个部署正站在其中的整个目录，
   包括宿主机自己的 `target/`——几百兆*这台*机器的产物，每次构建都发给引擎，而镜像自己会编译那份
   二进制。点名构建要读的文件（`Cargo.toml`、`Cargo.lock`、`rust-toolchain.toml`、`src/`），只
   多一行，目录却窄了一个。
9. **一个没被提交的 lockfile，或者一次不带 `--locked` 的构建。** 任何一个都把「同一份源码」的依赖
   那一半，变成 registry 今天答什么就是什么，而页面上的比对于是量的是两个瞬间，而不是两个目录。
   复现器和流水线都传 `--locked`，理由相同。
10. **把流水线当成流水线来读。** 规格把 `.github/workflows/ci.yml` 当*文本*读，而且它这么说；
    这里没有任何东西解析 YAML，而一个为了判缩进而加进 YAML 解析器的课程项目，就等于给它正在判的
    那棵树加了一个依赖。文本必须携带的是命令，按评审者会争论的顺序。
