# 容量是一个装着数字的模型，不是一种感觉

## 为什么

到目前为止每一步都落在一个测量上：写路径数自己的调用，一个 segment 的字节被黄金向量钉住，裁剪是
一个速率，一次运行被归给买单的那个阶段，一次长时间的浸泡观察着五个实时计数器。这一步讲的是那些
测量回答不了的问题。*每天一百万事件要花多少钱*，是在负载到来**之前**，由一个正在决定买几台机器的
人问出来的，而唯一诚实的答法是模型：几个有人量过一次的数字，在它们之上做算术，再加一份标价。

那是另一种产物，坏起来也不一样。今天错了的测量是某人的事故；错了的模型会在一年里被人用自信的语气
引用，写在一页没人重跑的纸上——而它出错的方式总是一样：一个常数，是在它底下的编码器改变之前量出来
的。所以这一步把模型和**比对**一起造出来。常数和存储自己的数字由同一套装置打印、在同一条车道里
受判，而一个不再匹配存储写出的东西的常数，会以它负责的那个量之名让 `slow:bench-budget@10` 变红。
一个没人拿存储比过的容量模型是一页纸；这一个是一份设计。

这一步立起的设计能力是 `ops/capacity-cost@design`：操作者据以规划的数字，以及它们仍然为真的证据。

## 任务

脚手架造了三个文件，插了一行：

- `src/engine/cost.rs`——模型，函数体是 `todo!`/`panic!`，整个表面都有文档；
- `tests/budget_cost.rs`——车道跑的那套装置，**完整的**：它用真实的写路径造一个存储、问两次查询、
  量三组文件，并把两边都打印出来。写任何东西之前先读它的模块文档；这一步受判的每个数字都来自它；
- `docs/capacity.md`——那一页的骨架，一个 TODO 桩；
- 以及在 `src/engine/mod.rs` 标记块里的 `pub mod cost;`。

**模型是一个把单位写进字段名的值。** `Model` 为项目决定的每个数字带一个整数——`bytes_per_sample`、
`series_overhead_bytes`、`log_bytes_per_sample`、`bytes_per_query`、`retention_days`、三个价格，
以及模型为它自己声称的容差——`Model::DEFAULT` 是这个项目出厂的那一个。每个字段的文档都说明它的数字
从哪来：对这个存储的一次测量（装置会打印它自己版本的每一个）、一个策略
（`lakelet/4.9-retention` 的），或者一个在页面上带着日期的标价。`Usage` 是把问题写成的值——每天
一百万事件、一千个 series、一万次查询、三十天——而 `Usage::DEFAULT` 是模型自己的默认问题。

**算术是名字里带着单位的方法**，而钱是以美元的**微单位**计：成本路径里任何地方都没有 `f64`，因为
一个取决于机器如何舍入的成本，是两台机器会给出不同答案的成本，而车道比对的是计数。
`sample_bytes_per_day`、`series_bytes_per_day` 和 `log_bytes_per_day` 是三个分开的项；
`bytes_per_day` 是它们的和；`stored_bytes` 是它乘以保留期；`ingest_micros`、`storage_micros` 和
`query_micros` 是一个月的三个份额，而 `monthly_micros` **恰好**是它们的和，写成对那三个方法的一个
表达式，让这个恒等式能被一个用例证伪，而不是在散文里断言。`yearly_micros` 是
`MONTHS_PER_YEAR` 个这样的月；月是 `DAYS_PER_MONTH` 天，只命名一次。有两个决定，文档论证它们，
规格钉住它们：保留期**为零天就是一天所持有的量**（一个运行中的存储在过期之前，磁盘上总有一天的
数据——不是零，也不是一次除法），而一个总额的三个份额是千分整数，加起来恰好是一千，由最大的那个
承担舍入。

**然后是让它成为设计的那一半：比对。** `Measured` 是一个存储实际写下的东西——segment、它们的
sidecar 索引、日志、记录、series、sidecar 据以写出的那些（segment, series）对，以及每次查询读了
多少——而 `Model::predicts` 是模型对同一批数字的说法。`Model::agrees` 把它们并排放在一起：每个量
一个 `Drift`，各自点名它出自哪个常数、方向（`exact`、`over`、`under`），以及以模型所说之数的整数
千分比计的距离。偏百分之五的模型在它声称的容差之内；偏百分之二十的不在，而答案会说出哪个常数动了、
往哪边动。`Estimate` 是把答案写成固定顺序的 `name=value` 行，只有整数——页面引用的就是这个。

**`docs/capacity.md` 是交付物。** 照着模型自己的输出写，绝不手写：那一块是
`Estimate::of(Model::DEFAULT)`，逐行打印，而保留期表是对同一个模型的另外三次调用。然后逐项论证——
`bytes_per_sample` 从哪来、装置把它量成了什么，一个 series 让 sidecar 花多少钱、这一项在高基数下
往哪边偏，保留期作为唯一由人选择的乘数（连同那张三行的表，以及两端彼此相比各花多少），查询那一项
引用 `lakelet/4.14-index-pruning` 的速率而不是重新量，三个价格连同它们的来源、区域和**读价目表的
日期**，再加一节讲**模型不是什么**：它不预测延迟，不给任何基数上限定价，不给
`lakelet/4.8-compaction` 重写的字节或存储自己的 manifest 定价，而它的查询项是一次裁剪后的读数，
不是一个平均值。页面上的每个数字，都是那一块里的一行、表格里的一个格子，或者装置的一行输出，并在
引用处点名。

不要碰 `tests/budget_cost.rs`——它是课程的文件，而且是完整的——也不要加依赖：`src/engine/cost.rs`
是对值做算术，它是这个项目里唯一一个什么都不能读的模块。

## 完成标准

- `cargo test -p lakelet --test spec_capacity`（在 `app/lakelet` 里）——十四个用例通过，每个一条
  主张：样本成本对着存储自己的编码
  （`the_models_sample_cost_is_what_the_stores_encoding_wrote`）；一个 series 在一份真实索引文件里
  占的份额（`the_series_overhead_is_one_index_files_share_of_its_series`）；在负载里和在常数上都
  线性（`the_storage_term_is_linear_in_the_event_rate_and_in_the_sample_cost`）；保留期就是那个
  乘数，而零天就是一天的量（`retention_is_the_multiplier_and_zero_days_is_one_days_worth`）；在
  一组 usage 矩阵上 `total == ingest + storage + query`，每个份额都是它自己那一项的
  （`the_total_is_the_three_shares_for_a_matrix_of_usages`）；页面上的块与模型对得上
  （`the_page_block_is_what_the_model_prints`）；月只命名一次，一年恰好是十二个它
  （`the_month_is_named_and_a_year_is_twelve_of_them`）；百分之五被接受、百分之二十被拒绝，并点出
  常数和方向（`agreement_accepts_a_model_five_percent_off_and_refuses_one_twenty_off`）；漂移算术
  按千分计，两个方向都在
  （`the_drift_arithmetic_counts_per_mille_and_keeps_the_direction`）；两次查询读数，以及模型对每
  一次的预测（`the_query_term_is_what_the_plan_opened`）；series 那一项定了价，四倍的 series 付四倍
  的钱（`the_series_term_is_priced_and_four_times_the_series_pay_four_times`）；引擎边界，以及一个
  什么都不打开的模块（`the_step_stays_inside_the_engine_and_reads_nothing`）；页面里没有留下没填的
  空白，它承诺的每一条主张都在（`the_page_exists_says_what_the_step_is_about_and_has_no_blanks`）；
  而保留期表就是对模型的三次调用（`the_retention_table_is_three_calls_to_the_model`）。
- `kiln run lakelet/4.20-capacity-model`——同样的用例，跑课程的副本。
- `kiln check lakelet/4.20-capacity-model --slow`——十个 must 闸门全绿，预算车道也在内：它打印存储
  的数字、模型的数字和两者之间的漂移，而页面必须是它的 `links` 闸门解析得到的那一个。
- `cargo test -p lakelet --test budget_cost -- --nocapture`——手动跑那条车道，你最初就是这样把常数
  写进 `Model::DEFAULT` 的：它打印的三个速率就是字段携带的数字取整，而 `bytes_per_query` 是选择性
  读数除以它的记录数。
- **然后让模型漂移，这才是重点。** 把 `Model::DEFAULT` 里的一个常数改百分之二十（比如
  `bytes_per_sample: 5`），再跑 `cargo test -p lakelet --test budget_cost -- --nocapture`：
  `drift_segment_bytes_permille_max`、`drift_on_disk_bytes_permille_max` 和两个查询漂移都会越界，
  `within_max` 变成 `1`。改回去，车道又绿了。
- `kiln run lakelet/4.14-index-pruning` 和 `kiln run lakelet/4.15-budget-regression`——仍然绿：这
  一步读它们的数字，两个都不改。

## 陷阱

1. **钱的路径上出现浮点数。** `14798` 微单位是整数；`0.014798` 不是，而在二进制浮点里，两倍的
   `0.014798` 不是 `0.029596`。只要有一项是 `f64`，两台机器对同一张账单的舍入就会不同，而比对计数
   的车道就没什么可比的。每个价格、每个份额、每个总额都是整数，除法只在最后做一次，用 `/`。
2. **在模型里面测量。** 诱人的捷径是让 `Model::predicts` 去看存储——问 manifest、stat 一个目录、
   读时钟——好让比对永远一致。那正是这一步通篇在讲的那种失败，只是高了一层：一个会测量的模型不是
   模型，是一次慢的测量，而且它回答不了一个还不存在的存储的问题。规格就是为这个去读
   `src/engine/cost.rs` 的：没有 `std::fs`、没有 `std::path`、没有 `std::time`、没有 `std::env`。
3. **一个宽到能把漂移藏起来的容差。** `agreement_permille` 是唯一能让一个正在漂移的模型看起来是
   绿色的数字，它只在模型里声明一次，预算车道把它当上界压住。把它放宽，和改基线是同一个错误：常数
   没有变好，测试变好了。
4. **一年当三百六十五天。** 把年算成对天数的一个表达式，得到的数字和十二张月账单不一样——最多差
   十一个微单位，而这正是让同一年的两份报告对不上账的那种差异。年就是 `MONTHS_PER_YEAR` 个月，
   舍入只在月里发生一次。
5. **在某个 `const fn` 里写 `todo!()`。** 模型的算术是 `const` 的——`Usage::DEFAULT` 就由其中
   一个构造——所以在那些函数体里写一个带格式化消息的 `todo!("…")` 是编译错误（`E0015`），不是
   运行时 panic。脚手架的这些桩函数正是因此用 `panic!("lakelet/4.20-capacity-model: …")`；把函数体
   写出来，或者在你迭代的时候保持这个形状。
6. **把 sidecar 的每 series 成本当成格式的性质。** 每个 segment 一个索引文件，它的大小不取决于这个
   segment 装了多少 series——于是一个 *series* 花多少钱是一次除法，而那个常数只在它被测量的工作
   负载上是对的。模型在高基数下会往*高*了偏，`docs/capacity.md` 必须这么说；一个把
   `series_bytes_per_day` 当成一个 series 的价格的读者，会删掉自己并不需要删的 series。
7. **手工编辑页面。** 块和表都要对着对模型的调用逐行、逐格比对。打进去的数字就是会失效的数字——
   而这是让一页数字保持为真的唯一办法，也是为什么它要从模型的一次运行里写出来，而不是从装置的一次
   运行里。
8. **数了 segment 就说这是存储。** 这个存储从不截断它的日志，所以它持有的字节大部分是原始载荷，
   而不是压缩过的 segment——`log_share_permille` 是 `885`，而样本是 `113`。一个把 segment 文件加
   起来的容量模型，只会给磁盘的十分之一计价，而发现这一点的演练，就是装置输出里的一行。

## 延伸阅读

- `course/tracks/lakelet/spec/4.20/capacity.rs`——那十四个用例，包括把 `docs/capacity.md` 读回来、
  重跑产生它的东西的那两个。
- `course/tracks/lakelet/scaffold/4.20-capacity-model.patch`——给你的东西：那个契约文件、那一页的
  骨架，以及判整个步的装置。
- `tests/budget_cost.rs`——车道：写路径、两次查询，以及比对的两边。先读它的模块文档；它是这里唯一
  会碰存储的文件。
- `src/engine/segment/mod.rs`——`bytes_per_sample` 所依据的那种布局，也是这个常数是一次测量而不是
  一份数据手册的原因。
- `src/engine/index/mod.rs`——sidecar 的固定大小，以及让一个 series 的开销成为那个值的除法。
- `src/engine/query/plan.rs`——`Plan::opened`，也就是「一次查询读了多少字节」不需要新仪器就能量出来
  的方式，以及 `lakelet/4.14-index-pruning` 让它变小的东西。
- `docs/cardinality.md`——这个模型线性计价、而存储并不线性的那个上限和台账。
- [Amazon Kinesis Data Streams pricing](https://aws.amazon.com/kinesis/data-streams/pricing/)——
  `Model::DEFAULT` 三个价格的出处，以及厂商自己的那个算例——它决定它的「GB」是 gigabyte 还是
  gibibyte。
- [Google SRE Workbook, "Managing Load"](https://sre.google/workbook/managing-load/)——把容量
  规划当成一次带模型的、反复进行的测量，也就是这一步的车道变成机械动作的那个习惯。
