# 存储的模型，以及一趟必须与它一致的随机游走

## 为什么

十二步全是用例，而每一个都是某个人想到的用例。手写测试套件就是这个形状，这不是批评：一条把规则说出来的
用例，正是规则得以成立的方式。但让你搭进去一周的 bug，是没人想到的那一个，而一个存储里这类 bug 比你至
今写过的任何东西都多——一次刷写在合并进行到一半时关掉一个段；一趟保留策略的截止点正好落在某个段*内部*；
一次重新打开，发现索引点名了一个设备从未留住的文件；一只时钟在两次追加之间倒退，让一条后追加的记录排到了
先追加的那条前面。这些你列不完。它们太多了，而你能列出来的，恰恰是你已经理解的那些。

找到它们的这项技术比属性测试还老，而且它不是一个库：为你存储里的**读者**所看到的东西再写一个*笨*实现，
用随机序列驱动两者，每做一次操作就比较一次。笨的那个叫**参考模型**。它可以是十行，可以很慢，但不许知道
真实现是怎么存数据的——因为整件事的窍门就在这里。一个自己带段的模型，会犯和存储一样的 bug。

那么读者看到的是什么？被追加的那些记录，按追加的顺序，减去保留策略已经忘掉的那段前缀。就这些。一次刷写
写一个文件，一次合并把其中四个重写成一个，一次崩溃留下一个孤儿，一次重新打开重放一份日志、删掉索引没有点
名的东西——而读者看不出其中任何一件发生过。这不是一个不错的性质，这是*那个*性质：它让合并变成可以在一台
正在响应查询的存储上运行的操作，也正是这一步的游走花六十四次操作想打破的东西。

属性测试的另一半，是让它有用的那一半：游走发现不一致时，必须说清*哪里*不一致，并且给出一段短到能读的
序列。一个种子加一份六十四次操作的记录，只是传闻；同一个失败，把没人需要的操作删掉之后，才是一个用例。
这就是**收缩**，也是"被静音的红色构建"和"被修好的红色构建"之间的差别。

## 任务

游走需要的东西都在树里。两个文件归你，装置不归你——这个划分是故意的，因为生成器和模型才是这堂课，而一个
会打印记录的游走只是一个装置。

**`src/engine/rng.rs`——归你。** 一个带种子的生成器，六个方法，不加新依赖：`rand` 是个好 crate，但在这里
是错的那个，因为它自己的文档拒绝承诺游走最需要的东西——同一个种子在每台机器上、永远，都是同一串数字。文
件里给的是状态、三次移位，以及乘法用的那个常数；文档注释里定的是围绕它们的所有规则，而每一条规则都是一个
用例所钉住的决定：

- **零种子是合法种子。** 零是 xorshift 唯一逃不出的状态——它的三次移位都还是零——而任何人往 `KILN_SIM_SEED`
  里敲的第一个值就是 `0`。在修正看得见的地方把它从零上拨开一次，而不是拒绝它；
- **`below(0)` 答 `0`。** 从空字母表里抽，只有一个合理的答案，而一个在这里 panic 的生成器会在别人的进程里
  失败——而且这不花任何代价：一个没有字母的字母表不发出任何字母，所以流也不动；
- **`between` 包含两端。** 一只时钟、一段时长、一个时间戳，都是"在这个 span 里的某处，而它的哪一端都是合法
  时刻"；半开区间会让每个 span 的最后一毫秒都取不到，而这恰恰是游走要在别的代码里找的那种盲区——一个什么
  都没指的 span 直接答边界，两端都不抽，这是 `below(0)` 的规则往上挪一层；
- **`chance(150)` 就是 `always`。** 写成大于一百的整数的概率，不是一个要校验的设置项，而是一句斩钉截铁的
  "是"；
- **`pick` 在空字母表上 panic。** 它没有值可答，而凭空造一个，会让游走执行一个没人写过的操作。

规格钉住一个**黄金向量**：这个生成器在种子 `1` 下答出的前四个数。这不是口味测试。游走的全部发现就是这串
序列，所以改动这段算术不是重构，而是改动项目里的每一个种子——一条写着"这四个数"的用例会大声失败，而不是
悄悄挪走某人的 bug 报告。

**`tests/support/model.rs`——归你，而且它本来就是故意笨的。** 一张记下存储被告知过的所有记录的表，外加
一个数：下界。七个方法，仅有的两个有内容的决定是：读按*那个顺序*返回被追加过的记录（一张表，不是一个
map——不管这些记录是关于什么的，读者拿到的都是一张表）；过期只移动下界，不删任何东西，因为存储也不删：一个横跨截
止点的段把它的旧记录留在磁盘上，只是不再用它们作答。

它住在 `tests/support/` 而不是 `src/`，因为它对存储的设想属于*测试*，而不属于存储本身：模型是一份契约的第
二个实现，写出来就是为了让测试去跟它不一致，把它放进引擎里，就是把"读返回什么"的第二个答案塞进被评判的
那个东西内部。这一步的规格把这个文件当文本读，只要它点名段、快照、清单或合并就失败——一个知道存储
怎么保存记录的模型会是第二个存储，而一趟比较这两者的游走，证明不了第一个的任何东西。

**装置不归你写，归你读。** `tests/support/walk.rs` 和 `tests/sim_model.rs` 是完整送来的，它们是两个要慢慢
读的文件：

- **一趟游走就是一个种子。** 一个数进去，一串操作出来——`Append`、`Flush`、`Merge`、`Expire`、`Reopen`、
  `Query`——用*你的*生成器抽出来。抽中哪个操作、哪条序列、多少条记录，时钟往哪个方向走，问哪个问题，全都
  只从那个种子里来：没有时钟、没有路径、没有地址、没有哈希种子；
- **时钟大约有四分之一的时间在倒退**，而且从不离开一个四小时的窗口，所以一趟游走的整段历史，就是一趟保留
  或一次查询能点名的一段模拟时间 span；
- **比较发生在每一次操作之后**，不是最后。只比较最终状态的游走，只会报告"六十四次操作，答案不一样"；每做
  一次就比较，才能点名改变了答案的那次操作，这就是"一次失败的运行"和"一件有人能着手处理的事"之间的差别；
- **记录里是计数、名字和摘要**，绝不是路径、地址、墙上时钟或未做掩码的浮点数。`slow:sim@3` 在同一个种子的
  两次运行之间比较的就是这个，所以它不是一个记日志的顺手之处——它是契约；
- **失败先收缩再上报**，所以日志里的那串序列是人能读的。

**"一致"是什么意思。** 每一次操作之后，

- 读者能看到的记录——`snapshot().records()`，清单点名的那些段，去掉所有低于 epoch 下界的东西——与
  `answerable()` 逐条相等，每个字段都比较（值按*比特*比，所以 `-0.0` 和 `NaN` 就是它们本来的值）；
- 存储的下界是 `floor()`，也就是一趟保留写进清单的那个数；
- 而在一次 `Query` 之后，桶就是那些桶。问题被故意问两遍：一遍走 `lakelet/4.11-query-engine`——从清单
  里画出的计划、它留下的段、每段各读一次——另一遍由 `lakelet/4.10-downsampling` 在模型的记录上算。两边用
  同一趟窗口处理是故意的：网格、不完整的桶和五个聚合是那一步及其规格的主题，一趟重新推导它们的游走会是它
  们的第二个实现。这趟游走评判的是存储的**记账**：一次查询打开了哪些段、一次合并替换了什么、一次重新打开
  重放了什么，以及下界在哪儿。

**最锋利的那条边，也是唯一一条值得读两遍的规则。** 模型被告知一批记录的时刻，是**刷写把它关进一个段**的时候，
不是追加被接受的时候。日志里有、段里没有的记录不算答案：这个构建的读者拿到的是段和一份清单，
而 `lakelet/4.11-query-engine` 读的正是这些。所以一条被接受但还没刷写的记录是不可见的，而 `Append` 之后
的比较，主张的是"接受一条记录不改变任何可读的东西"。在追加时就被通知的模型，第一次就失败，
`the store answers 0 record(s) and the model 2`——而错的是模型，存储是对的。

**种子，以及课程拿它判什么。** `slow:sim@3` 按每个种子各跑一遍这套装置（`KILN_SIM_SEED=1`、`7` 和
`20260101`），并对这些运行判三件事：每一趟都是绿的；标着 `replay` 的种子把记录打印两遍、逐字节相同；至少
两个种子打印*不同*的记录——三份完全相同的记录会说明装置从没读过种子，等于同一趟游走被报告了三次。最后这
一条，就是一次"一致"的记录故意不带种子的原因：在"一致"旁边打印一个种子，会让三趟游走因为一个跟游走无关
的理由而不同。失败的运行是例外，那里种子是读者最需要的第一样东西。

**收缩器的契约**，规格对它做断言而不是假设：答案仍然不一致；它的操作就是原来给的那些，顺序不变，只是少了
几个；而且**从里面拿掉任何单个操作，都不能还留下不一致**。刻意是"再没有明显可删的"，而不是"最小的"：最小
的是对每一个子集的搜索，而一个人在 bug 报告里读到的，是每个剩下的操作都承重的那串序列。

## 完成标准

- `cargo test -p lakelet --test spec_model_based`（在 `app/lakelet` 里）——十八个规格用例全过，每个一个
  主张：黄金向量与一个种子的重放（`a_seed_is_a_sequence_and_the_same_seed_is_the_same_sequence`）；一个不
  是常量流的零种子（`a_zero_seed_is_a_seed_and_not_a_constant_stream`）；`below` 落在范围内并覆盖它
  （`below_stays_in_its_range_and_covers_it`）；范围的十分之一拿到十分之一的抽取
  （`every_tenth_of_the_range_gets_its_share_of_the_draws`）；`between` 两端都含在内
  （`between_includes_both_ends`）；`pick` 取值的那个字母表
  （`pick_answers_from_the_list_it_was_given`），以及它对空字母表的 panic
  （`pick_has_nothing_to_answer_for_an_empty_alphabet`）；`chance` 说话算数（`chance_keeps_its_word`）；模型
  跨批次和序列的顺序（`the_model_answers_what_it_was_given_in_the_order_it_heard_it`）；下界向前移动、边界
  是一个答案（`the_floor_moves_forwards_and_what_it_forgot_stops_being_an_answer`）；一趟坏掉的游走收缩到它
  需要的那两个操作（`a_wrong_sequence_shrinks_to_the_operations_it_needs`）；十二次操作的游走在每一次之后
  都一致（`a_short_walk_agrees_after_every_operation`）；一次合并移动 epoch、把每条记录留在原处
  （`a_merge_changes_what_the_store_is_and_not_what_a_reader_sees`）；一个种子重放、两个种子不重放
  （`a_walk_replays_what_it_was_seeded_with`）；一次在一串序列中途重新打开
  （`a_walk_that_reopens_in_the_middle_still_answers_the_same_records`）；一次过期移动下界、答案正好按它忘
  掉的东西收缩（`an_expiry_moves_the_floor_and_the_answers_shrink_with_it`）；一次查询被回答两遍
  （`a_query_is_answered_by_the_engine_and_by_the_model_the_same_way`）；以及那条边界
  （`the_generator_is_engine_code_and_the_model_is_a_tests_idea_of_the_store`）。
- `kiln run lakelet/4.13-model-based-tests`——同一批用例，跑课程的副本。
- `kiln check lakelet/4.13-model-based-tests --slow`——每个 must 闸门都是绿的，包括 `slow:sim@3`（走三个
  种子、重放其中一个）和 `slow:mutants@80`（抽样你的补丁碰到的文件）。
- `kiln run lakelet/4.9-retention` 与 `kiln run lakelet/4.8-compaction`——仍然绿，未变：这一步在存储旁边加
  了生成器、模型和装置，存储里什么都没动。
- 在 `app/lakelet` 里 `KILN_SIM_SEED=7 cargo test -p lakelet --test sim_model -- --nocapture`——读一份记录：
  六十四次操作、每一次对存储的文件做了什么，以及每次之后模型与存储并排的摘要。`KILN_SIM_OPS=400` 走一趟
  更长的。

## 陷阱

1. **删掉下界所忘东西的模型。** 把 `expire` 写成 `accepted.retain(|record| record.ts_millis >= floor)`，看
   起来是更整洁的模型，而且能通过装置里的每一趟游走——因为读也看不见它删掉的东西。它会失败在那个真正算数
   的用例上：`len()` 是存储*持有*的东西，下界忘掉记录，而存储并没有丢掉它们，而 `model.len() == 32` 同时
   `answerable().len() == 20`，正是 `lakelet/4.9-retention` 在比较这一侧的全部内容。
2. **模型自己算出来的下界。** `expire(cutoff)` 把 cutoff 当作给定的——游走交给它的是保留那一趟会写进
  清单的数，也就是 `now - keep` 向*下*取到桶边界。一个再取整一次、或把策略窗口当成自己算出来的模型，会落
   在 `1700019900000`，而存储写的是 `1700020500000`，游走还没报告任何一条记录，就先报告了下界对不上。
3. **把 `chance` 写成 `below(percent) == 0`。** 读起来像同一件事，其实不是：这样 `chance(0)` 会触发，因为
   `below(0)` 是 `0`，而 `0 == 0`。抓住它的用例在 `percent = 0` 下抽一千次，期待什么也不发生；游走只能把
   它当成一只倒退频率远高于四分之一的时钟来抓。
4. **半开的 `between`。** `low + below(high - low)` 是自然的第一稿，而它永远抽不到 span 的最后一个瞬间——
   一个窗口结束在上面的那一毫秒，那个恰好等于下界的时间戳。用例要求一万次抽取覆盖 `3..=8` 的每一个瞬间；
   游走不会注意到，因为一只从不落在边界上的时钟照样能走。
5. **一个不是被钉住版本的生成器。** 任何"看起来等价"的算术——换一个乘数、把移位换个顺序、让 `below` 去查
   高位——都是另一个项目：黄金向量失败，随之每一份重放、每一份 bug 报告、每一趟游走的每一个种子都失败。改
   常数之前，先读用例里的那四个数。
6. **`pick` 给空字母表凭空造一个元素。** 在空切片上 `items[below(len)]` 会带着索引消息 panic，正是用例要
   的；而一个答 `items.first().unwrap_or(&default)` 的版本，会悄悄执行一个没人写过的操作，游走会把它报告
   成一个与"别的什么东西的模型"一致的存储。

## 延伸阅读

- `tests/support/walk.rs`——装置：六个操作、会倒退的时钟、每一行都经由它比较的摘要，以及收缩循环。先读
  `shrink` 那三句话的契约，再读函数体。
- `src/engine/compaction/snapshot.rs`——`records()` 与 `records_of()`：下界过滤、对着清单的计数检查，
  以及模型拿来比较的那一次调用。
- `src/engine/retention/mod.rs`——`Policy::cutoff`（向*下*取到桶边界）和 `Plan::is_empty`（为什么一趟什么都
  没删的保留不写清单，因此也不移动下界）。
- Hypothesis 的 `RuleBasedStateMachine`——正是这一步的 Python 形态，以及 `@rule` / `@invariant` 的划分，
  它决定了每一步之后检查什么。
- Quviq 的 `eqc_statem`——最早的状态机属性工具，以及让它值得一用的那个收缩。
- Vigna 的 *Further scramblings of Marsaglia's xorshift generators*——三次移位和那个星号从哪来，以及乘数
  买到了什么。
- `cargo-mutants`——`slow:mutants@80` 跑的是什么，以及为什么这里它抽样的文件是生成器。
