# 浮点、单调时间与时区：查询会算错的那几个数

## 为什么

`lakelet/4.11-query-engine` 留给你一个会解析、会剪枝、会规划、也会拒绝的查询引擎——而它答出的
每一个数，都是在一个窗口上 `+=` 出来的。这正是没人测的部分，因为大家写的那个测试是能通过的那个：
1、2、3、4 四个样本，不管你怎么折腾，加起来都是 10。

一个存储不是四个样本。一个窗口是十万个，累加器会到达一个量级，那里再加一个样本也落进总数的最后
一位之下，而每一次加法都在舍入——悄无声息，在小值上，方向取决于段被读进来的顺序。同样的查询对
同样的记录，在一次合并之后答得不一样。它的均值有点错，而建在它上面的容量规划也跟着有点错，错得
没人看得见。

而一天不是二十四小时。这个存储算过的每一个桶都坐在从 Unix 纪元数起的绝对网格上，这对秒、分、
小时都是对的——一小时在哪里都是一小时。**一天**不是：在 `Europe/Berlin`，一年里有一天是 23 小时
的样本，有一天是 25 小时，而一个数 86 400 个一秒步长的看板，会把两个不同的日子标成同一个日期，
还漏掉另一个的一小时。

## 任务

你需要的一切都在 `src/engine/query/agg.rs` 里，脚手架交付了它的声明和规则，没有函数体。那里有
四个决定，每一个都是决定，而不是语法。

**求和不是 `+`。** 写 `Sum`：一个补偿式累加器，把每次加法被舍入丢掉的那部分留着，最后加回去——
Kahan 的规则，Neumaier 的形式。把计数也留在里面，用 `u64`，因为均值是一个和除以一个计数，而一个
用 `f64` 携带的计数，就是一个一亿条记录的存储会发现的那个 bug。`naive` 故意留在模块里：那是所有
人都会写的实现，这一步的用例调用它，是为了展示它的代价，因为"补偿是必要的"这个主张，不跑另一条路
就提不出来。

**边界是代码里的一个数。** `BOUND` 是一个补偿求和允许的误差，相对于它加过的那些量值之和——是一个
尺度，不是一个指纹：一个相互抵消的求和，答案小、预算大，而一个对着答案声明的边界，会把它叫作精确。
`error_bound` 就是那条承诺，化成一个用例能要的数字，`BOUND * Σ|v|`，而**量值之和也走 `Sum`**：
用一个边界所约束的算术去算这个边界，会丢掉同样的小项，承诺得比自己想说的少。`agrees` 是给量值用的
比较；和 `lakelet/4.10-downsampling` 的 `agree` 不同，它底下没有一作为下限，而 `NaN` 和什么都
不一致——一个坏掉的聚合产出的正是这个。

**答案不许依赖存储读它的顺序。** 段从最老的开始读，合并会重写它们，崩溃会改变 epoch，而存储的
数据里满是倒退过的时钟。于是 `lakelet/4.10-downsampling` 的窗口遍历通过 `Sum` 累加，而不是
`+=`，一条记录按它的时间戳进桶，绝不按它在这次读取里排到的位置。那是 `downsample.rs` 里的一处改动，而且
不是可选的：它是"答案是记录的函数"和"答案是读的函数"之间的差别。

**一天不是二十四小时。** `Zone` 是一个名字，加上**这个构建交付的**偏移转换：`UTC`、
`Europe/Berlin` 连同它两年的转换，以及一个固定的 `±HH:MM` 偏移——后者是算术，不是表，因为固定
偏移永远不会过期，而表总是会。

- `Zone::parse` 回答 `Zone::SHIPPED` 里的名字，以及每个字段恰好两位的 `±HH:MM` 偏移，别的都
  作为**调用方错误**（`Refusal::Syntax`，分类 `2`）拒绝，而不是默认成 UTC：一个悄悄答了 UTC 的
  `--zone Europe/Berlinn`，是一个差了一整天、没人解释得清的看板。
- `Zone::offset_at` 在**表外**回答 `None`，而不是猜。这个构建知道 2024 和 2025；它不知道
  2019，为它编一个 `+01:00`，就是对一个没有数据的问题给出一个自信的答案。`Zone::covers` 是
  那段 span，而拒绝会点名它。
- `Zone::local_day` 给出某个瞬间所在的那个*本地*日的半开 span——时区拨快的那天 23 小时，拨慢的那天
  25 小时。解析本地午夜时，要用**那个午夜**生效的偏移；你自己那个瞬间的偏移，在时区切换的那天
  是错的。

**命令行。** `--zone <NAME|±HH:MM>`（默认 `UTC`）是 `--store` 旁边的旗标，而不是查询文本的
一部分，因为 `GROUP BY time(1d)` 说的是桶有多宽，不是它从哪个午夜开始。规则只有一个窗口宽，而且
故意很窄：

- 窗口**恰好是一天**时，桶是那个时区的**本地日**，于是它们的边界会动，计数也会变——拨快的那天
  装着 23 小时的样本，而网格装 24 小时，范围的头尾两天是部分的；
- 窗口是**任何别的宽度**时，时区什么都不改变，因为一小时在哪里都是一小时，而一条会挪动五分钟桶的
  规则，就是 `lakelet/4.9-retention` 用它计数、`lakelet/4.14-index-pruning` 将要对着它剪枝的
  那个网格旁边的第二个网格；
- 点名的表覆盖不到的范围，作为**调用方错误**拒绝，并点名覆盖的那段 span，而不是近似地回答。

`UTC` 是默认，而且在哪里都不是特例：UTC 的本地日*就是*绝对网格，所以一个说 `--zone UTC` 的
调用方和一个什么都不说的人，拿到同样的字节。这是你接线时要守住的不变量。

**课程给你什么，什么归你。**

- `src/engine/query/agg.rs`——**归你**。脚手架写了声明、文档注释和 `todo!()` 的函数体；每个
  函数体都归你，访问器也算。签名是接口，规则才是活。
- `src/engine/query/mod.rs`——模块树，`pub mod agg;` 已经加在它的标记块里。
- `src/engine/query/downsample.rs`——**归你**，而且它需要两样东西：它的窗口 `Tally` 通过
  `Sum` 而不是 `+=` 累加；以及在窗口是一天时，能按某个时区的本地日回答问题。`Answer`、
  `Bucket` 和 `downsample` 自己的签名都不变——`lakelet/4.10-downsampling` 的十七个用例仍然是
  你守着的承诺。
- `src/engine/query/exec.rs` 和 `src/cli/mod.rs`——**归你**。执行器需要一个接时区的入口
  （`execute` 的签名保持不变：裸的 `execute` 就是"没有时区"的意思），而工具需要在**两种**输入
  形式里都有这个旗标，因为第二种输入形式不许对同一个问题答得不一样。
- `src/cli/mod.rs` 的 `USAGE`——**归你，而且脚手架替你做不了这件事。** `USAGE` 是一个
  `const &str`，所以脚手架（它只能创建文件，或者在标记块里插行）改不了它；用法文本里 `--zone`
  那一半是你的改动。规格用 `USAGE.contains("--zone")` 钉住它，而 `--help` 直接和那个常量比，
  所以一个不点名这个旗标的用法文本，失败的是用例，不是读者。
- `EXPLAIN` **不加键**。`lakelet/4.11-query-engine` 的规格数着计划的那些行，第十三个会破坏一个
  你已经通过的步。时区可见的地方是它该在的地方：桶的边界和桶的计数。

**你最先看到的东西。** `cargo test -p lakelet --test spec_aggregation` 先构建，然后十七个
用例里失败十六个——每个失败都是一个 `todo!()` 的 `not yet implemented` panic，外加用法文本，
它还没点名这个旗标。这是正常的形状。

## 完成标准

- `cargo test -p lakelet --test spec_aggregation`（在 `app/lakelet` 里）——十七个规格用例
  通过，每条用例对应一条主张：补偿求和留住一个累计和会丢掉的项

  （`the_same_values_shuffled_are_the_same_answer`）；整数计数，以及什么都不是的均值
  （`an_empty_accumulator_has_no_mean_and_a_count_is_an_integer`）；`NaN` 和无穷的文档化行为
  （`a_value_that_is_not_a_number_is_not_invented`）；窗口遍历答出累加器答的东西
  （`a_window_answer_is_the_accumulators_answer`）；一个不在意存储读取顺序的窗口
  （`a_window_does_not_care_what_order_the_store_reads_in`）；十万条记录，读了多少就数了多少

  名字和固定偏移（`a_zone_is_a_name_this_build_ships_or_a_fixed_offset`）；各种拒绝，以及每个
  拒绝指向的那个字节（`a_name_nobody_shipped_is_the_callers_class`）；表里的两次转换

- 在 `app/lakelet` 里跑 `cargo run -q --bin lakeletq -- query --store <dir> --from <ms> --to
  <ms> --window 1d --agg count --zone Europe/Berlin`，旁边再跑一次不带 `--zone` 的同一个

## 陷阱

1. **把和吞掉的修正。** 一个无条件计算 `lost` 的 Neumaier 步骤，对一个含无穷的工作负载写出
   `inf - inf`，并为一个定义得完完整整的和答出 `NaN`：`1.0 + inf` 是 `inf`，而
   `running(&[1.0, f64::INFINITY])` 必须是 `inf`。当加法根本没有舍入——而是撞上了无穷、
   `NaN` 或溢出，这些不是 `f64` 靠舍入能处理的量——就跳过修正。
2. **用一个边界所约束的算术去算这个边界。** 把 `error_bound` 写成对量值的 `BOUND * naive(...)`，
   会以和求和一模一样的方式丢掉小项，并承诺一个比本意低几个数量级的边界。抓住它的是这个用例：
   对一个量值里装着十万个一的工作负载，`error_bound(&values) > BOUND * 1e16`。
3. **用完调用方那个瞬间的偏移去找本地日。** 在 `Europe/Berlin` 的 2024-10-27，本地 12:00 的
   瞬间在 `+02:00`，那一天开始时的本地午夜也在 `+02:00`——但本地 23:30 的瞬间在 `+01:00`，而
   同一个午夜*仍然*在 `+02:00`。`local_day` 是拿**那个午夜**生效的偏移去解析午夜的，而抓住
   单趟解法的那条用例，断言转换两侧的 span：`(1_729_980_000_000, 1_730_070_000_000)`，
   二十五小时。
4. **`--zone` 只接进了一种输入形式。** 两种形式是同一个问题的两种问法，而这个旗标正是它们可能
   走散的地方：`SELECT count(value) FROM cpu WHERE ts BETWEEN a AND b GROUP BY time(1d)` 带
   `--zone Europe/Berlin`，和同样范围、同样窗口的旗标形式，必须打印同样的字节。让 `--zone`
   留在 `--store` 旁边——两种形式里都是旗标——并让 `--from`/`--to`/`--window`/`--agg`/`--series`
   在 `--sql` 旁边被拒绝。
5. **回答表覆盖不到的范围。** 这个构建里的 `Europe/Berlin` 是 2024 和 2025。2023 的范围不是
   一个桶更少的答案，也不是一个要调用方自己注意到的 `None`：它是一次拒绝，分类 `2`，用一句话
   点名表覆盖的 span。一旦你让某一趟看见一个 span 外的记录，情况也一样——拒绝发生在那一趟之前，
   不是在里面。
6. **用 `f64` 携带计数。** `Bucket::count` 和 `Sum::count` 是 `u64`，而*均值*是唯一允许被一次
   除法舍入的东西。十万个 `0..99_999` 上的 `sum.mean()` 恰好是 `49_999.5`；一个经过浮点的
   计数，会答出一个看起来合理的东西。

## 延伸阅读

- `src/engine/query/downsample.rs`——`TOLERANCE` 和 `agree`：这一步自己的容差，以及一个
  *声明出来的*边界、而不是一个浮点 epsilon 背后的推理。
- `src/engine/retention/partition.rs`——绝对网格由之构成的 `floor(ts / width) * width` 算术，
  以及一个本地日必须匹配的半开 `[start, end)`。
- Kahan 求和和 Neumaier 的变体——补偿项，以及两个分支为什么挑较大的那个加数。
- CPython `math` 模块里的 `math.fsum`——恰好舍入的求和的一个参考实现，以及它自己写在文档里的
  限制。
- IANA 的时区数据库和 `zdump -v Europe/Berlin`——那个会过期的文件，以及那条打印出这张表
  转录自哪些转换的命令。
- `cargo-mutants`——`slow:mutants@80` 跑的东西，以及为什么一个只检查顺利路径的用例，会留下
  一个活着的 mutant。
