# 分帧就是接口：长度前缀加校验和的摄取协议

## 回顾

- `repo/workspace-layout@apply` — `mailer/1.1`：一个项目，一个 `[workspace]`，`cargo fmt` 和
  `cargo clippy` 在别的一切之前就接好了。
- `cfg/layered-config@design` — `jobq/3.4`：默认值在最底下的文件里，环境盖在它上面，旗标放在最后，再由
  一个函数把这四者解成程序其余部分读到的一个值。
- `obs/structured-logs@design` — `jobq/3.17`：机器读得懂、人也读得懂的行，因为凌晨三点总有人会去
  `grep` 它们。
- `time/clock-injection@apply` — `jobq/3.8`：时间是外面送进来的一个值，不是函数中间的一句
  `SystemTime::now()`。
- `cli/contract@apply` — `jobq/3.15`：二进制用一个退出码和一句话回答它的用户，并且拒绝它看不懂的
  东西。

## 变化

做到第四个项目，你已经知道一个骨架长什么样：一个库、一个二进制、一份配置、一个只装一次的订阅器，外加
一个夹具，它启动进程，等它说自己准备好了。这一步把这一整套重新立一遍——新的部分是，当一个**流**来自
机器而不是浏览器时，它是什么样子。

前三个 track 里，每个 `Bytes` 类型的 body 送来时都已经分好帧了：`axum` 递给你一个 `Json<T>`，边界是
别人处理的。这里边界由你写。一条 TCP 连接递给你的是字节，切在哪儿都行：一帧可以分两截到达，两帧可以
挤在一截里，对端可以只发半帧就走人，也可以在长度上撒谎。这一页上的协议一共四个字段，而四个字段每一个
都是因为上面某条事实才存在：

- 一个**长度**，让读者在拿到任何载荷之前就知道还该再读多少；
- 一个**版本**，让来自别的构建版本的帧在它的载荷被缓冲*之前*就被拒绝；
- 一个**校验和**，让被弄坏的载荷变成一次拒绝，而不是存储里的一个坏数字；
- 一个硬性**上限**，让对端决定不了这个进程占多少内存——四 GB 的长度，在承载它的那四个字节里就被拒绝，
  而不是等分配完了再说。

它背后的存储目前故意很笨：一个只追加的文件，每个被接受的载荷一条带长度前缀的记录。这不是你最终要定下
的设计——`4.3` 决定刷盘有多硬，`4.4` 给每条记录自己的校验和，好让撕裂的尾部可以被认出来，`4.5` 成批
写入，`4.7` 用列式段取代这些文件——但它让*这一步*的问题变得可回答：守护进程存下的，是不是客户端发来
的全部，而且只存一次？

守护进程这一侧的工作是解码器外面那个循环，有一条规则值得先写下来再动手：**一次拒绝结束的是那条连接，
不是进程**。在一串不是帧的字节之后，后面的任何东西都不能指望从一个边界开始，所以记下这一帧、写下原因、
丢掉这个客户端——然后接着服务。

## 任务

- 在 `src/protocol/frame.rs` 里实现帧编解码：`Frame::encode` 和 `frame::decode`，回答
  `Decoded::Frame(frame, consumed)`、`Decoded::Incomplete { needed }` 或
  `Decoded::Invalid { reason }`——再写 `frame::read_all`，它走一遍缓冲区，答出里面装着哪些帧，以及
  它们一共用了多少字节。
- 在 `src/protocol/batch.rs` 里实现载荷编解码：一个计数，然后那么多条记录；有一条出错时，拒绝要说清
  错的是第几条。
- 在 `src/engine/spool.rs` 里实现写入路径：`Spool::open` 建出存储目录，`Spool::append` 写一条带长度
  前缀的记录，并且只在它能被读回来之后才作答，`Spool::records` 按顺序把它们读回来——或者拒绝这个文件，
  而不是猜。
- 在 `src/service/ingest.rs` 里实现 accept 循环：接受、读进一个会留下装不下的部分的缓冲区、解码、存下、
  计数；用一个 `frame rejected` 行拒绝坏帧；每条连接记一行
  `connection closed accepted=… rejected=… bytes=…`，关闭时记 `stopped accepting`；还要回答端口探针，
  而不是每次健康检查都多出一行。
- 写 `docs/protocol.md`：布局、解码器给出的三种回答，以及对端能对我们做什么。它是这一步的一部分，不是
  这一步的总结——没人读得懂的线上格式，是一个带截止时间的线上格式。

## 完成标准

- `kiln run lakelet/4.1-ingest-protocol` — 十二个规格用例通过。
- `kiln check lakelet/4.1-ingest-protocol` — 每个 must 闸门都是绿的，包括 `links`（页面里的链接都能
  解析）和 `exit-code`（两个二进制都拒绝未知参数，并点出它的名字）。
- 在 `app/lakelet` 里跑 `cargo test -p lakelet`——上面那套测试，加上你自己加的东西。
- 守护进程要能回答一个真实客户端：`lakelet-load --target $(lakeletd --listen-addr 127.0.0.1:0
  --store-dir /tmp/lakelet-demo --check-config >/dev/null; echo …)` 是一道 shell 练习，但一个跑在
  `lakeletd` 旁边的 `lakelet-load` 必须以 `sent=<n> batches=<n>` 收尾，并在 `ingest.log` 里留下
  同样多条记录。

## 陷阱

- **`read` 不是消息边界。** 每次 read 解一次码、把缓冲区剩下的丢掉，客户端连着写两帧时它就丢帧，而在
  一个很快的本地套接字上，这件事一直看不见，直到载荷变大的那一天。把尾巴留下。
- **拿一个还没检查过的长度去分配。** 用线上读来的 `length` 去 `Vec::with_capacity(length)`，是一个
  远程的内存耗尽：拒绝必须发生在预留之前，上限之所以在长度到达的那四个字节里就检查，原因就在这里。
- **等整帧到齐再检查版本。** 如果来自别的版本的帧先被缓冲、后来才被拒绝，那个版本字节就白买了。把检查
  钉在第五个字节上——规格只发五个字节，就指望一次拒绝。
- **把半帧当成错误。** 在帧中间断开的客户端是正常流量（进程被杀、网络丢了）；它不留下记录，也不能被
  记成故障，更不能结束守护进程。
- **校验和盖住了头部。** 如果校验和把长度也盖进去，一个被弄坏的长度就由算术来发现，而不是由为它存在的
  版本和上限来发现——读者拿到的那句话还会指错字段。
- **在规格永远跑不到的代码路径里留下 `todo!()`。** `no-todo` 是一道闸门：这一步带来的每个桩都得实现，
  不只是有测试盯着的那些。

## 延伸阅读

- 在后面的 track 里重读 `docs/protocol.md`，试着只靠它写一个客户端。每一处你得靠猜的地方，都是这一页
  写错的地方。
- `lakelet/4.2-parser-fuzz` 用带种子的变异专门攻击这个解码器，它的语料库就是弄坏过它的那些输入。在
  语料库还不存在时先把变异器写出来，才是正常的顺序。
- 生产环境里这种形状的协议：PostgreSQL 的线协议（一个长度、一个类型字节，然后是 body）、Kafka 的记录
  批次（一个长度前缀、每批一个 CRC）、以及 Redis 的 RESP（一个类型字节，然后一个长度）。三个都出于
  同样的理由，选了同样的四个字段。
