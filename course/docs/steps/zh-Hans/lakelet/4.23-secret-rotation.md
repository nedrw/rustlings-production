# 轮换不断档：两把密钥同时有效，其中一把优先

## 回顾

- `sec/secrets-management@apply — mailer/1.4`：密钥搬出仓库，以及一个部署读它们所经过的四层——
  默认值、文件、环境、命令行。这一步保留的是那条规则：密钥是某人故意放在某处的值；它加深的是密钥
  的*集合*会在服务运行时变化：那里问的是「这个值从哪来」，这里问的是「这些值里哪一把在签名，而不
  签名的那把什么时候可以离开」。
- `sec/token-lifetime@apply — mailer/1.12`：一个 token 被签发、被验证、过期、只用一次——而*一个
  挺过了其中任何一项的 token 从来就不是 token*。那一步的窗口写进一行、由数据库比较；这里的窗口
  写进 token、由守护进程比较，而 token 之所以存在，靠的正是那一步故意不需要的东西：一把密钥。
  这一步加上的是那一步自己那句话所蕴含的后果——一个活一小时的 token，意味着它背后那把密钥必须
  继续存在一小时，而这正是让轮换成为一个算术问题、而不是一次编辑的东西。
- `sec/hmac-signing@apply — relay/2.11`：签你发出去的确切字节，把时间戳和一个 id 放进被签的材料
  里，用 `subtle` 而不是 `==` 比较 tag，因为一个在第一个错字节就停下的比较，会告诉另一头它的猜测
  对了多少。那一步把 `subtle` 和 `hmac` 加进了 relay 树；这一个把 `subtle` 加进*这棵*树，同样的
  理由用同样的两个 crate，只有一个差别，而它正是这里的全部要点：tag 据以计算的密钥会变，而旧的
  那把必须继续验证一段时间。

## 变化

这个项目的其他每一步，决定的都是*字节*会怎样：一帧是什么、一批怎么写入、一次查询怎么回答、一份
副本怎么恢复。这一步决定谁可以发送任何字节——而其中有意思的那一半不是检查，而是检查所用的密钥必须
更换的那一天，因为一个看起来安全了一年的部署，正是在那里被一条命令弄坏：删掉旧密钥，每个还拿着它
签的 token 的客户端，都会在它的下一次连接时被拒绝，在半路上，没有任何窗口让它们换钥。

所以这一步的形状是一个**环**，而不是一把密钥，四个决定由此而来：

- **环是一个文件目录，而目录就是开关。** 存储下面没有 `keys` 目录，就是认证关着；一个里面没有
  密钥的目录，是一次拒绝。这不是为了测试方便的让步——它是对一个没有密钥的部署*是什么*的诚实陈述，
  也是让早先几步交出的每一套装置（`lakelet/4.6-ingest-backpressure` 的过载场景、
  `lakelet/4.17-soak` 的长跑）都不改一行继续工作的原因：两者都连接一个没有环的存储并发送批次；
- **签名的密钥是最新的那一把，而两把都开着的时候两者都验证。** 规则只有一句——`not_before` 最新的
  那把开着的密钥负责签名——而它让轮换成为*对文件的一次编辑*，而不是守护进程里的一个时刻：没有状态
  要翻，没有重启要安排，也没有任何可以做了一半的东西；
- **一把密钥只有在更新的某把接管签名之后、客户端可能还持有的最长生命周期过去，才可以离开。** 一个
  用大多数客户端所要求的生命周期搭出来的界，对每个客户端都成立，唯独那个要求了最长 token 的客户端
  不成立——而它恰恰就是会被晾在外面的那个。所以模块答一个数字（`earliest_safe_retirement`），
  `lakeletq rotate --retire` 拒绝低于它，而守护进程会拒绝那些被一次手改的退休晾在外面的 token。提前
  退休是拒绝，不是警告；
- **环是按连接读的，里面没有任何东西读时钟。** 按连接读，正是让轮换在一个*运行中的*守护进程上
  生效的东西；把每个时刻都当成参数，正是让「这个环在这个时刻做什么」成为一个测试能用数字回答的
  问题的东西。前者的代价是每个客户端一次目录读和几把文件读，而页面会把这一点说出来，而不是假装
  它是免费的。

比较是这一步的代码看起来像 `relay/2.11` 的唯一地方：tag 是对经过网络的确切字节算的 HMAC-SHA-256，
用 `subtle` 比较，因为对 tag 用 `==` 会泄漏一个猜测在哪里分叉。

## 任务

脚手架造四个文件，加两行。`src/service/keys.rs` 是环——密钥词汇、token、五个带类型的拒绝（外加
「这根本不是 token」）、窗口算术——每个函数体都答 `todo!()`。`src/cli/rotate.rs` 是操作者的命令，
有一个函数体答 `todo!()`。`tests/sim_rotation.rs` 是**完整的**，在两者写出来之前会失败。
`docs/rotation.md` 是一个带页面那些标题的 `[TODO](TODO)` 桩。

**`src/service/keys.rs` 就是这一步。** 它不读时钟、不读环境，下面每一条都是关于这意味着什么的决定：

- 一个密钥文件是 `name=value` 行，名字是 `<id>.key`，密钥开着时带 `id`、`secret`（十六进制，
  大小写都行）、`not_before_millis`，而 `not_after_millis` 是*缺席的*。读取器是严格的，每次拒绝
  都点名文件和行，因为这个文件是凌晨三点被人手改的；
- `preferred` 是*文件*的性质，不是时钟的：`not_before` 最新的那把开着的密钥，并列时按 id 决出，
  于是读同一个目录的两台机器会一致。`issue` 是时钟进来的地方，它拒绝用一把窗口还没开的密钥签名，
  而不是造出一个它自己的读取器会拒绝的 token；
- `verify` 是一个页面和日志都能据以行动的带类型答案，按读者会问的顺序检查：这是我有的密钥吗、
  tag 是*这把*密钥在*这些*字节上的吗、密钥退休了吗、token 自己的窗口还开着吗。先查退休再查过期是
  故意的：密钥没了的客户端必须换钥，而那正是操作者最先需要的事实；
- token 是 `lakelet/4.1-ingest-protocol` 帧里的一个载荷——**`src/protocol` 里什么都不变**——而
  tag 覆盖它前面的那些字节，长度前缀和全部。签你发出去的东西；
- 而 `earliest_safe_retirement` 是整个这一步为之存在的那个数字。环不记录一把密钥*什么时候*到来，
  只有每个文件声明的 `not_before`，所以一把密钥可能签过名的最后时刻，是比它更新的那些密钥里最新的
  `not_before`，而它的 token 活到那个时刻加上 `Window::MAX_TOKEN_LIFETIME_MILLIS`。对一把还没有
  任何密钥从它手里接管签名的密钥来说，`None` 是诚实的答案：它还可能签，所以从环上知道不了它的
  token 全部消失之后的那个时刻。

**`src/cli/rotate.rs`** 是 `lakelet/4.10-downsampling` 立下、`lakelet/4.19-backup-restore` 又站过
一遍的同一份契约，落在三个操作上：`--add --id <ID> --secret <HEX> [--from <MILLIS>]` 写一个密钥
文件（密钥是操作者的——这个构建不生成密钥，而会生成它的东西是 `openssl rand -hex 32`，不是一个
带种子的生成器），`--retire <ID> [--at <MILLIS>]` 写密钥的终点，并拒绝任何低于安全时刻的东西，
`--list` 按从旧到新答出环，带每把密钥的窗口、它签不签名，以及它可以离开的时刻。`src/cli/mod.rs`
里的分发那一支、`USAGE` 行和类别映射归你，和 `lakelet/4.19-backup-restore` 为 `backup` 所做的
一模一样。

**守护进程那一半是 `src/service/ingest.rs` 里的三处编辑**，而它们的形状就是那节课：**按连接**读环
（正是这一点让轮换在一个运行中的守护进程上生效），环开着时把**第一个载荷当作 token**，并且在其他
拒绝被计数的地方**数一次拒绝**，好让一个从没进来的客户端出现在部署会读的数字里。那个循环里别的一切
都是 `lakelet/4.6-ingest-backpressure` 的，不能动。

**`docs/rotation.md` 是操作者的页面**，照着运行写：按顺序的流程、`--list` 打印出来的环、窗口的
算术、一段空档要付什么代价、拒绝在哪儿被计数、用一句话讲 `subtle` 比较、空环意味着什么，以及一张
这一步故意**不**做什么的清单——不生成密钥、不碰 HSM、没有吊销清单、不做重加密，环按连接读，而不是
靠一个 watcher。

## 完成标准

- `cargo test -p lakelet --test spec_rotation`（在 `app/lakelet` 里）——十六个用例通过，每个一条
  主张：空环就是认证关着，而一批就是一个首载荷
  （`an_empty_ring_is_authentication_off_and_a_batch_is_a_first_payload`）；只有一把密钥的环接受
  那把密钥签的 token，它的批次也到达
  （`a_ring_with_one_key_accepts_a_token_that_key_signed_and_its_batches_arrive`）；tag 差一个
  字节就被拒绝，而这次拒绝被记在那条连接上
  （`a_token_whose_tag_is_one_byte_different_is_refused_and_counted`）；过期的 token 点名两个
  时刻，而一个还没开的窗口是 `NotYetValid`，两个方向都如此
  （`an_expired_token_names_both_instants_and_a_window_that_has_not_opened_is_not_yet_valid`）；
  一把已退休的密钥签的 token 被拒绝，句子里带着它离开的那个时刻
  （`a_token_signed_by_a_retired_key_is_refused_and_its_sentence_names_the_instant`）；`issue` 用
  优先的那把密钥签名，并列和退休都算在内（`issue_signs_with_the_key_that_is_preferred`）；窗口是
  算术，提前一毫秒的退休被拒绝，并点名那个时刻
  （`the_rotation_window_is_arithmetic_and_a_retirement_one_millisecond_early_is_refused`）；正好
  在安全时刻退休会被接受，并带走最后一个 token
  （`retiring_at_the_safe_instant_is_accepted_and_takes_the_last_token_with_it`）；一次轮换在一个
  运行中的守护进程上生效（`a_rotation_takes_effect_on_a_running_daemon_without_a_restart`）；
  token 经由它的载荷来回一趟，而那个载荷是协议原样的一个帧
  （`a_token_round_trips_through_its_payload_and_that_payload_is_a_frame`）；`--add` 写出一把环
  能加载的密钥，`--list`/`--json` 按顺序打印环
  （`rotate_add_writes_a_key_the_ring_loads_and_list_prints_the_ring_in_order`）；其他每个错误都
  得到 CLI 契约分配给它的类别（`rotate_classes_every_mistake_the_way_the_cli_contract_does`）；
  页面带着命令打印的环（`the_page_carries_the_ring_the_command_prints`）；环不读时钟，而守护进程
  在一个地方读一次（`the_ring_reads_no_clock_and_the_daemon_reads_one_in_one_place`）；这一步之前
  的两个装置仍然发不带 token 的批次
  （`the_two_harnesses_that_came_before_this_step_still_send_batches_with_no_token`）；密钥文件按人
  写它的方式被读，而一个坏掉的文件点名文件
  （`a_key_file_is_read_the_way_a_person_writes_it_and_a_broken_one_names_the_file`）。
- `kiln run lakelet/4.23-secret-rotation`——规格通过；
  `kiln check lakelet/4.23-secret-rotation --slow`——每个 must 闸门都绿，`slow:sim@3` 也在内。
  那道闸门对每个种子（`1`、`7`、`20260101`）跑一次 `tests/sim_rotation.rs`，要求至少两份轨迹不同、
  种子 `1` 逐字节重放，并且没有任何一次运行打印自己的种子。
- **然后弄坏它，这就是那个演练。** 把窗口弄得太短——让 `earliest_safe_retirement` 对每把密钥都答
  「现在」，或者在新的那把到来的一刻就退休旧的——而抓住它的那个用例是算术那个：一次本该被拒绝的
  退休被接受了。放回去，它又绿了。

## 陷阱

1. **在新的密钥到来的一刻退休旧的。** 它读起来像一次轮换，实际上是一刀切：一分钟前连上的客户端，
   拿着已经没了的密钥签的 token，而它们在下次连接时被拒绝——对一个每批都连接的客户端来说，就是
   立刻。`earliest_safe_retirement` 是说该等多久的那个数字，而规格关于它写的那个用例，是一毫秒
   的算术。
2. **用寻常的生命周期搭一个界。** 「我们的 token 活五分钟，所以等五分钟」是一个对每个客户端都
   成立的界，唯独那个要求了这个部署可能签发的最长 token 的客户端不成立——而
   `MAX_TOKEN_LIFETIME_MILLIS` 存在，正是为了让那个数字只声明一次。`issue` 拒绝高于它的生命周期，
   理由相同。
3. **在启动时读一次环。** 轮换于是需要一次重启，也就意味着有一个窗口，守护进程跑着旧密钥、而磁盘
   上的文件说着新密钥——而一个把重启安排在退休之后的操作者，已经把所有人锁在外面了。环按连接读；
   代价是每个客户端一次目录读，页面把它点出来。
4. **一个空环意味着「拒绝一切」。** 一个还没打开认证的部署，就是一个没有密钥的部署，而一个在有人
   写下密钥文件之前拒绝每条连接的守护进程，会弄坏它有的每一套装置和每一个负载生成器——包括早先
   几步交出的那两个。开关是目录，而*另一个*状态（一个里面没有密钥的目录）才是拒绝，因为那是一个
   本来打算做认证的部署。
5. **环读不出来时就敞开。** 一个带着笔误的密钥文件不是「没有密钥」：它是一个认证开着、而守护
   进程解析不了环的部署。把它当成空环，会让所有人进来——越过操作者刚写下的那次退休。连接被拒绝、
   被计数，而警告点名那个文件。
6. **用 `==` 比较 tag。** 它能编译，它每次都正确，而它泄漏一个猜测在哪里分叉，因为比较在第一个
   错字节就停下。`subtle::ConstantTimeEq` 是修好它的那行代码，而规格的形状检查之所以存在，是因为
   一个计时断言会是一个 flaky 测试，而不是一个证明。
7. **签一个规范化的重新编码。** 一个在「用同样的方式」重建出来的字段上算出的 tag，是在它们的第二
   种拼法上算的 tag：它可以工作，直到一侧用不同方式写长度，或者一个字符串换了个大小写。tag 覆盖
   的是经过网络的那些字节，而经过网络的那些字节，就是读取器喂回同一个函数的东西。
8. **把就绪探针计成一个被拒绝的客户端。** 一个对每条什么都没带的连接都记一次拒绝的守护进程，会把
   每次健康检查变成一条警告，而操作者会不再读警告。一条没有流量的连接以 `debug` 记录，和这一步
   之前一模一样。
9. **就地写一次退休。** 守护进程按连接读这个目录，所以一个正在被重写的密钥文件，是一个可能被读
   到半截的文件——而半个密钥文件是一个拒绝加载的环，也就是拒绝客户端。写在旁边，然后改名。
10. **用存储自己的随机性生成密钥。** `lakelet/4.13-model-based-tests` 的生成器是故意带种子的：
    同一个种子在每台机器上都是同样的密钥，这对密钥材料来说恰好是错的。密钥由操作者提供，页面在
    命令旁边就这么说。
