# runbook 就是那套流程，演练就是证明

## 回顾

- `ops/runbook-drill@design — jobq/3.27`：**这一步正好越过一级的那根横档，以及它保住的形状。**
  在那里，页面被解析成*作为数据的阶段*（`src/engine/runbook.rs`），演练走页面点名的那些阶段，而
  读取器报告一个阶段欠着什么，而不是对它 panic——`without(stage, part)` 造出一个变异过的页面，
  缺口就是证据。这一步保留那些决定中的每一个，只换掉走路的是谁：仪器是课程自己的文件，它**对着
  一个活的存储**跑那些命令，所以页面不是和一个描述它的脚本比对，而是和这套流程所服务的部署比对。
- `ops/runbook-drill@apply — mailer/1.22`：**第一次演练和第一个页面。** 一次故障端到端重放，一份
  说有没有丢东西的报告，以及一个能用命令检查的承诺；四页「这个工具做什么」不是 runbook，而一次
  事故会问的五个问题（Symptoms、Signals、Steps、Verification、Escalation）才是这一页回答的。那
  一步*从*演练写出页面，好让两者没法漂开；在这里，漂移是仪器要抓的东西。
- `obs/metrics-slo@design — jobq/3.17`：**每个阶段背后的那个数字。** 一个信号是一条规则——信号、
  阈值、窗口、演练——而一个盯着没人发布的数字的页面，是一个关于想象中部署的页面。这一步加上的是
  另一个方向：SLO 页面点名保护每个数字的那个阶段，而 runbook 点名它的阶段所读的那些数字。
- `ops/backup-restore@apply — lakelet/4.19`、`perf/soak@apply — lakelet/4.17`、
  `obs/cardinality-cost@apply — lakelet/4.18`、`ops/capacity-cost@design — lakelet/4.20`、
  `store/tiering@apply — lakelet/4.21` 和 `sec/secrets-management@design — lakelet/4.23` 作为独立
  的槽位不在 `requires` 里，但这一页的每个阶段都是它们之一：副本和恢复、浸泡的计数器、上限和它的
  台账、模型的常数、sweep 和回来的路，以及轮换窗口。这一步是它们变成一套流程的地方——而树与那页
  显然会写的内容不一致的唯一地方，是 4.21：**没有命令做 sweep 或 hydrate**，所以第 7 阶段就这么
  说，并点名引擎实际有的那条回来的路。

## 变化

二十三步产出了动作，而每一步都交了讲解它自己那个动作的页面：`docs/dr-drill.md` 讲副本和恢复，
`docs/soak.md` 讲一次长跑据以判读的计数器，`docs/cardinality.md` 讲账单，`docs/capacity.md` 讲
模型，`docs/rotation.md` 讲环，`docs/perf.md` 和 `docs/format.md` 讲工作的形状。**没有一个是那套
流程。** 四页*这个工具做什么*不是 runbook，而 `jobq/3.27` 证明了光是说出来还不够：它把页面解析成
阶段，用一个脚本走它们，而那恰好比操作者需要的低了一级，因为一个*描述*流程的脚本，说不出页面上
的命令是不是这个部署拥有的命令。

所以这一步换掉走路的是谁。仪器是 `tests/runbook_harness.rs`，课程自己的文件，它做三件早先任何
页面都做不到的事：

- **它把页面解析成阶段，并且运行那些命令。** `$LAKELET_STORE` 是它用真实写路径造出来的存储，
  `$LAKELET_ADDR` 是它在上面启动的守护进程，而一个阶段，如果它的命令不是这个部署的程序之一，
  那就是一个**发现**——带着阶段编号、部分和一句话——而不是一次崩溃或者一个耸肩。一个点名
  `kubectl rollout restart` 的 runbook，是给另一个部署的 runbook，而这正是把这一点大声说出来的
  仪器；
- **一个阶段的状态是一次检查，不是一句话。** 页面点名仪器的一项检查（`settings-print`、
  `copy-holds-the-store`、`restore-holds-the-records`、`drill-agrees`、`counters-flat`、
  `bill-adds-up`、`cold-span-answered`、`window-respected`），而检查是在命令跑*之后*、对着存储
  做的：打开副本自己的 manifest，比对每个条目的长度和 crc32；拿恢复后的台账对存储的台账；拿负载
  的帧对守护进程自己的计数器；拿表对日志的记录和字节。「看起来没问题」，是没人能检查时一个阶段
  会说的话；
- **页面带着报告。** `## Verification` 里的块是仪器自己的输出，规格重跑仪器并逐行比对
  （`lakelet/4.19` 对它自己那一页的规则），里面没有墙钟也没有路径——所以一页满是裁断的东西保持
  为真，或者变红并点名动了的那个阶段。

两页是从两头读的同一份文件。`docs/runbook.md` 是那套流程——八个阶段，每个带着命令、要看的信号、
证明它的状态、回滚，以及通知谁——而 `docs/slo.md` 是流程守护的数字，旁边点名守护每一个的那个阶段，
错误预算用这个部署的失败实际支付时所用的单位计：**被计数的拒绝、丢失的记录、恢复所需分钟数**。
一个没有任何人的阶段守护的数字，和一个什么都不守护的阶段，两者都是失败，而规格检查两个方向。

这一步故意**不**做的事：它不给部署加命令（动作是 4.6–4.23 的，而 4.21 的根本不是命令），它不给
任何东西打分（「页面很好」不是机器拥有的性质），它也不承诺任何墙钟（RTO 在一台点名的机器上量出来
并引用，从不评判）。

## 任务

脚手架放了三个文件，一个都没接上：`tests/runbook_harness.rs` 是**完整的**——它是仪器，不是你的，
你改了它，`kiln reset lakelet/4.24-runbook-drill` 会把它放回去——而 `docs/runbook.md` 和
`docs/slo.md` 是桩，带着页面那些标题和阶段清单。两页都归你，而这是两页构成全部交付物的那一步。

**在写两页中任何一页的一行之前，先读装置的模块文档。** 它们就是契约：一个阶段是
`### <number>. <title>` 标题，五个部分（[`PARTS`]，以及其中哪一个是围起来的 `sh` 块），一个页面
可以为一个回滚给出的四个答案（一条命令、`none`、`nothing was taken`——以及哪些阶段可以说哪一个），
一条命令能以哪些程序开头（[`PROGRAMS`]），以及这些程序的动词和旗标背后的语法，仪器用来指向它所
造世界的变量（[`VARS`]），以及页面的开头必须弄对的那一个数字。

### `docs/runbook.md`——那套流程

八个阶段已经点名，按操作者取用它们的顺序。每一个都需要它的五个部分，而顺序不是装饰：负载之前先有
副本，恢复进一个不是存储的目录，一次预演，以及在做那个不能撤销的动作之前先算算术。

1. **把已经在的那些阶段写完。** 每条命令都是 `lakeletd`、`lakeletq` 或 `lakelet-load` 之一，
   带着那个程序声明的旗标——`lakeletq --help`、`lakeletd --help` 和 `lakelet-load --help` 就是
   语法，而装置从源码里读同样的字；
2. **点名你真的会去看的信号**，放在反引号里，并让它是这个项目报告的东西：守护进程日志行的字段
   （`queue drained`、`series ledger`、`store recovered`、`store write cost`）、这个项目的某一页
   说出的数字，或者装置打印的一个计数器。仪器把每个名字都按住到项目自己的文件上，所以一个听起来
   可信、却没有任何东西打印的计数器，是一个发现；
3. **从清单里挑那个状态**，挑属于那个动作的：`lakeletq inspect series` 旁边的 `bill-adds-up`，一次
   负载运行旁边的 `counters-flat`。一个在错误动作旁边的检查，什么也证明不了那个阶段，而读取器会
   这么说；
4. **把回滚那一列写成它本来就是的那一列。** 第 5 阶段往存储里放记录，它的回来的路是第 2 阶段取的
   副本；第 8 阶段写下一次退休，说 `none`，因为没有任何东西能撤销它；其他一切都只读，说
   `nothing was taken`。仪器判这个方向：一个取走了东西的动作，不能主张自己什么都没取；
5. **引用报告。** 跑 `cargo test -p lakelet --test runbook_harness -- --nocapture`，把它打印的块
   放进 `## Verification`——规格会重跑它并逐行比对，所以一个手改的数字是一个红用例，而不是一个
   过时的页面。

### `docs/slo.md`——流程守护的那些数字

- **每个数字一行**，带着它的来处（这个项目的一个文件，或者旁边课程自己的基线）、保护它的 runbook
  阶段，以及什么会弄坏它。规格把这一行按住到那个阶段上：一个阶段没点名的数字，是一行指向错误阶段
  的行；
- **用这门课的单位表示的错误预算**——被计数的拒绝、丢失的记录、恢复所需分钟数——并且是对着表已经
  携带的那些数字花的：一个提到页面没点名数字的预算，是一个没人同意的承诺；
- **预算花光时会发生什么**，说的是动作而不是情绪：你跑哪个阶段、改哪个数字，以及你拒绝改什么
  （调高一个上限来止住拒绝，是那种让一个数字看起来更好、而存储继续为它付钱的改动）。

## 完成标准

- 在 `app/lakelet` 里跑 `cargo test -p lakelet --test runbook_harness -- --nocapture`，它打印
  报告，而每一行都说 `verdict=holds`
- `cargo test -p lakelet --test spec_runbook`——十五个用例通过：下面十四个，加上仪器自己的测试，
  规格通过 `#[path]` 够到它
- `kiln run lakelet/4.24-runbook-drill`——规格在你的页面上通过，而**在桩上失败**
  （`kiln selftest lakelet/4.24-runbook-drill --track lakelet` 就是那一对，替你跑）
- `kiln check lakelet/4.24-runbook-drill`——九个 must 闸门是绿的：`spec-integrity`、`caps`、
  `i18n`、`fmt`、`clippy@4`、`no-todo`、`docs:public`、`exit-code` 和 `links`。这一步没有 `sim`、
  `soak` 或 `mutants` 闸门：仪器*就是*证据，而规格是跑它的东西
- 手动跑一次 `lakeletq inspect series --store <your store>`，在你造的存储上——`## Verification`
  点名的第二条命令，因为一个页面是关于某个人正坐着的那个盒子的主张
- `grep -c '^### [0-9]' docs/runbook.md` 是报告说它跑过的阶段数，而页面开头那一行的数字是同一个
  数
- `kiln run lakelet/4.23-secret-rotation`——这一页最后一个阶段在其上退休一把密钥的那个环，答法仍然
  一样，逐字节不变

### 规格判什么

十四个用例，每个一条主张：

| the case | the claim |
| --- | --- |
| `the_page_is_a_procedure_and_every_stage_names_its_parts` | 没有留下任何占位，开头的计数就是阶段数，而每个阶段答全五个部分 |
| `every_command_the_page_names_is_one_of_this_deployments` | 每条命令都是这个部署交付的程序，它的动词是那个程序声明的、每个旗标是它接受的一个——一个点名 `lakeletq tier sweep` 的页面是一个发现，不是一次崩溃 |
| `every_signal_the_page_names_is_one_this_project_reports` | 一个信号放进反引号里的每个名字，都是这个项目的某个源码或页面写下的名字 |
| `every_rollback_is_a_command_or_says_why_it_cannot_be` | 一条命令、`none`，或者 `nothing was taken`——而一个写存储的阶段不可以说最后一个 |
| `the_instrument_runs_every_stage_of_the_page_and_nothing_is_owed` | 仪器对着它造的存储跑每个阶段的命令，而每个阶段的检查都成立 |
| `a_stage_that_does_not_name_one_of_its_parts_is_a_finding` | 每个部分一个用例，用在规格自己写的页面上：一个对页面挥挥手放行的读取器，在这里失败 |
| `a_command_that_exits_non_zero_names_the_stage_that_failed` | 那个阶段、它打印了什么，以及 `verdict=failed`——一个把坏命令吞下去的演练是装饰 |
| `the_page_carries_the_report_the_instrument_prints` | `## Verification` 里的块是仪器的输出，重跑并逐行比对 |
| `the_slo_page_names_each_number_and_where_it_comes_from` | 每一行点名一个数字，以及每个数字出自的这个项目的一个文件 |
| `the_two_pages_cross_reference_each_other` | 每个数字点名它的阶段，每个阶段被一个数字点名，两个方向都成立 |
| `the_error_budget_is_counted_in_the_units_this_course_uses` | 拒绝、丢失的记录、恢复所需分钟数——而且没有表不携带的数字 |
| `both_pages_link_to_each_other_and_their_targets_exist` | 两页互相链接，而每个相对目标在项目里都解析得到 |
| `the_instrument_reads_no_wall_clock_and_runs_no_cargo` | 没有墙钟进入报告，仪器跑项目自己的二进制而不是 shell 出去调 `cargo`，而同一页的两次演练打印同样的字节 |
| `the_report_says_how_many_stages_ran_and_which_ones_roll_back` | 报告的摘要行说出那些计数，而每个用命令回滚的阶段都在自己那一行这么说 |

## 陷阱

1. **一个前面加了点数字的散文页面。** 一个说「看看存储」、从不点名一条命令、一个要看的数字、
   或者一个好答案长什么样的阶段，就是那种读一遍就被扔掉的 runbook 的形状。仪器报告阶段和部分，
   而规格的缺口用例，是把同一句抱怨用在*规格*自己写的页面上——所以一个变宽松了的读取器，即使
   页面通过了，也会在那里失败。
2. **一个没人发布的信号。** `series_reported_total`、`queue_pressure`、`replication_lag`：它们
   读起来像遥测存储会有的数字，而这个部署一个都没有。装置把每个反引号里的名字按住到项目自己的
   源码和页面上，所以失败是一个点名阶段和名字的发现，而不是一个操作者在凌晨三点发现它。
3. **一个说「再试一次」的回滚列。** 一个被拒绝的动作什么都没写，所以修复的是那次调用；一个重试
   一个永远会被拒绝的调用的阶段，是一个教响应者错误反射的阶段。而且这两列在两个方向上都要受判：
   一次读不可以发明一条回来的路，而那个往存储里写记录的动作不可以说自己什么都没取。
4. **一次没人能撤销的退休，写得像能撤销。** 第 8 阶段是这一页上唯一一个不能被撤销的动作：退休写
   一次就定了，密钥签的最后一个 token 已经发出去了，而环没有任何能重开一把密钥的命令。它的回滚
   列说 `none`，而在那个时刻*之前*这么说，就是这个阶段所讲的算术的全部。
5. **那条听起来可信的命令。** `lakeletq tier sweep --store …` 是这一页*想要*的命令，而它不
   存在：`sweep` 和 `hydrate` 是引擎的，`src/cli` 或 `src/bin` 下面没有任何东西调用它们，而一个
   点名一条没人有的命令的 runbook，是一个关于想象中部署的流程。第 7 阶段说出这个部署真正提供
   什么——读一下走掉的那个 span，以及在读存储之前先 `hydrate`——那才是操作者今天能据以行动的东西。
6. **从仪器里 shell 出去。** 一个在测试里跑 `cargo test` 的装置，会在 target 目录的锁上死锁：套件
   拿着它，子进程等着它，而这一步会挂起而不是失败。仪器跑项目自己的二进制（`CARGO_BIN_EXE_…`），
   而规格读它的源码把它按住到这一点上——和 `lakelet/4.19-backup-restore` 的用例跑 `lakeletq`
   而不是它背后的库是同一个理由。
7. **报告里的墙钟。** 一页引用的块是逐行比对的，所以里面的一段时间会让页面自己的数字取决于机器
   和时刻。RTO 属于散文，要点名机器（`docs/dr-drill.md` 对它的 1.02 s 就是这么做的），而仪器
   完全不读时钟：同一页的两次演练打印同样的字节。
8. **一个其实是第二份 runbook 的 SLO 页面。** SLO 页面是一张数字表，每个数字旁边一个阶段，底下
   压着一个预算，不是第二套流程。一个 runbook 的阶段没点名的数字，是一行指向错误阶段的行，而规格
   检查两个方向，因为一个没有任何流程守护的页面是一个承诺，而不是 SLO。
9. **照着实现写页面。** 读着 `src/` 写出来的 runbook，会罗列设置项和代码路径，而那正是响应者用
   不上的东西。从会把你叫起来的那个告警写起——「摄入正在被拒绝」「磁盘在满」「一个客户端说它的
   token 被拒绝了」——然后检查其中每一个都有一个阶段和一个数字在背后。
