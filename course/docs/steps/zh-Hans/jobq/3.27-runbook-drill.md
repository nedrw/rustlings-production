# 跑一遍 runbook：一次找出运维缺了哪一步的演练

## 回顾

- `ops/runbook-drill@apply`——`mailer/1.22-runbook`：**这一步加深的那个形状，以及它留住的两条教训。** 一
  个故障，从头到尾重放一遍；演练报告那个承诺（什么都没丢），而且跑两遍，一遍是坏掉的东西回来了，一遍是它再
  也没回来，因为第二遍才让第一遍成为证据。页面是*从*演练写出来的，所以两者没法各走各的；它的五个小节
  ——Symptoms、Signals、Steps、Verification、Escalation——是一次事故会问的五个问题。
- `obs/metrics-slo@design`——`jobq/3.17-error-budget-alerts`：**一个阶段据以判读的那些信号，以及它们身上
  在凌晨三点真正要紧的那一件事。** 那一步把规则写成了*信号、阈值、窗口、演练*，并让样本行成为窗口的组成单
  位。它在守护进程里还决定了，一次运行在退出的路上发布它的读数：这些数字按队列、按报告存在，而*现在*读它们
  的，是一条命令，不是一条流。
- `ops/dlq-tooling@operate`——`jobq/3.26-dlq-cli`：**这套流程中间几个阶段所做的那些动作。** 一个身份，一
  个动作，一个答案，一个退出码；被拒绝的动作什么都不写、什么都不挪；重放可逆，丢弃不可逆，所以丢弃要理由，
  也要名字。那些承诺是在那一步*立下*的；而这一步把它们写进一套流程，再重放一遍。
- `db/atomic-claim@design`（`jobq/3.7-leases-and-recovery`）和
  `async/graceful-shutdown@operate`（`jobq/3.7`）不在 `requires` 里，但有两个阶段按名字靠它们：一个已经
  离开的 worker 手里的行，在它的租约到期时回来；而一次超过排干死线还没结束的停止，会**把它的行交回去**，
  而不是攥着。

## 变化

二十六步产出了动作。每一步都交了讲解它自己那个动作的页面——schema 的流程（`docs/migration.md`）、告警规
则、死信这扇门、发布——而**没有一步交过那套流程**：一个响应者做这些动作的顺序，写给一个这些动作一个都没写
过的人看。四页*这个工具做什么*，不是一份 runbook，而弄清楚的办法就是去跑一遍：一套从没被执行过的流程是一
张愿望清单，而它缺的那个阶段，是没人会注意到的那个，直到需要它的那次事故。

所以这一步改的是交付物*是什么*。页面不再是一篇关于某个子系统的散文；它就是那套流程，而且它是**数据**
——`Runbook::of` 读它，演练走它，装置数它。由此有三个决定，而每一个都是写下来的流程会失败的一条路：

- **一个阶段欠着四样东西，而第四样是没人会写的那一样。** 命令、说它答得好的那个信号、说它没答好的那个拒
  绝，以及把队列救回来的那个回滚。`Runbook::gaps` 拒绝一个四样没有全部点名的阶段，而拒绝和回滚之所以和命
  令在同一张清单里，是因为它们是响应者在事故*当中*（而不是之后）需要的两样：一个拒绝只是一句话的动作，是
  一个会被重试进同一个拒绝的动作；而一个不能撤销的动作，必须在被做出来**之前**说清这一点。这条 track 迄今
  交的每一个页面都点了命令和信号；没有一个点过回滚，而注意到这件事的是演练（`grep -ri rollback docs/*.md`
  找到这个词一次，在 `scrollback` 里）。
- **演练走这一页，而不是描述这一页。** `tests/support/drill.rs` 读 `docs/runbook.md`，**按页面点名它们
  的顺序**取每个阶段点名的动作，并报告还欠着什么。两者两个方向都比一遍：一个页面点名、而演练取不了的动作，
  是一个没人跑过的阶段；一个演练认识、而页面没点名的动作，是这一步存在的目的要找出的那个阶段
  （`Report::unnamed`）。正是这一点让"一个没写过它的人能跑"成为一个性质，而不是一个希望——演练就是那个
  人，而它对那次事故没有记忆。
- **一个不会失败的演练是装饰。** 三个世界，后两个是反证：`Recovers` 是承诺；`Never` 是同一套流程，但没
  有人留下来接手队列，它报告还欠着的工作；而 `Refused` 那个世界，在说明它冲着哪几行的那个阶段**之前**，就
  做了那个不能撤销的动作——也就是回滚那一列必须写对的时刻。

**演练发现的、这条 track 一直缺的东西**——也是为什么这一页得被走过，而不能一口气写完：死信上的那些动作。
第 3 阶段说要去看那些行；*改变*它们的两个动作，是这个项目所有页面里从来没有人写进一套流程的两个阶段。重放
在讲解 3.16 的地方被点名，丢弃在这扇门的帮助文本里被点名——但一个读着这些累积下来的页面的响应者，找得到
*该看什么*，永远找不到*该做什么*，而演练把这件事大声说出来：一个它做了、页面没点名的动作，会以 `unnamed`
出现在报告里，并带上它需要的命令。后面跟着的那一对世界，是同一个发现的另一半：一个被拒绝的动作让队列停在
原地（所以修的是那次调用，不是队列），而丢弃的回滚那一列是 **none**——在任何人把这个动作对准一行之前，这个
词必须已经写在页面上。

引擎上加了两个名字，而两个讲的都是读一个页面，而不是写一个页面：`Runbook::of(page) -> Runbook` 从一个
markdown 页面里解析出带编号的阶段，而 `Runbook::gaps() -> Vec<Gap>` 回答每一个不可跑的阶段——空的、不完整
的，或者占着一个它的编号并不表示的位置。*不*在这里的：任何判断这些动作管不管用的东西。动作是在引擎自己的套
件里被证明的，而页面不是修队列的地方。

## 作业

脚手架加了四样东西，一样都没接上：`src/engine/runbook.rs` 是那个把判断留空了的读页器，`docs/runbook.md`
是那个有五个小节、五个没写完阶段的页面，`tests/support/drill.rs` 是那个摆出事故、报告它安排发生了什么的
演练，而 `tests/runbook_harness.rs` 是 `slow:bench-budget@10` 跑的那个装置。

### `src/engine/runbook.rs`——读页器，以及它在哪儿被声明

**还没有任何东西声明这个新模块**，而这是你的第一个决定：`src/engine/mod.rs` 需要
`pub(crate) mod runbook;`，以及四个公开名字的再导出（`Gap`、`PARTS`、`Runbook`、`Stage`）。在做出它之
前，规格和装置都编译不过——这就是 `kiln run jobq/3.27-runbook-drill` 最先给你看的那个失败。模块是
`pub(crate)`，不是 `pub`，理由 `jobq/3.2-public-api-baseline` 给过：调用方能点名的，就是 `mod.rs` 再导出
的那些。

三个函数体归你，而文件其余的部分——类型、访问器、`Display` 实现——是你留下的脚手架：

- `Stage::missing()` 答这个阶段没有点名的 `PARTS` 里的第一个。"没有点名"也包括点了名却什么都没答：
  `- rollback:` 是一个正准备想一想这件事的响应者的形状，而它和一个从没提过回滚的阶段是同一个缺口；
- `Runbook::of(page)` 是那个解析。一个阶段是一个带编号的 `###` 标题；一个部分是读作 `- command: …` 的
  一行（`PARTS` 里那四个名字），它一直延续到它下面折行的那些行，直到一个空行、一个标题，或者下一个部分。
  一个**没有**编号的 `###` 标题不是一个阶段——它是一个本该是阶段的位置上的标题，而它原本要点的那些动作，正
  是演练报成 unnamed 的那些；
- `Runbook::gaps()` 是那个判断：`Empty` 表示一个根本没有阶段的页面，`Missing` 表示一个忘了某个部分的阶
  段，`OutOfOrder` 表示一个编号和它所占位置不符的阶段。两者同时成立时，同一个阶段会两个都报，因为它们是两
  种不同的修法。

底下的两个自由函数（`numbered`、`named`）是解析需要的行读取器，而这个 crate 里别的东西都不许调它们：它们
是构成一个页面语法的细节。

### `docs/runbook.md`——那一页

五个小节在那儿（`mailer/1.22-runbook` 的那五个，按响应者读它们的顺序），阶段住在 `## Steps` 小节里，而
页面点名响应者要重放的那个演练。三件事：

1. **把已经在那儿的阶段写完。** 五个阶段各自点名它的命令、它的信号、它的拒绝和它的回滚，各自点名一个这个
   部署会答的类别，以及 `jobq/3.17-error-budget-alerts` 发布的一个信号。页面上有 `docs/dlq.md` 的退出码
   表可以照着读；
2. **加上演练找到的那些阶段。** 模块接上之后跑一次 `cargo test -p jobq --test spec_runbook`，读那个
   `unnamed` 清单：它点名的动作，就是页面缺的阶段。它们正是这次事故*所关于的*那两个——把一封死信放回去，
   和把一封扔掉——而页面得按它们该在的顺序把它们放进去，在滚动发布之前；
3. **把那个不能撤销的动作的回滚那一列写出来**，用的就是这一步所坚持的那个词：丢弃的回滚是 `none`，因为它没
   有回头路，而页面要在别人动手之前（而不是之后）读得到的地方说清这一点。

`links` 闸门跑这一页和项目里别的每一个 markdown 文件：相对目标得存在，`#anchors` 得对上一个标题，而该是目
标的地方放一个 `TODO` 是失败。规格查闸门查不了的：每个阶段都点了那四样东西，页面点了那些信号和类别，而演
练能重放它。

### `tests/support/drill.rs`——演练

它已经把事故摆好了，报告的是一个它*决定*的 `Report`，而不是它量出来的：四个作业被收下，一个 worker 认领
了全部四个，两次尝试花掉了它们的预算，一个作业还欠着一次，而一行仍然攥在即将被停掉的那个 worker 手里。它
没做的事，是问页面任何问题，而 `World::Never` 和 `World::Refused` 答的和 `World::Recovers` 一样。把它变
成一次演练，意味着四件事，按这个顺序：

1. **在做一个动作之前，先把页面和脚本比一遍。** 这个文件认识的动作（`ACTS`）和页面点名的阶段，是一张从
   两头读的清单；页面没点名的，就是那个发现，它会被报告，而不是被跳过；
2. **按页面的顺序走那些阶段**，做每一个的动作。一个阶段的命令不是那些动作之一，是页面和证据之间的漂移，而
   演练会用它取不了的那个命令说出这件事——不是一个被跳过的阶段；
3. **一边走一边核对页面自己的主张。** 演练就是干这个的：队列真的卡住了（`claimed` 比 `succeeded` 多），
   有一行真的是 `running`，两封死信真的在那儿，而那个把守护进程攥着的东西交回去的动作，真的挪动了一行；
4. **最后报告还欠着什么**，让世界来决定：`Recovers` 是之后有 worker 接手队列，`Never` 是没人接手，而
   `Refused` 是同一套流程里有一个动作做得太早了——被拒绝的动作什么都不写，这一点演练是断言出来的，不是假
   定的。

演练跑在一个文件里写明的时钟上，和一个不需要容器的存储上，所以整场重放是毫秒级的。**规格会把它跑好几遍**，
而 `slow:mutants@80` 还要把规格再跑十几遍：一次得等出来的事故，是一次让这些运行全都白白变慢的事故。

**这次演练诚实的地方**：它重放的那个拒绝是*这扇门*自己的——一个对准了不是死信的一行的动作，用类别 `2` 作
答（`jobq/3.26-dlq-cli`）。数据库拒绝写入是另一种拒绝，类别 `4`，而内存存储造不出它来；页面从那一个里留下
的是那一行，因为类别是响应者据以分支的东西，而两个类别对这套流程有同一个后果：什么都没写，所以修的是那次
调用，不是队列。带持久后端的部署，才是类别 4 那条路真实存在的地方，而 `jobq/3.26-dlq-cli` 自己的规格，是
它被真的二进制驱动着走一遍的地方。

### `tests/runbook_harness.rs`——课程的仪器

它读 `docs/runbook.md`，向这个 crate 的读页器要那些阶段，打印四个计数——`jobq-budget acts=6`、
`named=6`、`unnamed_max=0`、`unrunnable_max=0`——`slow:bench-budget@10` 拿它们和
`course/tracks/jobq/budget/3.27-runbook-drill.toml` 比。是动作和阶段的计数，永远不是秒，所以闸门在一台满
载的机器上和一台闲着的机器上给出同一个答案。文件是课程的，不是你的：改它就是改测量，而
`kiln reset jobq/3.27-runbook-drill` 会把它放回去。

### 规格判什么

九个用例，分三组，下面每一行都是你能跑的一个主张：

| the case | the claim |
| --- | --- |
| `the_page_is_a_procedure_whose_stages_all_hold` | 页面没留下任何占位，至少点名五个阶段，而每个阶段把 `PARTS` 的四样全答了——是通过这个 crate 自己的读页器判的 |
| `the_page_names_its_sections_the_drill_and_the_signals` | 那五个小节、响应者要重放的那个演练（`spec_runbook`）、`jobq/3.17` 的那些信号，以及脚本据以分支的那些类别 |
| `the_drill_runs_every_stage_the_page_names` | 演练按页面的顺序做页面点名的每一个动作，没有一个动作落下没被点名，而最后一个阶段所做的承诺，在有 worker 回来时成立 |
| `the_drill_reports_the_work_that_is_still_owed` | 同一套流程放在一个没人回来的世界里，报告还欠着的工作——而承诺在那里是破的，正是这一点让另一次运行成为证据 |
| `the_drill_replays_the_refusal_and_the_page_says_what_it_leaves` | 被拒绝的动作被走到，它所属的阶段在页面上，它的拒绝点名类别 `2`，它的回滚说 `none`，而流程其余部分没有变 |
| `a_stage_that_does_not_name_its_four_parts_is_a_gap` | 每个部分一个用例，外加一个点了名后面什么都没有的部分：一个由这个文件写的页面，于是一个对页面睁一只眼闭一只眼的读页器会在这里失败 |
| `a_stage_holds_the_place_its_number_says` | 1、2、3 是一套流程；重复的编号、跳过的编号、以及一个从 2 开始的页面都不是，而一个顺序不对、同时又不完整的阶段，两个都报 |
| `a_page_that_names_no_stage_is_prose` | 一个没有带编号阶段的页面是 `Empty`，一个没有编号的 `###` 标题不是一个阶段，而一个 `####` 标题是阶段里面的散文 |
| `a_part_wrapped_onto_the_next_line_is_read_whole` | 一个按可读宽度写出来的页面，整段解析得出来，而一个空行结束这个部分，而不是把它延长 |

## 陷阱

1. **一个只是前面加了编号的散文页面。** 五个阶段说着"去看那些死信"，从来不说用哪条命令、一个好的答案长什么
   样、一个拒绝是什么意思、或者怎么退回去，这就是一份读一遍就被扔掉的 runbook 的形状。`Runbook::gaps` 点
   名阶段和部分，装置数它们：在一个有人能照着走的流程上，`unnamed_max` 和 `unrunnable_max` 都是零。它防的
   那个失败很具体——那个读了"重放那些死信"、敲下 `jobqc dlq replay <ID>` 却没带 `--by` 的响应者，拿到的是
   类别 `2` 和一句拒绝；而一列从没说过需要名字，会把他们打发去读源码。
2. **一个在每个世界里都报告承诺守住了的演练。** 两个毫无差别的世界，是一次跑了两遍的演练；`Never` 和
   `Refused` 才让 `Recovers` 那次运行成为证据，而下面这个 `Report`，就是一个自己决定了自己答案的演练的样
   子——`stages` 是从页面上数出来的，不是走出来的；`unnamed` 是空的，因为什么都没比；而 `promise_held()`
   对一个没人碰过的队列答 `true`。
3. **把被拒绝的动作当成一次没做完的撤销。** 什么都没写，所以没有什么可回滚：修的是那次调用。一份拒绝那一列
   写着"再试一次"的流程，是一份教响应者去重试一个永远会被拒绝的调用的流程——而演练断言的是那个强的形式
   （`the rows are exactly where they were`、`no line in the record`），所以一扇在走向拒绝的路上开始写东
   西的门，会在这里失败，而不是在生产里。
4. **给丢弃配一个它没有的回滚。** 它是这一页上唯一一个不能撤销的动作，而一个为它列出回滚的页面，比一个什么
   都不列的页面更糟：响应者会以为有回头路，然后做了它。那个词是 `none`，而这个动作之所以要 `--by` 和
   `--reason`，是因为记录那一行就是活下来的全部。
5. **一个手工编号、又手工重排的阶段。** 一套流程是按页面的顺序走的，而 `OutOfOrder` 就是那句反对：重复的编
   号、跳过的编号，或者一个从 2 开始的页面，是一个步骤不在编号所说的位置上的页面。解析不排序，也不重新编
   号——页面是一个在压力下的人读的，所以它说什么就是什么。
6. **在演练里等租约。** 租约是一种真实的修法，而它要花 `worker.lease_seconds`——一个属于阶段的信号、而不
   属于测试的数字。为它睡一觉的演练，是规格会在 `slow:mutants@80` 底下跑十几遍的演练，也就是整套套件花几
   分钟看一个钟走。这里的钟冻在文件写明的某个时刻，而流程自己的那个阶段，才是快的修法。
7. **改装置或者基线，而不是改页面。** `tests/runbook_harness.rs` 是课程的文件，
   `course/tracks/jobq/budget/3.27-runbook-drill.toml` 是闸门读的那份拷贝：改其中任何一个，改的是仪器，
   而不是它量的那个东西。页面才是交付物。
8. **一个命令不是这个部署的阶段。** 演练只做 `ACTS` 里的动作，而一个点名编排器回滚
   （`kubectl rollout restart`）的阶段是漂移：演练没有对应的动作，并会说出它取不了哪条命令。一个给某个部署
   写的 runbook，点的是那个部署的二进制和信号，否则它就是一份关于一个想象中的部署的文档。
