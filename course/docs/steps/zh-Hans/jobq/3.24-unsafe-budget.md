# unsafe 预算：默认拒绝，每一个例外都写下来

## 回顾

- `unsafe/budget@aware`——`relay/2.21-supply-policy`：策略本身，以及它的代价。那一步在**每一个** crate 根上
  写了 `#![forbid(unsafe_code)]`，因为写在一个 crate 里的属性管不到另一个，而且它点名了这个属性*不*覆盖
  的两件事：依赖里的 `unsafe` 是别人的代码；有意花掉这份预算，要付一个写下来的理由，和一个评审者看得见的
  `#[allow]`。**这一步是那个位置上的 `apply` 一半**，而它加上去的那句话就是预算：一个从项目内部量出来的
  数字，闸门拿它去和课程的那份拷贝比。
- `api/library-design@apply`——`jobq/3.2-public-api-baseline`：引擎的表面就是 `src/engine/mod.rs` 再导出的
  那些，别的都不是，所以一个新模块在列进那儿之前不算公开。下面的审计是那个表面的一部分——调用方可以拿这个
  crate 的策略去跑任何源码——它和引擎的其余部分一样有文档、有测试。
- `perf/bench-budget@apply`——`jobq/3.22-bench-budget`：用计数而不是时钟搭出来的预算的形状，也是这一步的装
  置照着走的那个。这一步的计数更小，基线是三个零，而用同样的方式搭它的理由，是同一条理由：一个满载的机器会
  给出不同答案的数字，是没人守的数字。

## 变化

四个决定，把这一步和 `relay/2.21` 分开：

- **预算是一个数字，而项目自己量它。** `unsafe_occurrences`、`undocumented_max` 和 `unguarded_max`，是
  `kiln` 的 `unsafe-budget@0` 闸门从 crate 外面读的三件事——使用、理由、策略——按 crate 自己的审计报告
  出来的样子读。闸门拿它们去对课程的基线（`course/tracks/jobq/budget/3.24-unsafe-budget.toml`），于是零
  是某人写下来的一个决定，而不是评审里的一句话；而一棵花掉了预算的树，会被告知它花了多少。
- **注释不是一次使用，字面量也不是。** 数的是代码里的那个*词*。这听着像个细节，直到把这个模块写出来：下面
  那个模块提到这个关键字十五次——每一次都在注释里，或者在拼出这个词的字符串里——而这个 crate 的生产代码一
  次都没用过它，所以一个按整行读的扫描，会把对规则的讲解报成对它的使用。闸门读源码的方式也一样（它的词法器
  恰恰对这一点很小心），而拒绝*下一个*块的是编译器。
- **策略来自 manifest，不是来自属性。** `relay/2.21` 每个 crate 根要写一个 `forbid`；cargo 的 lint 表在
  一处为这个包的每个 target 拒绝，所以这里的项目只有一份策略，它在 `Cargo.toml` 里。一个级别的两种写法都
  算 cargo 的（`unsafe_code = "deny"` 和 `{ level = "deny" }`），`forbid` 算，`warn` 不算，workspace 的
  那张表也算——一份靠 grep 错了其中一处读出来的策略，是一份并不存在的策略。
- **拒绝是一张清单，按读者修它们的顺序排。** `check` 答*第一个*错的地方：先是策略，然后是理由，然后是数
  字。一个不拒绝的 crate，不能靠它的注释通过；一个光秃秃的 `// SAFETY:` 不是一个理由；而超出预算时，它点
  名那个计数，而不是说"太多"。

## 作业

脚手架加了一个模块和一个装置。**还没有任何东西声明这个模块**：接上 `src/engine/mod.rs` 是你的第一个决定，
在做出它之前，规格和装置都编译不过。

### `BUDGET`、`WINDOW` 和三个名字——数字也是内容

`BUDGET` 是零，`WINDOW` 是三：这个 crate 允许多少次使用，以及一条理由最远可以写在一次使用上面几行。三个
指标名，是装置打印的东西，也是课程的基线所用的写法，放在一张两边都读的清单（`UNSAFE_METRICS`）里。
manifest 拒绝的那个 lint 是 `unsafe_code`——是 lint，不是关键字，这就是一份策略和对它的一次使用之间的区
别。

### `Occurrence` 和 `Audit`——一个文件关于自己说了什么

一个 `Occurrence` 是一行，以及它有没有理由，理由随它带着：一份只说 `documented: false` 的报告，会把评审
者打发去打开那个文件。一个 `Audit` 是一个文件、它的使用，以及这个 crate 的策略——策略是 crate 的，之所以
每个文件都带一份，是因为每一次使用都拿它来判。模块外面什么都造不出这两个中的一个：`audit` 是唯一的构造函
数，所以装置打印的数字，永远是扫描产出来的数字。

### `audit(file, source, denies_by_default)`——扫描

三条规则，每一条都是规格里的一个用例：

1. **一行的代码，是 `//` 之前、`"…"` 之外的那些东西。** 注释一直到行尾；字面量在下一次没有转义的引号处结
   束。跨行的块注释或原始字符串按行来读——这个收窄是明写在模块文档里的，不是藏起来的，而且这个 crate 两样
   都不写；
2. **数的是那个词，不是那个名字。** `unsafe_code` 是 lint；`unsafe` 是关键字。一个带着
   `#![deny(unsafe_code)]` 的 crate 根，拒绝了这个 lint，什么都没使用；
3. **测试不是生产代码。** 一个由 `#[cfg(test)]` 把关的条目，不管在文件里坐在哪儿、嵌套得多深，都被跳过，
   而它上面和下面的行照样计数。一个用到这个关键字的测试，说的是测试自己的事，而把它算进去的计数，会把一个
   项目往写更糟的测试上推。

一条使用算*有文档*，当它上面最近的一行 `// SAFETY:` 最多在 `WINDOW` 行以内，**而且带着理由**。一个光秃秃
的标记不是一个理由，它不会退回去借用更早的注释，而块下面的标记不在块上面。一条理由该写什么，由它所服务的
那次评审来定：它要说的是，这次使用如果错了，会坏掉什么。

### `denies_unsafe_code(manifest)`——策略，从 manifest 的文本里读

lint 表从一份 `Cargo.toml` 的文本里读：包的看 `[lints.rust]`，它带的成员看 `[workspace.lints.rust]`，
每一处都认 cargo 写一个级别的两种方式，`deny` 和 `forbid` 算数，`warn`/`allow` 不算。解析不了的 manifest
答 `false`，因为对一份读不出来的策略，诚实的读法就是它不在那儿。这个函数收文本而不是路径：读文件是调用方
的事，也正因如此，规格能拿夹具来测这份策略，装置能拿项目自己的 manifest 来测。

### `check(audits, budget)`——拒绝，按读者修它们的顺序

**先是策略**（一个不拒绝的 crate，没有一条规则让这些例外成为*它的*例外），**然后是理由**（某人写的一行），
**然后是数字**（删掉一个块，或者有意把预算调高）。每一条拒绝都点名文件，而带行号的那条点名行号：
"unsafe budget exceeded" 会把读者打发去 grep。

### `counts(audits)`——装置打印的那些行

每个指标一行，`jobq-budget <name>=<value>`，而且**永远三行都在**：数字是测量，拒绝是评审者读的东西，所
以一次拒绝的运行照样把它们打印出来。缺掉的指标对闸门来说是 `blocked` 而不是失败，而一道 blocked 的闸门对
这个 crate 什么也没说。

### `Cargo.toml`——策略落在哪儿

项目 manifest 里的 `[lints.rust]` 有一段标出来的位置，里面空着：这条 deny 就该写在那儿，一次盖住库和两个
二进制。`unsafe-budget@0` 查它，规格的倒数第二个用例查项目自己的 manifest，而让它成为一条规则而不是一个习
惯的是编译器——`src/` 底下的下一个 `unsafe { }` 会构建失败，直到有人有意写上一个 `#[allow]`。

### `tests/unsafe_budget.rs`——装置，它是课程的文件

装置走一遍项目自己的 `src/**/*.rs`，读项目自己的 `Cargo.toml`，审计每个文件，打印那三行。它就是仪器：学
习者改它，就是学习者在改测量，而 `kiln reset jobq/3.24-unsafe-budget` 会把它放回去。它在打印任何东西之前
还会断言这次遍历找到了东西，因为一次没读到任何文件的遍历给出的三个零，不是测量。

### 规格判什么

| the case | the claim |
| --- | --- |
| `the_count_is_the_word_in_the_code_and_not_the_text_around_it` | 一个满是注释、文档注释和字面量的文件没有使用；`#![deny(unsafe_code)]` 拒绝的是 lint，不算一次使用；理由的文本随它带着 |
| `a_reason_in_the_window_above_is_what_documents_a_use` | 四次使用，四种距离：上一行算有文档，`WINDOW` 行以内算有文档，光秃秃的标记不算，再远一行就不算——而没有文档的使用数，就是预算所用的那个数字 |
| `tests_are_not_production_code` | 一个 `#[cfg(test)]` 模块外面那两次使用算，里面那两次（嵌套的那个也算）不算；一个测试模块够不到它上面那一行 |
| `the_budget_is_a_number_and_going_over_names_the_count` | 预算之内 `check` 答 `Ok(count)`，超了答带着那个计数的 `Refused::Over`；`BUDGET` 是零；没有文件就是没有使用 |
| `the_refusals_come_in_the_order_a_reader_fixes_them` | 一棵同时违反三条规则的树，先因为策略被拒，然后因为理由，然后因为数字 |
| `the_policy_is_the_manifest_and_both_spellings_say_it` | 一个级别的两种写法、workspace 的那张表、`forbid` 算、`warn`/`allow` 不算，以及一份解析不了的 manifest |
| `the_crate_holds_its_own_budget` | 项目自己的 manifest 拒绝了这个 lint，而它自己的生产代码里一次使用都没有——遍历走的是 `src/`，而关于这个关键字说得最多的那个文件，就是这一步自己的模块 |
| `the_report_is_the_three_facts_a_harness_prints` | 三行、名字在一张清单里、一个没有守卫的文件被第三个数计进去，以及什么都没量到也把三行都打印出来 |

## 完成标准

- `kiln run jobq/3.24-unsafe-budget` — 八个用例通过：数代码而不是数文本、窗口、测试、预算、拒绝的顺序、
  策略的两种写法、这个 crate 自己的数字，以及装置打印的那些行。
- `kiln check jobq/3.24-unsafe-budget` — 每个 must 闸门都是绿的。要读的是 `unsafe-budget@0`：
  `0 unsafe occurrence(s) in 37 production file(s), each with a // SAFETY: note, and unsafe_code is denied in .../Cargo.toml`。
  闸门要的是那个标记，而这个模块要的是标记后面那个理由，两者之中这个读法更严，也是预算不是零的那一天真正要
  紧的那个——光秃秃的标记能过闸门的标记检查，而装置会报出一个没有文档的使用。
- `cargo test -p jobq --test unsafe_budget -- --nocapture` 打印 `jobq-budget
  unsafe_occurrences=0`、`jobq-budget undocumented_max=0` 和 `jobq-budget unguarded_max=0`。
- `kiln selftest jobq/3.24-unsafe-budget --track jobq` — 慢路径。要读的行是
  `3 metric(s) within ±10% of the course baseline: unsafe_occurrences 0, undocumented_max 0,
  unguarded_max 0`，以及没装 `llvm-tools-preview` 的机器上 `slow:?coverage@80` 答的 `⚠ blocked`
  ——那是那里的诚实答案，不是这一步的失败。
- 你要是把 `unsafe { }` 块放在 `src/` 底下任何地方，`cargo check -p jobq` 会失败，而失败信息会点名拒掉它
  的那个 lint。加上一个评审者会要的 `#[allow]`，树又能构建了——而装置随后打印 `unsafe_occurrences=1`，那
  就是闸门在告诉你花了多少。

## 陷阱

1. **数文件，而不是数代码。** 这一步自己的模块提到这个关键字十五次——十四次在它的文档里，一次在拼出它所数
   的那个词的常量里——而这个 crate 的生产代码一次都没用过它。一个按整行读的扫描，会在一棵一次都没有的
   crate 里报出十五次使用，而它最先标出来的，正是讲解这条规则的那个文件。
2. **不看字面量就切 `//`。** `let text = "unsafe // not a comment";` 是一个含有注释标记的字面量，而在第一
   个 `//` 处把行切开，是同一个错误的另一个方向的短版本：它把标记之后的一切都藏起来，包括一次使用。一行的
   代码，是 `//` 之前、*字面量之外*的那些东西，而规格的夹具两半都有。
3. **光秃秃的 `// SAFETY:`。** 它看起来像证据，其实什么都没说，而且比没有注释更糟：一个 grep 这个标记的评
   审者找到了它，就不再往下找。从四行以上借理由的那种也一样——读者最先看的那一行，是紧贴在块上面的那一
   行。
4. **把注记写在块*下面*。** `unsafe { … }` 后面跟一句 `// SAFETY: …`，是关于已经写好的代码的注释，而给
   下一个读者的答案是 `git log`。窗口在上面，而闸门也是沿着同一个方向读那三行。
5. **把测试数进去。** `#[cfg(test)]` 模块里的一个 `unsafe`，和库里的一个是两种不同的陈述，而把它算进去的
   计数，会把一个项目往写更糟的测试上推——这正是 `clippy` 在决定一个 lint 管什么时所做的同一个划分。这段
   区域从被把关的条目开括号的地方开始，到它的块结束的地方结束，嵌套的模块也在内。
6. **把 `unsafe_code` 数成一次使用。** 这个 lint 的名字出现在 manifest 里、模块自己的指标里，以及一个
   crate 根可能带的属性里（`#![deny(unsafe_code)]`）；一份把自己所禁的东西数进去的策略，永远满足不了。
7. **一个 crate 根上一个属性。** `relay/2.21` 点名的那个陷阱，在原则上还是陷阱，只是在这里换了形状：cargo
   的 lint 表为这个包的每个 target 拒绝，所以项目只有一份策略——而在一个有两个二进制的项目里，只在 `lib.rs`
   写 `#![forbid]`，是一份有两个洞的预算。这个项目的答案是 manifest 的那张表，加上 crate 自己的审计去读
   它。
8. **靠 grep 读策略。** `unsafe_code = "deny"` 和 `unsafe_code = { level = "deny" }` 都是 cargo 的写法，
   `forbid` 是拒绝而 `warn` 不是，workspace 的那张表对它带的成员也算。一个只找一个字符串的扫描，别的都找
   不到，而它给出的答案是*没有拒绝*——用错的理由给出了对的拒绝。
9. **把 `_max` 指标读成目标。** `undocumented_max` 和 `unguarded_max` 是上界：一个不再处于没有守卫状态的文
   件，是通过的，而没人需要为此去改基线。第一个数字是精确的，而一棵花掉预算的树，会按闸门带着计数报出来的
   方向把它推上去。
10. **改装置或基线，而不是改代码。** `tests/unsafe_budget.rs` 是课程的文件，
    `course/tracks/jobq/budget/3.24-unsafe-budget.toml` 是闸门读的那份拷贝：改其中任何一个，改的是仪器，
    而不是它量的那个 crate。`kiln reset jobq/3.24-unsafe-budget` 会把装置放回去。

## 延伸阅读

- [The `unsafe_code` lint](https://doc.rust-lang.org/rustc/lints/listing/allowed-by-default.html#unsafe-code)
  — 这一步的策略所拒绝的那个 lint，以及 `deny`、`forbid` 和 `warn` 对它各自意味着什么。
- [The Cargo book: `[lints]`](https://doc.rust-lang.org/cargo/reference/manifest.html#the-lints-section) —
  策略所住的那张表，包括 workspace 的写法，以及写一个级别的两种方式。
- [The Rustonomicon](https://doc.rust-lang.org/nomicon/) — 一个 `unsafe` 块究竟允许你做什么，而一条
  `// SAFETY:` 理由，就是对着这份背景写的。
- [Rust Secure Code WG: `unsafe` guidelines](https://rust-lang.github.io/unsafe-code-guidelines/) — 一份
  理由里必须有什么，以及为什么"这是安全的"不是一个答案。
- [Clippy: `undocumented_unsafe_blocks`](https://rust-lang.github.io/rust-clippy/master/index.html#undocumented_unsafe_blocks)
  — 同一条规则做成一个 lint，给那些允许这个关键字、并且想让编译器坚持要理由的 crate。
- [Miri](https://github.com/rust-lang/miri) — 会去检查一次使用是否*健全*的那个工具，而这正是这一步的审计
  故意不回答的问题：计数讲的是不安全的量有多少，而理由是把健全性摆到评审者面前的东西。
- `course/tracks/jobq/spec/3.24/unsafe_budget.rs` — 那八个用例写成的测试，包括一条理由可能所处的四种距
  离，以及项目自己的数字。
- `course/tracks/jobq/budget/3.24-unsafe-budget.toml` — 闸门读的基线，以及它跑的命令。
- `relay/2.21-supply-policy` — 策略那一半，而这一步就是它的 `apply`。
- `jobq/3.22-bench-budget` — 建在计数上的预算的形状，以及这一步的装置照着走的那个写法。
