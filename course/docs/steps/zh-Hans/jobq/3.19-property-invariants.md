# 性质胜过例子：随机游走守得住的不变式

## 为什么

这个项目到目前为止写下的每一个用例都是一个例子：提交这两个作业、认领一个、断言那一行。一个例子是
某个人就"哪些输入有意思"做的一个决定，而没人想到的那些输入，正是缺陷住的地方。套件继续通过，而它
底下的代码在变，因为它从来没被问过那个会被这次改动弄坏的问题。

还有第二笔代价，而它才是这一步要讲的。一条你*问*不了的规则，是一条你查不了的规则。
`jobq/3.14-job-state-machine` 正是因为这个，才把一个作业的生命变成一个全函数，而它自己的文档许下了
这一步要写的那场游走：状态和事件是列表，每个答案是一次调用，所以"存不存在一个操作序列，结束在本不该
结束的地方？"是一个程序能问的问题。缺的是那台机器：它问几百次，而在答案是否定的时候，把那个否定它的
用例交回来。

所以，让一条性质值得写的，不是那条性质：是那个**反例**——一个种子，以及把它弄破的那些操作。没有它，
一次红的构建是在对某个得手工复现的人说"这个队列某处坏了"。有了它，这次事故是 CI 日志里的一行，而
修复从一个已经存在的测试开始。

## 作业

脚手架加了一个模块，而**还没有任何东西声明它**：照 `jobq/3.13-queue-authz-attribution` 接 `authz`、
`tenant` 和 `usage` 的方式去接线 `src/engine/mod.rs`，是你的第一个决定，而在它做成之前规格不编译。
文件里的形状带来四个决定。

### 生成器是一个种子，而种子就是全部状态

`Rng` 把一个 `u64` 变成一场游走要播放的操作序列。算术是整数算术，别的什么都没有——没有时钟、没有线程
id、没有地址、没有哈希种子——因为一个重放不了的发现只是传闻，而一条 CI 日志要有价值，就需要同事能在
自己的机器上，用消息里的那个数字造出同一个失败。`splitmix64` 是模块文档论证的那套实现：一个计数器加
两步混合。

`Rng::below(bound)` 是游走唯一问它的东西，而它在两处边界上都有讲究。它答在自己范围之内（一场抽到
字母表之外索引的游走，游走的就不是这个模型），而在没有东西可抽的时候，它答*某个东西*：当 bound
除不尽 2^64 时，取余不是完全均匀的，而这个取舍是故意的，因为一场游走是对反例的搜索，不是给统计量的
抽样。

### 每一步之后都问一次不变式

`Invariant::holds` 拿到的是历史和刚刚发生的那一步，而游走在第一个说"不"的步上停下。这句话的两半都是
决定：

- **那一步，而不是那个状态。** "一个完成的作业永远不会再被分发出去"是一句关于前和后的话；一个只看
  状态的检查器要说这句话，就得留一份轨迹的副本，而那正是这一步存在要避免的第二份实现；
- **历史，而不只是最后一个事件。** 一场游走里两次完成，是一条关于队列*看见了什么*的性质，而一次
  拒绝也算在里面：事件发生了，机器说了不。

一次拒绝是一**步**：`transition` 拒绝二十四对里的十六对，所以一个在第一次拒绝时就停下（或者把事件
丢掉）的游走器，只会看到作业本来就要走的那些移动——而关于作业结束的每一条性质都会成立，因为没有任何
东西到过那里。

### 模型就是引擎的那张表，而一个用例可以重放

`Machine` 就是 `transition`，不是它的第二份拷贝：对着拷贝的性质，是对拷贝的测试。`Model` trait 存在
的理由是另一个方向——一场游走对准某条有人*故意改过*的规则，而 `jobq/3.20-mutation-threshold` 拿一张
这样的规则表做的正是这件事——而要让那个有意义，没被改过的模型必须是真的那一个。

`walk` 生成并播放；`replay` 播放一个有人写下来的用例；`shrink` 拿掉这次失败不需要的东西。`shrink`
的契约是三句话，而规格三条都检查：答案仍然破坏那条不变式；它的操作就是给它的那些，顺序不变，只是少了
几个；以及**答案里再也拿不掉任何一个操作**。它绝不能是"最小的那个"：那是对每个子集的搜索，而一个人
读的用例，是那个显然没有什么可再拿掉的。

### 有意不改的东西

那张表（`transition`）、字母表（`STATES`/`EVENTS`，游走从里面抽，而不是重新声明一遍）、模型的拒绝，
以及每一个更早的套件。字母表也是这场游走没有时钟事件的原因：`sched/delayed-timers@apply`——
`jobq/3.11-delayed-timers` 让一个 `queued` 行*到期*，而从不在状态之间移动它，因为到期是那一行的
性质，不是它所在的一个状态。对着模型的游走，是对着状态的游走；时钟是 store 的事。如果下面某行
`DONE WHEN` 失败了，那就是装置和引擎不一致——而*那个*，正是这一步的形状要抓的缺陷。

## 完成标准

- `kiln run jobq/3.19-property-invariants` — 九个用例通过：生成器的两个承诺、每一步之后都问一次的
  不变式（包括它根本不可能成立的那种情况）、把一次拒绝当作一步、由引擎自己的表驱动的那场游走、对着
  真实模型的性质、一个被找到并重放的埋下的缺陷，以及收缩。
- `kiln check jobq/3.19-property-invariants` — 每个 must 闸门都是绿的。
- `kiln check jobq/3.14-job-state-machine` — 那张表回答得仍然一样：这一步加了一种问它的方式，不是
  第二条规则。

## 陷阱

1. **在游走结束时才问不变式。** 它少一行代码，而它产出的反例，由这场游走播放过的每一个操作组成：那个
   失败的用例，被埋在之后随机游走加上去的噪声里。规格交给游走一条不可能成立的不变式，然后指望*一个*
   操作回来。
2. **一个不是种子函数的生成器。** `SystemTime::now()`、`RandomState`、一个 `HashMap` 的迭代顺序、
   一个线程 id——每一样都让游走每次运行都不一样，而消息里的种子于是什么也复现不出来。同一个种子出发的
   两场游走是一场游走；规格比较它们。
3. **在第一次拒绝就停下。** 它读起来像宽容，而它是反面：游走永远到不了 `failed` 或 `succeeded`，而
   那条关于终态作业的性质，因为错误的原因通过。规格走八个种子、每个四十步，并检查四个状态都到过。
4. **一个重述那张表的 `Model`。** 它今天跟 `transition` 一致，而两者中有一个被改的那一天，就是这条
   性质开始测试拷贝的那一天。规格把游走产出的每一步都通过 `transition` 重放一遍，然后比较。
5. **把被拒绝的事件从历史里丢掉。** 那条性质于是讲的是队列做了什么，而不是到达了什么，而那个模型拒绝
   一切的情况，就是这一点显形的地方。
6. **一个停在第一条更短序列上的 `shrink`。** "更短"不是契约：用例必须做到拿掉任何一个操作、失败都
   仍然存在，而规格自己逐个拿掉来检查这一点。
