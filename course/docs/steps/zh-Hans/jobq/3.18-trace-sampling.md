# 追踪一个队列：传播进 worker，以及保住尾部的采样

## 回顾

- `obs/tracing-propagation@apply`——`relay/2.19-trace-propagation`：**这些 id 是写下来的，不是一路
  传过去的。** 一次投递的 trace 存在活发生的那一行上，每一跳都有自己的 span，头部是解析出来再重新生成
  的，而不是转发的；而一个服务读不懂的头部，开启一条新 trace，而不是拒绝这个请求。这里也是同一个形状，
  而这个队列让其中每一句都更难：投递服务的 worker 是*它自己*的进程，而这个队列的 worker 可能是另一个
  二进制、在另一台主机上、由另一个部署启动。
- `obs/metrics-slo@design`——`jobq/3.17-error-budget-alerts`：**样本和日志行。** 这一步让日志行长
  大：`Attempt` 已经在写一次查询所需的、关于某次尝试的那些字段，而 trace 的字段是最后四个——trace
  id、这一跳的 span，以及这一跳是否被保留。两步是一个故事：计数器说一个队列在烧，日志行说是哪些作业、
  为什么，而 trace 把"哪些作业"变成了"哪个请求，来自哪个调用方"。
- `delivery/dlq@operate`——`jobq/3.16-dlq-tooling`：**第二个生命不会开启一条新 trace。** 一次重放把
  一个作业的行写回队列，而那一行就是 trace 住的地方——所以这些 id 原封不动地穿过重放。这不是这一步的
  偶然；它正是为什么，一次以重放收场的事故，是从提交这个作业的那个请求，到最终成功的那次尝试的一条
  trace。

## 变化

**上下文必须穿过一道对岸没有调用方的边界。** `relay/2.19` 把一个 `traceparent` 从一次 HTTP 请求
带进一次投递；那个请求是*在场*的——在它的 extensions 里、在它的 span 里——而准入它的一切都还在跑。
这里，队列就是那道边界：接受这个作业的那个请求已经返回了，跑它的 worker 可能是这个请求从没说过话的
一个副本，而一个存在 header map、task-local 或 span 里的上下文，到那时已经没了。那一行是唯一的载体
——这也是为什么这些 id 是列，而不是中间件的事。

**这个决定做两次，而这就是这一步的全部。** 人会忍不住把"采样"读成一个问题、一个答案。它是两个问题，
在两个时刻问，带着两种不同数量的信息：

- **在门口**，已知的只有 trace id，所以决定是一个*占比*——而它必须是 id 的函数，而不是时刻的函数，
  因为问同一条 trace 的两跳必须一致，而一个计数器或一个时钟会让它们不一致。它也是这个决定唯一能被
  *记录下来*的时刻：这个部署的占比是一个设置项，而一个明天会改的设置项，不能改写今天已经做过的决定；
- **在出口**，结果已知，而那恰恰是门口看不见的。**运维需要的那条 trace，是事先没人要过的那条**——
  一个失败、花光预算、成了死信的作业。所以一次失败的尝试，不管门口说了什么都要保留，而 worker 是唯一
  能做这个决定的地方。

**不允许**的是重新掷一次。一跳再去问自己的采样器，是用比门口更少的信息决定同一个问题，然后把已经
拿到的答案扔掉——而它丢掉的，正是它自己所在的那条 trace。门口的答案跟着那一行走，这一跳读它，而出口
的规则是 `door said yes || this hop failed`：一个函数，一个地方。

**一跳就是一个 span，在这里铸出来。** 上下文故意不带 span id：门口和尝试是两跳，而一个带着门口 span
的上下文，会让整个队列在瀑布图里看起来像一步。每一次尝试铸自己的 span，于是一次重试看得见是一次重试，
而不是一次很长的尝试——同一条规则，`relay/2.19` 用在订阅者边界上，这里用在一道里面有*队列*的边界上。

**缺的是 trace，不是传播。** 这个项目里没有 collector、没有 exporter，也没有 `otel` crate，而加一个
也不会让这一步讲的这件事更成立：决定是那个值，id 在行上，字段在日志行上。一个部署拿一条被保留的 trace
做什么，是它自己的事，而 `jobq/3.27-runbook-drill` 是运维练习使用它的地方。

## 作业

三个地方，而脚手架已经把第一个开了个头：

### `src/engine/trace.rs`——词汇

脚手架加了这个模块，论证已经写好，缺六个函数体：两个 id 的语法、头部的语法、采样器的决定、门口，以及
出口。**还没有任何东西声明它**——`src/engine/mod.rs` 里的再导出，就是 `jobq/3.16-dlq-tooling` 对
`dlq` 用过的形状——而在它做成之前规格不编译，这就是这一步在说它要什么。

- `TraceId` / `SpanId`——格式的语法，全小写，从不全零。一个这个 crate 不会写出来的 id，就是它不会
  接着用的 id；
- `Traceparent`——解析、`child`、`Display`：头部是解析出来再重新生成的，永远不是转发；
- `Sampler`——这个部署的占比，由 id 决定：`always`、`never`，以及一个千分比的占比。`decide` 是门口
  那段算术；
- `Context`——旅行的是什么东西：`of`（门口）、`stored`（往返里读的那一半）、`exported`（出口的
  规则），以及两个访问器；
- `Hop`——一跳：作业的上下文，加上*这次*尝试的 span。

### 那一行——载体

`Job` 多了上下文，`trace()` 跟其他访问器放在一起；`SubmitRequest` 多了 `with_trace`：知道周边上下文
的那个调用方把它建一次，引擎存下给它的东西。两个 store 都存它（`migrations/0007_traces.sql`——
**脚手架把它留成了一段论证而不是语句**，而它描述的那三个决定归你），而 `revived` 带着它穿过一次重放，
不碰它。

一个没人要求追踪的作业，**没有** trace，而不是有一个假的：在真相是"没人要过"的地方写一个 `false`，
是之后每块仪表盘都会当成真实决定的一条序列。

### 日志行——出口

`Attempt` 多了那一跳，而 worker 每次尝试铸一个（`Hop::of(&context)`）并把它传进去。日志行多了
`trace_id`、`span_id` 和 `sampled`，每一行都写，作业没有 trace 时就是空的：字段集合保持一种形状，
`sampled` 是*实际生效*的决定，而不是门口的（一次失败的尝试即使门口说了不，也显示 `true`），而这
一切让 `grep trace_id=<the id your collector showed you>` 成为一次查询。

### 有意不改的东西

`jobq/3.1`–`jobq/3.17` 认证过的一切：`--check-config` 的那些键、`draining` 那一行、退出码、CLI 的
语法和退出码、settle 的拒绝、认领的顺序、轨迹的身份、死信视图和它的拒绝，以及 `jobq/3.17` 放在日志行
上的字段。这一步加一个模块、行上的一个字段、两个列，以及日志行上的三个字段；它已经承诺过的东西一样都
不动。

  持久后端，它的两个列，就是内存 store 展示不了的全部；
- `kiln check jobq/3.18-trace-sampling` — 每个 must 闸门都是绿的；
- `kiln run jobq/3.17-error-budget-alerts` 和 `kiln run jobq/3.16-dlq-tooling` — 更早的套件仍然
  通过：这一步让日志行和行长大，不改两者任何一方的规则；
- 在你自己的一个部署上跑 `psql -c "select trace_id, trace_sampled from jobs"`：被追踪的调用方提交的
  每个作业都有一个 id，其余没有 id，而尝试失败的那些 `trace_sampled` 为 true。

## 陷阱

1. **把上下文放在 task-local 或 span 里。** 在"提交一个作业、看着尝试紧接着发生"的那个测试里，它
   管用——而尝试不会紧接着发生：它发生在另一个进程里，几分钟之后，可能是在一次重启之后。那一行是这个
   队列唯一的载体。
2. **只在出口做决定。** 只采样每个失败的作业、别的都不采，听起来比两个决定的规则更好，而它做不到：
   出口看见的是一次尝试，不是整条 trace——一条之后会失败的 trace 中间的那个成功，早就被丢掉了，而
   运维打开的瀑布图中间有一个洞。
3. **只在门口做决定。** 直觉的实现，而它丢掉的恰恰是这一步名字里的那条 trace：一个在采样关闭时提交、
   失败了三次的作业，留下三条哪里都没有 trace id 的警告，而这次事故是一串没人留下的 id。
4. **在跳上重新掷。** worker 再调一次 `Sampler::decide`，是同一个错误刷了一层新漆，而且它比只在门口
   做决定*更糟*：它碰巧有一半的 trace 跟门口一致，于是活下来的 trace 是硬币留下的那些，而门口留下的
   那些恰是它丢掉的。
5. **在 worker 那里重新生成 trace id。** "它不过是一个 id"——可现在提交的一侧和运行的一侧是两条
   trace，除了一个时间戳什么都不共享，而那就是运维手里代替瀑布图的东西。
6. **复用父的 span。** 两跳共用一个 span，让队列消失了：这次尝试看起来像提交它的那个请求的一部分，而
   作业等的那四秒，是调用方延迟里的四秒。
7. **每个作业一个 span，而不是每次尝试一个。** 一次重试是一跳。两次尝试共用一个 span，会让第二次看
   起来是第一次的延续，而那正好是重试的反面。
8. **接受全零的 id，或者大写。** `0000…` 是格式自己用来表示"没有 trace"的词：接受它，会把每一个发它
   的调用方一起放进同一条 trace，而大写对人来说是同一个 id，对每一个存它的索引来说都是不同的 id。
9. **把调用方的字节转出去。** 一个把头部原样透传的服务，会变成谁发什么都转的中继——包括那些在下一个
   系统里会坏掉的 id。解析它，留下 trace，生成你发出去的头部。
10. **trace 不是一列。** 把 id 放进载荷里，或者放进一张以作业为键的侧表，是作业身份住的第二个地方
    ——而先变旧的那一个，就是没人 join 的那一个。
