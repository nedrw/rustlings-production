# 时间是依赖：把时钟注入进来，剩下的交给编译器拒绝

## 为什么

这个引擎做的每一个决定，都是拿一个时刻去比较。这个作业到期了吗？这份租约过期了吗？那个 worker 还活着
吗？今天，每一个问题的答案都来自读操作系统的墙上时钟——一个存储里有七处调用点，另一个里有五处——而正是
这一点，让这个引擎里最有趣的那一半既没法测试，在生产上也不可靠。

可测的那一半一眼就能看见：一个动不了时间的测试套件，只能*等*着看一份租约过期、或者一个作业到期，所以它
顺利的时候慢，不顺利的时候飘，而这份飘，最终落在每一个在负载很高的机器上跑它的人头上。

生产的那一半更糟。两个 worker 各自读各自的墙上时钟，"租约过期了"就成了一条意见，而不是一个事实；而两只
时钟之间的差异——一个带着漂移的容器、一台被暂停过的虚拟机、一只被 NTP 拨过的钟——会变成重复执行的工作，
或者一个卡在那里、直到有人注意到的作业。一个进程给行盖上时间戳，另一个进程判定它已被放弃；它们俩能共同
谈论的那只时钟，只能是别人递给它们的那一只。

## 作业

- 引擎多了一个 `Clock` 端口：只有一个方法 `now()`，回答 UTC 的墙上时钟时刻；另有一个 `SystemClock`
  实现，没人另行指定时，进程用的就是它。
- 两个存储都在构造时接收自己的时钟（`MemoryStore::with_clock`、`PostgresStore::with_clock`），跟它们
  现在接收租约的方式一样——构造函数就是注入口，所以前面几步钉住的签名一个都不用动。
- **存储不许自己读墙上时钟。** 项目的 `clippy.toml` 对库代码拒绝 `chrono::Utc::now`、
  `chrono::Local::now` 和 `std::time::SystemTime::now`，而 `clippy@3` 把这条禁令变成错误。全项目只有
  `SystemClock` 一处带着写明理由的 `#[allow]`。
- 单调时钟留在它该在的地方：测量某件事花了多久是另一个问题（`std::time::Instant`），守护进程自己的关机
  截止时间也仍然用它。

## 完成标准

- `kiln run jobq/3.8-clock-injection` — 五个规格用例通过。
- `kiln check jobq/3.8-clock-injection` — 每个 must 闸门都是绿的，包括 `clippy@3`（执行禁令清单的就是它）
  和 `semver@baseline`（公开表面只多了名字）。
- 在 `app/jobq` 里跑 `cargo clippy --lib -- -D clippy::disallowed_methods` — 干净。

## 陷阱

1. 只在测试需要的地方注入时钟——一个存储里盖租约时间戳的那处照旧调用 `Utc::now()`，套件仍然通过，因为
   能抓住它的那个用例（一次必须靠时钟走到才发生的过期）正是没人写的那个。两个存储，每一个时刻。
2. 用新端口去算*时长*、取代 `std::time::Instant`——从此墙上时钟一往回调，关机截止时间也跟着往回走，一个
   被要求停下的进程要花一个小时才停得下来。时刻用墙上时钟，间隔用单调时钟。
3. 把注入的时钟当成到处传的 `DateTime<Utc>`（把"现在"当成一个值）——那样每个调用点都得被塞一个新时刻，
   而存储自己在同一次操作里的几次比较会各说各话。端口是*问的时候才回答*的。
4. 给某个存储模块加上 `#[allow(clippy::disallowed_methods)]`——禁令清单就是执行机制，一个不写在
   `SystemClock` 上的 allow，等于把这条规则一个文件一个文件地删掉。
5. 让默认时钟隐式存在，但*是错的*：`MemoryStore::new()` 必须能在完全没有时钟的情况下继续工作，因为前面
   每一步都是那样构造它的（`jobq/3.1-engine-boundary` 和一致性套件都是）。

## 延伸阅读

- `chrono::DateTime<Utc>` 与 `std::time::Instant` — 程序保存的两种时间，以及标准库为什么只把其中一种当作
  墙上时钟提供。
- Clippy lint 清单里的 `clippy::disallowed_methods` — 这一步的 `clippy.toml` 写下的那段配置，包括路径
  该怎么拼。
- `docs/authoring.md` §7.4 — 这条禁令为什么只针对库目标（引擎住的地方），而不管测试目标。
- `jobq/3.7-leases-and-recovery` — 那一步的租约，这一步把它的过期判断挪到注入的时钟上；没有这一步，那一步
  关于恢复的承诺，上限就是参与其中的那几只时钟。
