# 只往允许去的地方投递：目标校验

## 为什么

订阅者就是一个 URL，而选它的是*租户*。这个服务的全部内容就是：有人注册，填上
`https://their-app.example/hooks`，然后这个进程就对他们敲进去的任何东西发 HTTP 请求。所以有意思的问
题不是"我们能不能到达它"，而是**"同一个请求还能把我们带到别的什么地方去"**。

在这类真实事故里，答案每一次都是部署自己的网络：

- **元数据端点。** 每家云厂商都在一个固定地址上发放实例凭据——`169.254.169.254`，IPv6 那边是
  `fd00:ec2::254`。它就在链路本地段里，不需要任何认证，任何能从实例内部发出一个 HTTP 请求的人，都能把
  角色的凭据读出来。一个肯去拨租户敲进来的任何 URL 的 webhook 服务，就是那一个请求；
- **进程自己的邻居。** `127.0.0.1` 上住着管理端口、健康端点和指标导出器；数据库和内部服务在
  `10.0.0.0/8`、`172.16/12` 和 `192.168/16` 里。它们之所以够得着，*恰恰因为*它们假定网络外面没有人能发问；
- **而失败是无声的。** 一次发往内部地址、回了 `200` 的投递，会被记成已投递。日志里没有任何地方看着不对：
  一个租户正在调用元数据服务，而服务还挺得意。

这一步所基于的那个客户端——`outbound/http-client@apply`，第 `relay/2.7-outbound-client` 步——讲的是
*时间*：三个截止时间、连接复用，以及一个数跳数、遇到环就拒绝的重定向策略。那些这里都不重讲，也都不是问
题所在。`relay/2.7` 决定一次尝试可以花多久、能跟多远；这一步决定**它到底能不能发生**。

而这个判断有一个形状，几乎能逮住每一次初次的尝试：

> URL 不是地址。

`http://evil.example/hook` 对字节最终去哪儿一字不说。地址由对该名字作答的那一方在建立连接的那一刻决
定——而那是攻击者挑选的一方。经典 bug 是这样一个检查：解析这个名字，满意了，然后把*名字*交给 HTTP 客
户端，客户端又解析了**一遍**。攻击者对第一个问题回一个公网地址，对第二个回 `169.254.169.254`。两次回
答之间的窗口就是整个攻击，它有个名字：DNS rebinding。

## 任务

脚手架加了 `src/target.rs`：类型、端口，以及函数体是 `todo!()` 的签名。里面的一切都是
`target::Rules` 的——一次部署愿意跟谁说话——外加两个回答不同问题的检查。

### `src/lib.rs` 与 `src/target.rs`

声明模块，然后实现：

- `Class::of(address)`——一个地址的分类：`Public`、`Loopback`、`Private`、`LinkLocal` 或 `Metadata`。
  IPv4、IPv6，以及 **IPv6 地址里的那个 IPv4 地址**（`::ffff:127.0.0.1` 是戴了顶帽子的 `127.0.0.1`，只
  读文本的检查两个都看不见）；包含元数据端点的链路本地段（先把那一个地址查掉：一份放行整个 `/16` 邻居
  的允许清单，仍然拒绝那个用凭据作答的地址）；`100.64.0.0/10`、组播，以及留给文档和基准测试的段，一律
  算作非公网。`Class::as_str` 就是最后落进运维 `last_error` 里的那个词。
- `host_of(url)`——一个目标的 host 和端口，或者这段 authority 为什么成不了一个目标。形状只有两种：带方
  括号的 IPv6 字面量（`[::1]:8443`），以及其余一切；**方括号存在，是因为地址里的冒号不是端口分隔符**，
  而带着凭据的 authority（`http://user@host/`）会被拒绝，不会被解析。名字只规范化一次——小写、去掉
  末尾的点——被解析、被判断的都是规范化后的那个形式。
- `check_name(name)`——那些只可能指"这里"的名字：`localhost`、`*.localhost`、`*.local`、`*.internal`。
- `Rules`——四个开关（loopback、private、link-local、metadata）、`permissive()`（什么都不拒绝）、
  `public_only()`（只要公网）、`allows()`、`allows_local_names()` 和 `check()`。`Rules::of(&Config)`
  是部署自己的那一份：**`delivery.allow_private_targets` 默认是关的，除非部署自己把它打开**。
- `check(url, rules)`——注册阶段*不解析任何东西*就能判定的一切：authority 的形状、一个字面量地址，以及
  一个意思就是"这里"的名字。
- `Resolver`——那个端口：host 在这里变成地址，而它之所以是个端口，是因为测试没法让一个真正的名字服务对
  着检查回答一套、对着连接回答另一套。`System` 是部署用的实现，建在 `tokio::net::lookup_host` 上。
- `pin(host, rules, resolver)`——**只解析一次**，检查这个名字答出的*每一个*地址，然后回客户端即将连接的
  那个 `SocketAddr`。`Unreachable::Refused` 是一个判断，`Unreachable::Unresolved` 是一次失败；调用方对
  这两者的处理不一样。
- `Unreachable` 与 `Refusal`——一个目标为什么不是这个服务会去够的那一个，用点出地址和规则的话说出来
  （`"10.0.0.5 is a private address…"`、`"…is a metadata address…"`、
  `"`localhost` is a name that means this machine…"`）。`Refusal::kind()` 是那个稳定的标记。

### `src/config.rs`

加一个 `delivery` 段，带 `allow_private_targets: bool`，来源是 `delivery.allow_private_targets`（文件）
或 `RELAY__DELIVERY__ALLOW_PRIVATE_TARGETS`（环境变量），**默认 `false`**，走和其他每一个设置项一样
的分层去读，不是布尔值就拒绝。在 `--check-config` 里报告它（`delivery.allow_private_targets = false`）。

### `src/outbound.rs`

- `Policy` 多出一个 `targets: Rules`。`Policy::default()` 必须保持*宽松*：库的调用方和测试构建的都是这
  个值，而这条 track 自己的规格（以及 `relay/2.7` 的）拨的是 `127.0.0.1` 上一个脚本化的服务器。服务的
  规则来自 `Policy::of(&Config)`。
- `Client::resolving(policy, resolver)`——一个通过注入的 `Arc<dyn Resolver>` 解析名字的客户端；
  `Client::new` 仍然用 `System`。
- 连接路径：用 `target::host_of` 拆出 authority，用 `target::pin` 拿到地址，然后**连到那个地址上**。检
  查和 socket 之间，没有任何东西再去问名字服务。
- 两类失败分开归类：拒绝是 `Outcome::Permanent`（再试一次会解析同一个名字、问同一条规则——那是一个判断，
  投递带着一条读得懂的理由埋进 `dead_letters`），而名字服务没有作答，仍然是 `Outcome::Retryable`，和任
  何别的、对订阅者不置一词的失败一样。

### `src/http.rs` 与 `src/openapi.rs`

`POST /endpoints` 跑 `target::check(&url, &Rules::of(state.config()))`，拒绝时回 **`422`**、
`error = "target_rejected"`——那是对一个被读懂的 URL 做出的策略判断，不是一个没被读懂的 body 的 `400`。
把这个状态码加进文档：`relay/2.3-contract-first` 的规则是，一条路由能回的每一个状态码都得有 schema。

## 完成标准

- `kiln run relay/2.12-ssrf-defense` — 规格通过
- `kiln check relay/2.12-ssrf-defense` — 每个 must 闸门都是绿的
- `cargo test --test spec_ssrf -- --nocapture`——九个用例：注册边界、拒绝的 URL 与拒绝的地址这两张矩阵、
  rebinding 的夹具、重定向的那一跳，以及配置构建出来的发送方
- `RELAY__DATABASE__URL=… RELAY__BOOTSTRAP__TENANTS=acme=… cargo run -- --check-config | grep delivery`——
  设置项在报告里，而且是 `false`
- `curl -sS -o- -w '%{http_code}\n' -X POST localhost:8080/endpoints -H 'Authorization: Bearer …' -d '{"url":"http://169.254.169.254/latest/meta-data/"}'`——
  `422`，而且 body 点名了那个地址

## 陷阱

1. **查了名字，然后又连着名字去连。** 检查解析了一次，满意了，接着
   `TcpStream::connect(("evil.example", 80))` 又解析了*一遍*——第二个回答是攻击者的。代码看着哪儿都没错，
   而能抓住它的测试得把解析器驱动两次。规格就是这么做的：一个先答公网地址、再答 `10.0.0.5` 的名字，必须
   只被问一次。
2. **用 `split(':')` 从 authority 里读 host。** `http://[::1]:9/hook` 于是读出来的 host 是 `[`，检查通
   过，连接落到回环接口上——方括号存在的意义，恰恰是不让地址里的冒号被当成端口。同一类 bug：
   `http://public.example@127.0.0.1/hook`，`@` 前面那部分是攻击者挑的一个用户名。
3. **只拒绝 IPv4。** `http://[::1]/`、`http://[fd00::1]/`，以及每个 IPv4 地址的 `::ffff:` 写法，是同一
   个协议换代之后的同一批地址，而 `::ffff:169.254.169.254` 就是戴了顶帽子的元数据端点。一个 `Ipv4Addr`
   分支写了、另一个分支是 `todo!()` 的分类器，是一个留着绕行路线的分类器。
4. **把投递时的检查变成唯一的检查，或者把注册时的检查变成唯一的。** 只在投递时查，意味着租户注册了一个
   永远不可能成功的目标，再从 `dead_letters` 里知道；只在注册时查，意味着一个会改答案的名字大摇大摆地走
   进来。两个检查，两个问题，文件里写明了哪个是哪个。
5. **把 `Policy::default()` 改严。** 每一个拨 `127.0.0.1` 上脚本化目标的测试都构建它，所以一个严的默认
   值会让 `relay/2.7` 的十个用例在最终代码上变红——失败看着像客户端坏了，而不像一条安全判断。严格属于部
   署，写在 `Policy::of` 里，那也是唯一一份可以配置的。
6. **把拒绝归成可重试。** 于是 `127.0.0.1` 被重试到预算用尽，订阅者被一堆永远投不出去的请求反复捶打，而
   死信说的是 "gave up after N attempts"，而不是点名那个地址。
7. **解析出的地址里*任意一个*是内部的就拒绝——或者反过来，去连那个不是的。** 一个既答公网地址、*又*答内
   部地址的名字，是这个服务根本不会去拨的名字：挑自己喜欢的地址，就是挑攻击者想要的那个地址，而把"有一
   个地址没过"和"有一个地址过了"搅在一起，正是一个检查变成抛硬币的方式。
8. **忘了重定向是第二个问题。** `Location` 是陌生人的指令。查这一跳很便宜，而这一跳恰恰是攻击者第一次不
   会发的；链上每一跳都要过同一套规则，这也是这里没有"第一跳"例外的原因。
9. **悄悄变成 false 的设置项。** 把 `RELAY__DELIVERY__ALLOW_PRIVATE_TARGETS=1n` 读成"没匹配上 `true`，
   所以是 false"，就把部署的一次有意决定变成了它写下的反面。值在读的地方解析，而不是布尔值的文本就是一
   次配置错误。
10. **把 `delivery.allow_private_targets` 读成"SSRF 检查"。** 它不是那个检查的开关——检查无论如何都跑，只
    是规则不同。这个设置项改变的，是部署把谁当作订阅者；它存在，是因为一个测试（以及一个躲在网络边界后面
    的部署）本来就可能有 `127.0.0.1` 上的订阅者。

## 延伸阅读

- [OWASP: server-side request forgery](https://owasp.org/www-community/attacks/Server_Side_Request_Forgery)
  ——这一步讲的那个攻击，以及一张读起来像本文件"陷阱"一节的绕过清单
- [RFC 6761 §6.3](https://www.rfc-editor.org/rfc/rfc6761.html#section-6.3) ——`localhost` 被定义为指回
  环接口，这也是拒绝这个*名字*不需要任何解析的原因
- [AWS: instance metadata and user data](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-metadata.html)
  ——`169.254.169.254` 和 `fd00:ec2::254`，以及一个被攻破的注册流程能对它们发的每一个请求
- [RFC 6890](https://www.rfc-editor.org/rfc/rfc6890.html) ——特殊用途地址段的登记表，`Class::of` 就是它
  的一份实现
- [Rust: `Ipv6Addr::to_ipv4_mapped`](https://doc.rust-lang.org/std/net/struct.Ipv6Addr.html#method.to_ipv4_mapped)
  ——`::ffff:` 这种写法，按标准库自己的话
- [MDN: `URL`](https://developer.mozilla.org/en-US/docs/Web/API/URL) ——userinfo、带方括号的 IPv6 host，
  以及一段 authority 由什么拼成
- [`tokio::net::lookup_host`](https://docs.rs/tokio/1.53.1/tokio/net/fn.lookup_host.html) ——`System`
  拿它解析，以及为什么它答的是一个*列表*
